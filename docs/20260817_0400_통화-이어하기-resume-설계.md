## 0. 무엇을 만드나

```
5분쯤 비버 발화가 끝나면
  → 소켓 종료 → 화면 정지 + 모달(기존 "구독하기/통화종료" 재사용)
  → "구독하기" 누르면 → 새 WS 연결 → 비버가 이어서 첫 마디
  → 최대 3조각 = 15분
```

**왜 하나**: 프론트에서 5분이 넘으면 목소리가 느려지거나 끊긴다. 전화를 끊었다 다시 걸면 그 증상이 사라진다.

⚠ **성공 판정 기준을 정확히 잡아야 한다.** websocket 에이전트가 클라 코드 주석에서 인용한 실측이 있다 —
`cascade_experiment.dart:62` 에 *"6분 통화에서 빈채널왕복이 4ms → 1,443ms 로 선형 증가"* 가 기록돼 있고,
용의자는 **마이크 레코더/플랫폼 채널 적체**다. 소켓·Live 세션은 그 곡선에 없다.

⇒ 그렇다면 증상을 고치는 활성성분은 **"소켓 재연결"이 아니라 "클라 오디오 파이프라인 재시작"** 이다.
**이 설계의 성공 판정은 "재연결했다"가 아니라 "6분 이후 지연이 사라졌다"로 잡는다.**
⛔ 나중에 클라가 "빠르게 하려고 파이프라인을 유지"하는 최적화를 넣으면 증상이 조용히 돌아온다.
그 사실을 클라 판넬에 명시적으로 넘긴다.

## 3. ⛔ 가장 중요한 발견 — "통화"는 코드에서 **"한 자리(sitting)"의 대용치**다

조각화는 이 대용치를 **조용히 3배로 희석**한다. 실측 소비처:

| 소비처 | 위치 | 조각화 후 | 성격 |
|---|---|---|---|
| fast-track ④ `before_first_mention` | `normalcall_service.py:1372` | **무조건 True** | ⛔ 데이터 오염 |
| 순증 상한 `NET_GAIN_CAP_PER_CALL` 2.0 | `mastery_service.py:53` | 6.0 | ⛔ 데이터 오염 |
| 인용 dedup `seen` | `normalcall_service.py` 검증부 | 같은 문장 3회 인정 | ⛔ 데이터 오염 |
| INTRODUCED→PRACTICING `prev_last_call != call_id` | `mastery_service.py:302-307` | 한 자리 안에서 승격 | ⛔ 데이터 오염 |
| SEL3 쿨다운 2통화 | `mastery_repository.py:288-306` | 0.67자리 | ⚠ 선별 품질 |
| G4 창 "최근 5 증거통화" | `mastery_service.py:504` | 1.67자리 | ⚠ 선별 품질 |
| 브리지 "증거통화 3회" | `mastery_repository.py:260` | 1자리 | ⚠ 선별 품질 |
| `_load_history` summaries 5건 | `normalcall_service.py:320` | 오늘 하루로 도배 | ⚠ 프롬프트 품질 |
| 통화 목록·평균 통화시간 | `call_repository.py:40` | 하루 3줄, 평균 15분→5분 | ⚠ 지표 왜곡 |

### ⭐ fast-track 구멍 — 오케스트레이터가 직접 확인

```python
# normalcall_service.py:1372
before_first_mention = (mention_pos is None or pos < mention_pos)
```

조각2의 전사에는 **조각1의 비버 발화가 없다** → `mention_pos is None` → **무조건 True**.

⇒ **조각1에서 비버가 가르친 표현을 조각2에서 두 번 쓰면 "비버가 말하기 전에 스스로 썼다"로 판정된다.**
fast-track 은 마스터 3조건을 통째로 건너뛰므로 **하루 만에 MASTERED(미확정) 직행**이다.
지금 15분 단일 통화에서는 이 가드가 **정상 작동 중**이고, 조각화가 그걸 깬다.

### 해법 — `root_call_id` 하나로 전부 푼다

```sql
call.root_call_id   BIGINT NULL   -- 조각 체인의 뿌리. NULL = 단독 통화 또는 첫 조각
call.fragment_index SMALLINT      -- 0=첫 조각. 연장 횟수 = 이 값
UNIQUE (root_call_id, fragment_index) WHERE root_call_id IS NOT NULL   -- 멱등의 심판
```

집계를 `COALESCE(root_call_id, call_id)` distinct 로 바꾸면 **파라미터 값을 하나도 안 바꾸고** 의미가 복원된다.
⭐ 과거 데이터는 root=NULL → 자기 자신 → **재계산 결과 불변. 백필 불필요.**

⭐ architect·mastery 두 에이전트가 **서로 모른 채 같은 컬럼을 제안**했다. 강한 신호다.

## 4. v1 범위 — 무엇을 지금 막고 무엇을 미루나

에이전트 둘이 갈렸다. architect 는 "v1 수용 + 계측"(유료 0명), mastery 는 "지금 막아라".

**오케스트레이터 판정: 데이터를 오염시키는 것만 v1, 나머지는 계측 후.**
근거 — 선별 품질 저하는 되돌릴 수 있지만, **가짜 MASTERED 는 되돌리기 어렵다**(오늘 634행을 지운 그 일).

| v1 필수 (데이터 오염) | v1 제외 (품질만) |
|---|---|
| fast-track 가드 창을 **세션 전사**로 | SEL3 → 세션 단위 |
| 순증 상한 `NET_GAIN_CAP_PER_CALL` → **세션당 2.0** | G4 창 / 브리지 / 버벅임 |
| 인용 dedup `seen` → **세션 누적** | `_load_history` summaries |
| INTRODUCED→PRACTICING 의 `prev_last_call` → **세션 비교** | 통화 목록·평균 통화시간 |

⛔ **파라미터 값은 하나도 바꾸지 않는다. 단위만 통화 → 세션.** ★게이밍 방어 고정 원칙 유지.

⚠ 단 **인용 매칭 창은 조각 유지** — 다른 조각의 발화가 이번 조각 증거로 둔갑하면 이중 적립이다.
**가드 창만 세션, 적립 창은 조각.**

## 5. 프로토콜 계약

### 클라 → 서버 (필드 1개)
```python
class ClientStart(BaseModel):
    ...기존 전부 유지...
    resume_call_id: int | None = None   # None(구버전 포함) = 새 통화 = 기존 경로
```
별도 핸드셰이크를 만들지 않는다 — `_read_initial_start` 는 6프레임/2초 상태기계라 복제 비용이 크다.

### 서버 → 클라 (신규 타입 1개)
```python
class ServerCallMeta(BaseModel):
    type: Literal["call_meta"] = "call_meta"
    call_id: str
    fragment_index: int = 0
    extensions_left: int = 0     # ⭐ 클라 모달 분기는 이 값만 본다 (플랜 해석 금지)
    fragment_seconds: int
```

⭐ **call_id 를 시작 시점에 준다.** `call_ended` 를 못 받고 끊긴 조각도 이어하기 기준점을 가져야 한다.

⭐ **전송 조건**: `extensions_left > 0 or fragment_index > 0` 일 때만
→ **Free 의 일반 통화는 프레임이 1개도 안 는다(바이트 동일).**

⛔ `ServerCallStarted` 를 확장하지 마라 — 그건 `create_call` **이전**에 나간다. call_id 를 실으려면
순서를 옮겨야 하고, 그러면 아바타 표시가 DB 왕복 3회만큼 늦어진다.

⭐ **모달 분기를 서버가 정한다.** `character_id`·`target_language` 를 클라가 정하다 터진
그 계열(`protocol.py:41-65`, 통화 701건 중 421건 엉뚱한 캐릭터)을 반복하지 않는다.

### 거절 계약
기존 `DAILY_LIMIT` 선례와 동일 — `ServerError(code, message, recoverable=False)` 후 close.
**call 행 미생성 · Live open 0 · Gemini 비용 0.**

| code | 조건 | 클라 동작 |
|---|---|---|
| `RESUME_NOT_ALLOWED` | Free | 구독 유도 유지 |
| `RESUME_LIMIT` | 횟수 소진 | "통화종료"만 |
| `RESUME_EXPIRED` | TTL 초과 | resume 없이 재연결 = 새 통화 |
| `RESUME_INVALID` | 없음/타인/level_test/중복 | 홈으로 |

⛔ **정책 거절은 절대 "새 통화로 자동 전환" 하지 않는다** — 조용히 일일 한도·과금을 소모하는 게 더 나쁘다.
반대로 **기술적 실패**(스냅샷 없음)는 거절이 아니라 **강등 진행**이다(R5).

## 6. 선별 스냅샷 — 왜 DB 여야 하나

⛔ **인메모리 불가.** 새 WS 는 **다른 Cloud Run 인스턴스**로 갈 수 있다(세션 어피니티 없음).

```
call_resume_context (신설)
  call_id  PK/FK → call ON DELETE CASCADE
  payload  JSONB   ≈4~6KB
```

⭐ **`call` 컬럼이 아니라 별도 테이블인 이유**: `call` 은 목록·상세에서 전체 컬럼 로드가 도는
뜨거운 테이블이다. 5KB JSONB 를 얹으면 통화 목록 20건에 100KB 가 딸려온다.

⭐ **시작 시점에 저장한다** (종료 시점 아님). 조각이 어떻게 죽든 목록이 남아야 한다 —
종료 시 저장은 "정상 종료 경로에서만 존재하는 데이터"가 되고, 그건 **이어하기가 가장 필요한
상황(비정상 종료)에서 없다.**

⭐ **연장 예산이 남은 회원만 저장** → Free 는 한 행도 안 쓴다.

## 8. 대화 설계 — 비버는 조각 경계를 몰라야 한다

### 경계에서 아무 말도 주입하지 않는다

⛔ **"잠깐만" 같은 대기 발화조차 금지.** 이 프로젝트 사고 3건이 전부
*"서버가 중단/종료 개념을 주입 → 모델이 실행"* 이었다:

- `call_id=870` — 프롬프트에 "본편을 끝내면"을 썼더니 **4분 24초에 자체 종료**
- `call 683` — 재접지 슬롯에 "그만할래요"가 섞이자 **30초 뒤 작별**
- `build_continue_reminder` 주석: ***"끝내지 마라"조차 쓰면 안 된다 — 금지어가 곧 씨앗이 됐다***

⭐ 그리고 **경계를 "자연스러운 지점"에 맞추려 하지 마라.** 시퀀스가 깨끗이 닫힌 자리에서 멈추면
그게 진짜 끝처럼 읽힌다. **미완의 질문 한가운데서 멈추면 그 미완성이 재개의 연료**가 된다.
기본 지시문이 이미 모든 비버 턴을 질문으로 착지시키므로(`persona_prompt.py:170`)
컷의 지배적 케이스는 자동으로 그 모양이다.

### 종료 사유별로 갈린다

| 사유 | 조각 1·2 | 조각 3(마지막) |
|---|---|---|
| 5분 시계 만료 | **무음 컷** — 주입 0 | 기존 종료 시드 **무수정** |
| 무음 3단 | **그대로 작별** | 그대로 |
| GoAway 스왑 불가 | **그대로 작별** | 그대로 |

⛔ **조각3도 비버에겐 1·2와 완전히 동일하다.** "이번이 마지막"을 알려주는 순간 870 재발이다.
차이는 100% 서버측이다.

### ⛔ 종료 시드 주입구가 여러 곳이다

```
call_session.py  2235 · 2310 · 2503 · 2571   ← 호출부 4곳 (오케스트레이터 직접 확인)
```
호출부마다 분기하면 **반드시 하나를 빠뜨린다.**
⇒ **관문을 `_inject_close_seed` 첫 줄 하나로 만든다.** 조각 모드면 발화 주입 없이 종료 경로로.
그러면 4곳 전부가 자동으로 옳게 동작하고 종료 규약의 단일 소유권 가드도 그대로 산다.

### 재개 첫 마디 — 금지가 아니라 **첫 행동 지정**

⛔ "인사하지 마라"는 인사 개념을 활성화한다(종료 어휘에서 이미 3번 당한 메커니즘).
⭐ 대신 **슬롯을 채워버린다**: `네 첫마디는 학습자에게 던지는 질문 하나다`.
질문으로 시작하라고 못박으면 인사가 들어갈 자리가 물리적으로 없다.

⭐ **모드 재질문도 금지가 아니라 상태 제공으로 막는다** — 시드가 `지금 다루는 것: {항목}` 을 주면
되묻는 게 비정합이 된다.

⭐ **시제 고정**: `하던`·`했었` 같은 과거형은 단절을 함의한다. 전부 `너는 지금 대화하는 중이다`.

### 공백은 마킹하지 않는다

⛔ "어디 갔었어?" 금지 — ①해명을 요구하는데 왕초보는 사과를 못 한다 ②사실이 아니다(사용자는
버튼을 눌렀다) ③간극을 대화 사건으로 승격시켜 위 전제를 스스로 파괴한다.

⇒ 비버는 gap 값에 **접근하지 못한다.** 서버가 계산해서 **시드 종류만** 고른다.

| gap | 서버 동작 |
|---|---|
| <45초 | 짧은 재제시 또는 항목 전진 |
| 45초~5분 | 문장을 한 번 더 또박또박(재제시는 원래 하는 일이라 티가 안 난다) |
| >5분 | **이어하기 제안 자체를 접는다** — "지금 대화 중"이라는 전제가 거짓이 되는 지점 |

### ⛔ 슬롯 위생 — 마지막 비버 발화 원문을 넣지 마라

⭐ **conversation-design 이 새로 찾은 위험**: L1 청크를 가르치던 중 컷되면 그 원문이
**"안녕히 가세요"** 다. 그걸 시드에 인용하면 **서버가 조각 경계에서 작별 문장을 제어 메시지로
주입**하게 된다 — 683의 자리 + 870의 맥락이 겹친다.

⇒ 원문을 인용하지 말고 **"아직 답 안 나온 질문"이라는 지시만** 주고 원문은 모델이 자기
컨텍스트에서 꺼내게 한다.

| 슬롯 | denylist | 근거 |
|---|---|---|
| `topic` | **건다** | 사이드카 자유 문자열 = call 683 이 난 자리 |
| `covered`·항목 라벨 | **걸지 않는다** | 2026-08-16 확인 — 걸었더니 L1 청크 "안녕히 가세요"가 사라져 비버가 이미 가르친 걸 또 가르쳤다 |
| 마지막 비버 발화 원문 | ⛔ **슬롯 자체를 만들지 마라** | 위 |

## 8-b. ⭐ 세션 재연결 기계를 **없앤다** (2026-08-17 사장님 지시)

15분 통화를 한 세션으로 버티려고 만든 세대 루프는, 조각이 5분이면 **사장(死藏) 코드**다.

### 데이터 — 실제로 언제 도는가 (라이브 56건)

```
재연결 0회   53건   길이 0~508초
재연결 1회    3건   길이 496 · 512 · 536초      ← 전부 8분 이상

⭐ 5분 30초 이하 48건 중 재연결 발생: 0건
```

난 3건은 정확히 `SESSION_ROTATE_AT_S = 480.0`(8분) 회전 시계가 돈 것이다.

### 트리거 3개의 처리

주석(`call_session.py:130-133`)이 명시: *"스왑 트리거는 GoAway 가 **아니라** 이 시계다.
GoAway 는 보조 트리거, 스트림 종료는 폴백."*

| 트리거 | 5분 조각에서 | 처리 |
|---|---|---|
| 회전 시계 480s | **절대 안 돈다** | 통째로 제거 |
| GoAway | 시간 무관하게 올 수 있음 | ⭐ **조각 조기 종료 + 이어하기 모달** |
| 스트림 예고없는 종료 | 시간 무관 | ⭐ 같음 |

⭐⭐ **핵심 통찰: 이어하기가 재연결을 대체한다.** GoAway 가 4분에 와도 재연결로 살릴 필요가 없다 —
조각을 거기서 끝내고 "이어서 하시겠습니까?"를 띄우면 사용자가 새 세션으로 잇는다.
이어하기가 하는 일이 정확히 그것이다.

### 제거 대상

```
_watch_session_rotate        회전 시계 워처
_swap_eligible               자격 판정 (호출 3곳)
SESSION_ROTATE_AT_S / MAX_RECONNECTS / RECONNECT_MIN_REMAINING_S / SWAP_FLAP_GUARD_S
세대 루프(_run_one_generation 반복) → 단일 세션
resume_handle 영속화 고민     (애초에 안 하기로 했지만 코드도 사라짐)
```

⭐ **이게 없애는 가장 큰 것**: websocket 에이전트가 최우선 위험으로 꼽은
*"두 층(기존 재연결 ↔ 이어하기)이 겹칠 때"* 라는 질문 **자체가 사라진다.**

⚠ **대가**: 지금은 GoAway 를 사용자 모르게 넘겼는데 앞으로는 모달이 뜬다.
5분 통화 GoAway 관측 0건이라 실害는 없어 보이나, **0건이 "없다"는 뜻은 아니다.**
⇒ GoAway 조기 종료를 **로그로 계측**하고, 유의미하게 잦으면 그때 재도입을 재검토한다.

⚠ **회귀**: `test_normalcall_ws.py` 의 `test_reconnect_*` 4건과
`test_reconnect_closes_previous_session` 은 **지우지 말고 뒤집어라** —
"회전 시계가 돌지 않는다" · "GoAway 는 스왑이 아니라 조각 종료로 간다"로.

## 9. WS·타이밍

- **소켓은 서버가 닫는다** — 현행 `_finish_call` 그대로, close code 1000.
  ⛔ 커스텀 close code 금지: 클라는 `call_ended` 를 받으면 `_expectClose` 를 세우고 조용히 넘긴다.
  사유는 **JSON `call_ended.reason`** 에 싣는다 — 구버전 앱은 `reason` 을 안 보고 그냥 끝낸다(안전한 폴백).
  ⛔ 새 타입(`type:"segment_end"`)을 만들면 구버전 앱의 `default: break` 에 걸려 **통화가 안 끝나고 멈춘다.**

- **클라는 `call_ended` 를 받고 닫아라.** 서버는 전사 커밋 → 분석 트리거 → `call_ended` 순서다.
  먼저 닫으면 **마지막 최대 60초치 전사가 커밋 전**일 수 있고, 그 꼬리가 브리프에서 통째로 빠진다.

- **재연결 공백 3~5초 추정** (서버 실측 2.2s 중앙 + 클라 2.8s).
  ⚠ 3초 이내면 "잠깐 끊긴 느낌", 5초 넘으면 "전화가 끊겼나?"다. **경계선이다.**
  통화 화면을 유지하고(종료 화면으로 가면 안 된다) 별도 phase 가 필요하다.

- ⛔ **예산·백스톱이 조각마다 리셋된다.** 절대 백스톱 540s 는 조각당이라 3조각이면 **최대 27분**
  Live 과금이 논리적으로 가능하고, 체인 전체를 막는 상한이 코드 어디에도 없다.
  ⇒ **체인 상한을 DB로 판정한다** — 첫 조각 `call_date` 기준 경과가 상한을 넘으면 거절.

- **원가는 오히려 내려간다**: 조각을 새로 시작하면 컨텍스트가 4,600대로 리셋된다.
  실측(2026-08-16) 5분 $0.19 × 3 = **$0.57** ≈ 연속 15분 $0.56. 손해 없음.
