## 1. ⛔ 앱팀이 안 적은 진짜 병목 — **`purchase_token` 을 저장하지 않는다**

`iap_receipt`·`subscribe` **어디에도 없다.** 토큰은 요청 → `verify()` → `acknowledge()` 로
흘러가고 **버려진다**(`iap_service.py:107`·`:208` 이 전부).

⇒ **두 방안 다 이것 없이는 불가능하다.** 스토어에 다시 물으려면 토큰이 있어야 한다.
⇒ RTDN 도 안 된다: 알림에 토큰은 실려 오지만 **토큰 → 회원** 매핑이 필요하고, 그 매핑이
   저장된 토큰이다. (09-28 이후 구매는 `obfuscatedExternalAccountId` 로도 되지만 **그 전
   구매는 안 된다** — 지금 만료된 4건이 정확히 그 전 구매다.)

## 2. ⭐ 좋은 소식 — 재조회 코드는 이미 있다

`core/iap.py:215` `_verify_google` 이 이미 `purchases/subscriptionsv2/tokens/{token}` 을
GET 해서 `subscriptionState` 를 보고 `expiryTime` 을 `VerifyResult.expires_at` 로 돌려준다.
애플도 `_verify_apple`(`:409`)이 같은 모양이다.

⇒ **재조회 = 같은 `verify()` 를 다시 부르는 것.** 새 스토어 API 코드가 필요 없다.
⇒ 상태 매핑도 공짜다: 갱신됐으면 `ok=True` + 새 `expires_at`, 끝났으면 `reason="invalid"`.

## 3. 설계 — 입구 3개, 갱신 함수 1개

```
                    ┌──────────────────────────────────────┐
읽을 때(2단계) ───→ │  refresh_from_store(receipt)          │
스케줄 스윕(3단계) ─→ │   = iap.verify() 재호출 → 결과 반영   │ ──→ subscribe.end_date
스토어 알림(4단계) ─→ │  ⭐ 알림 본문은 절대 안 믿는다        │       billing_state
                    └──────────────────────────────────────┘
```
⭐ **알림은 트리거일 뿐, 진실은 항상 스토어 재조회다.** 그래서 세 입구가 한 함수를 공유한다.

### 1단계 — 토큰 보존 (전제)
- `iap_receipt.purchase_token` Text **NULL** + 인덱스(RTDN 이 토큰으로 찾아온다).
- `iap_receipt.last_store_check_at` DateTime(tz) NULL — 재조회 쓰로틀용.
- ⛔ **기존 5행 백필 불가** — 토큰이 어디에도 없다. 그 회원들은 앱 「구매 복원」을 한 번
  누르면 채워진다(앱에 이미 있는 기능 · 전부 샌드박스 테스트 계정이라 실손 0).
- ⛔ 토큰은 **로그에 찍지 않는다**(스토어 자격에 준한다). 기존 로그도 토큰을 안 찍는지 확인.

### 2단계 — 읽을 때 자기치유 ⇒ **이것만으로 출시 차단이 풀린다**
`/subscriptions/status` · `/purchases/entitlement` 에서, `source='store'` · `end_date` 지남
· 토큰 있음 · 쓰로틀 통과이면 `verify()` 재호출:

| 결과 | 처리 |
|---|---|
| `ok=True` | `end_date = expires_at` 갱신 → **갱신 반영 완료** |
| `reason='invalid'` | 진짜 끝(해지·환불·만료) → 지금과 같이 Free |
| `reason='unavailable'` | ⛔ **박탈하지 않는다.** 저장값 그대로 + 다음에 재시도 |

⛔ 마지막 줄이 핵심이다 — 스토어가 잠깐 죽었다고 유료 회원을 Free 로 떨구면 안 된다.
⛔ **통화 경로(`entitlements.effective_plan`)에는 스토어 호출을 넣지 않는다.** 통화 시작마다
   외부 네트워크가 끼면 통화가 스토어 장애에 묶인다. 앱이 시작할 때 상태를 읽으니 거기서
   치유되고, 통화는 치유된 저장값을 읽는다.
- 쓰로틀 `IAP_RECHECK_MIN_INTERVAL_S`(기본 3600). 진짜 해지한 회원은 매 호출 재조회가
  되므로 필요하다.

### 3단계 — 스케줄 스윕 (앱을 안 열어도 반영)
`POST /internal/refresh-subscriptions` — 기존 `/internal/dispatch-calls` 의 인증·스케줄러
패턴을 그대로 재사용한다. 만료됐고 토큰 있는 `source='store'` 행만 훑는다.
⇒ 환불·해지가 앱을 안 열어도 반영된다.

### 4단계 — RTDN / Apple V2 (즉시 반영) — ⚠ 사장님 승인 사안
- 공개 엔드포인트 2개 신설 + 앱팀이 콘솔에 URL 입력.
- Play: Pub/Sub push 의 **OIDC 토큰 검증**(audience=우리 URL · issuer=accounts.google.com
  · SA 이메일 일치) → 토큰으로 재조회.
- Apple: **JWS x5c 체인을 Apple Root CA 로 검증** → 재조회.
- 처리 이벤트: RENEWED·RECOVERED·IN_GRACE_PERIOD·ON_HOLD·CANCELED·EXPIRED·REVOKED.
- ⇒ 1~3단계는 외부 설정이 **0** 이라 먼저 배포할 수 있다. 구글도 「RTDN 만 믿지 말고
  폴링 백스톱을 두라」고 권고하므로 3단계는 4단계가 와도 남긴다.

## 4. 같이 처리 — §22-⑤⑦ (체험·주기)
재조회 함수가 **이미 스토어 응답을 손에 들고 있다** ⇒ 같은 자리에서 채운다.
- 검증·재조회 때 `is_trial` 기록: Google `lineItems[].offerDetails.offerId == 'trial-7d'`
  (이미 `core/iap.py:265` 에서 **로그로만** 찍고 있다) · Apple `offerType`.
- `SubscriptionStatusOut` 에 `billing_period`·`product_id`·`is_trial`·`trial_ends_at` 추가
  (DB 엔 이미 다 있다 — 응답에만 없다).
- ⇒ `verify()` 를 두 번 열지 않게 §24 와 같은 흐름에서 처리한다. 커밋은 분리.

## 5. 수용 기준
- [ ] 만료된 store 구독 + 유효 토큰 → 상태 조회 1회로 `end_date` 가 미래로 이동
- [ ] 스토어가 `invalid` → Free (지금과 동일)
- [ ] 스토어가 `unavailable` → **저장값 불변**(박탈 없음) + 재시도
- [ ] 쓰로틀 안에서 두 번 호출 → 스토어 호출 1회
- [ ] `source='manual'` 행은 **절대 건드리지 않는다**(사장님이 넣은 7건)
- [ ] 토큰 없는 기존 행은 조용히 통과(에러 아님)
- [ ] 통화 경로에 스토어 호출이 **생기지 않았다**(회귀로 고정)
- [ ] 전체 회귀 2113 유지 + 신규
