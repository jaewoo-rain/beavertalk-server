## 1. 목표 & 범위

### 목표
지금 **하나의 지시문**이 공부·대화 두 모드를 다 담고 있다(`persona_prompt.py:197-203`).
이걸 **통화 종류 자체로 갈라** 각각 전용 프롬프트를 만든다.

```
표현학습(expression)   18개 표현을 드릴 → 3개마다 퀴즈 → 오답퀴즈       ⭐ 이번 범위
프리토킹(freetalk)     100% 학습 언어로 자유대화. 항목 주입 없음        ⭐ 프롬프트만
```

### MVP 범위
- 두 코스의 **전용 프롬프트** + 공통 불변 규칙의 변수화
- 표현학습 **학습 플로우 전체**(선별 → 드릴 → 퀴즈 → 오답퀴즈 → 저장)
- 표현학습 **선별 함수**(개수를 변수로)
- **퀴즈 판정** — 정규화/어절 대조 + LLM 하이브리드
- **조각 경계 진도 승계**(15분 = 5분 소켓 3개)
- 힌트 제거

### 비범위 (사장님 지시로 뒤로 미룸)
- 프리토킹의 주제 선정·배운 표현 활용 — **미기획**. 지금은 페르소나+캐릭터로만 대화
- 캐릭터 DB 손보기 — 마지막에
- 클라(버튼 2개 · WS 파라미터) — 나중에
- 레벨업 전환으로 죽는 기존 사슬의 **코드 정리** — 별건(§8)

## 2. ⭐ 아키텍처

### 2-1. 통화 종류 축이 하나 늘어난다

```
call_type   normal | level_test | expression | freetalk      ← 새 값 2개
engine      live | cascade                                    (기존)
call_mode   study | chat                                      ⚠ 표현학습·프리토킹에선 안 쓴다
backend     vertex | studio                                   (2026-09-08 신설)
```

⛔ **`call_mode`(study/chat)는 이 두 코스에서 죽는다.** 그 축은 «한 통화 안에서 모드가
바뀐다»는 전제 위에 있었는데(`call_session.py:4162` 사이드카 모드 전환), 코스를 가르면
그 전제가 사라진다. ⇒ 기존 `normal` 통화에서만 계속 산다.

### 2-2. 프롬프트 폴더 분리 (사장님 지시)

```
core/prompts/
    __init__.py
    common.py        ⭐ 불변 공통 — 두 코스가 같이 쓴다
    expression.py    표현학습 전용 조립
    freetalk.py      프리토킹 전용 조립
core/persona_prompt.py   ⚠ 그대로 둔다 — normal·level_test 가 계속 쓴다
```

**`common.py` 에 들어갈 것**(사장님: *"공통적인 규칙은 변수로 만들어서 공통으로 쓴다"*):
- 통화를 계속 이어간다(먼저 작별하지 마라 · 종료 시드 규약)
- 언어학습 밖 질문 회피(*"너는 누가 만들었어?"* → 학습으로 되돌린다)
- 대괄호 금지(⛔ 실측: `[공부 모드]` 를 TTS 가 소리 내어 읽었다 — `persona_prompt.py:309`)
- 종료 태그 · 무음 넛지 · 캐릭터 3필드 주입 틀

⚠ **복사하지 말고 `common.py` 가 소유**한다. 지금 `persona_prompt.py` 도 그 문자열을
쓰므로, 옮긴 뒤 **기존 출력 바이트가 같은지** 스냅샷 시험으로 못박는다(§7).

### 2-3. 데이터 — 기존 테이블에 컬럼 2개

⛔ 새 테이블을 만들지 않는다. `member_item_progress` 는 이미 **회원×항목 1행**이라
조각·통화·날짜와 무관하게 진도가 이어진다(사장님 요구: *"다음날 통화할 때 이어서"*).

```sql
ALTER TABLE member_item_progress
  ADD COLUMN quiz_passed_at timestamptz,   -- NULL = 미통과. ⭐ 완료 판정의 유일한 기준
  ADD COLUMN drilled_at     timestamptz,   -- 마지막으로 드릴한 시각(NULL = 한 번도 안 꺼냄)
  ADD COLUMN drilled_call_id bigint;       -- 그 통화(되짚기용)
```

⚠ **노출 «횟수» 컬럼은 안 만든다.** 사장님 정정(2026-09-10): 3회가 아니라 **1회**면 된다.
⇒ 횟수가 아니라 «했나/안 했나»이므로 timestamp 하나로 끝난다. 연속 접기 알고리즘도 불필요.

### 2-6. ⭐ 퀴즈 판정 — 하이브리드 + 재접지 배관

**판정**(사장님 채택):
```
① 정규화(공백·문장부호·조사 말미 제거) 후 정확 일치   → 통과.  LLM 0, 비용 0
② 공통 어절 0                                      → 오답.  LLM 0
③ 그 사이                                          → 사이드카(LLM) 1회
```
⛔ 유사도만으로는 안 된다 — 정답 `안녕히 가세요` 에 `안녕히 계세요`(뜻이 반대)가
두 글자만 다르다. 뜻을 봐야 하고 그건 LLM 몫이다.
⭐ 퀴즈의 정답이 **항목 표면형 그 자체**라(사장님 Q21) 사이드카에 정답을 그대로 넘긴다.

**주입 타이밍**(사장님 지시 — *"재접지 때랑 동일한 타이밍"*):
```
_arm_reground()                    쪽지 준비(즉시 조립 가능한 것으로 먼저 채움)
   ↓ 대기
_maybe_attach_reground_on_mic()    업링크 마이크 프레임 + frame_rms ≥ 임계
   ↓
비버에게 얹기
```
⛔ 이 두 관문이 *"혼자 두 번 말하거나 말하다 마는"* 버그를 막는다:
프레임이 그 자리에 있다 = 클라(`_micGated`)와 서버(`turn_id is None`)가 각각
«비버는 안 말한다»를 보증했다. RMS 는 «침묵 프레임이 아니라 사람이 진짜 입을 열었다».

⚠⚠ **사이드카를 미리 던져야 한다.** `_arm_reground` 는 사이드카를 **안 기다린다** —
실측(통화 1360): arm→얹기 **1.18초** vs 사이드카 **1.4초** ⇒ 결과가 조용히 버려졌다.
⇒ **퀴즈 3문항을 다 물어본 직후**에 판정을 띄워 둬야 오답퀴즈 시점에 준비돼 있다.

⚠ 아래는 전부 **지금 코드에 있는 기계**다(실측). 표현학습은 여기에 얹는다.

```

0:00  WS 열림
      ├─ 서버가 지시문 1회 조립 → setup 으로 주입 (⛔ 이후 못 바꾼다)

      │    · 조각2·3 이면 "1~N 은 완료. N+1 부터" 를 같이 넣는다
      └─ Live 연결 (Free·Pro=Vertex 2.5 / Max=AI Studio 3.1)

0:03  선톡 시드 → 비버가 먼저 인사 → 바로 1번 항목

      │  nc-client->gemini   마이크 → Gemini (barge-in off)        │

      │  nc-idle             무음 3단 넛지                          │
      │  nc-reground         ⭐ 재접지 arm 판정(주기·압축 감지)       │

      └────────────────────────────────────────────────────────┘

      매 비버 발화 끝 ─→ _flush_beaver_segment

                             (LLM 0 · 즉시 · 압축과 무관) → expr_drilled 누적
```

### ⚠ 컨텍스트 압축 — «적» 이 아니라 **쪽지를 최신단에 둬야 하는 이유**

> ⛔ **정정(2026-09-10).** 이 절의 옛 제목은 «압축이 이 설계의 최대 적이다» 였다. **과장이었다.**
>   · sliding window 는 **최근 것을 남긴다** ⇒ 비버는 «방금 뭘 했는지» 를 안다
>   · 지시문(항목 목록)은 **압축에 안 지워진다**
>   · 통화 1360 의 진짜 원인은 9638a26 이 이미 적어 둔 대로 **«압축이 아니라 우리가 넣어준
>     쪽지»** 다 — 7개를 드릴한 시점에 `covered=3/3` 이라는 **부분 목록**이 나갔고, 비버는
>     목록에 없는 4개를 «안 한 것» 으로 읽어 1번으로 되감았다.
>   ⇒ 압축이 하는 일은 «오래된 쪽지를 밀어내는 것» 이므로, 대응은 «압축을 이기는 것» 이
>     아니라 **쪽지를 최신단에 두고 그 내용을 온전하게 유지하는 것**이다.
>   ⚠ 조각 경계는 이와 **무관하게** 서버 상태가 필요하다 — 새 세션은 이전 대화가 0이다.

```
설정(app-api 실측)   TRIGGER=8000 토큰 → TARGET=7000 으로 접는다
                    (코드 기본값은 16000/12000)

실측 사고(통화 1360, 2026-09-09)
  04:55:56  압축 #4 발동 — 16,372 → 7,153  (9,219 토큰 삭제)
  04:56:37  비버가 1번 항목으로 **되감았다**. 마지막 91초(30%)가 반복이었다
```

⚠ 압축은 **오래된 대화부터 지운다** — 통화 초반에 가르친 것이 제일 먼저 사라진다.
⇒ 그래서 «무엇을 했나» 를 **쪽지가 온전히** 실어야 한다. 부분 목록이 나가면 그 목록이
  «전부» 로 읽혀 되감기를 부른다(1360). 압축이 사고를 **만든** 게 아니라, 압축이 지운
  자리를 **덜 채운 쪽지**가 사고를 만들었다.

**대비책 3중:**

```
① 지시문(setup)    ⛔ 압축에 안 지워진다 — 항목 18개는 여기 있다
② 서버 누적        진도(covered_nums / expr_quiz_pass / expr_quiz_fail)는 파이썬 메모리 + DB.
                   압축과 완전히 무관하다 (9638a26 의 covered_nums 규율)
                   ⭐ 판정 자체는 **전사를 읽는 LLM** 이 한다(2026-09-10 재설계) — 그 전사도
                      서버가 갖고 있어 압축과 무관하다
③ 재접지 쪽지      ①②를 근거로 «지금까지 한 것»을 주기적으로 다시 말해 준다
```

⭐ **핵심은 ②다.** LLM 의 기억(압축되는 것)에 진도를 맡기지 않는다 — **서버가 원본을 갖는다.**

### 재접지 — 언제, 어떻게 얹히나

```
arm 판정(nc-reground)   간격 = 통화길이/2.5, 최소 120초 ~ 최대 240초
                        통화당 최대 8회(REGROUND_MAX_PER_CALL)
                        + 압축이 감지되면 즉시 arm

_arm_reground()         쪽지를 **즉시 조립 가능한 것**으로 먼저 채운다
   │                    ⛔ 사이드카를 기다리지 않는다
   ├─ _spawn_reground_sidecar()  ← LLM 사이드카를 **동시에** 띄운다(맥락 슬롯 보강)
   │                              늦게 오면 아직 안 얹힌 쪽지를 업그레이드
   ▼ 대기
_maybe_attach_reground_on_mic()
   관문① 업링크 마이크 프레임이 왔다  = 클라(_micGated)+서버(turn_id None) 이중 보증
   관문② frame_rms ≥ 임계             = 침묵이 아니라 사람이 진짜 입을 열었다
   ▼
얹기 — 비버가 다음 턴에 이걸 읽고 말한다
```

⛔ 두 관문이 **«비버가 혼자 두 번 말하거나 말하다 마는» 버그**를 막는다.
⚠ 실측: arm→얹기 **1.18초** vs 사이드카 **1.4초** ⇒ 사이드카 결과가 조용히 버려진 적이 있다.

### ⭐ 표현학습이 여기에 더하는 것 — 딱 둘

```
(가) 드릴 검출     _flush_beaver_segment 의 문자열 대조에 항목 18개를 물린다
                   ⇒ LLM 0. 이미 있는 기계에 목록만 갈아 끼운다

(나) 퀴즈 판정     3문항을 다 물어본 **직후** 사이드카를 미리 던진다
                        │
                        ├─ ① 정규화 정확일치  → 통과 (LLM 0)
                        ├─ ② 공통 어절 0      → 오답 (LLM 0)
                        └─ ③ 애매             → LLM 1회
                        ▼
                   결과를 state 에 넣어 두면 **다음 arm 때 쪽지에 실린다**
                   ⇒ 오답퀴즈 시점에 이미 준비돼 있다
```

⚠ **새 배관을 만들지 않는다.** (가)는 기존 검출기에 목록만 바꾸고, (나)는 기존 재접지
쪽지에 한 줄 더 싣는다. 타이밍 안전장치(2관문)를 그대로 물려받는 것이 핵심이다.

⇒ **값만 추가하면 된다. 구조 변경 0.**

### ⛔ 왜 표현학습에 «새 화제»가 위험한가

```
학습자가 답을 못 떠올려 조용하다
   ↓  60초
비버: "가볍게 새 화제로 이어가라"  ← 일반 통화의 1단 시드
   ↓
그 항목을 **건너뛴다.** 드릴도 퀴즈도 안 된 채 다음으로 넘어간다
```

⚠ 표현학습에서 무음은 «대화가 끊겼다»가 아니라 **«학습자가 지금 항목을 못 하고 있다»** 이다.
화제를 바꾸면 안 되고, **그 항목을 더 쉽게 다시 물어야** 한다 — 레벨테스트 시드와 같은 성격이다.

### 새로 넣을 시드

```python
# 표현학습 1단 — 화제를 바꾸지 않고, 지금 항목을 쉽게 다시 묻는다
_NUDGE_SEED_1_EXPRESSION = (
    f"{CONTROL_TAG} 학습자가 잠깐 조용하다. 이 메시지는 소리내 읽지 말고, 작별하지 말고 "
    "**화제를 바꾸지 말고**, 지금 다루던 표현을 한 번 더 또박또박 들려준 뒤 "
    "따라 말해 보라고 네 캐릭터대로 한 번만 청하라."
)

# 프리토킹 1단 — 일반과 같은 성격이되 **학습 언어로** 이어간다
_NUDGE_SEED_1_FREETALK = (
    f"{CONTROL_TAG} 학습자가 잠깐 조용하다. 이 메시지는 소리내 읽지 말고, 작별하지 말고 "
    "학습 언어로 가볍게 새 화제 한 문장만 이어가라."

⚠ 2단·3단 시드는 **공통으로 둔다** — "거기 있어? 잘 들려?"와 작별은 코스와 무관하다.

| | 1단 | 2단 | 3단 | 근거 |

| **표현학습** | **60초** | +10 | +12 | 일반과 같게 시작. ⚠ 드릴은 학습자가 문장을 떠올리는 시간이라 **줄이지 마라** |

```
① 선톡      "안녕 잘 지냈니?" 가볍게 인사 → ⭐ 바로 1번 항목

④ 퀴즈      ⭐ 3개마다 — 모국어로 상황·문장을 주고 학습 언어로 맞히게 한다

**시간 초과**: 다 못 해도 된다 — 미완은 다음 통화 앞으로 간다(§2-4 정렬).

### ⭐ 캐릭터를 살리는 자리
사장님 요구의 핵심은 **피드백에서 캐릭터가 극대화**되는 것이다. 프롬프트에 **4상황 틀**을
두고 캐릭터 3필드(`role`·`personality`·`rules`)가 채우게 한다.

```
정답      욕쟁이 → 욕하면서 칭찬 / 소심이 → 우러러보며 "너처럼 똑똑하면 좋겠다"
오답      욕쟁이 → 신랄하게 비판하고 고쳐준다 / 소심이 → "나도 잘은 모르는데 아마…"

포기      캐릭터대로 넘어간다
```
⚠ DB 는 마지막에 손보기로 했으므로, **지금은 프롬프트 틀만** 만든다.
