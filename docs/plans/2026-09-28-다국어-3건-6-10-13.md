## 2. §6 차시 제목 — 별 표 + 좁게 시작

### 규모
| | |
|---|---|
| `situation` 고유 문자열 | ko 491 + ja 348, 합집합 **836**(공통 3) · 평균 15자 |

| ⭐ 회원이 실제로 닿은 차시 | **ko 3개 · ja 1개**(`cur_member_lesson` distinct) |

### 설계
- 새 표 `cur_lesson_i18n` — (**차시 키**, `locale`) 유니크 → `situation` 번역
- `GET /cur/me`·`GET /cur/lessons` 응답에 **`situation_translation: Optional[str]`** 추가
- 번역 없으면 **`null`**(앱이 한국어만 표시) — ⭐ 요청서가 그렇게 요구했고
  **부분 적재가 설계된 동작**이다
- ⇒ **L1 3차시 × 29 = 87행부터** 적재하고 검수분만 넓힌다. `sound_lesson_i18n` 이
  그렇게 했다(검수 전엔 비워 뒀다)

### ⚠ 키를 무엇으로 하나 — 구현 전 확인
조사자 지적: `lesson_id` 는 재시드(`/__dev/cur-reseed-l1`·`cur_l1_layout`)로 **바뀔 수 있다**
(재시드가 실제로 id 를 바꾸는지는 **확인 못 했다**).
⇒ **먼저 확인해라.** 바뀌면 `code` 나 원문 해시를 키로 쓴다. `sound_lesson_i18n` 은
`sound_key`(안정된 문자열)를 썼다 — 그 선례를 따르는 게 안전하다.

### 📌 요청서에 없지만 같은 문제
같은 응답의 **`topic`**(`cur_topic.name` 65개, 예 「가족과 친척」)도 한국어다.
⇒ 이번 범위에 **넣지 않는다**(요청 밖). 다만 표를 만들 때 **topic 도 담을 수 있는 모양**으로
두면 나중에 표를 또 만들지 않는다 — 그 정도만 고려한다(⛔ 미리 만들지는 마라, YAGNI).

## 3. §10 통화 제목 — 열 때 번역 + 캐시

### 실측
| | |
|---|---|
| 요약 있는 통화 | **1,312건**(한글 213 · 비한글 1,099) · 평균 28자 · 최대 177자 |
| 최근 30일 | 433건 |
| 목록 한 페이지 | `GET /calls` 기본 **limit 20**, 최대 100 |
| 언어가 섞인 회원 | 통화 기록 있는 활성 회원 **8명 전원** |

원인 확정: 요약은 **통화 시점 `locale`** 로 만든다(`normalcall_service.py:3524`,
`_LOCALE_LABEL[locale]`). 회원이 모국어를 바꾸면 그 뒤 통화만 새 언어가 된다.
⭐ 대조 증거: member 20 의 `sentence.locale=ko` 통화 40건 중 **39건이 한글 요약**,
`en` 126건 중 **125건이 비한글** — 통화 시점 locale 을 따른다는 게 데이터로 확인됐다.

### ⛔ B2B 에 같은 표가 **이미 운영에 있다** — 그런데 그대로 못 쓴다
`call_summary_translation`(`call_id`, `locale`) 유니크 + `source_locale`,
B2B alembic `e1f2a3b4c5d6` 로 **운영에 생성됨(0행)**. 서비스도 있다(`summary_service.py`:
열 때 1회 번역 → 캐시 · 원본 불변 · genai 없으면 원문 + `translated=false`).

⛔ **앱 데이터에선 원본 언어 판정이 깨진다**(조사자 실측):
- `summary_service.py:40-44` 가 원본 언어를 **`sentence.locale` 첫 행**으로 판정하는데,
  요약 있는 1,312건 중 **813건은 `sentence` 가 0행**이다 ⇒ `None` ⇒ **같은 언어여도 번역을 부른다**
- `sentence.locale` 에 정규화 안 된 값이 있다(`en-US` 1 · `ko-KR` 1)

### ⚠ 표 이름이 겹친다 — 반드시 정하고 시작해라
앱 서버·B2B·콘솔이 **같은 DB** 를 쓴다. 앱 서버가 `call_summary_translation` 을 새로
만들려 하면 **이미 있는 표와 충돌한다.**
| | |
|---|---|
| **(가) 있는 표를 같이 쓴다** ⭐ | 같은 개체(`call_id` → 번역)다. 표를 둘 만들 이유가 없다 |
| (나) 다른 이름으로 새 표 | 같은 것이 두 개가 된다 — 어느 쪽이 정본인지 영영 모른다 |

⭐ **(가) 채택.** 단 ⛔ **앱 서버는 이 표에 대한 마이그레이션을 만들지 마라**(이미 있다 —
만들면 실패한다). DDL 소유는 **B2B alembic(`alembic_version_b2b`)** 이고 양쪽이 읽고 쓴다.
⚠ 그 사실을 **모델 docstring 에 적어라** — 다음 사람이 앱 쪽 마이그레이션을 만들려 한다.
⚠ B2B 는 `SUPPORTED=("ko","en")` 뿐인데 앱은 30언어다. 표 모양은 같아 문제없지만
**B2B 가 스키마를 바꾸면 앱이 깨진다** — 그 위험을 주석에 남긴다.

### 설계
1. **앞으로**: 분석 시점에 요약 언어를 `call` 에 저장(**정규화된 값**). 컬럼 추가 1개
2. **조회**: `member.language` 와 다르면 `(call_id, locale)` 캐시를 보고, 없으면 번역 후 저장
3. **과거 행**(원본 언어 미저장): 저장된 게 없다. ⇒ **한글 포함 여부로 ko/비-ko 만 가른다.**
   비-ko 끼리(en vs de)는 모르지만 **「대상 언어와 다른가」만 알면 되므로** 충분하다
   (대상이 ko 가 아니면 비한글은 일단 번역 대상으로 둔다 — 조사자 절충안)
4. **비용 상한**: 목록 한 페이지 **20건** × 처음 보는 `(call, 언어)` 만. 캐시가 있으면
   같은 회원이 다시 봐도 **0콜**. ⭐ 28자 명사구라 **20건을 한 번에 묶어 1콜**로 보낼 수 있다
5. ⛔ **genai 가 없으면 원문 + 번역 실패 표시**로 떨어진다(B2B 가 이미 그 규율이다). 통화
   목록이 번역 때문에 죽으면 안 된다(R5)

### ⚠ 구현 전 확인
- **동기 번역 지연을 목록 API 가 견디나** — 조사자가 genai 지연을 재지 않았다.
  ⇒ 먼저 재라. 못 견디면 「캐시 있는 것만 번역해 주고 나머지는 원문 + 비동기 채움」이다
- `locale_override` 를 앱이 언제 보내는지(member 20 이 통화마다 언어가 갈린 원인) — 미확인

## 4. §13 캐릭터 — 표 하나 + 번역은 대부분 있다

### 규모
| | |
|---|---|
| 캐릭터 | **5개**(Baba·Bibi·Popo·Rara·Dudu) |
| `tags` | JSON **영문 한 벌**(예 Baba `["Savage","Blunt","Tsundere"]`) · 고유 15개 |
| `description`·`story` | **한국어 한 벌** |
| ⭐ 이미 있는 번역 | 앱 `character_copy_overrides.dart` 에 **29언어 × 5 = 145쌍** |
| 새로 번역할 것 | **태그 15개 × 29언어**뿐 |

### 설계
- 새 표 `character_i18n` — (`character_id`, `locale`) → `description`·`story`·`tags`(JSON)
- `sound_lesson_i18n` 과 **같은 병합**(없는 칸은 원본 유지 · 빈 값으로 원본을 지우지 않는다)
- `GET /characters`·`/characters/{id}`·`/members/me/characters` 셋 다 **인증 필수**라
  `member.language` 를 서버가 안다(`routers/character.py:20-35`·`:60`) ⇒ 요청에 언어를 안 싣는다
- 적재 원본은 앱 `character_copy_overrides.dart` 145쌍 ⇒ **앱팀에 그 파일을 달라고 한다**
  (⚠ **검수 여부를 모른다** — `sound_lesson_i18n` 의 「기계번역을 그냥 붓지 마라」 규율이
  여기도 걸린다. 검수됐는지 확인 후 적재)

### ✅ 결정됨 — `tags` 는 **한국어 사용자에게 한국어로** 준다
2026-09-28 사장님: **「한국어 선택한 사람은 한국어 줘도 돼.」**

⛔⛔ **이게 `sound_lesson_i18n` 선례와 갈리는 유일한 지점이다. 반드시 읽어라.**

| | `sound_lesson_i18n` | `character_i18n` |
|---|---|---|
| 원본의 언어 | **한국어**(`lessons.json`) | `description`·`story` 는 **한국어** · `tags` 는 **영어** |
| `ko` 행 | ⛔ **금지**(적재 검증이 `i18n/ko.json` 을 거부) | ⭐ **필요**(태그 때문) |

⇒ `character_i18n` 에는 **`ko` 행이 있어야 한다.** 그 행은 **`tags` 만 채우고**
`description`·`story` 는 **비운다**(null → 칸 단위 폴백으로 원본 한국어가 나간다).

⛔ **다음 사람이 「선례에 맞춰 ko 행을 없애자」고 하면 그게 회귀다.** 이유가 다르다 —
저쪽은 한국어가 **원본**이라 번역이 필요 없고, 여기는 `tags` 의 원본이 **영어**라 한국어가
**번역 대상**이다. 그 사실을 모델 docstring·적재 스크립트 양쪽에 적어라.

⚠ 그리고 적재 검증에서 **`ko` 행의 `description`·`story` 가 비어 있는지** 확인해라 —
거기에 한국어 원문을 복사해 넣으면 원본이 두 곳에 생겨 갈린다(`sound_lesson_i18n` 이
`ko.json` 을 금지한 이유가 정확히 그것이다).
