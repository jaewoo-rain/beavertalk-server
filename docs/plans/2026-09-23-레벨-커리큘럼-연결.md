## 3. 구현 범위

### T1. 시작 차시 = 그 언어 레벨의 첫 차시 (placement)

**두 자리에 각각 넣는다. 한 곳에 몰면 안 된다.**

#### T1-a 생성 — `curriculum_service.py:148 ensure_progress`
진도 행이 **없을 때** 만드는 lesson 을 `no=1` 대신 **그 언어 레벨의 첫 차시**로.
- 레벨 조회는 `mastery_repository.get_language_level(db, member_id, language)` **그걸 쓴다**
  (언어 우선 → ko 한정 `korean_level` 폴백 규칙이 이미 들어 있다. 새 접근자 만들지 마라)
- repo 에 `first_lesson_of_level(db, language, level_no)` 추가 —
  `where language=? and level_no=? order by no limit 1`.
  인덱스 `ix_cur_lesson_level_no(language, level_no, no)` 가 이미 있어 그걸 탄다
- 폴백 사슬(R5): 그 언어 레벨 → (레벨 NULL·그 레벨 차시 0건) → `no=1` + 로그 1줄
- ⛔ **행이 이미 있으면 절대 건드리지 않는다**(지금 동작 유지). 이동은 T1-b 만 한다

#### T1-b 재측정 이동 — `normalcall_service.py:3420 _save_level_assessment`
레벨테스트 판정이 확정되는 **그 함수 안, 같은 커밋**에서 진도 포인터를 새 레벨 첫 차시로 옮긴다.

이 자리가 맞는 이유(이미 다 갖춰져 있다):
- `get_member_for_update` 로 **회원 단위 직렬화**가 걸려 있다(동시 레벨테스트 2건 방어)
- `upsert_language_level`(ko dual-write) · `record_placement`(history) · `db.commit()` 가 한 트랜잭션
- 통화의 `target_language` 로 **언어가 이미 확정**돼 있다(`language = call.target_language or "ko"`)
⇒ 여기에 «그 언어 진도 포인터 이동» 을 한 줄 더 얹으면 **레벨과 진도가 어긋난 중간 상태가 없다.**

- **위아래 양방향**으로 옮긴다(D1) — 올라가도 내려가도 그 레벨 첫 차시
- ⛔ **레벨 값 비교로 판정하지 마라.** 2→2 여도 재측정은 일어난 것이다. 이 함수가 불린 것
  자체가 «재측정했다» 는 이벤트다. ⚠ 단, 그래서 **배우던 차시가 날아간다** —
  레벨이 같으면 그 레벨 첫 차시로 되돌아간다. 그게 D1 의 귀결이다(사장님 확정)
- ⛔ 배운 기록(`cur_member_lesson`·`cur_member_item`)은 **지우지 않는다**(§5 참조)
- ⚠ 진도 행이 아직 없으면(레벨테스트를 먼저 본 신규 회원) 여기서 만들지 않아도 된다 —
  다음 표현학습 통화의 T1-a 가 새 레벨로 만든다. 만들면 두 곳이 같은 일을 한다

### T2. 포인터가 레벨 경계를 넘으면 레벨 갱신
`curriculum_service.py:473-480`(`complete_freetalk` 의 포인터 이동 자리):
```python
nxt = repo.next_lesson(db, lesson.language, lesson.no)
if nxt is not None:
    prog.lesson_id = nxt.lesson_id
    moved = True
    # ⭐ 여기: nxt.level_no != lesson.level_no 면 레벨업
```
갱신 대상 — **T1-b 와 같은 함수를 쓴다**(산식을 두 곳에 두지 않는다):
- `mastery_repository.upsert_language_level(db, member_id, language, nxt.level_no)`
  (ko 면 `member.korean_level` dual-write 가 그 안에 있다)
- `member_level_history` 1행 — 필드: `from_level`(lesson.level_no) · `to_level`(nxt.level_no) ·
  `reason`(신규 값, 예 `'curriculum'` — `'placement'` 와 구분해야 이력에서 갈린다) ·
  `trigger_call_id`(그 프리토킹 통화) · `language`
  ⚠ `trigger_call_id` 에 **UNIQUE(uq_mlh_trigger_call)** 가 걸려 있다 — 멱등 키다.
    같은 통화로 두 번 불려도 2행이 안 생긴다(재시도 안전). 그걸 **믿고** 쓴다
- ⛔ `db.commit()` 은 **포인터 이동과 같은 커밋**. 레벨만 오르고 진도가 안 간 상태가 남으면
  다음 통화가 새 레벨 재료로 옛 차시를 가르친다

### T3. 기존 회원 진도를 레벨에 맞게 끌어올린다
운영 ko 진도 6명뿐 — 지금이 가장 싸다. **스크립트로**(마이그레이션 아님), dry-run 기본.
- ⛔ **올리기만 한다.** `목표차시.no > 현재차시.no` 일 때만. 레벨 1인데 이미 no=10까지 간 사람을
  되돌리면 배운 걸 다시 시킨다
- ⛔ 배운 기록(`cur_member_item`·`cur_member_lesson`)은 건드리지 않는다. **포인터만** 옮긴다
- 언어별로 돈다(ko 진도는 ko 레벨, ja 진도는 ja 레벨)

### T4. 옛 승급 사슬 **끊기** (삭제 아님 — D4)
`normalcall_service.py:2623-2628` 의 `evaluate_level_up` 호출을 **모든 콜타입에서** 끊는다.
- 지금은 `skip_level_up = call_type in ("expression","freetalk")` 라 **`chat` 과 `level_test` 는 돈다**
- ⇒ `chat`(자유대화)이 옛 체크판 기준으로 레벨을 올릴 수 있다. **진도와 무관하게.** 이건 D7 로 끊는다
- ⛔ 테이블(`member_item_progress`·`item_evidence`)과 `mastery_service` 코드는 **남긴다.**
  `apply_evidence`(증거 적재)도 그대로 둔다 — 나중에 쓸 수 있고, 지우면 되돌리기 어렵다
- `skip_level_up` 플래그 자체는 남겨도 되고 없애도 된다(호출이 사라지면 죽은 인자다). 빌더 판단

## 4. ⛔ 반드시 지켜야 할 함정

### 함정 1 — 레벨은 **언어별**이다
- `member.korean_level` = **ko 전용 스칼라**(옛 칸)
- `member_language_level` = 회원×언어 1행 (UNIQUE(member_id, language))
- `cur_member_progress` 도 **언어 축**을 갖는다

⇒ **일본어 진도를 만들 때 한국어 레벨을 보면 안 된다.**
한국어 레벨 5 인 사람이 일본어를 새로 시작하면, 일본어 레벨테스트 전이므로 **일본어는 1차시부터**여야 한다.
`mastery_repository.get_language_level(db, member_id, language)` 가 이미 «언어 우선 → ko 한정 폴백» 규칙을
갖고 있으니 **그걸 쓴다**(새 접근자를 만들지 않는다).

### 함정 2 — 레벨이 바뀌면 **통화 재료가 통째로 갈아탄다**
레벨은 표시용이 아니다. 실제 동작을 가른다:
- `lang_band`(`mastery_repository.band_of`) → **프롬프트의 code-switching 밴드**
- `pick_expression_items` 등 재료 선별이 **레벨 정확일치**

⇒ 레벨업이 통화 중에 일어나면 안 된다. `complete_freetalk` 은 통화 **종료 후**라 안전하지만,
구현할 때 이 순서를 깨뜨리지 말 것.

### 함정 3 — 자동 강등이 사라진다 (되돌릴 길은 재측정 하나뿐)
진도는 앞으로만 가므로 통화로는 레벨이 오르기만 한다. 옛 체크판에는 강등·`placement 굴복`
(F 1건에 즉시 굴복) 같은 자동 안전망이 있었는데 **그게 없어진다**(D3 확정).
⇒ 레벨테스트가 과대평가했을 때 되돌리는 길은 **사용자가 직접 재측정하는 것 하나뿐**이다.
   앱에 재측정 진입점이 반드시 살아 있어야 한다 — 이게 유일한 복구 경로다.

### D7 — 자유대화는 레벨을 올리지 않는다 (설계에서 따라오는 결론)

그대로 두면 이렇게 갈린다:

```
진도:  레벨 2 차시(no=10) 에서 공부 중
chat 통화 몇 번 → 옛 체크판이 korean_level 을 3 으로 올림
⇒ 레벨은 3, 진도는 레벨 2 차시. 두 값이 싸운다.
```
레벨은 표시용이 아니라 **프롬프트 밴드(`lang_band`)와 재료 선별**을 가르므로(함정 2),
그 상태에서는 **레벨 3 재료로 레벨 2 차시를 가르친다.**

⇒ «진도 = 레벨의 유일한 소스» 라는 결정이 이미 답을 담고 있다. **chat 도 끊는다.**

**귀결(받아들이는 것):** 자유대화만 하는 사용자는 레벨이 오르지 않는다.
새 설계에서 레벨은 «커리큘럼 어디까지 갔나» 이고, 자유대화는 커리큘럼이 아니므로 일관된다.
⚠ 다르게 가려면(자유대화도 레벨을 올린다) 진도를 함께 밀어야 하는데, 그건 «대화 좀 했다고
차시를 건너뛴다» 는 뜻이라 학습 설계가 무너진다. 그래서 끊는 쪽을 택했다.

### ⚠ D1 × D3 의 경계 — 여기가 이 기획에서 제일 헷갈리는 곳이다

「강등 없앤다」와 「항상 새 레벨로 이동」은 **그냥 두면 서로 부딪힌다.** 확정된 경계는 이렇다:

| 레벨이 내려가는 경로 | 허용? |
|---|---|
| 통화(표현학습·프리토킹·자유대화)로 인한 **자동** 강등 | ⛔ **없다.** 진도는 앞으로만 가므로 레벨도 오르기만 한다 |
| 사용자가 **직접 레벨테스트를 다시 봐서** 낮게 나옴 | ✅ **내려간다.** 진도도 그 레벨 첫 차시로 뒤로 간다 |

⇒ 규칙 한 줄: **«레벨은 스스로 내려가지 않는다. 사용자가 다시 재보면 내려간다.»**

#### 그래서 T1 은 두 가지 일을 한다 — 구분해서 구현할 것
| 상황 | 동작 |
|---|---|
| 진도 행이 **없다**(첫 표현학습) | 그 언어 레벨의 첫 차시로 **생성** |
| 진도 행이 **있는데 레벨테스트를 다시 봤다** | 새 레벨의 첫 차시로 **이동**(위아래 양방향) |
| 그 외(평소 통화) | **건드리지 않는다** |

⛔ 「레벨테스트를 다시 봤다」를 **레벨 값 비교로 판정하지 마라.** 레벨이 그대로(예: 2→2)여도
재측정은 일어난 것이고, 그때 진도를 그 레벨 첫 차시로 되돌리면 **배우던 차시가 날아간다.**
⇒ **레벨테스트 통화가 끝나는 그 자리에서** 한 번만 이동시킨다(이벤트 기준, 값 비교 아님).

#### ⚠ 되돌아갔을 때 남는 기록
진도가 뒤로 가도 `cur_member_lesson`·`cur_member_item`(배운 기록)은 **지우지 않는다.**
- 그 차시를 다시 하면 이미 드릴한 항목은 `review=True` 로 나온다(`select_items` 기존 규율)
- 「안 배운 걸로 한다」는 **건너뛴 차시**에 대한 결정이지, **배웠다가 되돌아간 차시**가 아니다
- ⇒ 기록은 남기고 포인터만 옮긴다. T3 스크립트와 같은 규율
