## 0. 한 줄

**레벨테스트는 «시작 차시»를 정하고, 그 뒤로는 진도가 레벨을 올린다.**
차시 포인터가 L1 마지막(no=3)에서 A1 첫 차시(no=4)로 넘어가는 순간이 곧 레벨 1→2 다.
레벨은 **스스로 내려가지 않는다** — 사용자가 레벨테스트를 다시 봤을 때만 내려간다(D1·D3).

### ① 레벨테스트 결과가 표현학습 시작점에 **전혀 반영되지 않는다**

|---|---|---|---|

`curriculum_service.py:148 ensure_progress` 가 무조건 `lesson_by_no(language, 1)` 로 만든다.
주석에 그대로 적혀 있다 — **«레벨테스트→시작 차시 연결은 별건»**. 아직 안 붙인 것이다.
커리큘럼 코드는 `korean_level` 을 **한 번도 읽지 않는다**(grep 0건).

⇒ 레벨 2 를 받아도 생존회화 1차시부터 시작한다.

### ② 반대 방향도 끊겨 있다 — 표현학습으로는 레벨이 **영원히 안 오른다**

`call_session.py:4299`:
```python
skip_level_up=call_type in ("expression", "freetalk")
```
표현학습·프리토킹은 승급 판정(`evaluate_level_up`)을 **안 돌린다.** 지금 레벨을 올릴 수 있는 건
`chat`(자유대화)과 레벨테스트뿐이다.

이건 실수가 아니라 **의도된 차단**이었다(코드에 근거 있음, 2026-09-10 QA):
승급 판정은 «이번 통화의 증거» 가 아니라 **기존 progress 상태**로 판정해서, 검출을 안 한 통화가
트리거가 되어 옛 기준으로 승급이 찍혔다. 승급하면 `korean_level` 이 바뀌고 `pick_expression_items`
가 레벨 정확일치라 커리큘럼 분모가 통째로 갈아탄다.

⇒ **주력 학습 경로(표현학습)가 레벨 시스템과 완전히 분리돼 있다.**

## 2. 결정된 설계 — 진도가 레벨의 단일 소스

사장님 확정(2026-09-23):
- 표현학습·프리토킹을 하면서 **레벨이 자동으로 올라간다**
- **L1 에서 A1 으로 이동하면 그게 레벨업이다**
- 레벨업 시 체크판(레벨 상태)을 갱신한다

### 그래서 역할이 이렇게 갈린다

| | 역할 |
|---|---|
| **레벨테스트** | **시작 차시를 정한다**(placement). 재측정하면 그때마다 다시 정한다(D1) — 그 외 시점엔 레벨을 건드리지 않는다 |
| **진도(`cur_member_progress`)** | 레벨테스트 사이 구간에서 **레벨의 유일한 소스**(올리기 전용) |
| **옛 체크판 승급(`evaluate_level_up`)** | **불필요해진다** — 걷어낼 대상 |

### 레벨업이 일어나는 지점은 **코드에서 정확히 한 군데**다

`curriculum_service.py:473-480`(`complete_freetalk` — 프리토킹까지 끝나 포인터가 넘어가는 자리):

```python
if nxt is not None:
```

**`nxt.level_no != lesson.level_no` 면 레벨업이다.** 포인터가 앞으로 가는 유일한 자리이므로
(나머지 `:563` 은 dev 리셋) 여기 한 곳만 보면 된다.

## 3. 구현 범위

### T1. 시작 차시 = 그 언어 레벨의 첫 차시 (placement)
`ensure_progress` 가 행을 만들 때, `no=1` 대신 **그 회원의 그 언어 레벨의 첫 차시**로.
- 레벨 2 → no=4(`A1-T01-1`). 한 레벨 낮춰 시작하지 않는다(사장님 확정)
- 폴백 사슬(R5): 그 언어 레벨 → (레벨 없음·NULL·그 레벨 차시 0건) → `no=1`
- ⛔ 레벨을 못 읽었다고 통화를 막지 않는다. 조용히 `no=1` + 로그 1줄

### T2. 포인터가 레벨 경계를 넘으면 레벨 갱신
`complete_freetalk` 의 포인터 이동 자리에서 `level_no` 변화를 감지해:
- `member_language_level.level_no` 갱신
- ko 면 `member.korean_level` 도 함께(dual-write — 기존 규율)
- `member_level_history` 에 이력 1행

### T3. 기존 회원 진도를 레벨에 맞게 끌어올린다
운영 ko 진도 6명뿐 — 지금이 가장 싸다. **스크립트로**(마이그레이션 아님), dry-run 기본.
- ⛔ **올리기만 한다.** `목표차시.no > 현재차시.no` 일 때만. 레벨 1인데 이미 no=10까지 간 사람을
  되돌리면 배운 걸 다시 시킨다
- ⛔ 배운 기록(`cur_member_item`·`cur_member_lesson`)은 건드리지 않는다. **포인터만** 옮긴다
- 언어별로 돈다(ko 진도는 ko 레벨, ja 진도는 ja 레벨)

### T4. 옛 승급 사슬 정리
`evaluate_level_up` · `skip_level_up` 플래그 · 옛 체크판(`member_item_progress`·`item_evidence`)
→ **언제 어디까지 걷어낼지는 아래 결정 D4 참조.**

## 4. ⛔ 반드시 지켜야 할 함정

### 함정 1 — 레벨은 **언어별**이다
- `member.korean_level` = **ko 전용 스칼라**(옛 칸)
- `member_language_level` = 회원×언어 1행 (UNIQUE(member_id, language))
- `cur_member_progress` 도 **언어 축**을 갖는다

⇒ **일본어 진도를 만들 때 한국어 레벨을 보면 안 된다.**
한국어 레벨 5 인 사람이 일본어를 새로 시작하면, 일본어 레벨테스트 전이므로 **일본어는 1차시부터**여야 한다.
`mastery_repository.get_language_level(db, member_id, language)` 가 이미 «언어 우선 → ko 한정 폴백» 규칙을
갖고 있으니 **그걸 쓴다**(새 접근자를 만들지 않는다).

### 함정 2 — 레벨이 바뀌면 **통화 재료가 통째로 갈아탄다**
레벨은 표시용이 아니다. 실제 동작을 가른다:
- `lang_band`(`mastery_repository.band_of`) → **프롬프트의 code-switching 밴드**
- `pick_expression_items` 등 재료 선별이 **레벨 정확일치**

⇒ 레벨업이 통화 중에 일어나면 안 된다. `complete_freetalk` 은 통화 **종료 후**라 안전하지만,
구현할 때 이 순서를 깨뜨리지 말 것.

### 함정 3 — 자동 강등이 사라진다 (되돌릴 길은 재측정 하나뿐)
진도는 앞으로만 가므로 통화로는 레벨이 오르기만 한다. 옛 체크판에는 강등·`placement 굴복`
(F 1건에 즉시 굴복) 같은 자동 안전망이 있었는데 **그게 없어진다**(D3 확정).
⇒ 레벨테스트가 과대평가했을 때 되돌리는 길은 **사용자가 직접 재측정하는 것 하나뿐**이다.
   앱에 재측정 진입점이 반드시 살아 있어야 한다 — 이게 유일한 복구 경로다.

| **D4** | 옛 체크판을 언제 걷나? | **일단 끊기만.** 승급 사슬만 끊고 테이블·코드는 둔다 |

| **D6** | 진도율 표기 | 프론트 협의 — 레벨 안에서의 진도(«A1 3/17») 제안 |

### ⚠ D1 × D3 의 경계 — 여기가 이 기획에서 제일 헷갈리는 곳이다

「강등 없앤다」와 「항상 새 레벨로 이동」은 **그냥 두면 서로 부딪힌다.** 확정된 경계는 이렇다:

| 레벨이 내려가는 경로 | 허용? |
|---|---|
| 통화(표현학습·프리토킹·자유대화)로 인한 **자동** 강등 | ⛔ **없다.** 진도는 앞으로만 가므로 레벨도 오르기만 한다 |
| 사용자가 **직접 레벨테스트를 다시 봐서** 낮게 나옴 | ✅ **내려간다.** 진도도 그 레벨 첫 차시로 뒤로 간다 |

⇒ 규칙 한 줄: **«레벨은 스스로 내려가지 않는다. 사용자가 다시 재보면 내려간다.»**

#### 그래서 T1 은 두 가지 일을 한다 — 구분해서 구현할 것
| 상황 | 동작 |
|---|---|
| 진도 행이 **없다**(첫 표현학습) | 그 언어 레벨의 첫 차시로 **생성** |
| 진도 행이 **있는데 레벨테스트를 다시 봤다** | 새 레벨의 첫 차시로 **이동**(위아래 양방향) |
| 그 외(평소 통화) | **건드리지 않는다** |

⛔ 「레벨테스트를 다시 봤다」를 **레벨 값 비교로 판정하지 마라.** 레벨이 그대로(예: 2→2)여도
재측정은 일어난 것이고, 그때 진도를 그 레벨 첫 차시로 되돌리면 **배우던 차시가 날아간다.**
⇒ **레벨테스트 통화가 끝나는 그 자리에서** 한 번만 이동시킨다(이벤트 기준, 값 비교 아님).

#### ⚠ 되돌아갔을 때 남는 기록
진도가 뒤로 가도 `cur_member_lesson`·`cur_member_item`(배운 기록)은 **지우지 않는다.**
- 그 차시를 다시 하면 이미 드릴한 항목은 `review=True` 로 나온다(`select_items` 기존 규율)
- 「안 배운 걸로 한다」는 **건너뛴 차시**에 대한 결정이지, **배웠다가 되돌아간 차시**가 아니다
- ⇒ 기록은 남기고 포인터만 옮긴다. T3 스크립트와 같은 규율

## 7. 순서

```
T1(placement) ─┐
               ├→ T3(기존 회원 끌어올리기, dry-run → 검토 → apply)
```
