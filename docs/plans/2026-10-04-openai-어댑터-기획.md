## 1. 목표 · 범위 · 비범위

### 목표
표현학습 통화의 엔진을 Gemini Live → **OpenAI Realtime(`gpt-realtime-2.1-mini`)** 으로 바꿔 **15분 1통 $0.35 대**에 든다. 수단은 **새 어댑터 1개 + 접점 최소 수정**이고, `call_session.py` 복제는 하지 않는다.

### 범위 (1차)
1. `core/openai_live.py` **신규** — `LiveSessionProtocol` 6-메서드 구현.
2. 접점 수정 — 클라이언트 선택 · 끊김 판정 · 통화 길이/조각 정책 · 재접지·압축 기계 **차단**.
3. 서버가 쥐는 것 **3개**(퀴즈 창 · 재시도 한도 · 정답 판정) — §4.
4. 새 지시문(백지) — §5. ⛔ 전문은 빌드 때.
5. 종료 규약 — 15분 소켓 끊기 + 정상 종료 신호 — §6.
6. 결과 LLM 2레인 — §7.
7. 원가 계기판에 **cached 차원 추가**(§3-J) — 안 하면 OpenAI 원가를 **약 3배 과대계상**한다.

### 비범위
- **한국어(ko)만.** ja 「か」 구멍, 그 밖 언어 후순위.
- **표현학습(expression) 먼저.** 프리토킹·레벨테스트·자유대화(chat)는 Gemini 유지.
- 조각 분할 · 재개 쪽지 · `resume_handle` · 컨텍스트 압축 · 격식 백스톱 · 통화중 판정 사이드카 · 목록 부정 방어 · 번호 진행 강제 — **만들지 않는다**(측정에서 안 깨졌다).
- ASR 날조 완화책 — §9 에 비용·효과만 적고 **1차에서 뺀다**.
- Gemini 경로 제거 — 하지 않는다. `usage_engine` 으로 갈라 **공존**시킨다.

## 2. 아키텍처 · 데이터 흐름

### 2.1 전체 그림 (바뀌는 자리만 굵게)

```
Flutter ──PCM16/16k(binary)──▶ ws_router ──▶ call_session(run_call)
                                                │  2펌프 + TaskGroup + asyncio.timeout  ⛔ 무수정
                                                │
                                   live_session_factory(client, settings, **kwargs)
                                                │
                           ┌────────────────────┴────────────────────┐
                    core/gemini_live.open_session        **core/openai_live.open_session (NEW)**
                           │                                         │
                    Gemini Live WS                          **OpenAI Realtime WS**
                    PCM16/16k 그대로                        **16k→24k 업샘플(어댑터 내부)**
                                                            **PCM16/24k 입·출력 통일**
                           └──────── yield LiveEvent ───────┘
                                      (동일 계약)
Flutter ◀──PCM24k(binary)── call_session ◀── LiveEvent(kind="audio")
Flutter ◀──JSON(text)────── protocol.py  ⛔ 무수정
```

⭐ **요점: 어댑터가 「Gemini 모양」으로 번역해 올린다.** `call_session` 은 자기가 무슨 엔진을 쓰는지 **거의 모른다**. 아는 자리가 §3 의 접점이고, 그걸 최소화하는 것이 이 설계의 전부다.

### 2.2 6-메서드 매핑 (계약은 `core/gemini_live.py:172-186` `LiveSessionProtocol`)

| 메서드 | 시그니처(그대로 유지) | OpenAI 구현 |
|---|---|---|
| `send_audio` | `async def send_audio(self, pcm16_16k: bytes) -> None` | ⭐ **이름이 16k 인 채로 둔다**(호출부 `call_session.py:5664` 무수정). 어댑터가 **내부에서 24k 로 업샘플**해 `input_audio_buffer.append`(base64). ⛔ 리샘플 위치를 여기로 고정하는 것이 이 설계의 핵심 결정 — §8-R1 |
| `send_reground` | `async def send_reground(self, text, *, turn_complete: bool = True) -> None` | ⛔ **1차에서는 호출 자체를 차단한다**(§3-G). 구현은 `conversation.item.create(role="user")` + `turn_complete=True` 일 때만 `response.create`. ⛔ **`session.update` 로 `instructions` 를 갈아끼우지 마라** — 프리픽스가 바뀌어 캐시가 전부 깨진다(10-03 문서 §8 설계제약 1) |
| `send_text_turn` | `async def send_text_turn(self, text: str) -> None` | `conversation.item.create(role="user", input_text)` + `response.create`. 선톡 시드·넛지 시드·종료 시드·루프 차단 쪽지가 전부 이 통로다(`call_session.py` 4919·6072·6205·6488·6542·6704) |
| `send_persona` | 동일 | `send_text_turn` 과 **같은 몸통, 다른 메서드**로 둔다 — 합치면 재접지 회귀의 관측 채널이 오염된다(`gemini_live.py:181-183` 의 이유가 그대로 유효) |
| `send_tool_response` | `async def send_tool_response(self, fn_id, fn_name) -> None` | `conversation.item.create(type="function_call_output", call_id=fn_id)` + `response.create`. ⭐ `set_face` 는 **어댑터가 즉시 자동응답**하고 `auto_acked=True` 로 올린다 — 소비측(`call_session.py:5896` `if not getattr(event, "auto_acked", False)`)이 두 번 답하지 않는다 |
| `events` | `def events(self) -> AsyncIterator[LiveEvent]` | OpenAI 서버 이벤트 → `LiveEvent` 정규화. 표 §2.3 |

### 2.3 OpenAI 이벤트 → `LiveEvent` 정규화표

`LiveEventKind`(`gemini_live.py:140-143`)는 9종이다. **enum 을 늘리지 않는다** — 늘리면 `call_session` 의 분기를 건드려야 하고 Gemini 쪽 회귀가 같이 흔들린다.

| `LiveEvent.kind` | OpenAI 서버 이벤트 | 채우는 필드 | 비고 |
|---|---|---|---|
| `audio` | `response.output_audio.delta` | `audio=PCM24k bytes` | ⭐ 출력은 변환 없음. 우리 재생 파이프라인이 이미 PCM24k(`core/audio.py:19`) |
| `out_tr` | `response.output_audio_transcript.delta` | `text` | 비버 자막 |
| `in_tr` | `conversation.item.input_audio_transcription.delta` / `.completed` | `text`, `is_final` | ⭐ `is_final` 은 `.completed` 에서 True. **이 필드가 살아 있어야 무음 3단 넛지·퀴즈 판정·모드 관문이 돈다** |
| `turn_end` | `response.done` | — | ⭐ 턴 상태기계의 축. ⛔ `response.output_audio.done` 이 아니라 `response.done` 에 맞춘다 — 툴콜 턴은 Response 가 2개이고(10-03 §4) **2번째의 done 이 진짜 턴 끝**이다 |
| `usage` | `response.done` 의 `response.usage` | `usage=<shim>` | §3-I |
| `tool_call` | `response.function_call_arguments.done` | `fn_name`, `fn_id`, `fn_args`, `auto_acked=True` | `{"emotion":"happy"}` 3/3 정상(재측정 완료) |
| `interrupted` | `response.done` with `status="cancelled"` | — | barge-in off 라 거의 안 난다. **올려도 무해**(`call_session.py:5931` 이 받는다) |
| `go_away` | ⛔ **없다** | — | **영원히 yield 하지 않는다** |
| `resume_update` | ⛔ **없다** | — | **영원히 yield 하지 않는다** |

### 2.4 ⭐ Gemini 전용 필드를 어떻게 두나 (사장님 질문)

**결론: `LiveEvent` 를 한 글자도 안 바꾼다. 어댑터가 그 필드를 그냥 안 채운다.**

| 필드 | 소유 kind | OpenAI 어댑터 | 그러면 호출부는? |
|---|---|---|---|
| `time_left` | `go_away` | `go_away` 를 **안 올린다** | `call_session.py:5906-5913` 분기에 **영영 진입하지 않는다**(죽은 분기, 무해) |
| `resume_handle` · `resumable` | `resume_update` | `resume_update` 를 **안 올린다** | `:5952-5955` 미진입 ⇒ `state.resume_handle` 이 영구 `None` ⇒ `:4873` 의 `if state.resume_handle:` 이 거짓 ⇒ **`resume_handle` kwarg 가 어댑터에 안 넘어간다**. ⭐ 연쇄가 저절로 맞는다 |
| `auto_acked` | `tool_call` | ⭐ **쓴다 — `True` 로 채운다**(Gemini 전용이 아니다) | `:5896` 이 중복 응답을 막는다 |
| `fn_args` | `tool_call` | 쓴다 | `:5783` 이 `emotion` 을 읽는다 |
| `is_final` | `in_tr` | 쓴다 | `:5994` 재접지 자리 선택 + 넛지 |

⛔ **왜 필드를 지우지 않나**: `LiveEvent` 는 `@dataclass(slots=True)` 이고 Gemini 어댑터·테스트 가짜 세션 수십 개가 이 모양에 묶여 있다(`tests/test_normalcall_ws.py` 에 `send_audio`/`events` 가짜가 20개 이상). **필드를 빼면 OpenAI 와 무관한 회귀가 터진다.** 안 쓰는 칸은 `None`/`False` 기본값으로 두는 것이 비용 0 이다.

### 2.5 어댑터 규율 (CLAUDE.md 「core 는 도메인·DB 를 모른다」)

`core/openai_live.py` 가 **아는 것**: PCM 바이트 · 문자열 · tool 선언 · 자기 WS 프로토콜.
**모르는 것**: `call_id`·`member_id`·플랜·커리큘럼·퀴즈 상태·DB. `system_instruction`·`voice`·`tools` 는 `realtime` 이 조립해 넘긴다. 이 규율을 깨면 `gemini_live.py` 와 비대칭이 생겨 팩토리 주입이 성립하지 않는다.

### 2.6 어댑터 공개 심볼 (제안)

```python
# core/openai_live.py
DEFAULT_VOICE: str                       # "marin" (10-03 §6 실측 음색)
OPENAI_REALTIME_MODEL_DEFAULT: str       # "gpt-realtime-2.1-mini"

def build_openai_session_config(*, system_instruction: str, voice: str,
                                tools: object | None,
                                input_language_codes: list[str] | None,
                                ) -> dict: ...
    # session.update 페이로드 1개. 입·출력 모두 audio/pcm rate=24000(세션 중 변경 불가).
    # turn_detection = {"type": "semantic_vad"}   ← §8-R2

class OpenAIRealtimeSession:              # LiveSessionProtocol 구현
    async def send_audio(self, pcm16_16k: bytes) -> None: ...

@contextlib.asynccontextmanager
async def open_session(client, settings, *,
                       system_instruction: str,
                       voice: str = DEFAULT_VOICE,

```

⛔⛔ **`open_session` 의 시그니처를 `core/gemini_live.py:613-624` 와 글자까지 같게 둔다.** 이유: 호출부 `call_session.py:4890` 이 `live_session_factory(client, settings, **factory_kwargs)` 로 부르고, `factory_kwargs` 는 `:4868-4889` 에서 **값이 있을 때만** 키를 넣는 규율로 조립된다. `resume_handle`·`vertex` 를 받아 **조용히 무시**하는 것이 조건분기를 추가하는 것보다 싸고 안전하다.
⚠ 첫 인자 `client` — OpenAI 는 공유 클라이언트가 필요 없다(요청마다 WS). **받아서 무시하거나, lifespan 이 만든 `app.state.openai_realtime` 를 받는다.** §3-B 에서 정한다.

2. 10-03 §8 설계제약 1 — 세션 중 주입은 캐시 프리픽스를 안 깨는 `conversation.item` 이어야 하고, 그래도 **매 주입이 턴당 입력을 늘린다**.

| 안 | 내용 | 평가 |

| **G-1(권고)** | `state` 에 엔진 플래그를 두고 `_reground_watch` 를 **TaskGroup 에 올리지 않는다**(`:4909` 한 줄 조건) | 가장 작고 가장 확실. ⚠ R4 심사 대상 — 통화 회귀 필수 |

### 3.5 ⭐ H — 절대 백스톱은 **안 건드려도 된다**(내가 확인)

`call_session.py:4139-4140`:
```

```
`ABSOLUTE_CALL_TIMEOUT_S = 540.0`(`:173`), `SEED_TO_HANGUP_S = 22.0`(`:181`).
⇒ `state.call_duration_s = 900` 이면 `max(540, 952) = **952초**`. **백스톱이 저절로 따라 올라간다.**
⚠ 지금 900 이 안 되는 이유는 백스톱이 아니라 `CALL_FRAGMENT_S = 360.0`(`call_service.py:152`)이다. 바꿀 자리는 **거기**다.
⛔ R4 「절대 백스톱」 불변식은 **무수정**이다 — 상수도 식도 안 건드린다. 입력(`call_duration_s`)만 바뀐다. 이게 이 설계에서 R4 를 가장 적게 건드리는 길이다.

### 3.6 ⭐ I — usage shim (0줄로 끝내는 방법)

`_record_usage`(`:2709-2746`)는 전부 `getattr` 이고 `_modality_pairs`(`:2595-2608`)는 `m.modality.name` / `m.token_count` 만 읽는다. ⇒ 어댑터가 이 모양의 가벼운 객체를 올리면 `call_session` 은 **0줄**이다.

```python
# core/openai_live.py 내부 — 도메인을 모르는 순수 변환
_Mod = namedtuple("_Mod", "modality token_count")      # modality 는 str("AUDIO"/"TEXT") 로 둔다
                                                        #   → _modality_pairs 가 .name 없으면 str(mod) 폴백(:2604)
_UsageShim = namedtuple("_UsageShim", [
    "prompt_token_count", "response_token_count", "total_token_count",
    "thoughts_token_count", "cached_content_token_count",
    "tool_use_prompt_token_count", "prompt_tokens_details", "response_tokens_details",
])
```
매핑: OpenAI `usage.input_tokens`→`prompt_token_count` · `output_tokens`→`response_token_count` · `total_tokens`→`total_token_count` · `input_token_details.cached_tokens`→`cached_content_token_count` · `input_token_details.{audio,text}_tokens`→`prompt_tokens_details` · `output_token_details.{audio,text}_tokens`→`response_tokens_details` · `thoughts_token_count=None` · `tool_use_prompt_token_count=None`.

⚠ **잃는 정보 1개**: `cached_tokens_details.{audio,text}_tokens` 의 **분해**가 `cached_content_token_count` 한 칸에 접힌다. 그게 §3.7 의 문제다.
⚠ `_observe_compression`(`:2725`)이 `prompt_token_count` 하락을 「압축」으로 읽는다 — OpenAI 는 truncation off 라 단조증가여야 하지만, **툴콜 턴의 2-Response 구조**(10-03 §4)가 톱니를 만들 수 있다. ⇒ 로그에 `압축 감지` 가 뜨면 **오탐**이다. G-1 로 재접지를 끄면 해롭지 않지만 **로그 오독 주의**를 문서화한다.

### 3.7 ⛔⛔ J — 원가 계기판에 **cached 가 없다.** 안 고치면 OpenAI 를 3배 비싸게 본다

`normalcall_service.py:1807-1840`:
```
estimate_usage_cost_usd(*, in_audio=0, in_text=0, out_audio=0, out_text=0) -> float
```
**`cached` 파라미터가 없다.** 그리고 `LIVE_TOKEN_PRICE_USD`(`:1799`)는 단가표 **하나**다.

| | OpenAI mini 실제 | 현 코드가 계산할 값 |
|---|---|---|
| in_audio 정가 | $10.00/1M | $3.00/1M |
| in_audio **cached** | **$0.30/1M** | ⛔ **칸이 없다 — 전량 정가로 계산** |
| 실측 캐시 적중 | `in_audio` **89.8%** | — |

⇒ `in_audio` 의 90% 를 33배 비싸게 계산한다. **계기판이 「OpenAI 가 더 비싸다」고 거짓 보고한다.**

**설계(2단)**
1. 단가표를 `usage_engine` 으로 가른다 — 10-03 절감안 §1.4(a) 가 이미 같은 처방을 냈다(「산식은 그대로, 단가표만 `usage_engine` 으로」). 3.1 의 `in_text $0.75`/`out_text $4.50` 오류도 **같은 커밋에서 같이 고친다**.
2. **`cached_in_audio` · `cached_in_text` 를 산식에 **더한다**.
   `estimate_usage_cost_usd(*, in_audio, in_text, out_audio, out_text, cached_in_audio=0, cached_in_text=0, engine=None)`
   ⛔ 기본 0 ⇒ **기존 Gemini 호출부는 바이트 동일**(Gemini 는 캐시 미지원이라 영구 0).
   ⚠ 과금은 `in_audio` 가 **정가분 + 캐시분의 합**인지 **정가분만**인지 벤더마다 다르다. 10-03 실측 표(§1)는 `in_audio` 와 `cached_audio` 가 **별도 열**로 왔다 ⇒ **정가분 = `in_audio − cached_audio`** 로 보고 산식을 쓴다. ⛔ **이 가정은 결제 콘솔 1일분 대조로 확정해야 한다**(§10).
3. ⭐ **`usage_engine` 태그**
   - 사장님 지시는 `'openai:...'` 였다. ⚠ **기존 계약과 어긋난다**: `build_engine_tag(mode, *components)`(`:1857`)의 형식은 `<모드>:<구성요소>` 이고 **모드 자리는 `live`** 다. 그리고 `ENGINE_LIVE_OPENAI = "live:openai-realtime"` 가 **`:1854` 에 이미 있다.**
   - ⇒ **권고: `build_engine_tag("live", "openai-realtime-2.1-mini")` = `live:openai-realtime-2.1-mini`.** 모델까지 박아 둬야 모델 교체 후 집계가 갈린다(`:1863` 의 설계 의도 그대로).
   - 사장님 요구(「테스트 데이터를 한 쿼리로 지운다」)는 **그대로 충족**된다: `DELETE … WHERE usage_engine LIKE '%openai%'`.

### 4.1 퀴즈 창 열기 — 코드로 쥔다

**근거**: 3라운드 연속 0. 그리고 서버에 **이미 상태기계가 있다** — `_arm_expression_quiz_cue`(`call_session.py:1819`) · `expr_quiz_cue_pending`(`:997` 부근 슬롯) · `_close_expression_quiz` · `_expression_quiz_tick`(`:1297`). 즉 **창을 여는 기계는 만들어져 있고, 비버가 자발적으로 안 열 뿐이다.**

**설계**: 서버가 **큐 문구를 주입**해 창을 연다 — 기존 경로 재사용.
- 트리거: 「신규 항목 N개를 다뤘다(`covered_nums`)」 → 큐 arm → 다음 학습자 발화 자리에 얹기.
- ⛔ **재접지 슬롯과 공유하지 않는다** — 코드 주석(`:1313`)이 이미 그렇게 못질해 뒀다. G-1 로 재접지를 꺼도 **퀴즈 큐는 살아 있다**(별 슬롯).
- ⚠ 주입은 `send_text_turn`(완결 텍스트 턴)으로 간다. OpenAI 에서 캐시 프리픽스를 안 깬다(대화 끝 append).

**수용 기준**: 15분 통화 1건에서 **퀴즈 창 ≥ 2회 열림 + 닫힘**. 자발 개시는 **0을 기대값으로 둔다**(기다리지 않는다).

### 4.2 재시도 한도 — ⭐ 지시문 먼저

**왜 지시문 먼저인가**: 실측의 절반이 **출구 부재**다. 코드로 쥐면 「서버가 3회에 끊는다」가 되지만, **소진 뒤 무엇을 하라는 말이 지시문에 없으면** 비버는 여전히 같은 자리를 돈다 — 증상이 「8턴 체류」에서 「서버가 넘긴 뒤 어색한 침묵」으로 **옮겨갈 뿐이다**.

**지시문 처방 2개**(§5 에 재등장)

## 6. 종료 규약 — 15분 소켓 끊기

### 6.1 사장님 지시 정리
1. ⛔ **종료 시드를 안 넣는다.** 15분이면 서버가 **소켓을 끊는다.**
2. ⚠ **무음 3단 넛지는 유지**하고, 거기엔 **종료 시드가 맞다**(3단 = 작별 시드 주입, `IDLE_CLOSE_S=12.0`, `call_session.py:209`).
3. ⚠ 지시문 11행 제거(§5.3).
4. ⚠ PR #21 의 `CALL_INTERRUPTED` 와 충돌 회피.

### 6.2 ⭐ 좋은 소식 — 「정상 종료 신호 먼저 보내고 끊는」 경로가 **이미 있다**

`call_session._finish_call`(`:7406-7449`)이 하는 일, 그대로:
```
(fragment_end 가 아니면)
  ① ServerCallEnded(call_id=..., reason="done")  를 보낸다        (:7444)
  ② playback_done ack 를 PLAYBACK_DONE_WAIT_S(7.0s) 까지 기다린다  (:7446, :190)
  ③ close()                                                      (:7449)
```
⇒ **새 프레임을 만들 필요가 없다.** `call_ended{reason:"done"}` 이 정상 종료 신호다.

### 6.3 ⛔ 그래서 설계 규칙은 하나다 — **생(raw) close 를 하지 마라**

| | |
|---|---|
| ⛔ 하면 안 되는 것 | 900초에 `client_ws.close()` 를 직접 부르기. 그러면 `_finish_call` 을 건너뛰어 **정상 종료 신호가 안 나간다** ⇒ PR #21 의 비정상 종료 경로(`beaver_turns > 0`)가 발동 ⇒ 학습자에게 「통화가 예기치 않게 끊겼어요」 |
| ⭐ 해야 하는 것 | 시계워처(`_watch_call_clock`, `:4907`)가 **기존 종료 신호를 올려** TaskGroup 을 내리고, `finally` 가 **반드시 `_finish_call` 을 타게 한다**(`:7406` 이 finally 의 맨 끝에서 불린다 — `:7422` 주석이 그 사실을 명시) |

### 6.4 프레임 순서 · 프론트 계약

```
t=900.0  서버 시계워처: 종료 결정
         ⛔ 종료 시드 주입 없음 (send_text_turn(close_seed) 를 건너뛴다)
         → 통화 종료 신호 raise → TaskGroup 전원 취소
t=900.x  finally: 마지막 flush · 판정 · usage · 전사 저장
         (fragment_end == False 이므로)
         ──▶  call_ended { call_id, reason: "done" }      ← ⭐ 정상 종료 신호
         ◀──  playback_done { turn_id }                   (≤ 7.0s 대기)
         ──▶  close()
```
- ⛔ `fragment_saved` 는 **안 보낸다**(`state.fragment_end` 가 False여야 한다). 보내면 **클라가 재연결한다**.
- ⚠ `reason` 은 `str` 자유 필드(`protocol.py:326`)다. `"done"` 을 **그대로 쓴다** — 새 값을 만들면 구버전 앱의 분기가 어디로 가는지 알 수 없다.
- ⚠ **PR #21 과의 접합은 빌드 때 반드시 눈으로 확인**(§0 — 읽지 못했다). 확인할 것: *「`CALL_INTERRUPTED` 를 보내는 조건에 `call_ended` 를 이미 보냈는가가 들어 있는가」*. 안 들어 있으면 **그 조건에 가드를 넣는다**.

### 6.5 ⛔ 900초 경계의 **경합** — 사장님이 말하지 않은 위험

클라도 900초에 자기 틱으로 경계를 판정한다(`fragmentBoundaryAction`). **서버의 close 와 클라의 틱이 같은 초에 붙는다.**

| 누가 먼저 | 결과 |
|---|---|
| 서버 `call_ended` 먼저 | ✅ 정상 결과 화면 |
| 클라 틱 먼저 + `finalClose` | ✅ 「응답까지 하고 종료, 재연결 없음」 — 의도대로 |
| 클라 틱 먼저 + `sheet` | ⛔ **이어하기 시트가 뜬다** — §6.6 의 전제가 깨진 경우 |
| 클라 틱 먼저 + `seamless` | ⛔⛔ **조각2 를 연다** — 단일 세션 붕괴 |

⇒ **처방: 서버 시계를 클라보다 **먼저** 울리게 한다.** `state.call_duration_s` 를 **895초 전후**로 두고 `remaining_s` 는 **900** 을 보낸다(클라 경계는 900, 서버 종료는 895). ⛔ 두 값을 같게 두면 매번 경합이다. **결정 필요 — §11-D2.**

### 6.6 ⭐⭐ 프론트 계약 — 사장님 전제를 검증했다. **맞다. 그리고 값이 하나 더 있다**

### ⛔ 사장님 전제에 **빠진 값 1개 — 세 번째 값이 필요하다**

`seamlessEligible = seamlessEligibleCourse(course)` 이고 `seamless_fragment.dart:74-75`:

```
course == CallCourse.expression || course == CallCourse.freetalk
```
⇒ **`course` 가 `null`(일반·`chat`·레벨테스트)이면 `seamlessEligible == false`** ⇒ 900초에 **`sheet`**(유료라도!).

⇒ ⭐ **서버는 세 값을 함께 보내야 한다: `course` ∈ {expression, freetalk} + `remaining_s: 900` + `max_fragments: 1`.**
다행히 1차 범위가 **표현학습**이라 자동 충족된다. 하지만 **전제로 명문화**해야 한다 — 나중에 `chat` 에 확대하면 **이 한 값 때문에 시트가 뜬다**.
⚠ 서버에서 `course`·`fragment_index`·`max_fragments`·`remaining_s` 는 `call_type in ("expression","freetalk","chat")` 일 때만 실린다(`call_session.py:3734`, `:3750`) — `chat` 은 서버는 보내는데 **클라가 eligible 로 안 본다.** 지금 있는 비대칭이다.

### 7.2 설계 — 레인 2개

| | **빠른 레인** | **느린 레인** |

### 7.3 ⭐ 진도 판정을 빠른 레인에 얹는 근거

측정이 말한 것: **끝에 전사 1회로 11/12**. 그리고 **창 단위는 6개 중 2~3개만 값이 생겼다 — 더 낫다.**
⇒ 진도 판정은 ①전사만 필요하고 ②한 번만 돌면 되고 ③결과 화면이 **바로** 쓴다(어느 항목을 뗐나) ⇒ **빠른 레인의 정의에 정확히 들어맞는다.**
⛔ **통화 중 판정 사이드카는 만들지 않는다**(측정에서 더 나빴다).

### 7.4 ⚠ usage 가산의 함정

`SIDE_LLM_KEYS` 는 **키 2개**다. 레인을 늘리면서 **새 키를 만들면** `SIDE_USAGE_KEYS`(`:2023`, 「이 통화가 곁가지를 쟀나」 판정용)와 집계 루프(`:2038`)가 **새 키를 모른다** ⇒ 그 비용이 조용히 사라진다.
⇒ **처방: 새 키를 만들지 말고 `"analysis"` 에 합산한다.** 분리 집계가 필요해지면 그때 `SIDE_LLM_KEYS` 에 키를 **추가**하고 `:2023`·`:2038` 을 같은 커밋에서 고친다.

### 7.5 레인 경계의 불변식
- ⛔ **두 레인이 같은 행을 같이 쓰면 안 된다.** 빠른 레인 = 제목·진도, 느린 레인 = 문장·요약·발음·복습. 겹치면 마지막에 끝난 쪽이 이긴다(경합).

### 10.3 측정이 **아예 안 본** 축
- 15분 통화의 **전사 품질 전체**(날조율은 1건 표본)
- 발음평가·복습 생성이 OpenAI 전사로 정상 동작하는가
- `fragment_ended_at`·`resume_context` 등 **조각 전제 컬럼**이 단일 세션에서 어떻게 남는가
- 15분 세션 중 **네트워크 끊김** 1회가 났을 때의 복구(세션 재개 문서 없음 — 10-03 §8.5)
