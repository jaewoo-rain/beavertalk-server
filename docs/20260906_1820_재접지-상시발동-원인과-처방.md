실측 근거: 통화 **1310**(오전 10:24) · **1324**(저녁 18:03, 클라 수정 후)

> **한 줄**: 재접지가 첫 턴부터 켜지는 건 **arm 조건이 절대값**이기 때문이고, 그 뒤 계속
> 켜지는 건 **바닥(지시문)이 트리거의 90% 를 먹어서 압축이 진짜로 5~7번 돌기** 때문이다.
> 앞엣것은 코드로 지금 고친다. 뒤엣것은 **비용 결정이 걸려 있어 사용자 판단이 필요하다.**

## 2. 원인 ① — arm 조건이 절대값이라 첫 턴부터 참이다

`call_session.py:3742`
```python
if state.usage_prompt_peak >= trigger * REGROUND_ARM_RATIO:
    return "compress"
```
`trigger=8000`(env) × `REGROUND_ARM_RATIO=0.85`(`call_session.py:200`) = **6,800**.
그런데 통화 시작 8초의 peak 가 **7,194** 다. 대화가 한 줄도 안 쌓였는데 이미 참이다.

주석은 "컨텍스트가 트리거의 85%까지 **찼다**"라고 말하는데, 실제로 채운 건 대화가 아니라
**시스템 지시문**이다. **바닥을 안 빼고 재는 것이 버그다.**

증상 = QA #1(45초에 첫인사 재발). 주입이 `자리=마이크`(학습자 발화 시작)라, 학습자가 첫
문장을 만드는 위에 브리프가 얹혀 비버가 자기 과제를 버린다.

## 3. 원인 ② — 바닥이 트리거의 90% 라 압축이 진짜로 돈다

`build_system_instruction` 을 실제로 렌더해 쟀다(합성 항목, `scripts` 아님 · 일회성 측정):

```
본편5 + 예비25 (현행)   9,355 자
본편5 + 예비5           8,150 자
본편5 + 예비0           7,843 자
공부 블록 없음           4,641 자
  → 예비 25개 = 1,512 자 (지시문의 16.2%)
```

예비 25개는 `mastery_repository.py:248-249`(`STUDY_MAIN_TOTAL=5` / `STUDY_RESERVE_TOTAL=25`).
`teaching_plan=30` 로그가 그 30개다. **5분 통화에서 실제로 도는 항목은 4~5개**다.

⇒ 바닥 7,194 / 트리거 8,000 = **90%**. 대화가 들어갈 자리가 **806 토큰**뿐이라 압축이
5분에 5~7번 돈다. 그때마다 `post-compress` 로 재접지가 또 arm 된다. **원인 ①을 고쳐도
②가 남으면 재접지는 계속 뜬다.**

## 4. ⭐ 비용 논거가 실측으로 흔들린다

`docs/20260805_1830_압축-트리거-하향-논증.md` 와 QA 문서는 "**8,000 은 비용 때문에 일부러
내린 값이라 못 올린다**"로 닫혀 있었다. 그런데 통화 1324 실측이 그 전제를 흔든다.

```
턴당 prompt 10,476  중  바닥 7,194  ⇒ 69% 가 지시문
압축이 잘라낼 수 있는 건 나머지 31% (대화·오디오) 뿐이다
```

**Live 는 매 턴 프롬프트 전액 재과금이다.** 바닥은 압축해도 안 줄어든다(매 턴 다시 실린다).
즉 트리거를 16,000 → 8,000 으로 내려 아낀 건 **턴당 최대 800~3,000 토큰**인데, 그 대가로
5분에 압축 5~7회(= 비버가 앞부분을 5~7번 잊음) + 재접지 5회를 샀다.

⇒ **진짜 비용 레버는 트리거가 아니라 바닥이다.** 예비 25개를 5개로 줄이면 지시문이
1,205자(≈900~1,200 토큰) 줄고, 그건 **매 턴 전부**에서 빠진다.

## 5. 처방 — 3개, 성격이 다르다

### A. arm 을 바닥 기준 상대값으로 (코드 · 지금 한다 · 논쟁 없음)
`usage_prompt_floor`(통화 첫 usage 의 prompt)를 기록하고,
```
peak - floor >= (trigger - floor) × REGROUND_ARM_RATIO
```
로 바꾼다. "대화가 남은 자리의 85% 를 채웠나"를 재는 것 — 주석이 원래 말하던 뜻이다.
⛔ `trigger - floor <= 0` (바닥이 이미 트리거 초과) 이면 ①을 끄고 ②`post-compress` 에만
맡긴다 — 안 그러면 지금과 똑같이 상시 참이 된다.
**효과**: 첫 턴 발동(+8초)이 사라진다 = QA #1 해결. 나머지 arm 은 ②로 남는다.

### B. 예비 항목 25 → 5 (코드 · 사용자 확인 필요)
`STUDY_RESERVE_TOTAL = 25 → 5`. 바닥이 ≈1,200 토큰 줄어 대화 자리가 806 → 2,000 으로 2.5배.
압축 횟수가 줄고, **매 턴 원가도 같이 준다.**
⚠ 부작용: 학습자가 본편 5개를 빠르게 소화하면 예비가 모자랄 수 있다. 5분 통화 실측은 4~5개
소화라 여유롭지만, **15분 통화에선 다시 봐야 한다.**
⚠ `teaching_plan` 카드도 30 → 10 이 된다(같은 소스). **화면에 보이는 항목 수가 줄어든다** —
프론트/기획 확인 필요.

### C. 트리거 8,000 → 상향 (설정 · 사용자 결정 필요)
`gcloud run services update ... LIVE_CTX_TRIGGER_TOKENS=11000 LIVE_CTX_TARGET_TOKENS=9000`.
코드 변경 0, 재배포 0, 되돌리기 1줄. **§4 가 이걸 지지한다.**
⚠ 5분 통화 원가가 오른다(늦은 턴에서 최대 +3,000 토큰/턴). 얼마나 오르는지는 통화 1건 재면 나온다.
