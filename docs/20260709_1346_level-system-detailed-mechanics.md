## 관통 원칙 3개 (모든 부품에 적용)

1. **AI는 증인, 코드가 심판** — LLM 출력은 인용 검증·상한·규칙 게이트를 통과해야만 데이터가 된다.
2. **증거 로그(item_evidence)가 원본, 나머지는 전부 파생값** — 상태·버벅임 판단·승급·비버 멘트까지 모두 계산값. 별도 플래그 필드 금지(이중 소스 방지). 규칙 변경 시 과거 로그로 전체 재계산(리플레이) 가능해야 한다.
3. **선별은 SQL, AI에겐 골라서 떠먹임** — closed-set. 벡터DB/랭체인 불필요의 근거. 비용은 사용자 수와 무관하게 통화당 고정.

## ① 통화 시작 시퀀스

```
1. WS 연결 + Supabase 토큰 검증 → member find-or-create (기존 코드 무변경)
2. member.korean_level 분기:
   null → 레벨테스트 대본 (call_type='level_test' 기록)
   있음 → 일반 통화 대본
   ※ ClientStart.call_type 명시 시 그것이 우선(미래 재측정 통로). 추가 DB 비용 0.
3. (일반) 재료 조회 — 통화 시작 때 1회, 통화 중 DB 접근 없음(1분 flush 제외):
   a. level 프로파일 1행
   b. 공부용 10개 (②)
   c. 대화용: 아는 문법 ≤40 + 유도 표현 5 (③)
   d. 승급 직후 여부: member_level_history 최신 행 이후 증거통화 == 0 → 승급 멘트 1줄 (⑧)
   e. 버벅임/브리지 여부 (⑨) → 복습 비중 결정
4. build_system_instruction 순수 문자열 조립 (LLM 0)
5. ServerTeachingPlan 1회 push — P2.5 카드 화면용. 데이터 없으면 미전송.
   기존 클라는 미지 타입 무시(무해 확인됨). P0~P2 는 클라 무수정.
```

## ② 공부 모드 10개 선별 규칙

```
본편 5:
  슬롯 1~2. 복습 0~2개: status='PRACTICING' AND level_no <= 내레벨
            ORDER BY 감쇠점수 ASC (가장 위태로운 순)  ※ 브리지/버벅임 시 확대(⑨)
  슬롯 3.   신규 문법 정확히 1개 (2개 금지 — 항목당 75~90초, 2개면 통화 70% 소모):
            내 레벨 문법 중 progress 행 없음 → 교재 단원 순서 첫 항목
  슬롯 4~5. 신규 어휘 2~4개(본편 합계 5): 내 레벨 core 어휘 미학습 → 우선순위 점수순
예비 5: 신규 어휘만 (1개당 35~45초 — 종료 시드가 언제 와도 절단 위험 최소)

밴드별 본편 구성: L1 = 청크 3 + 어휘 1(문법 0) / 초급 = 복습 0~2 + 문법 1 + 어휘 2~4
                 / 중급 = 어휘 상한 3 / 고급 = 복습 0~1 + 어휘 3~4
```

제외 필터 (재교육 낭비 방지):
| 규칙 | 조건 | 효과 |
|---|---|---|
| SEL1 | status='MASTERED' (fast-track 미확정 포함) | 공부 큐 영구 제외 |
| SEL2 | 자발 1+ && 오류 0 && 최근 14일 사용 | 공부 제외 → 대화 재활용 풀로 |
| SEL3 | 직전 주입에서 성공 | 2통화 쿨다운 (**F였으면 즉시 재출제**) |
| SEL4 | 선발화 관측(이미 아는 티) | 우선순위 최하위 |

미소화분은 다음 통화 선두로 이월. 로드 10/실소화 4~6 — "다 못 가르쳐도 서두르지 마라" 프롬프트 명문화.

## ③ 대화 모드 유도 5개 선별

```
3개: PRACTICING 중 last_evidence_at 가장 오래된 순   (주력 복습)
1개: MASTERED 중 가장 고령                            (리텐션 불시 점검)
1개: 최근 7일 내 INTRODUCED 중 1개                    (갓 배운 것 굳히기)
```
- 유도 상황 힌트 = freetalking.json 문법↔미션 인덱스 기계 조회(부팅 시 1회 로드, 필드 철자 `Misson1/Misson2/Mission3` 주의). 폴백 = 고정 템플릿 + 예문.
- 상한 5 이유: 학습자 한국어 발화 기회 5~15회/통화. 유도 규칙: 표현당 2회 시도 후 포기, "하나도 못 꺼내도 실패 아님", 어휘 whitelist 미주입(안 지켜짐 — 프로파일 서술 + 아는 문법 40 soft + "범위 밖이면 모국어 뜻 병기" 폴백으로 통제).

## ④ 교습 절차 (공부 모드 — 항상 문장 중심, 사전식 강의 금지)

```
문법: ①뜻·쓰임 모국어 1~2문장 ②예문 또박또박→따라 ③흥미 반영 즉석 예문→따라
      ④응용 질문("너는 주말에 뭐 하고 싶어?")→학습자 자기 문장 산출 ⑤한두 곳만 교정
어휘: ①뜻 모국어 ②단어 따라 ③"아는 문법만 쓴" 예문 따라   ← 새 요소는 단어 하나만
청크(L1): ①상황 설명 ②통문장 천천히 따라 ×2 ③문법·조사 설명 금지(통암기)
복습: 회상 질문 1개("지난번 그거 한국어로 어떻게 말하지?") → 성공=칭찬+다음(E2 기록),
      실패=정답 1회 들려주고 다음(E1) + 다음 통화 복습 큐 재등록. 오래 머물지 않음.
```
어휘 예문은 아는 문법으로, 문법 예문엔 그날 어휘를 태움 — 사용자 입에 오르는 건 항상 완성 문장.

## ⑤ 통화후 분석 파이프라인 (순서 고정 — P2.6 재정렬 반영, 2026-07-09 구현)

```
0. 전사(텍스트) 선저장 [통화 종료 finally] — 최종 persist 는 save_segments(upload_audio=False):
   전사 행을 먼저 커밋(voice_url=None) → 분석 태스크 즉시 생성(우선 착수).
   오디오 MP3 변환·업로드(~9s)는 별도 백그라운드 태스크(upload_segment_audio)로 병렬,
   완료 시 해당 행 voice_url UPDATE (실패 시 None 유지 — R5).
   ※ 통화중 1분 점진 flush 는 종전 그대로 upload_audio=True.
1. 전사 조립 (기존 _build_dialog 재사용)
2. 후보 30 구성: 오늘 주입 ~12(공부 10 + 유도 교집합 제외분) + PRACTICING last_evidence_at ASC 18
3. LLM 1콜 (기존 분석 콜에 detections 병합 — 추가 콜 0, ~$0.007):
   후보마다 none/E1(모방)/E2(유도)/E3(자발)/F(오류) + USER 발화 원문 인용 필수
3.5 ⚡ 요약·표현(Sentence)·status=done 단일 커밋 (_save_analysis) — 결과 페이지
   폴링이 **여기서 풀린다**(TTS×N·체크판 대기 없음). 빈 전사→done(빈 결과) /
   LLM 실패→failed 규약은 종전 유지. **done 이후 단계의 실패는 status 를 되돌리지
   않는다**(로그만 — 결과 화면 무손상).
3.6 문장 TTS 루프 — done 이후 같은 태스크에서 후행. 실패/미완이면 voice_url None
   → 재생 시점 온디맨드 합성(POST /sentences/{id}/tts)이 폴백.
4. 서버 검증 게이트 (done 이후 후행 — 순서대로):
   ✗ item_id 후보 밖 → 폐기
   ✗ quote 가 USER 전사에 부재(공백 정규화 후 부분일치) → 폐기      ← 환각 차단
   ✗ E3인데 직전 2 BEAVER 턴에 동일 표현 → E1 강등                  ← 앵무새 방어
   ✗ 4음절 미만·항목 단독 발화 E2/E3 → E1 강등
   ✗ 동일 정규화 인용 중복 → 1건
5. item_evidence append (call_id, item_id, grade_raw/final, quote, turn_index, text_hash)
6. 카운터·점수 갱신 + 상태 재계산(⑥) — 상한: 항목당 순증 +2.0/통화,
   MASTERED 승격 문법2·어휘6·청크4, INTRODUCED 8, fast-track 2
7. evaluate_level_up (⑦) — 같은 서비스 흐름, 4~7 은 여전히 **단일 commit**
   (done 커밋과 분리 — 부분 실패해도 결과 화면 무손상, 체크판만 재시도 대상)
   ※ (D15) 구 7단계 "call 유효성 산출·저장" 폐지 — 통화 수 파생값은 "증거통화"
     (item_evidence 에 행이 있는 distinct call)로 계산, call 컬럼 캐시 없음
```
30 밖 발화의 유실은 수용(순환으로 다음 통화에 포착 — MASTERED 는 어차피 2통화 필요라 지연일 뿐 손실 아님). 실측 후 30→50 조정 가능. open-set 은 P3.
레벨테스트(analyze_level_test_call)는 원래 판정+done 단일 커밋이라 P2.6 무변경.

## ⑥ 상태 전이 (점수·카운터의 순수 함수)

점수 Δ: E0 +0.25 / E1 +0.5 / E2 +1.0 / E3 +1.5 / F −1.0. 클램프 0~6.

```
UNSEEN → INTRODUCED:  E0/E1 1건 (즉시)
INTRODUCED → PRACTICING: E2+ 성공 1건 || 서로 다른 통화 2회 E1
PRACTICING → MASTERED: ①score≥3.0 ②성공 증거 2통화·2일 분산 ③E2+ 2건 중 E3≥1
                       ④최근 증거 ≠ F   — 4개 전부
MASTERED 강등: 없음 (fast-track 미확정만 예외. 감쇠는 P3)
L1 특례: INTRODUCED 에 따라말하기 인정, MASTERED = 2통화 사용(E2 인정, E1만 배제)
```
항목 유형별 "잘씀" 판정 참고(검출 지시문에 반영): 어휘=에코 배제 자발 / 문법=결합 어휘 2종+ / 문형=슬롯 충전물 2종+ / 청크=상황 적합 산출.

### fast-track (미학습→잘씀 1통화 직행)
같은 통화에서 5조건 전부: ①E3 2건 ②서로 다른 문장(hash 상이 && Jaccard<0.5) ③사이 USER 턴≥2 ④≥1건이 비버 최초 언급 이전 turn_index(미주입 항목은 자동 충족) ⑤F 0건. → provenance='fast_track', 미확정.
- 다음 대화 통화 리텐션 슬롯 최우선 재확인: E2+ 1건 → 확정 / 2회 기회에서 F만 → PRACTICING 복귀(score 2.0) / 14일 무F → 자동 확정.
- **미확정분은 레벨업 G2 미산입.** 통화당 fast-track ≤2.

## ⑦ evaluate_level_up (통화 분석 커밋 직후, 멱등)

```
0. member_level_history 에 trigger_call_id 존재? → 종료          [UNIQUE 멱등 키]
1. member 행 FOR UPDATE                                           [동시 분석 경합 방지]
2. k >= 13 → 종료 (최고 레벨)
3. 집계 (전부 현재 레벨 k 항목 한정):
   Q1 상태별 카운트 — mastered 는 fast-track 확정분만
   Q2 레벨 진입(history 최신 행 created_at) 이후 경과일 (G5 재료)
   Q3 최근 5 "증거통화"(item_evidence 에 행이 있는 distinct call, 최신순)의
      F비율 (분모 <10 이면 pass)
4. 게이트: G1 배움(초90/중85/고80%) && G2 잘씀(초55/중50/고45%)
        && G4 F비율(<30/25/20%) && G5 잠금(승급 후 3~10일 — 일수만)
   ※ (D15) 체류 게이트(G3) 폐지 — G1/G2 와 이중 규제(배움·잘씀을 채우면 통화 수는
     자연 충족). 재측정 하향 진입의 "G3 요구 ½" 완화도 함께 소멸.
5. 통과 → 단일 트랜잭션: korean_level = k+1 (항상 +1) + history 행
   (reason='gate_promotion', trigger_call_id, gate_snapshot JSONB)
정체 구제: 30통화/45일 && G1 충족 && G2 미달 → 15통화마다 G2 −5%p(하한 45/35%)
          + 승급 프로브 콜(미숙달 S(t) 하위 10개 강제 편성, E2+ 7/10 → 면제 승급)
```

## ⑧ 승급 멘트 (D3 — UI 없음, 파생 계산)

통화 시작 시 `history 최신 행이 gate_promotion && 이후 증거통화 == 0` 이면 프롬프트에 1줄:
```
[승급 알림] 학습자가 최근 실력이 늘어 오늘부터 조금 더 어려운 내용을 다룬다. 통화 초반에
{locale_label}로 "저번에 정말 잘했으니까 오늘은 조금 어려운 것도 해볼까?"처럼 자연스럽게
한 번만 언급하라. 레벨·점수·단계 같은 단어는 쓰지 마라.
```

## ⑨ 버벅임/브리지 컨트롤 (필드 없음 — 선별 시점 파생 계산)

```
통화 시작, 항목 선별 직전:
1. history 에서 현재 레벨 진입일
2. 진입 후 증거통화 < 3 → 무조건 브리지 믹스 (이전 레벨 복습 70% : 신규 30%)
3. 진입 후 5통화 이내 && 최근 3 증거통화에서 현재 레벨 항목
   (F비율 ≥ 50% || E2+ 성공 0건) 3연속 → 소프트 강등 믹스 (복습 70%)
4. 회복: F비율 < 30% 통화 2연속 → 정상 믹스 (복습 30% : 신규 70%)
```
비용: 회원당 최근 3~5통화 증거 수십 행 집계 — ms 단위, 통화당 1회.

## ⑩ 레벨테스트 판정 (P1)

```
통화 중: 판정 0 — 4계단 프로빙(인사·자기소개 → 과거·계획 → 경험·의견 → 추상 논증).
        계단당 2회 무난히 답하면 상승, 막히면 모국어 안심 + 쉬운 질문 후 하강. 교정 금지.
        비버 첫마디가 "시험 아님" 프레이밍 담당(인터스티셜 없음 — D11).
통화 후:
0. USER 발화 합계 <20자 → LLM 콜 없이 스킵, 미저장, status=done (다음 통화 자동 재테스트)
1. generate_structured 1콜, temperature 0. 필드 순서 강제(구조화 출력 내 CoT):
   evidence(인용) → reasoning → band(3지선다) → level_in_band(1~4) → level_no
   → confidence → sample_quality → summary → feedback_for_learner(레벨 숫자 금지)
2. 서버 클램프: band-level_no 불일치 → 계산 교정, 그래도 불일치 → 밴드 중앙값−1
3. 특수: 발화 있으나 전부 모국어 → L1 저장 / sparse+low → 1단계 하향 / LLM 실패 → failed·미저장
4. 단일 commit: korean_level + call(assessed_level/note/summary) + status=done
   + grandfathering: ≤k−2 전 항목 MASTERED(placement, score 3.0) / k−1 INTRODUCED / ≥k UNSEEN
   placement 는 실증거에 즉시 굴복(F 1건 → PRACTICING score 1.0)
루브릭: {rubric} 텍스트 슬롯 — assets/level/leveltest_rubric.md → 코드 상수(13레벨 프로파일 압축) 폴백
```

## ⑪ teaching_plan / 클라 범위 (사장님 문답 확정)

- **P0~P2: 클라 무수정.** start(character_id)만 — locale 도 서버가 member.language 로 해결.
- teaching_plan 은 **P2.5 레벨1 카드 화면 전용**(사장님 요청 기능): 통화 시작 직후 서버→클라 1회 push. 클라 작업 = 메시지 수신 → 카드 위젯(TEACH/RECALL 상태기계·자막 매칭) → hint_used 송신. 데이터 없으면 미전송 = 기존 화면. 구버전 앱은 미지 타입 무시(확인됨).
- 힌트: 2단계(첫 음절 → 전체). hint_used 는 MVP 저장만, 판정 반영(2단계 후 발화=모방 취급)은 P3.

## ⑫ 에이전트 구조 (사장님 문답 확정)

**통화 엔진 1개 + 대본(system_instruction 템플릿) 2종**(일반 / 레벨테스트) + L1 공부 블록 변형 1개.
레벨별 차이는 대본이 아니라 **대본에 꽂는 데이터**(레벨 프로파일 + SQL 선별 항목). 레벨별 에이전트 13개 금지(규칙 중복 13벌·일관성 붕괴). 캐릭터 목소리·말투는 사용자 선택 그대로(콜타입 = 통화 목적 축, 캐릭터 = 음색·말투 축).

## ⑬ 동적 힌트 — 질문별 예시 답변 (D16, P2.5)

### 목적
사용자가 비버 질문에 말이 막히는 상황 방지. 비버가 "어디 가세요?" 하면 힌트 상자에
**예시 답변 3줄**: `화장실에 가요` / `hwajangsire gayo` / `I'm going to the bathroom`.

### 동작 흐름 (통화 중 — 서버 사이드카)
```
1. 비버 발화 종료(turn_end) 감지 — 서버는 output_transcript 로 질문 전문을 이미 보유
2. 서버가 사이드카 LLM 1콜 (generate_structured, flash 계열, 구조화 출력):
   입력 = 비버의 직전 질문 + 레벨 프로파일("이 사람이 아는 범위의 문법·어휘로") + 모국어
   출력 = { korean, roman, native }  ※ 로마자는 서버 RR 규칙 변환 우선(LLM 폴백)
3. WS 텍스트 메시지 push: { type:"hint", turn_id, korean, roman, native }
4. 클라: 힌트 상자 표시(접힌 상태 → 탭하면 공개 권장 — 항상 노출하면 회상 학습이 죽음)
```

### 왜 이 구조인가
- **Live 모델(비버)에게 시키면 안 됨**: 생성한 것을 소리 내어 말해버림 — 화면 전용 데이터를
  분리해 내보낼 통로가 Live 오디오 세션에는 없다.
- **타이밍 정합**: barge-in off 라 사용자는 비버 말이 끝나야 발화 가능 — 사이드카 생성
  0.5~1.5초가 정확히 "생각하는 틈"에 도착한다.
- **generate_structured 통화 중 첫 사용**: 지금까지는 통화 종료 후에만 썼으나(요약·검출·판정),
  힌트는 통화 도중 HTTP 단발 콜. Live 소켓과는 별개 연결이라 상호 간섭 없음(점진 flush 와
  같은 검증된 패턴 — 통화 경로 밖 백그라운드).

### ⛔ 격리 원칙 (R4/R5)
- 2펌프 경로에 끼우지 않는다 — turn_end 시 **fire-and-forget 태스크**(강참조 보관, 통화 종료
  시 취소). 힌트 생성이 느리거나 실패해도 통화는 무영향, 힌트만 미표시(graceful).
- 힌트 태스크는 세션당 동시 1개(새 turn_end 가 오면 이전 미완 힌트는 취소 — 낡은 질문의
  힌트가 늦게 뜨는 혼선 방지).

### 오염 방지 (사장님 확정)
- 힌트를 **연 순간** 클라가 기존 통화 WS 로 `{ type:"hint_used", turn_id }` 전송 — 별도
  REST API 불요(소켓이 이미 열려 있음), 유실돼도 사용자에게 유리한 쪽 오차라 ack 불요.
- 통화후 분석에서 해당 turn 의 증거는 **따라말하기(E1) 수준으로 강등** — 힌트 보고 읽은
  발화가 자발(E3)로 잡혀 "잘씀"이 부풀지 않게. (정적 카드 힌트(⑪)와 동일 규칙으로 통일)

### 비용·적용 범위
- 힌트 1건 ≈ $0.0005 (질문 1문장 + 레벨 요약 입력, 3줄 출력) → 통화당 10~15건 ≈ 1센트 미만.
- 적용 순서: L1(생존)·레벨테스트 우선 → 전 통화 확장은 서버 플래그로(레벨이 높을수록 힌트
  의존을 줄이는 정책 여지).
