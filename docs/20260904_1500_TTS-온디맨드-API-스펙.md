# TTS 온디맨드 API 스펙 — 문장을 주면 음성 바이트를 돌려준다

작성 2026-09-04 · 상태 **기획 확정 / 미구현** · 프론트 전달용

| 항목 | 결정 |

## 1. ⚠ 기존 것과 다릅니다 — 헷갈리지 마세요

```
POST /api/v1/sentences/{id}/tts   →  {"voice_url": "..."}   JSON · Storage 저장 · 저장된 문장
POST /api/v1/tts/speech           →  MP3 바이트             바이너리 · 저장 안 함 · 임의 문장
```

학습 문장 재생은 **계속 위쪽**을 쓰세요. 아래는 저장 안 된 임의 문장 전용입니다
(힌트 읽어주기, 사용자 입력 발음 듣기 등).

## 2. 요청

```
POST /api/v1/tts/speech
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{ "text": "안녕하세요, 만나서 반갑습니다" }
```

또는 특정 캐릭터 목소리를 지정하고 싶을 때:

```json
{ "text": "안녕하세요, 만나서 반갑습니다", "character_id": 2 }
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `text` | string | ✅ | 합성할 문장. **1~200자** |
| `character_id` | int | — | 이 캐릭터의 음색으로 합성. **안 주면 회원의 대표 캐릭터**(`member.character_id`) |

⭐ **목소리 이름도 언어 코드도 안 보냅니다.** 서버가 정합니다:

```
목소리  character_id → character.voice.name
        ⭐ character_id 를 안 주면 member.character_id (사용자가 고른 대표 캐릭터)
        그래도 없으면 언어 기본 음성
언어    member.target_language (JWT 의 회원)        (없으면 "ko")
```

⚠ 대표 캐릭터 폴백은 **통화와 같은 규칙**입니다 — `resolve_call_character` 의 폴백 사슬이
  「알람 캐릭터 → member.character_id(대표) → 가장 싼 캐릭터」이고, 여기선 알람이 없으므로
  **대표 캐릭터부터** 시작합니다. 두 곳이 같은 규칙을 쓰면 «통화에선 A 목소리인데 TTS 는
  B 목소리» 같은 어긋남이 안 생깁니다.

⚠ 이건 기존 `/sentences/{id}/tts` 와 **같은 결정 방식**입니다. 앱에 벤더 목소리 이름
  (`"Leda"` 같은)이 굳지 않게 하려는 것이고, 캐릭터 음색을 바꿔도 앱은 그대로입니다.
⚠ `member.target_language` 는 통화의 대상 언어와 **같은 단일 소스**입니다
  (`member.py:57` 주석). 즉 통화에서 듣던 언어·목소리와 일치합니다.

## 3. 응답 200 — JSON 이 아닙니다

```
HTTP/1.1 200 OK
Content-Type: audio/mpeg
Content-Length: 24576
Cache-Control: private, max-age=86400
ETag: "a1b2c3..."

<MP3 바이트>
```

바디가 **MP3 바이너리 그대로**입니다. 파싱하지 말고 플레이어에 넘기거나 임시 파일로 쓰세요.

---

## 4. ⛔⛔ 가장 중요 — 응답 형식이 상태코드마다 다릅니다

```
200  → Content-Type: audio/mpeg       바디 = MP3 바이트
그외 → Content-Type: application/json 바디 = {"detail": {"code","message"}}
```

⇒ **바디를 읽기 전에 상태코드를 먼저 보세요.** 200 을 가정하고 JSON 파싱하면 MP3 를
  파싱하다 깨지고, 반대로 에러 JSON 을 오디오로 넘기면 재생기가 조용히 실패합니다.
  **이 API 의 유일한 함정입니다.**

| 상태 | code | 언제 | 프론트 대응 |
|---|---|---|---|
| 401 | `HTTP_401` | 토큰 없음/만료 | 재로그인 |
| 404 | `HTTP_404` | 준 `character_id` 가 없는 캐릭터 | 입력 오류 |
| 422 | `HTTP_422` | `text` 가 비었거나 200자 초과 | 입력 교정 |
| 503 | `HTTP_503` | ⛔ TTS 비활성/합성 실패 | **음성 없이 텍스트만** |

⛔ **503 폴백은 선택이 아닙니다.** TTS 는 외부 서비스(Cloud TTS)라 키가 없거나 장애면
  서버가 죽지 않고 503 으로 떨어집니다(이 프로젝트의 graceful degradation 규율).
  **재시도로 풀리는 오류가 아닙니다** — 앱이 음성 없이도 동작해야 합니다.

---

## 5. ⚠ 알고 가는 위험 — 잠금 검사를 안 합니다

사장님 결정으로 **캐릭터 잠금 검사를 넣지 않습니다.**

⇒ 무료 사용자가 아무 `character_id` 나 넣어 **유료 캐릭터 음색을 들을 수 있습니다.**
  기존 `/sentences/{id}/tts` 는 「본인 통화의 문장」이라 자연히 막혔는데, 이 API 는
  그 보호가 없습니다.

⚠ 나중에 막고 싶으면 판정기는 이미 있습니다 — `character_service._unlock(owned, all_unlocked)`
  (소유 먼저, 그다음 구독). 붙이면 403 한 줄입니다. **지금은 안 붙입니다.**

---

## 6. ⛔ 저장을 안 하면 캐시가 없습니다 — 원가가 여기서 샙니다

기존 API 는 Storage 에 올려 두고 `voice_url` 이 있으면 재합성을 건너뛰었습니다.
**이 API 는 그 방어가 없습니다.** 같은 문장을 열 번 요청하면 **열 번 합성하고 열 번 과금**됩니다
(Cloud TTS 는 문자 수 과금).

| 방어 | 값 | 누가 |
|---|---|---|
| 길이 상한 | 200자 (초과 422) | 서버 |
| ETag / 304 | `sha256(text+character_id+language)` | 서버 |
| ⭐ **같은 문장 반복 금지** | — | **프론트 (로컬 캐시)** |

### ⛔ 분당 호출 한도는 **안 넣습니다** (사장님 결정 2026-09-05)

넣으려다 조사에서 막혔습니다 — 사실만 적습니다:

```
기존 레이트리밋      이 저장소에 없다 (429 언급은 전부 벤더 쿼터 얘기)
Redis 등 공유 저장소  없다
Cloud Run maxScale   5   ⛔ 인스턴스가 최대 5대
```

⇒ 메모리 카운터는 **인스턴스마다 따로 셉니다.** "분당 20회"가 실제로는 최대 100회가 되고,
  인스턴스가 재시작하면 0으로 돌아갑니다. **«막고 있다»는 착각만 주는 장치**입니다.
  DB 로 정확히 세려면 테이블 + 마이그레이션 + 매 요청 쓰기가 붙는데, 이 API 의 크기에
  비해 과합니다.

⭐ 대신 이렇게 봅니다:
- 버튼을 **사람이 누를 때만** 불립니다(자동 폴링이 아님) — 폭주 표면이 작습니다
- Cloud TTS 자체가 **분당 요청 쿼터로 429** 를 던집니다(실측 기록: `cascade_reply.py:127`
  「분당 상한이 10인데 대답 하나가 이미 3~6회다」). 벤더가 먼저 막습니다
- 길이 200자 + ETag 304 로 **1회 원가와 재요청 원가**를 둘 다 누릅니다

⚠ 나중에 새면 그때 넣습니다. 넣을 자리는 `service` 진입부 한 곳이고, 그때는 **DB 로**
  하는 게 맞습니다(메모리는 위 이유로 안 됩니다).

⚠ 세 번째가 프론트 몫입니다. 서버에 캐시가 없으므로 앱이 받아 둔 바이트를 재사용해야
  합니다 — 없으면 화면을 다시 그릴 때마다 재합성됩니다.
⭐ ETag 는 저장 없이도 동작합니다. 같은 요청이면 **재합성 없이 304** 를 주므로 원가가 0 입니다.
  ⇒ 프론트가 `If-None-Match` 를 보내 주면 이 절약이 실제로 발생합니다.

---

## 7. 프론트 체크리스트

1. ✅ 상태코드를 **먼저** 확인 — 200 만 오디오, 나머지는 JSON
2. ✅ **503 폴백** — 음성 없이 텍스트만 보여주는 경로 필수
3. ✅ **로컬 캐시 + `If-None-Match`** — 서버에 캐시가 없다
4. ✅ `character_id` 는 **선택** — 안 보내면 대표 캐릭터. 목소리 이름·언어는 보내지 않는다
5. ✅ `text` 는 200자 이내

## 8. 서버 구현 메모 (내부, 구현은 나중)

- `core/tts.synthesize(text, language, voice) -> (mp3_bytes, "audio/mpeg") | None`
  가 **이미 있습니다.** 새 어댑터 만들지 마세요. `None` 이면 503.
- ⛔ `core/storage.upload` 를 **부르지 않습니다** — 이 API 의 요점이 그것입니다.
- 응답은 `fastapi.Response(content=mp3, media_type="audio/mpeg")`.
  ⚠ `response_model` 을 붙이지 마세요(JSON 직렬화가 끼어듭니다).
- 라우터 자리: `domains/learning/routers/` 아래 새 파일 또는 기존 라우터.
  경로 규칙은 `/api/v1/<리소스>/...` (main.py:40 `API_PREFIX`).
- 레이어 규율: routers 는 DTO 검증 + 인증 + service 호출만. 합성은 service 소유.
- ⚠ 핸들러는 **async** — `synthesize` 가 async 입니다.

  경로도 `/tts/speech` 라 sentence 와 무관하다.

## 9-2. 결정 흐름 (service 가 소유)

```
1. text 검증           비었거나 200자 초과 → 422
2. character_id 해석    준 값 → 그대로 / 안 줬으면 member.character_id
                       ⛔ 준 값이 없는 캐릭터면 404
                       ⚠ 대표 캐릭터도 없으면? → voice=None 으로 진행(언어 기본 음성)
3. 언어                member.target_language, 없으면 "ko"
4. ETag 계산           sha256(f"{text}|{character_id}|{language}")[:32]
                       If-None-Match 와 같으면 → 304 (⭐ 합성 안 함, 원가 0)
5. 합성                core.tts.synthesize(text, language, voice)
                       None 이면 → 503
6. 응답                Response(mp3, media_type="audio/mpeg",
                                headers={ETag, Cache-Control})
```

⛔ 잠금 캐릭터 검사는 **안 한다**(§5). 무료 사용자가 유료 음색을 쓸 수 있다 — 알고 가는 위험.

## 9-4. 회귀에서 못박을 것

| # | 시험 | 왜 |
|---|---|---|
| 1 | 200 이면 `content-type: audio/mpeg` 이고 바디가 **바이트** | 이 API 의 유일한 계약 |
| 2 | `character_id` 생략 → `member.character_id` 목소리로 합성 | 대표 캐릭터 폴백 |
| 3 | `character_id` 명시 → 그 캐릭터 목소리 | 지정 경로 |
| 4 | 없는 `character_id` → 404 | 조용히 폴백하면 안 된다 |
| 5 | `text` 빈 문자열 / 201자 → 422 | 길이 방어 |
| 6 | `tts.synthesize` 가 None → **503** | ⛔ graceful degradation(R5) |
| 7 | 같은 요청 두 번 → 같은 ETag | 캐시 계약 |
| 8 | `If-None-Match` 일치 → **304 이고 `synthesize` 호출 0회** | ⭐ 원가 0 임을 못박는다 |
| 9 | 비로그인 → 401 | 인증 |

⭐ 8번이 이 기능의 핵심 회귀다. 저장을 안 하므로 **304 가 유일한 서버측 절약**이고,
  그게 깨지면 조용히 매번 재합성한다(로그에도 안 남는다).

## 9-5. ⚠ 위험과 미결

1. **대표 캐릭터가 없는 회원** — `member.character_id` 가 NULL 일 수 있다(온보딩 전).
   ⇒ 404 로 막지 말고 **언어 기본 음성**으로 합성한다. 음성이 안 나오는 것보다 낫다.
2. **`member.target_language` 가 NULL** — 같은 이유로 `"ko"` 폴백.
3. **200자 상한이 충분한가** — 한 문장 기준이다. 문단을 읽어 줘야 하면 상한을 올리는 게
   아니라 **프론트가 문장 단위로 쪼개** 보내는 게 맞다(그래야 캐시도 문장 단위로 먹는다).
4. **원가 계기판에 안 잡힌다** — 통화가 아니라 `call` 행이 없다. 이 API 의 TTS 사용량은
   지금 어디에도 안 쌓인다. ⚠ 쓰기 시작하면 «왜 Cloud TTS 청구가 늘었지?» 를 못 되짚는다.
   ⇒ 최소한 **로그 한 줄**(회원·글자수·언어·캐시적중)은 남긴다. 집계는 나중에.
5. **동시 요청** — 같은 회원이 버튼을 연타하면 같은 합성이 병렬로 돈다. 서버에 캐시가
   없으므로 둘 다 과금된다. ⚠ 프론트 디바운스가 실질적 방어다(§7-3).
