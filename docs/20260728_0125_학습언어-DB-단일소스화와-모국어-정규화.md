# 학습 언어 DB 단일 소스화 + 모국어(locale) 정규화

작성 2026-07-28 01:25 · 대상 `domains/account`, `core/languages.py`, `domains/learning/realtime`, 앱 `mypage`/`normalcall_controller`

## 0. 지시 (사장님)

1. 기존 NULL인 사람들 `ko`로 바꾸고, 프론트가 **DB 값을 받아** 마이페이지에 표시
2. 학습 언어를 **클라가 보내지 않게** 하고 **DB에서만** 뽑아 쓰게
3. `ko-KR` 정규화

## 1. 현황 (실서비스 실측, 활성 회원 23명)

```
call.target_language  : ko 709 / fr 7 / ja 3        ← 비-ko는 도그푸딩 10건
member.language(모국어): en 8 / NULL 5 / ko 4 / ko-KR 3 / ja 2 / zh 1
member_language_level : ko만 9행
```

| 값 | 현재 원본 | 문제 |
|---|---|---|
| `locale`(모국어) | `member.language` | `ko-KR` 3건·NULL 5건이 **영어로 폴백** |
| `target_language`(학습 언어) | 앱 SharedPreferences | DB에 자리 없음. 하이드레이션 레이스 |

### 결함 A — `ko-KR`이 영어가 된다

`_LOCALE_LABEL`은 ISO 639-1 키만 갖는데 앱이 BCP-47 id(`ko-KR`)를 그대로 `PATCH /members/me`로 보낸다
(`mypage.dart` 언어 피커의 `l.id`를 변환 없이 `updateLanguage(picked)`).

```
'ko'    -> 한국어
'ko-KR' -> 영어(English)   ← 미스매치
NULL    -> 영어(English)
```

**23명 중 8명이 잘못된 모국어로 통화 중이다.** 프롬프트에 "학습자의 모국어는 영어(English)다"가 박힌다.

### 결함 B — 학습 언어 하이드레이션 레이스

```dart
String build() {
  unawaited(_hydrate());   // 비동기, 안 기다림
  return defaultCode;      // 즉시 'ko'
}
```

`_hydrate()`가 끝나기 전에 통화가 시작되면 저장된 선택을 무시하고 `ko`가 나간다. 잠금화면 수신통화가
정확히 그 구간이다(콜드스타트 → accept → 즉시 connect). `ac75666`·`e3cc330`이 부팅을 단축해 오히려
경주 여지가 커졌다. 앱 재설치 시 학습 언어가 리셋되는 문제도 같은 뿌리다.

지금은 비-ko 사용자가 실질 0명이라 증상이 안 드러날 뿐이다.

## 2. 설계

### 2-1. `member.target_language` 추가 (지시 2)

```python
target_language: Mapped[Optional[str]] = mapped_column(
    Text, server_default=text("'ko'"), comment="학습 대상 언어(ISO 639-1). NULL=기본 ko"
)
```

- `member_language_level(member_id, language)`이 "어떤 언어들을 배우는지"는 이미 안다.
  없던 건 **그중 지금 활성인 게 뭔지**뿐 → 스칼라 1개로 충분(정규화 대안은 §5).
- `server_default`는 신규 행만 커버 → 마이그레이션에서 기존 행 UPDATE 필요.

### 2-2. 클라 → 서버 전송 중단, DB 단일 소스 (지시 2)

`ClientStart.target_language` 필드는 **스키마에 남기되 환경과 무관하게 항상 무시**한다.

필드를 제거하지 않는 이유: 이미 배포된 앱이 계속 보낸다. 제거하면 pydantic 검증에서 422로 통화가
아예 안 열린다. 하위호환을 위해 받되 쓰지 않는다(구버전 탐지용 info 로그만 남긴다).

> ⚠ **처음엔 `duration_min`처럼 "prod 에서만 무시" 게이트로 짰다가 되돌렸다.** 실서비스
> `beavertalk-app-api`의 `ENV`가 `prod`가 아니라 **`test`** 라(3개 서비스 전부) 그 게이트는
> 무력하다 — 클라값이 그대로 이겨서 프론트를 고치기 전엔 버그가 남는다. 같은 이유로
> 기존 `duration_min`의 prod 게이트도 실서비스에서 동작하지 않는다(별건).
> **언어 게이트에 `ENV`를 다시 끌어들이지 마라.**

데모(`scripts/level_call_demo.html`)는 통화 전에 `PATCH /members/me {target_language}`를
호출하도록 바꿨다 — 실제 앱과 같은 경로를 타므로 데모가 곧 회귀 테스트가 된다.

### 2-3. 모국어 정규화 (지시 3)

`core/languages.py`에 헬퍼를 둔다 — 언어 코드 규칙의 단일 소유자.

```python
def normalize_locale(value: str | None) -> str | None:
    """BCP-47/로케일 문자열 → ISO 639-1 소문자. 'ko-KR'→'ko', 'en_US'→'en'."""
```

**쓰기·읽기 양쪽에 적용한다**(방어적):
- 쓰기: `MemberService.update` / `onboarding` — 저장 전에 정규화 → 새 오염 차단
- 읽기: `build_system_instruction` 호출부 — 과거 데이터·외부 경로 대비

### 2-4. 데이터 백필 (지시 1·3)

마이그레이션 `upgrade()` 안에서 처리해 dev/prod 어디에 돌려도 같은 결과가 되게 한다.

```sql
UPDATE member SET target_language = 'ko' WHERE target_language IS NULL;
UPDATE member SET language = 'ko'        WHERE language IS NULL;
UPDATE member SET language = split_part(language, '-', 1) WHERE language LIKE '%-%';
UPDATE member SET language = lower(language)              WHERE language <> lower(language);
```

⚠ **모국어 NULL → `ko` 는 지시대로 적용하되 의미상 짚어둔다.** 이 앱은 외국인 학습자용이라
모국어 미상(5명)을 한국어로 단정하면 프롬프트가 그들에게 한국어로 설명하게 된다. 현재 폴백(영어)이
외국인에게는 더 안전하다. 다만 그 5명은 도그푸딩·테스트 계정일 가능성이 높고, 사장님 지시가 명시적이라
`ko`로 넣는다. 되돌리려면 `downgrade()`가 아니라 대상 `member_id`를 기록해 두고 개별 UPDATE 해야 한다
(마이그레이션은 원래 값을 보존하지 않는다) — 적용 전 대상 목록을 덤프해 둔다.

### 2-5. 응답 노출 (지시 1)

프론트가 DB 값을 읽어 마이페이지에 표시할 수 있게 노출한다.

- `MemberRead.target_language` — `GET /members/me`
- `MyPageOut.target_language` + `MyPageOut.language` (이미 있음) — `GET /members/me/profile`
- `MemberUpdate.target_language` — `PATCH /members/me` 로 변경

## 3. 앱 변경

| 파일 | 변경 |
|---|---|
| `normalcall_controller.dart` | `start` 페이로드에서 `target_language` 제거 |
| `mypage.dart` | 학습 언어 행을 `learningLanguageProvider`가 아니라 **DB 값**으로 표시, 변경 시 `PATCH /members/me {target_language}` |
| `mypage.dart` | 모국어 PATCH 전에 `ko-KR → ko` 변환(서버도 정규화하지만 클라도 맞춘다) |
| `learning_language_controller.dart` | prefs 단일 소스 폐기 → 서버 값 캐시로 강등하거나 제거 |

## 4. 배포 순서 (역전 금지)

1. **서버 먼저** — 컬럼·백필·정규화·응답 노출. 이 시점엔 non-prod에서 클라값이 여전히 우선이고
   prod는 DB를 쓴다. 구버전 앱은 계속 `target_language`를 보내지만 prod에서 무시되며, 값이 전부
   `ko`라 동작 변화가 없다.
2. **앱 나중** — 전송 제거 + 마이페이지 DB 바인딩.

역순으로 하면 앱이 전송을 멈춘 상태에서 서버에 컬럼이 없어 전원 `ko` 고정이 된다(현재도 사실상 `ko`라
치명적이진 않지만 도그푸딩이 깨진다).

## 5. 채택하지 않은 대안

`member_language_level`에 `is_active BOOLEAN` + partial unique index. 정규화는 더 깔끔하지만
"회원당 정확히 하나 true" 제약과 조회 join이 늘어난다. 활성 언어는 회원당 1개 스칼라라 컬럼이 단순하다.
