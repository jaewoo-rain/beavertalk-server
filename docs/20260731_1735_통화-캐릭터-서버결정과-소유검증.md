# 통화 캐릭터를 서버가 정한다 (+ 소유 검증)

작성 2026-07-31 · 서버 + 앱 동시 변경 · prod DB 1회성 정리 포함

---

## 0. 한 줄

통화 상대를 **클라가 지정하던 통로를 닫고** 서버가 정한다. 수신통화는 알람에서,
그 외에는 `member.character_id` 에서.

---

## 1. 왜 — prod 실측 두 건

### ① 통화의 60%가 엉뚱한 캐릭터로 진행됐다

```
통화 캐릭터 vs 회원이 고른 캐릭터
  불일치 421 · 일치 280 · 전체 701

  통화=1(BABA) 선택=10(Rara) : 214건
  통화=2(BIBI) 선택=10(Rara) :  96건
  통화=1(BABA) 선택= 9(Popo) :  72건
```

범인은 앱의 한 줄이었다:

```dart
// call_loading.dart
final characterId = args is int ? args : 1;   // 인자 없으면 무조건 BABA
```

`callLoading` 진입 경로 6개 중 **인자를 넘기는 건 홈과 수신통화 2곳뿐**이다.
마이페이지·기록없음·기록목록·온보딩완료 4곳은 인자 없이 push 한다 → 전부 BABA.
Rara 를 고른 사람이 기록 화면에서 전화를 걸면 BABA 가 받았다.

### ② 소유 검증이 아예 없었다

`_load_member_character` 는 `db.get(Character, character_id)` 만 했다 —
`member_character` 조인이 없었다.

```
미구매 캐릭터로 진행된 통화 126건
  member=20 → Bibi($10) 96건
  member=4  → Bibi($10) 26건
  member=26 → Bibi($10)  1건
  member=27 → Bibi($10)  3건
```

앱을 고친 클라이언트라면 유료 캐릭터를 얼마든지 부를 수 있었다. IAP 를 붙이는
마당에 뚫린 채로 둘 수 없다.

**둘의 뿌리가 같다 — 캐릭터를 클라가 정했다.**

---

## 2. 어떻게

### 서버가 두 출처에서만 읽는다

```
수신통화(알람)  inbound_call_id → push_dispatch_log → alarm.character_id
그 외 모든 경로  member.character_id (소유 확인)

폴백 사슬: 알람 캐릭터 → 대표 캐릭터(소유 확인) → 가장 싼 캐릭터
```

`domains/learning/service/normalcall_service.resolve_call_character()`.

### 왜 대표 캐릭터 하나로 안 되나

**알람마다 캐릭터를 따로 고를 수 있다**(`alarm_add.dart`). `member.character_id`
하나로는 그걸 표현할 수 없다. 그렇다고 WS `start` 는 그 통화가 어느 알람에서 왔는지
알 방법이 없었다 — 그래서 발송 기록에 통화 id 를 남기고 그걸로 되짚는다.

```
발송: _claim() 이 call_id(uuid4) 발급 → push_dispatch_log 에 저장 → 푸시로 전송
수신: 앱이 그 call_id 를 start.inbound_call_id 로 되돌려줌
해석: call_id → push_dispatch_log → alarm → character
```

### 이게 "클라가 고르는 것"이 아닌 이유

앱이 돌려주는 건 **자기가 만들지 않은 불투명한 uuid** 다. 위조해도 얻는 게 없다 —
남의 uuid 는 모르고, 알아도 알람 주인이 아니면 거절된다(`row.member_id != member_id`).
캐릭터를 고르는 통로가 되지 않는다.

### 거절이 아니라 폴백이다

캐릭터 문제로 연결을 끊지 않는다. 통화는 사용자가 **이미 마이크를 켜고 기다리는**
순간이라, 여기서 끊으면 "전화가 안 됨"으로 보인다. 조용히 폴백하고 경고 로그를
남긴다(운영에서 집계 가능).

### 화면 얼굴도 맞춘다

서버가 알람 캐릭터로 대화하는데 앱이 `myProfile.characterId` 로 아바타를 그리면
**대화 상대와 화면 얼굴이 어긋난다**(이 문제는 변경 전에도 있었다). 서버가 결정 직후
`call_started {character_id}` 를 보내고 앱이 그걸로 그린다.

## 3. 바뀐 것

### 서버

| 파일 | 변경 |
|---|---|
| `realtime/protocol.py` | `ClientStart.character_id` → **폐기**(받되 무시), `inbound_call_id` 추가, `ServerCallStarted` 추가 |
| `realtime/call_session.py` | `start.character_id` 대신 `resolve_call_character()` 사용 + `call_started` 전송 |
| `service/normalcall_service.py` | `resolve_call_character()` 신규 |
| `push/models/push_dispatch_log.py` | `call_id` 컬럼(nullable, UNIQUE) |
| `push/service/dispatch_service.py` | `_claim()` 이 `bool` → `Optional[str]`(call_id 발급), `_ring(alarm, call_id)` |
| alembic `3549a9133f9d` | `push_dispatch_log.call_id` |

`character_id` 를 **지우지 않은** 이유는 `target_language` 와 같다 — 이미 배포된 앱이
계속 보내는데 제거하면 pydantic 422 로 통화가 아예 안 열린다.

### 앱

| 파일 | 변경 |
|---|---|
| `normalcall_controller.dart` | `start()` 인자 제거, `startFromIncoming({callUuid})`, `start` 페이로드에서 `character_id` 제거·`inbound_call_id` 추가, `call_started` 수신 → `CallState.characterId` |
| `call_loading.dart` | `args is int ? args : 1` **삭제** |
| `home.dart` / `incoming_call_coordinator.dart` | 라우트 인자에서 캐릭터 제거 |
| `call.dart` | 아바타를 서버 결정(`state.characterId`) 우선으로 |
| `character_providers.dart` | `characterByIdProvider` 분리(대표 캐릭터 ≠ 통화 상대) |

⚠ **앱을 안 고치면 ①은 안 고쳐진다.** 서버가 "안 보내면 내가 정한다"로 바뀌어도
앱이 계속 `1` 을 보내면 "안 보냄"과 "BABA 선택"이 구별되지 않는다.

### 안드로이드 수신통화 주의

안드로이드는 accept 직후 `endAllCalls()` 로 CallKit 을 정리하고 `start()` 경로로
들어온다(`startFromIncoming` 을 안 탄다). 그래도 알람 캐릭터가 필요하므로
`start(inboundCallId:)` 로 통화 id 만 따로 넘긴다 — 끊기용 `callUuid` 와는 분리했다.

## 4. prod 1회성 정리 (완료)

소유 검증을 그냥 켜면 미구매 Bibi 를 쓰던 4명이 **다음 통화부터 캐릭터를 잃는다.**
지금은 결제가 실제로 돌지 않아(무료 지급 = `is_test_grant`) 그들이 규칙을 어긴 것도
아니다. 쓰던 캐릭터가 말없이 바뀌는 게 더 큰 사고라 소유권을 먼저 줬다.

```
scripts/grandfather_character_ownership.py --env-file .env --apply
→ 부여 완료: 4 건 (purchase_price=0 — 매출 아님)
   member=4, 20, 26, 27 × Bibi
```

스크립트는 `--env-file` 을 **필수**로 받는다. `core.config` 는 `.env` → `.env.local`
을 병합해 뒤가 이기는데, 이 저장소는 **`.env`=실서비스 / `.env.local`=dev 로
뒤집혀** 있어 기본값에 맡기면 엉뚱한 DB 를 친다(실제로 겪었다).

## 6. 남은 것

- **배포 전 마이그레이션**: `alembic upgrade head` (dev·prod 각각). 컬럼 추가라
  무중단.
- **앱 배포 전까지**: 구버전 앱은 계속 `character_id` 를 보내지만 서버가 무시하고
  대표 캐릭터로 연결한다 → ①이 **서버만 배포해도 절반은 고쳐진다**(대표 캐릭터로
  통일). 알람 캐릭터는 앱이 `inbound_call_id` 를 보내야 살아난다.
- **CallKit 한글 하드코딩**: `callkit_service.dart` 의 `'비버 튜터'` / `'한국어 통화'`
  — 서버 쪽은 `core/push_defaults.py` 로 정리했지만 앱은 남아 있다. 앱은 l10n 이
  있으니 제대로 현지화 가능.
