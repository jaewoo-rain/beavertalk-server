## 1. 비용 — 결정의 근거

실측 기준선: 5분·22턴 = 입력 209,974 토큰, 원가 약 **$0.58** (입력이 81%).

| 통화 길이 | 추정 원가 | 비고 |
|---|---|---|
| 5분 (현행) | $0.58 | |
| 9분 | 약 $1.6 | 재연결 없이 오늘 코드로 가능 |
| 15분 | 약 **$2.5~2.9** | **3배가 아니라 4~4.5배** — 5분은 컨텍스트가 차오르는 구간이 절반인데 15분은 대부분을 상한에서 보낸다 |

단가(1M 토큰, Vertex·AI Studio 동일): 텍스트 입력 $0.50 / **오디오 입력 $3.00** / 텍스트 출력 $2.00 / **오디오 출력 $12.00**. 오디오는 초당 약 25 토큰 누적.

⚠ **전사도 과금된다** — 입출력 전사를 둘 다 켜고 있고, 전사 텍스트가 텍스트 출력 요금으로 별도 청구된다.

⚠ **`target_tokens` 튜닝은 효과가 없을 수 있다.** 커뮤니티 실측에서 `target_tokens` 를 512 vs 8,000(16배)로 바꿔도 누적 과금이 거의 같았다(오히려 작은 쪽이 9% 비쌌다). 원인 추정 — 슬라이딩 윈도우가 **USER 턴 경계에서만** 자르는데 오디오 턴 하나가 커서 작은 target 에 도달 자체가 불가능. **비용 레버는 `target` 이 아니라 `trigger` 일 가능성이 높고, 그마저 우리 환경 실측이 필요하다.**

→ **압축 트리거는 `16000/12000` 유지로 시작한다.** 8k 하향은 단계 0 계측이 근거를 보여줄 때만.

## 2. 단계 구성

각 단계는 **독립 배포 가능**하고 **env 로 되돌릴 수 있어야** 한다.

### 단계 0 — 계측 (스파이크 A) ← 지금 여기

**범위**: `usage_metadata` · `session_resumption_update` 정규화 + 로깅. `session_resumption` 설정만 켜고 **재연결은 하지 않는다.**

**동작 변경 0.** 로그만 늘어난다.

확인할 것:
1. **이 모델이 핸들을 실제로 발급하는가** — 안 나오면 재연결 설계 전체가 무효다.
2. **5분 통화가 16k 에 닿는가** — 안 닿으면 단계 3(트리거 하향)의 근거가 소멸한다.
3. **실제 토큰·원가** — 지금까지 전부 추정이었다. 모달리티별 분해로 확정한다.
4. GoAway `time_left` 의 실제 값·형식.

**통과 조건**: 전 스위트 그린 / 실기기 5분 1통에서 오디오·자막·종료가 로그 외엔 동일 / dev 5분 3통 + 데모 15분 2통의 토큰 곡선 수집.

**롤백**: env 스위치 또는 로그 제거 1커밋.

### 단계 1 — 스파이크 B (최소 재연결)

단계 0 에서 핸들이 나오면 진행. 세대 루프 최소 구현으로 **재개 후 재인사 / 1011 / 재과금**을 확인한다.

⚠ **재개 후 비버가 다시 인사하면 15분화를 보류한다.** 모델이 재개를 "세션 시작"으로 인식하는 것이므로 우회가 어렵다.

### 단계 2 — 재연결 본구현

**진입 조건**: 스파이크 B 통과 + fake factory 12개 `**kwargs` 정리 + `REGROUND_MODE` monkeypatch 3줄 정리.

여기서 **D1(통화 길이 env 분기)을 적용**한다.

**킬스위치**: `MAX_RECONNECTS=0` 이면 기존 테스트가 수정 없이 전부 통과해야 한다.

### 단계 3 — 재접지 통합 (트리거 16k 유지)

**진입 조건**: 단계 2 가 dev 에서 3일 / 통화 10건 무사고.

### 단계 4 — 트리거 하향 (조건부)

**진입 조건**: 단계 0 데이터가 근거를 보여줄 때만. 근거 없으면 **진행하지 않는다.**

⚠ 여기가 진짜 위험 지점이다 — 압축이 5분 통화에도 걸리기 시작하므로 **"15분 기능"인 줄 알았던 변경이 전 일반 통화를 건드린다.**

## 3. 재연결 아키텍처 요약

세부는 `docs/20260804_0159_*.md`.

- **세대 루프**: `_run_session` 을 세대 루프로. 연결 1개 = TaskGroup 1세대. 세션은 세대 지역 변수, `_CallState` 만 세대를 건넌다. 별칭이 존재할 수 없어 좀비를 구조적으로 막는다.
  - 반려한 대안: 활성 세션 슬롯 간접참조 — 송신 지점이 5곳 이상이라 **한 곳만 빠뜨리면 죽은 세션에 주입**.
- **스왑 트리거**: 주 = `SESSION_ROTATE_AT_S`(≤540) 예정 스왑(결정적·테스트 가능). 보조 = GoAway. 폴백 = 스트림 종료·송신 오류.
- **턴 경계 게이트**: 종료 시드와 동일한 `turn_id is None and not user_turn_open`. **종료가 스왑보다 항상 우선.**
- ⚠ **스왑 직전 열린 턴을 강제 종결**해야 한다. 안 하면 클라가 `turn_end` 를 못 받고 `turn_id != None` 이 남아 **barge-in off 게이트가 마이크를 영구 차단**한다.
- **백스톱 3층**: 통화 시계 / `SESSION_ROTATE_AT_S`(세션당) / `ABSOLUTE_CALL_TIMEOUT_S`(전체). 무한 루프 방어는 예산보다 **플래핑 가드 30초**가 본체.
- **`transparent`**: v1 보류. 우리가 끊는 시점을 우리가 고르므로 미소비 오디오가 없다. 네트워크 급습 폴백에서만 필요할 수 있어 스파이크 결과로 판단.

## 5. 재접지 통합 설계 요약

- **트리거를 시각 비율에서 압축 신호로.** `usage_metadata.prompt_token_count` 관측 — 급감 = 압축 발생.
- **선제 arm(0.85 × trigger)**: 압축 **직전**에 얹은 요약은 최신단에 있어 그 압축을 반드시 살아남는다. 압축을 감지한 **뒤** 주입하면 "이미 잊은 채로 1~2턴"이 뜬다. 사후 감지는 선제 arm 실패(유저 침묵) 시의 보정.
- **사이드카는 문장을 만들지 않는다.** 서버가 준 항목 목록에서 **번호를 고르고** 짧은 슬롯 값만 반환. 문장 조립은 코드. → `persona_prompt` 의 "LLM 생성 0, 순수 조립" 규율이 유지된다.
- **모드는 서버가 sticky 로 고정.** 사이드카가 다른 값을 줘도 전사에 실제 존재하는 인용으로 명시적 전환이 증명될 때만 교체(AI 는 증인, 코드가 심판). → 압축이 초반을 삼켜도 **모드는 사이드카 없이도 보호된다.**
- **주입 경로는 현행 `on_user_turn` + `turn_complete=False` 를 승계.** 새 주입 경로를 만들지 않는다.
- **5분 하위호환**: 최대 간격을 `통화길이/2.5`(120~240초 클램프)로 파생 → 5분은 2회로 현행과 실질 동일. 부수 효과로 `usage_metadata` 가 안 오면 **자동으로 시간 기반 주기 주입으로 강등**(R5).
- **주입 빈도는 분당으로 본다**: 현행 5분 2회 = 0.40회/분, 15분 6회(16k 유지) = 0.40회/분 — **동일**. 8k/6k 는 0.87회/분로 2.2배.

### ⛔ 이 설계의 최대 신규 위험

사용자가 **"이제 그만할래요"** 라고 말한 걸 사이드카가 요약에 담고, 서버가 그걸 **다시 컨텍스트에 주입**하는 경로. 태그는 분리했지만 **어휘만으로도 같은 일이 난다**(call 683: 재접지 30초 뒤 작별).

→ 방어는 프롬프트가 아니라 **코드**여야 한다. 주입 조립 전에 종료 어휘 denylist(`종료·마무리·작별·끝내·그만·안녕히·bye`)를 걸어 걸린 원소만 버린다. 회귀 테스트는 **적대적 페이로드**(`facts=["이제 그만할래요"]`)를 넣어 결과에 안 나오는지 단언한다.

### 신규 위험 하나 더

통합 주입이 약 250 토큰인데 **사용자의 한마디보다 크다.** 파트 맨 앞에 "학습자가 방금 한 말에 먼저 반응하고"가 없으면 비버가 유저를 무시하고 주입 텍스트에 응답한다(문맥 없는 화제 전환). 현행 리마인더(120~170 토큰)엔 없던 위험.

### 구조 변경이 조용히 깨는 것 (사전 정리 대상)

1. **fake factory 12개 중 9개가 엄격 시그니처.** 전례 — `tools` 를 조건부 kwarg 로 우회했더니 **tools 경로가 테스트를 한 번도 안 타는 죽은 경로**가 됐다. 재연결 착수 **전에** 전부 `**kwargs` 로 정리한다.

## 8. 이 계획이 증명하지 못하는 것

- 가짜 세션은 Gemini 의 **실제 재개 시맨틱**을 모른다. 핸들이 유효한데 컨텍스트를 일부만 돌려주는 경우는 pytest 로 못 잡는다 → D2·D3 실기기 전용.
- **`turn_complete=False` 로 오디오 VAD 턴에 텍스트를 병합하는 것은 여전히 Gemini 공식 보장이 아니다.** 사이드카 주입 전체가 이 미보장 위에 서 있다. 실기기에서 이중발화가 보이면 **설계 전제를 재검토**해야지 테스트를 느슨하게 하면 안 된다.
- 압축 발동을 usage 급감으로 "추론"하는 것 자체가 간접 신호다. **미탐(주입 누락)은 무해, 오탐(불필요 주입)은 이중발화 위험** → 임계는 미탐 쪽으로 보수적으로.
- 15분 × 동시 N 의 메모리는 pytest 로 검증 불가 — 용량 산정 + 부하 1회 필요.
