# 🔴 반드시 해야 할 것 — 3건

## 1. `GET /calls/{id}/resume-status` 에 `tz` 를 붙여 주세요
**지금 앱이 이 호출에만 시간대를 안 보냅니다.**
`normalcall_remote_data_source.dart:44` 의 `getResumeStatus` 가 `plan_override` 만 싣습니다.
같은 파일의 달력(`:57`)·daily-status 는 `DeviceTimezone.params` 를 이미 보냅니다.

```dart
queryParameters: <String, dynamic>{
  if (planOverride != null) 'plan_override': planOverride,
  ...tzParams,   // ⭐ 달력·daily-status 와 같은 값
},
```
- 서버는 `tz`(IANA) 우선 → `tz_offset_min` 폴백 → **없으면 UTC**
- 안 보내면 **최대 9시간 어긋납니다.** 한국 시각 자정 전후에 「이어갈 수 없다」거나
  `max_fragments` 가 틀리게 옵니다(하루 예산을 UTC 날짜로 세니까요)
- 파라미터 이름·값은 WS `start.tz`·달력과 **완전히 같습니다**

## 2. 발음 리포트 `sessions[].score` 가 **`null` 로 올 수 있습니다**
`GET /calls/{id}/pronunciation-report` → `sessions[]`

전엔 「점수 없음」을 **0 으로 뭉개서** 보냈습니다. 그래서 `delta` 가 없는 하락을 만들었습니다
(운영 실측: 96점 다음 통화가 `delta: -96`, 화면엔 「96점 하락」). 이제 **`null`** 입니다.

- ⭐ **크래시는 안 납니다** — `learning_summary.dart:16` 의 `_asInt(null)` 이 `0` 을 돌려줍니다.
  즉 지금 앱은 **종전과 똑같이** 동작합니다(0 으로 그립니다)
- ⇒ **`delta` 와 똑같이 「—」 로** 처리해 주세요. `null` = 「그 통화에서 발음 챌린지를 안 눌렀다」,
  `0` = 「진짜 0점」입니다
- `delta` 는 이미 앱이 null 을 「—」 로 처리하고 있습니다(같은 파일, 「"no previous session"
  is not "no change"」). `score` 에 같은 규칙만 적용하면 됩니다
- `delta` 도 이제 **양쪽 다 점수가 있을 때만** 옵니다. 점수 없는 통화가 끼어도 비교 사슬은
  안 끊깁니다(96 → 없음 → 82 면 82 의 `delta` 는 **−14**, 0 대비가 아닙니다)

# ⚪ 알아만 두기 — 앱 변경 불필요

## 8. 발음 이력에 **표현학습·프리토킹 통화가 새로 나타납니다**
`recent_calls` 가 `call_type = 'chat'` 만 골라서, 지금 학습의 **주력 경로가 통째로 빠져** 있었습니다.
이제 `!= 'level_test'`(학습 달력과 같은 기준)입니다. 과거 통화도 **소급됩니다**(조회 필터만 바뀜).
⇒ 줄 수가 늘고, 전에 안 보이던 통화가 보입니다. 정상입니다.

⚠ 그 중 **「문장 0 / 점수 없음」 줄이 많습니다** — 통화만 하고 발음 챌린지를 안 누른 경우입니다.
실측으로 점수 있는 세션이 **1개뿐인 회원이 흔합니다**(「채점 세션 2개 미만이면 평균선 생략」
하신 판단이 맞았습니다).

## 9. 통과 수가 **절반쯤으로 보일 수 있습니다 — 그게 맞는 수입니다**
「N개 중 M개 통과」가 현지인 표현 짝을 같이 세서 **실제의 2배**였습니다. 이제 기본 문장만 셉니다.
⚠ 평균 점수(`overall`·`pronunciation`·`fluency`·`rhythm`)는 `/result` 와 같게 **짝 포함** 유지입니다.

## 10. 레벨이 **진도로 자동 상승**합니다
프리토킹 통화가 끝나고 다음 차시로 넘어갈 때 오릅니다. `call_ended` **받기 전에 이미 커밋**되니
분석을 기다릴 필요 없습니다. 통화로는 **절대 내려가지 않습니다.**
⚠ **레벨업 알림 UI 가 없습니다** — 사용자는 마이페이지에 들어가야 압니다. 축하 화면이 필요하면
말씀해 주세요(프롬프트를 안 건드리는 방식으로 통화 결과에 실어 드릴 수 있습니다).

## 11. `POST /subscriptions` · `DELETE /calls/{id}` 가 **admin 전용**이 됐습니다
- 앱 전수 검색으로 **둘 다 호출 0건**을 확인했습니다 — 영향 없습니다
- 진짜 구독은 `POST /purchases/verify` 로 갑니다(그쪽은 안 건드렸습니다).
  앱이 쓰는 `GET /subscriptions`·`GET /subscriptions/status`·`POST /subscriptions/{id}/cancel`
  **전부 그대로**입니다
- 이유: `POST /subscriptions` 는 금액 검증이 `> 0` 뿐이라 아무 회원이나 본인 JWT 로
  `premium` 을 스스로 지급할 수 있었고, `DELETE /calls/{id}` 는 하루 예산이 `SUM(total_time)`
  이라 하드 삭제 = **예산 환급**이었습니다

## 12. 옛 `pro`/`max` 플랜이 DB 에 다시 들어와도 **`premium` 으로 정규화**됩니다
구버전 서버(app-api)와 DB 를 공유하는 동안 결제자가 조용히 Free 로 떨어지던 구멍을 막았습니다.
