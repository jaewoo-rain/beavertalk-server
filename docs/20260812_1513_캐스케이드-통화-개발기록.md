## 1. 왜 캐스케이드인가 — 동기는 원가다

Gemini Live 는 오디오를 그대로 주고받는 한 덩어리 API 라 **간단하지만 비싸다.**
캐스케이드는 같은 통화를 **세 벤더로 쪼개** 각 조각에서 싼 것을 고를 수 있다.

| | Live(기존) | 캐스케이드 |
|---|---|---|
| 구조 | 오디오 in → 오디오 out (한 덩어리) | 오디오 → **STT** → 글자 → **LLM** → 글자 → **TTS** → 오디오 |
| 끼어들기 | 사실상 불가(barge-in off 로 운영) | **가능** — 사용자가 말하면 비버를 끊는다 |
| 원가 | 오디오 토큰 단가가 지배 | STT 가 통화 원가의 **53%** [실측] |
| 대가 | — | **조각이 많아 실패 지점도 많다**(이 문서의 대부분이 그 이야기다) |

> ⚠ 캐스케이드의 본질적 대가: Live 는 한 번의 왕복이지만 캐스케이드는 **STT 왕복 + LLM 왕복 +
> TTS 왕복**이 직렬로 붙는다. 그래서 이 기록의 절반이 "지연을 어디서 깎았나"이다.

## 2. 벤더 선정 — 실측으로 골랐다

### 2-1. STT: 41개 언어 code-switching [실측]

우리 사용자는 **외국인 학습자**다. 모국어로 묻고("이거 한국어로 어떻게 말해요?") 한국어로 따라
말한다. 그래서 STT 는 **두 언어를 한 발화 안에서** 알아들어야 한다.

| 벤더 | 41개 언어 중 성공 | 비고 |
|---|---|---|
| **OpenAI Realtime 전사** | **39 / 41** | 언어 지정 없이 자동 감지 |
| ElevenLabs | 27 / 41 | |
| Google STT v2 | **16 / 41** | 기존 사용 벤더 |

**Google 이 왜 탈락했나** [실측] — 공식 문서상 "다국어 지원"인 조합이 실제로는 무너졌다:

| 조합 | Google chirp 결과 |
|---|---|
| 한국어 + 영어 | ✅ 정확 |
| 한국어 + 일본어 | ⛔ `" \| 동가스가 좋아요."` — **한국어까지 사라짐** |
| 한국어 + 프랑스어 | ⛔⛔ **아무것도 안 나옴** |
| 아랍어 · 중국어 | ⛔ 지원 자체가 400 에러 |

> ⭐ 이 실측이 규칙 하나를 만들었다: **벤더 주장은 후보 선정 기준일 뿐 결론의 근거가 아니다.**

### 2-2. TTS: 첫 소리 지연(TTFB)과 읽기 속도 [실측]

| 엔진 | 첫 조각까지(TTFB) | 성질 |
|---|---|---|
| Chirp3-HD (Google) | **165~212ms** | 빠르다. 감정 지시를 **못** 받는다 |
| Gemini-TTS | 805~1271ms | 감정 지시 가능. **분당 요청 상한이 있다**(§6-5) |
| OpenAI TTS | 545~953ms | 감정 지시 가능(`instructions`) |

**읽기 속도의 목표 숫자**는 사장님이 "딱 좋다"고 하신 **Live 의 실물**에서 뽑았다 [실측]:
`한국어 7.7자/초`(Live 9건 중앙값). 내가 고른 상수가 아니다.

### 2-3. 최종 구성과 이유

| 조각 | 선택 | 왜 |
|---|---|---|
| STT | **OpenAI Realtime 전사** | 41개 언어 중 39개 성공 — **어학 앱의 본질 요건**(code-switching)에서 압도적 |
| LLM | **Gemini 2.5 Flash** | 기존 자산(프롬프트·분석 파이프라인)을 그대로 쓴다. 속도도 충분 |
| TTS | **Gemini-TTS** | 사장님 판단("지금 좋아 잘돼") + 감정 지시 가능. ⚠ 쿼터 위험은 §6-5 |

## 3. 해결한 결함 — ①증상 ②원인 ③근거 ④해결 ⑤남은 것

### 계열 A. 소리가 사라지거나 깨진다

#### A-1. ✅ 홀수 바이트 조각 — 클라가 오디오를 통째로 버렸다 ⭐ 이번 작업 최대 결함

| | |
|---|---|
| **증상** | 사장님: "**음성이 깨지고 말이 잘게 씹힌다**" — 특정 엔진에서만, 가끔 멀쩡한 통화도 있었다 |
| **원인** | `core/openai_tts.py` 가 HTTP 청크를 **받은 그대로** 흘렸다. PCM16 은 **2바이트가 표본 하나**인데 벤더의 청크 경계가 표본 중간에 떨어진다. 클라의 `new Int16Array(buf)` 는 홀수 길이에서 예외를 던지고, `onMsg` 에 try/catch 가 없어 **그 조각이 재생도 기록도 없이 사라졌다** |
| **근거** [실측] | 벤더 조각 234개 중 **홀수 208개(89%)**. Chirp 0%(1920의 배수) · Gemini 0%(gRPC 메시지 단위) — **엔진 간 차이는 이 하나였다.** 조각 1369바이트 = **28.5ms 짜리 구멍이 초당 열댓 번** |
| **해결** | `d4908fb` — 1바이트를 **버리지 않고 다음 조각으로 이월**(버리면 그 뒤 전부가 반 표본 밀려 잡음이 된다). 정렬 자리는 **요청 경계**(`speak_stream`) — 어댑터에 넣으면 다음 어댑터가 또 홀수를 내고, 송출 경계는 조각의 연속성을 모른다. 불변식 **I6("클라로 나가는 오디오는 항상 짝수 바이트")** 추가. `0d3e28f` — 클라 방어 + 홀수 개수를 로그에 남긴다 |
| **남은 것** | 없음. 벤더는 여전히 홀수를 보내고(요청당 34~72개) **우리가 계속 막고 있다** — 로그로 확인 가능 |

> ⭐ 교훈: **조용한 실패가 하루를 먹었다.** 클라가 예외를 삼켜 아무 흔적이 없었고, 그래서
> 원인을 엉뚱한 곳(묶음 크기·첫 문장 규칙)에서 두 번 찾았다(§5).

#### A-2. ✅ 반열림 소켓에서 사용자 말이 40초 사라졌다

- **증상/위험**: 송신은 실패하는데 수신이 안 끝나는 소켓에서 **모든 오디오를 조용히 버렸다**
- **원인**: `core/openai_stt.py` `push_audio` 실패가 경고 한 줄만 남기고 끝났다
- **해결**: `6f77576` — 실패 시 큐에 `STREAM_ERROR` 를 넣어 **세션이 이미 가진 경로**로 흘린다

#### A-3. ✅ STT 가 한국어만 듣고 있었다

- **증상** [실측]: 5회 연속·36초 동안 전사 0. `u11~u15 speech_ms=1194/946/1025/1206/1200, text=''`.
  사장님 확인: "11~15는 **영어로** 말했다"
- **원인**: `language_codes=[한 개]` — 필드는 리스트인데 하나만 넣었다
- **해결**: `b35cc2a` — 학습 언어 + 모국어를 같이 싣는다. ⚠ 1차 문서 확인 후 적용(모델 제약 있음)

#### B-1. ✅ 아무도 안 들은 대답이 계속 나왔다

| | |
|---|---|
| **증상** | 사장님: "**음성이 끊겼으면 삭제돼야 하는데 계속 나온다**" |
| **근거** [실측] | 판정 24건 중 실제로 끊은 건 **1건**, `대답 취소됨` 로그는 **한 줄도 없었다**. 사용자 발화가 대기열에서 **7.1초** 기다린 뒤 낡은 말에 답한 사례 |

#### B-2. ✅ 턴이 30초 굳어 통화가 죽었다

- **증상** [실측]: `대답 취소됨` 뒤 **30초 동안 로그 한 줄도 없음** → 통화 종료.
  사장님: "내 턴이라면서 시작 안 해"
- **원인**: 그 턴에 **걸린 시계가 하나도 없었다** — 침묵 타이머는 `speech_end` 가, 전사 타이머는
  전사가 와야 걸리는데 STT 가 `speech_begin` 하나만 보내고 조용해졌다
- **해결**: `bf41b6f` — 턴은 **열리는 순간부터** 마감 시계를 갖는다

#### B-3. ✅ barge-in 안전망이 멀쩡한 대답을 죽였다

- **증상** [실측]: `rms=0.0077` 에서 안전망이 비버를 끊고 **30초 완전 침묵**
- **판단**: 0.0077 은 침묵 대역(0.0000~0.0030)과 발화 대역(0.011~0.44) **사이의 회색지대**
- **해결**: `cb49212` — 사장님 지시대로 **글자로 인식할 때만 끊는다.** 안전망 삭제

#### B-4. ⚠ 한 발화가 두 턴이 된다(부분 해결 — 방아쇠 확정)

| | |
|---|---|
| **증상** | 사장님: "**응답이 느리다**" / "끼어들어도 이전 이야기 끝내고 다음 이야기하는 것 같다" |
| **로그** [실측] | `u1 speech_ms=2294 미완=yes '스터디 코리안 투데…'` → 1초 뒤 `u2 speech_ms=230 '영 한국어 공부하자.'` → **준비 중이던 대답을 버리고** 새로 만든다 |
| **원인** [실측] | **중복 확정이 아니었다.** 실제 벤더에 붙어 이벤트 전량을 받아 확인: `item1 audio 52~1728ms` / `item2 audio 1812~3808ms` — **간격 84ms.** 벤더 VAD 가 문장 사이 짧은 숨에서 **한 발화를 둘로 나눈다** |
| **해결** | `b22551b` — 오디오 간격이 좁으면 **한 발화로 잇는다**(열린 턴은 계속, 이미 닫혔으면 앞 조각 텍스트를 새 턴 앞에 붙인다) |
| **판정 근거** | ⛔ **오디오 시각만** 쓴다 — 벽시계로는 그 84ms 가 **453ms** 뒤에 도착했다. 값 300ms = 실측 갈림(84ms)의 3.5배이면서 사람이 일부러 두는 쉼(≥500ms)보다 작다 |
| **남은 것** | 다음 통화에서 `u1/u2` 분리가 실제로 사라지는지 확인 |

### 계열 C. 지연 — "응답이 느리다"

#### C-1. ✅ 언어 구간마다 벤더 왕복이 직렬로 붙었다

| | |
|---|---|
| **증상** | 사장님: "**언어 바뀔 때 살짝 끊긴다**" |
| **근거** [실측] | 한국어 구간이 **5자인데 1.0~1.35초**(대부분이 벤더 왕복). 그 동안 재생할 게 없어 소리가 빈다 |
| **해결** | `65dbef4` — 뒤 구간을 **앞 구간이 재생되는 동안 미리 합성**한다. 실측 구간 대기 **2.36초 → 0.00초** |
| **지킨 것** | 송출 순서 · 실시간 페이싱(I3) · 취소 시 선행분 폐기 · 짝수 바이트(I6) · **엔진별 동시 요청 상한** · 한 구간 실패해도 나머지 송출 |
| **남은 것** | 첫 구간 왕복(~0.9초)은 못 숨긴다 — 앞에 재생할 게 없다 |

#### C-2. ✅ 대답이 19초짜리 독백이었다

- **증상** [실측]: 한 대답이 **18.7초(196자)**. 그동안 사장님 발화가 대기열에서 **14.2초** 대기
- **해결**: `bc23d73` — LLM 출력 상한(`max_output_tokens=40`). 프롬프트 문구가 아니라 **호출 파라미터**
- **값의 근거** [실측] — 꼬리를 버린 뒤 실제 발화 길이:

  | 상한 | 평균 | 최악 |
  |---|---|---|
  | 없음 | 15.4초 | 19.2초 |
  | 36 | 8.2초 | 9.3초 |
  | **40** | **9.1초** | 12.4초 |
  | 44 | 11.5초 | 15.0초 |

- **문장이 잘리지 않게**: 상한에 걸리면 **마지막 미완성 문장을 버린다.** 버린 꼬리는 소리로도
  이력에도 안 들어간다(하지도 않은 말을 했다고 믿으면 다음 턴이 어긋난다)
- **남은 것**: 8회 중 1회는 문장 1개(5.0초)로 얇아진다 → env 로 44~52 조절 가능

#### C-3. ✅ 구간마다 앞뒤 침묵이 곱해졌다

- **근거** [실측]: `Gemini ko 3자/1.5초 = 2.0자per초` — 3글자에 1.5초. 같은 조건에서 Chirp 은 5.3
- **원인**: 말이 느린 게 아니라 **구간마다 앞뒤에 침묵이 붙는다.** 어학 대화는 언어가 계속 바뀌어
  구간이 잘게 쪼개지므로 그 침묵이 **구간 수만큼 곱해진다**
- **해결**: `a5ece71` — 구간 앞뒤 침묵 절단. 한국어 1.3 → **6.2~7.4자per초**

#### C-4. ✅ OpenAI TTS 가 Chirp 의 규칙 두 개를 물려받았다

- **① 묶음 크기**: `"Gemini 면 400, 아니면 160"` → OpenAI 가 Chirp 의 160 을 탔다(`849fd94`)
- **② 첫 문장 단독 송출**: 조건이 `_gemini_realtime()` → 또 Chirp 규칙을 탔다(`a04ec0e`).
  실측 첫 배치 오디오 **800·1000·1450ms** 인데 선행버퍼가 1500ms → **버퍼를 못 채우고 끊긴다**
- **재발 방지**: `7f5df25` — 엔진 이름으로 분기하던 자리 **8개를 성질 표 하나로** 모았다.
  새 엔진이 표에서 빠지면 **회귀가 먼저 실패**한다
- ⚠ 이 두 건은 **끊김의 진짜 원인이 아니었다**(진짜는 A-1 홀수 바이트) — §5 참조

### 계열 D. 원가·계측이 거짓말을 했다

#### D-1. ✅ '첫소리' 지표가 페이서 대기를 포함하고 있었다

- **원인**: `첫소리` 의 TTS 항목이 "첫 문장 완성 → **첫 배치 전량 송출 완료**"였다.
  송출은 실시간 페이싱을 거치므로 **사용자가 이미 듣고 있는 시간**을 "기다린 시간"으로 셌다
- **근거** [실측]: `TTS=1200` 이 3회, `2160/2161` 이 2회 반복(네트워크는 이런 값을 반복하지 않는다) ·
  `721ms(133자) < 3599ms(62자)` — 글자 수와 무관
- **해결**: `a3059c5` — 첫소리를 **LLM첫조각 / 문장완성 / 벤더 / 송출**로 쪼갰다

#### D-2. ✅ 폴백에서 문자를 두 번 셌다

- **원인**: 폴백 시 `record_tts(문장, 실제엔진)` 을 한 번 더 불렀다 = **같은 문장을 두 번**
- **왜 중요한가**: 원가가 이 프로젝트의 **유일한 동기**이고, 하필 그 숫자가
  "캐스케이드가 Live 보다 싼가"의 근거로 쓰인다
- **해결**: `4902d7b` — 벤더 이름만 정정(`retag_tts`)

#### D-3. ✅ 감정 로그가 거짓말을 했다

- **증상**: `tts=openai-...` 인데 로그는 `감정=인사(미적용:cloud-tts-chirp3-hd)` —
  감정은 실제로 들어가고 있었는데 **로그만 아니라고 말했다**
- **해결**: `ea30635` — 판정을 한 곳으로

#### D-4. ✅ 세션 절대 백스톱이 없었다

- **위험**: 턴 시계 넷이 전부 "이벤트가 정상적으로 흐른다"를 전제한다. 그 전제가 깨지면
  **아무 시계도 안 걸리고 세션이 무기한 산다** — STT 가 통화 원가의 53% 인데 마이크는 상시개방
- **해결**: `a448134` — 1200초 절대 백스톱. 정상 통화는 절대 안 닿는다(닿으면 그 자체가 결함 신호)

|---|---|

### 계열 F. 독립 QA 점검에서 나온 것 (통화가 죽는 계열)

> 별도 세션이 **읽기만** 하고 코드를 점검해 8건을 냈다(문서: `20260811_0017_cascade-코드점검.md`).
> 그중 상위 3건이 "통화가 죽거나 말이 사라지는" 계열이었다.

#### F-1. ✅ 비버가 말하는 중 열린 사용자 턴은 침묵 타이머를 못 걸었다

- **원인**: `_on_speech_end` 가 `state == USER_SPEAKING` 을 요구했는데, `_open_turn` 은 비버가
  말하는 중이면 **일부러 상태를 안 뺏는다**(끼어들기 겹침 허용). 그래서 **주 경로**가 조기 반환됐다
- **왜 치명적인가**: 글자가 끝내 안 나온 턴이 **30초 상한까지** 갔다
- **해결**: `d8f8de6` — 이 함수가 묻는 것은 "누가 말하는가"가 아니라 **"닫을 턴이 있는가"** 다.
  상태 축과 턴 축을 갈랐다

#### F-2. ✅ `CANCELLING` 을 푸는 전이가 하나도 없었다

- **위험**: 한 번 굳으면 이후 **모든 턴**이 정상 상태로 못 가고 F-1 이 영구화된다
- **해결**: `d8f8de6` — 대답이 끝나는 자리에서 **자기 세대일 때만** 푼다(늦게 죽은 옛 태스크가
  새 대답의 상태를 덮으면 그것도 같은 굳음이다)

#### F-3. ✅ 같은 수정이 '이어가기' 경로에는 안 들어갔다

- **증상 위험**: `_run_resume` 의 마무리에 **대기열 배수·상태 해제·세대 가드**가 셋 다 빠져 있었다
  → 그 경로로 가면 **사용자 말이 사라진다**
- **원인** [확정]: 새 회귀 9건이 `_run_resume` 를 **한 번도 안 지났다** — 격자가 *상태*는 세웠는데
  *경로*를 안 세웠다
- **해결**: `24a0b47` — 회귀를 **경로 축**으로 다시 짰다

#### F-4. ✅ 끼어들기 판정의 200ms 대기가 턴 펌프를 통째로 멈췄다

- **원인**: `_bargein_allowed` 안의 `sleep(200ms)` 가 **STT 이벤트 펌프와 같은 태스크**에 있었다
- **해결**: `d3b5bad` — 대기를 걷어내고, 송출 경쟁은 불변식 예외로 흡수

#### F-5. ✅ 턴 종료 사유가 거짓으로 찍혔다(`reason=max`)

- **증상**: 열린 지 얼마 안 된 턴이 `reason=max`(30초 상한)로 닫힌 것처럼 보였다
- **원인** [실측]: 이벤트 루프가 타이머보다 **미세하게 일찍** 깨어나(윈도우 clock resolution
  ~15.6ms) 마감 판정이 잘못 걸렸다. 30초 간격처럼 보인 건 **우연**이었다
- **해결**: `04c5d86` — 허용오차를 두고, 바쁜 대기도 같이 없앴다

## 4. 관측 — "조용한 실패를 없앤다"가 이 프로젝트의 규율이 됐다

같은 종류의 사고가 반복됐다: **아무 흔적이 없어서 원인을 못 찾는다.** 그래서 계측을 늘렸다.

| 로그 | 무엇을 답하나 |
|---|---|
| `요청=[99자·2.98s·대기0.91s·홀수52]` | 요청별 길이·오디오 초·**구간 대기**·**벤더가 보낸 홀수 조각 수** |
| `첫소리=2959ms(LLM첫조각 1404 + 문장완성 83 + 벤더 1257 + 송출 213)` | 지연이 **어디서** 생기는지 |
| `감정=없음(버린태그:공부 모드)` | 태그가 안 온 건지 **집합 밖이 온 건지** |
| `글자=102(상한잘림 꼬리12자버림)` | 길이 상한에 걸렸는지 |
| `tts_fallbacks=N` (통화 요약) | 쿼터로 **목소리가 몇 번 바뀌었는지** |
| `⚠ tts 응답이 너무 짧다` | 벤더가 도중에 끊었는지(status 200 인데 오디오만 짧게 온 사례가 있었다) |

## 5. ⭐ 판단이 뒤집힌 기록 — **이 절이 제일 중요하다**

> 목적은 누구 탓이 아니라 **"무엇을 안 재고 결론냈나"** 를 남기는 것이다.
> 8일 동안 **결론이 최소 9번 뒤집혔다.** 공통점은 하나다 — **재기 전에 말했다.**

| # | 틀린 결론 | 실제 | 무엇을 안 쟀나 |
|---|---|---|---|
| 1 | "Chirp 이 답이다"(STT) | 한국어+영어 **한 쌍**만 보고 일반화. 41개 언어로 재니 Google 16/41 | **표본이 1쌍이었다** |
| 2 | "첫소리가 2배 느려졌다" | 지표가 **페이서 시간을 포함**하고 있었다(D-1) | 지표의 정의를 안 봤다 |
| 3 | "선행 합성이 실통화에서 안 먹는다" | 인용한 로그가 **Gemini 통화**였다(그 엔진은 설계상 직렬). 같은 시간대 OpenAI 통화는 정상 동작 | 로그 줄의 **엔진 필드**를 안 봤다 |
| 4 | "묶음 크기가 끊김의 원인" | 아니었다 | 진짜 원인(홀수 바이트)을 못 봤다 |
| 5 | "첫 문장 단독 규칙이 원인" | 아니었다(둘 다 실재하는 결함이긴 했다) | 같은 이유 |
| 6 | "Gemini 는 분당 10회라 **선행 합성을 하면 안 된다**" | **논리가 틀렸다.** 상한은 분당 **요청 수**이고 선행 합성은 같은 요청을 1~2초 일찍 부를 뿐 총량을 안 늘린다 | 쿼터의 **단위**를 안 따졌다 |
| 7 | "어제 429 가 두 번 났다" | 로그 검색이 `첫배치=11**429**ms` 의 **부분 문자열**에 걸린 것. 실제 TTS 폴백은 08-10 이후 없다 | 매치된 줄을 안 열어봤다 |
| 8 | "중복 확정(같은 오디오를 두 번)" | 벤더 VAD 가 **한 발화를 둘로 나눈 것**(B-4) | 벤더 이벤트를 직접 안 받아봤다 |
| 9 | "이력에 태그가 없어 모델이 따라 뗀다"(내 가설) | **반증됐다** — 태그 없는 이력에서도 5/5 생존 | 가설을 세운 즉시 쟀다(이건 잘한 쪽) |

### 여기서 나온 작업 규칙

1. **재현 없이 고치지 않는다.** 재현이 안 되면 "미상"이라고 쓴다
2. **로그를 인용할 땐 그 줄 전체를 본다**(엔진·모드 필드가 결론을 뒤집는다)
3. **한 쌍으로 일반화하지 않는다**
4. 상수를 인용할 땐 **주석이 아니라 상수 선언**을 본다
5. **"모른다"를 적는다** — §7 이 그 절이다

## 6. ⛔ 미해결 목록

### 6-1. 앞부분 끊김 — 클라에 시작 지터 버퍼가 없다
- **증상**: 비버가 말을 시작하는 **앞부분**이 살짝 끊긴다
- **원인** [추측]: 서버는 선행버퍼(1500ms)를 두고 보내지만 **클라는 도착 즉시 재생**한다.
  네트워크 지터가 첫 조각들에 그대로 드러난다
- **다음**: 클라에서 재생 시작 전 N ms 를 모으는 지터 버퍼. 값은 실측으로 정해야 한다

### 6-2. 끼어들기 구멍 — 비버가 '생각 중'일 때
- **증상**: 사용자가 말해도 안 끊기는 구간이 남아 있다
- **원인** [확정]: barge-in 은 **전사가 나와야** 친다(사장님 지시). LLM 생성 중(THINKING)에는
  비버가 아직 소리를 안 내므로 '안 들림'으로 기각된다
- **다음**: THINKING 구간의 취소 규칙을 따로 정의해야 한다

### 6-3. 중복 확정 계열의 잔여
- B-4 를 고쳤지만 **실통화에서 사라지는지 미확인**. 다음 통화 로그로 확정

### 6-4. 태그 표기 충돌의 잔여
- E-2 를 고쳤지만 **방아쇠 재현 실패**. 다음 통화의 `버린태그:` 로 확정

### 6-5. ⛔ Gemini-TTS 429(분당 요청 상한)
- **왜 문제인가**: 상한을 넘으면 그 통화는 Chirp 으로 폴백한다 = **통화 도중 목소리가 바뀐다.**
  사장님은 그걸 **소리로만** 아신다
- **실측**:

  | 항목 | 값 |
  |---|---|
  | 문서상 상한 | 분당 10회 [1차] |
  | 대답당 요청 / 오디오 | 중앙 **3회** / **9.4초** |
  | 추정 분당 요청(사용자 발화 3·5·8초) | **14.5 / 12.5 / 10.3회** → **상시 초과** |
  | 7일 최대 관측 | **42회/분**(08-10) |
  | 실제 429 폴백 | 08-07 무더기(묶음 개선 전) + **08-10 08:34 한 건**. 그 뒤 없음 |

- ⚠ **12회/분도 42회/분도 429 가 안 났다** — 실효 상한이 문서와 다르다는 뜻이다.
  그래서 "문서상 10회니까 안전/위험"으로 판단하지 않는다
- **완화**: 통화 요약에 `tts_fallbacks=N` 을 남겨 **몇 번 바뀌었는지** 숫자로 답할 수 있게 했다
- **다음**: 쿼터 증액 신청(현재 미승인) 또는 폴백 대상을 Chirp 대신 OpenAI TTS 로 바꿀지 판단

### 6-6. 캐스케이드가 회원·캐릭터 DB 를 안 읽는다
- 지금은 데모 경로라 **고정 페르소나**로 돈다. 실서비스는 회원의 캐릭터·레벨·이력을 읽어야 한다
- **다음**: Live 경로(`call_session`)가 하는 조립을 캐스케이드에도 붙인다

### 6-7. 앱이 AEC 힌트를 안 보낸다
- 서버는 클라가 에코 제거(AEC)를 켰는지 **모른다**. 그래서 에너지 게이트를 보수적으로 잡는다
- **다음**: 앱이 `aec` 힌트를 보내면 게이트를 건너뛸 수 있다(서버 쪽 수용은 이미 되어 있다)

## 7. 아직 못 잰 것 / 미확인

> **"모른다"를 적는 게 이 프로젝트의 규율이다.** 아래는 추측으로 채우지 않은 칸이다.

| 항목 | 왜 못 쟀나 |
|---|---|
| OpenAI TTS 단가 | 과금 단위가 **오디오 토큰**인데 초→토큰 환산율이 문서에 없다. 원가 계산에서 **0원이 아니라 '미상'으로 드러나게** 해 뒀다 |
| Gemini-TTS 의 실효 쿼터 | 문서는 분당 10회인데 42회/분에도 429 가 안 났다. 실제 임계 미확인 |
| Gemini-TTS 동시 요청 한도 | 1차 자료 없음 → 선행 합성 깊이를 3 이 아니라 **2** 로만 올렸다 |
| ElevenLabs TTS 성능 | ⛔ **실측 전에 접었다.** "성능이 나빠서 버린 것이 아니다" |
| 마커 분할을 끄면 한국어 발음이 어떻게 되는가 | 요청 수를 줄이는 레버지만, **영어 음성이 한국어를 읽으면 학습자가 틀린 발음을 따라 한다**(사장님 판단으로 이 길은 닫혔다) |
| OpenAI STT 의 영어 음차 현상 | 사장님 보고("스터디 코리안 투데이")를 **재현 못 했다**. 표본 2건 |
| 캐스케이드 vs Live 실제 원가 비교 | 계측은 갖췄으나 **같은 조건의 통화 표본**이 아직 부족하다 |
