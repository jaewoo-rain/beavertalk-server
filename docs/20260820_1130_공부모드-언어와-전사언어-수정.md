## 1. 무엇이 이상했나

### ① 입력 전사가 엉뚱한 언어로 찍힌다

| 학습자가 말한 것 | 전사된 것 |
|---|---|
| "피우다" | `フィウダ` (일본어) |
| "다" | `套` (중국어) |
| "아주" | `और च` (힌디어) |
| (짧은 응답) | `für 10` · `kumite` · `तककी` · `Sí.` |

⛔ 화면만의 문제가 아니다. 이 전사는 `CallRawData.content` 로 **저장**되고, 이어하기
요약(`normalcall_service._resume_transcript`)과 통화후 문장 추출·증거 인용 검증이 그걸 읽는다.
⇒ **증거가 안 잡히고 레벨업이 안 도는 원인**이 될 수 있다.

### ② 공부 모드인데 설명·지시가 한국어로 나간다

모국어가 영어(`locale=en`)인 학습자에게:

```
오늘은 "피우다"라는 단어 배울게. "피우다"는 "to bloom" or "to smoke" 이런 뜻이야. 따라해 봐.
"다" 아니고 "다". 디귿 발음이야. 다시 해봐.
```

불변 규칙 3 은 정반대를 지시한다 — *"'공부 모드'는 … 설명·지시·리액션은 레벨과 무관하게
전부 {locale_label}로 한다"*.

## 2. 원인

### ① 전사 — 언어 힌트를 안 준다

`core/gemini_live.build_live_config` 이 빈 설정을 넘긴다:

```python
input_audio_transcription=types.AudioTranscriptionConfig(),   # 언어 힌트 0
```

설치된 SDK(google-genai **2.18.1**)의 `AudioTranscriptionConfig.language_codes` 설명:

> BCP-47 language codes providing hints about the languages present in the audio.
> **If omitted or empty, defaults to automatic language detection.**

⇒ 지금은 자동 감지에 전부 맡긴 상태다. 1~2음절 한국어는 자동 감지가 못 버틴다.

### ② 공부 모드 — 규칙은 맞고 **예시가 어긋난다**

지시문을 실제로 조립해 확인했다(`build_system_instruction`, locale=en, study_items 3건, 4,542자).
규칙 3 은 정확히 쓰여 있다. 문제는 절차 블록(`core/persona_prompt._study_procedure`)이다:

```
- 문법: ① 뜻·쓰임을 1~2문장 설명 … ④ 응용 질문(예: "너는 주말에 뭐 하고 싶어?")
```

- **`docs/prompts/README.md` 원칙 4 정면 위반** — 지시문 4,542자를 통틀어 **리터럴 대사가
  나오는 유일한 자리**가 여기고, 그게 한국어다. *"모델은 규칙과 예시가 다르면 예시를 따른다."*
- **멀티랭귀지 버그(덤)** — `{target}` 치환이 아니라 **박힌 한국어**다. 프랑스어 학습자에게도
  "너는 주말에 뭐 하고 싶어?" 가 그대로 간다.

## 3. 수정

### ① 전사 언어 (코드)

1. `core/gemini_live.py` — `build_live_config(..., input_language_codes=None)`.
   **None/빈 값이면 종전과 바이트 동일** ⇒ 기존 테스트·스냅샷 무영향
2. `open_session` 통과 → `call_session._input_language_codes()` 가 `[학습언어, 모국어]`를 만든다
3. `core/config.py` — 킬스위치 `LIVE_INPUT_LANGUAGE_CODES`(기본 on).
   ⛔ Gemini 가 이 필드를 거부하면 **통화가 전부 안 열린다**. env 하나로 되돌릴 구멍을 남긴다(R5)
4. **출력 전사는 안 건드린다** — 로그상 비버 쪽 전사는 멀쩡하다

#### ⭐ 매핑을 새로 만들지 않았다 (착수 후 계획 수정)

계획엔 `core/languages.py` 에 ISO→BCP-47 표를 새로 만든다고 썼다. **그렇게 하지 않았다** —
`core/stt.normalize_language_codes` 가 이미 있고, 캐스케이드가 **같은 결함을 2026-08-08 에
이미 겪고** 만든 것이다(모국어 발화 5회 연속 36초가 `text=''` 로 사라진 사건).
표를 하나 더 만들면 같은 질문에 답이 둘이 된다.

그쪽 규율 하나가 특히 중요했다 — **"검증한 코드만 매핑하고 모르는 건 버린다"**
(`_STT_LANGUAGE_ALIASES = {"en": "en-US", "ko": "ko-KR"}`). 내가 처음 쓴 표에는
`ja-JP`·`zh-CN`·`fr-FR`·`vi-VN` 이 **추측으로** 들어 있었다. 틀린 코드는 그 언어를 조용히
안 들리게 만든다 — 지금 고치려는 결함과 **같은 실패**다. 그래서 되돌리고 기존 것을 썼다.

#### ⛔⛔ 부분 힌트는 무힌트보다 나쁘다 (all-or-nothing)

기존 함수를 그대로 쓰면 `ja` 는 버려지고 `en-US` 만 남는다. 그건 **일본어 발화를 영어로
알아들으라고 시키는** 꼴이라 지금보다 나쁘다. 그래서 `_input_language_codes()` 는
**하나라도 매핑이 안 되면 통째로 포기한다**(빈 목록 = 힌트 없음 = 종전 동작).

| 학습/모국어 | 결과 |
|---|---|
| ko / en | `["ko-KR", "en-US"]` ← 오늘 사장님 통화 |
| ko / ko | `["ko-KR"]` (중복 제거) |
| ja / en · ko / vi | `[]` — **오늘과 완전히 같다** |

⇒ 실제로 동작이 바뀌는 조합은 **ko·en 뿐**이다. 나머지 언어는 회귀 위험이 0 이고,
표를 채우고 싶으면 v2 supported-languages 표를 확인해 `_STT_LANGUAGE_ALIASES` 에 넣으면
두 경로(캐스케이드·라이브)가 같이 좋아진다.

⚠ **한계**: SDK 에 필드가 있는 건 확실하나, Live 백엔드가 실제로 존중하는지는
**통화 1건으로만** 확인된다. 안 먹으면 서버 후처리(스크립트 판별 `core.languages._SCRIPT_RANGES`)로
거르는 2안으로 간다.

⚠ 사소한 흠: 코드를 버릴 때 찍히는 경고가 `[stt-v2]` 접두어를 단다(라이브 통화인데).
로그를 읽을 때 헷갈릴 수 있어 적어 둔다.

#### ⛔ 캐스케이드를 지울 때 (사장님 지적 2026-08-20)

*"캐스케이드가 아니라 라이브만 고치는 거 알지? 캐스케이드 안 쓴대."* — 맞다. 캐스케이드
세션 파일은 한 줄도 안 건드렸다. 다만 **라이브가 `core/stt.py` 의 함수 하나를 빌려 쓴다.**

위험한가 확인했다:
- `core/stt.py` 는 캐스케이드 전용이 **아니다** — 발음 챌린지(`stt_session.py` → `/pron/stt/ws`)도
  쓴다. 캐스케이드를 들어내도 이 파일은 남는다.
- 무거운 `google.cloud` import 는 전부 **함수 안**에 있다 → import 만으로 라이브가 무거워지거나
  죽지 않는다(R5 안전).
- 빌려 쓰는 건 **순수 함수 하나**(코드 표기 변환)다. 캐스케이드 로직이 아니다.

⇒ **지금은 그대로 둔다**(사장님 판단). 대신 나중에 안 깨지게 **기록을 세 군데** 박았다:
| 어디 | 무엇 |
|---|---|
| `core/stt.py` 의 `normalize_language_codes` 바로 위 | "캐스케이드 전용이 아니다 — 같이 지우지 마라" + 쓰는 곳 셋 |
| `docs/20260813_0040_캐스케이드-데모잔재-정리목록.md` **§2-b** | 정리 작업자가 실제로 여는 문서. [유지] 항목으로 등재 |
| `tests/test_stt_languages.py` ④ 절 머리 | "여기부터는 라이브 회귀다 — 지우지 마라" |

끊고 싶어지면 `_STT_LANGUAGE_ALIASES`(두 줄) + `_BCP47_RE` + 함수 본문을 라이브로 옮기면
된다(5분).

### ② 공부 모드 언어 (프롬프트) — **A안만**

`_study_procedure` 의 ④ 리터럴 한국어 예시를 언어중립 표현으로 교체한다.

⛔ **B안(절차에 "설명은 모국어로" 재명시)은 하지 않는다.** 원칙 3(중복은 한 규칙에 위임)과
마찰한다 — 설명 언어는 규칙 3 이 소유한다. A안 뒤 통화를 다시 듣고, 그래도 한국어로 설명하면
그때 판단한다.

⛔ Live 공용 본문(`_INVARIANTS_TEMPLATE`)은 건드리지 않는다 — 규칙 3 자체는 맞게 쓰여 있다.
스냅샷 동결본(`tests/test_persona_prompt._ORIG_INVARIANTS_TEMPLATE`)도 그대로다.
기존 테스트는 `"유형별 절차:"` 헤더만 검사하고 ④ 예시는 안 본다(확인함).

## 5. ⛔ 테스트 가짜 팩토리 29개가 깨졌다 (예상 못 한 대가)

첫 전체 회귀에서 **29 failed**. 전부 같은 원인이었다:

```
factory() got an unexpected keyword argument 'input_language_codes'
```

가짜 세션 팩토리들이 `(client, settings, *, system_instruction, voice)` 로 **엄격하게**
선언돼 있다. 이건 사고가 아니라 **의도된 설계**다 — 운영 코드가 `tools`·`resume_handle` 을
"값이 있을 때만" 넘기는 이유가 그것이고(`_run_one_generation` 주석), 그 규율 덕에
"운영이 실제 `open_session` 이 모르는 인자를 넘기는" 사고가 테스트에서 잡혀 왔다.

내 코드도 같은 규율을 따랐지만(`if state.input_language_codes:`) **소용이 없었다** —
기본 시나리오가 ko 학습/en 모국어라 값이 **항상** 있다. `tools` 처럼 "평소엔 None"이 아니다.

⇒ **가짜 팩토리 쪽을 `**_kw` 로 열었다**(9곳, 3파일). 운영 코드를 테스트 더블에 맞춰
구부리는 것보다 낫다고 판단했다. 대가는 정직하게 적는다 — 그 그물이 **한 칸 성겨졌다.**
`build_live_config`/`open_session` 이 이 인자를 실제로 받는지는 이제
`tests/test_gemini_live_config.py` 의 새 케이스 2건이 지킨다.

**사장님 관측** — "자막으로는 알겠다고 뜨는데 소리는 계속 웃고 있음".

### ⛔⛔ 이 어긋남은 **웃음·"음~" 같은 비언어 발성 한정이다 — 말에서는 안 난다**

사장님이 두 번 짚었다(2026-08-22): *"딱 웃음소리 음 이런 거만 그래"*.
⚠ **"오디오가 전반적으로 밀린다"로 읽지 마라.** 내가 처음 그렇게 적었고 그건 과장이다.
말하는 구간에서는 자막과 소리가 맞는다.

왜 비언어 발성에서만인가 — **그 구간엔 자막이 아예 없다.** 로그에 그대로 있다:
`172.7s → 177.7s`(5.0초) · `181.3s → 187.1s`(5.8초) 동안 전사 조각이 **한 개도 안 온다**.
소리는 그 시간을 채우는데 자막은 그 구간을 **건너뛰고 다음 말로 넘어간다** ⇒ 딱 여기서만
"자막은 다음 말, 소리는 아직 웃음"이 된다. 말할 때는 자막과 소리가 같은 내용을 같이
흘려보내므로 어긋난 게 안 느껴진다.

한 번 벌어진 차이는 안 줄어든다 — `scripts/engine_demo.html:175-176` 이 이렇다:
```js
const t = actx.currentTime; if (playT < t) playT = t;   // 대기열이 **비었을 때만** 따라잡는다
n.start(playT); playT += ab.duration;                   // 앞서 있을 때 줄이는 코드는 없다
```
`playT` 를 만지는 곳은 통화 시작의 `playT = 0` 뿐(`:198`)이라 통화 끝까지 그대로 간다.

방증 — 긴 웃음 턴 **뒤에만** 학습자 발화가 비정상적으로 끊긴다(소리 끝나기를 기다린 시간):

| 턴 종료 | 다음 학습자 발화 | 공백 |
|---|---|---|
| `128.8s`(8.2초 웃음 턴) | `159.6s` | **30.8초** |
| `188.1s`(15.9초 웃음 턴) | `236.8s` | **48.7초** |
| 그 외 정상 턴 | — | 보통 3~8초 |

⚠ **미확정 한 가지**: "비언어 발성 오디오가 몰아서 온다"까지는 확인 못 했다 — 데모 페이지가
오디오 조각 도착 시각을 안 찍는다. `playPCM24k` 에 `playT - actx.currentTime`(밀린 초)을
찍는 줄 하나면 다음 통화에서 **웃음 구간에서만 튀는지** 바로 보인다.
⭐ 다만 **고치는 쪽은 이 답을 몰라도 된다** — 대기열이 N초 이상 앞서면 잘라내는 처리는
원인이 무엇이든 똑같이 듣는다. 계측은 고치기 위해서가 아니라 이해하기 위해 한다.
