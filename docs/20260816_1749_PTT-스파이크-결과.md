## 2. 받은 응답 원문

### 대조군 — 지금 우리가 보내는 설정
```
session.created
session.updated — turn_detection={'type':'server_vad', 'threshold':0.5,
                                  'prefix_padding_ms':300, 'silence_duration_ms':300}
                  noise_reduction=None
                  model='gpt-4o-mini-transcribe'
error — code=input_audio_buffer_commit_empty  param=None
        "buffer too small. Expected at least 100ms of audio, but buffer only has 0.00ms"
(커넥션 **유지된 채** 종료)
```

### 본시험 — PTT 가 요구하는 설정
```
session.created
session.updated — turn_detection=None   noise_reduction=None
input_audio_buffer.committed
conversation.item.added / conversation.item.done
conversation.item.input_audio_transcription.completed      ← 수동 커밋으로 전사까지 왔다
(커넥션 **유지된 채** 종료)
```

## 3. 이걸로 확정된 것 (플랜 §11 의 "확인 못 한 것" 중 1번 해소)

| 항목 | 값 | 왜 중요한가 |
|---|---|---|
| `turn_detection: null` | **허용된다** | PTT 성립의 전제. 이게 안 되면 설계가 통째로 (b)로 바뀐다 |
| 수동 `input_audio_buffer.commit` | **된다**(전사까지 옴) | 릴리즈 시점을 우리가 정한다 = 벤더 침묵창 회수 |
| `silence_duration_ms=300` | **실제로 적용됨** | "안 먹고 500 으로 돌지도"라는 의심이 있었다 — **아니었다.** 지연 200ms 는 안 새고 있다 |
| `noise_reduction` 벤더 기본 | **`None`(꺼짐)** | 문서에 없던 값. 5분 지연 폭증 보고가 있는 기능이라 기본이 꺼짐인 게 중요하다 |
| `threshold` 기본 | `0.5` | 우리가 안 보내는 값 |
| `prefix_padding_ms` 기본 | `300` | ⭐ speech_started 의 `audio_start_ms` 가 **말 시작보다 300ms 앞**을 가리킨다는 뜻 |

⚠ `prefix_padding_ms=300` 은 **병합 gap 계산에 직접 영향**이 있다(`_is_same_utterance` 가
`audio_start_ms − audio_end_ms` 를 본다). 지금 VAD 경로의 gap 값에 이 300 이 이미 섞여 있다.

## 4. 🔴 함정 — `input_audio_buffer_commit_empty`

대조군에서 **실제로 받은** 에러다.
```
code=input_audio_buffer_commit_empty   param=None
```
· 설정 거절도 스트림 death 도 아니다. 그냥 "지금 커밋할 오디오가 없다"이고 **커넥션은 산다.**
· ⛔ **`param` 이 없다** — 그래서 "`param` 이 `session.` 으로 시작하면 비치명"이라는 규칙에
  안 걸린다.
· ⭐⭐ **PTT 는 릴리즈마다 commit 을 보낸다.** 사용자가 눌렀다 **100ms 안에 떼면**(오조작·오타)
  이 에러가 **정상 조작에서** 난다.

⇒ 2026-08-16 결정 ⓐ 로 **비치명 목록에 넣었다**(`core/openai_stt.py` 의 `_NON_FATAL_CODES`).
⛔ 목록은 **좁게** 유지한다 — 벤더 error 를 통째로 비치명으로 뒤집으면 진짜 스트림 death 를
놓친다. 새 사례는 **실제로 받은 코드만** 하나씩 더한다(추측으로 넣지 마라).

---

## 5. ⚠ 새 워커가 먼저 알아야 할 것 (이 스파이크 밖)

1. **벤더 error 는 기본이 치명이다.** `core/openai_stt._translate` 가 `STREAM_ERROR` 를 올리면
   `cascade_session` 이 **무조건 통화를 종료**한다(`raise _Stop`). 2026-08-16 에 설정 거절과
   위 commit-empty 만 비치명으로 갈라 뒀다. **새 오류 코드를 만나면 그 목록부터 봐라.**
2. **`session.updated` 계기판이 이미 있다** — `[stt-openai] 세션 확정 — model=… turn_detection=…
   noise_reduction=…`. 설정이 안 먹으면 그 줄이 알려 준다. `turn_detection:null` 을 보내기
   시작하면 그 줄에 `turn_detection=None` 이 떠야 정상이다.
3. 플랜 §4 의 경고는 유효하다: **PTT 에서 `_is_same_utterance` 를 그대로 쓰면 안 된다**
   (오디오 시각 축이 무너진다). §9 의 `_turn_idle_at`·`_check_audio_clock` 도 그대로다.
4. ⛔ 아직 **아무도 안 잰 것**: 사람이 버튼을 떼는 지연(말끝 → 릴리즈). 플랜 §11-3.
   이 값이 200ms 면 PTT 의 지연 이득이 **마이너스**가 된다.
