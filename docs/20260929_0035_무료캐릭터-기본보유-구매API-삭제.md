# 무료 캐릭터 처음부터 보유 + 무료 지급 구매 API 삭제 (2026-09-29)

## 사장님 지시
「무료 캐릭터는 처음부터 보유한 상태로 시작하게 하고, 그러면 저 API 없어도 되지 않나」 → 맞다.

## 사실(bt-back 확인)
- `POST /characters/{id}/purchase` 는 돈을 받지 않고 지급했다(`purchase_service` 「지금 이 함수는 결제를 하지 않는다」,
  `is_test_grant = price > 0 and card_info is None` 이면 경고만). 운영 유료 보유 24건 중 영수증 1건.
- 운영 캐릭터: Baba(0, 보유 61) · Bibi(0, 14) · Popo/Rara/Dudu(4.99).
- Bibi 를 **고르기만** 하면(행 없음) 통화 시작 소유 검증에서 가장 싼 캐릭터(=Baba)로 조용히 폴백됐다.

## 결정 — 파생 계산(행을 만들지 않는다)
- `entitlements.is_free_character(character)` = `price is not None and price == 0`. **소유** 축(is_owned=true · unlock_source="owned").
  - 가격 NULL 은 무료 아님(모르면 잠금). 판정은 원가 — 할인가 0 은 소유를 주지 않는다(되돌려야 하는 축이 아님).
  - 행을 안 만드는 이유: `entitlements.py` 머리의 규율(접근은 읽는 시점 파생)과 같다. 가입 훅·백필·마이그레이션 0,
    기존 75행은 그대로 둬도 결과 동일.
- 적용 지점(같은 함수):
  - `character_service.list_characters`·`get_character`(is_owned)
  - `character_service.list_owned`(`GET /members/me/characters`) — 행 + 0원 캐릭터. 행 없으면 `purchase_price=0`·`purchase_date=null`
  - `normalcall_service.resolve_call_character` ② 대표 캐릭터 소유 검증
- `POST /characters/{id}/purchase` 삭제 + `purchase_service.py`·`schemas/purchase.py`(다른 호출부 0 — grep 확인)·패키지 export.
  유료 지급은 `POST /purchases/verify`(스토어 영수증)뿐. ⛔ `payment` 모델·표·`iap_service` 는 안 건드림(prem-build §22-⑥ 진행 중).

## 안 한 것
- `GET /purchases/entitlement` 의 `owned_character_ids` 에는 0원 캐릭터를 **넣지 않았다** — `iap_service` 는 prem-build 가
  동시에 만지는 파일이라 충돌 회피. 앱이 이 목록으로 잠금을 그리면 Bibi 가 잠겨 보일 수 있다 → 필요하면 통합 후 1줄.
- 가입 시 스타터 행 지급(`member_service._resolve_default_character`)은 그대로 둠(무해 — 결과 동일).

## 앱 영향(flutter dev `cb0ed56` 읽기 확인)
- `avatar.dart` `_deliver` 가 삭제 API 를 부르는 경우 2가지: ① 무료 캐릭터 「받기」 ② 영수증 없는 mock 결제 레일.
  ①은 무료가 이제 처음부터 `is_owned=true` 라 버튼이 안 뜬다. ②는 dev 전용 — 실결제는 `/purchases/verify` 를 이미 탄다.
  ⇒ 앱팀 후속: 레거시 경로(`character_remote_data_source.purchase`) 삭제 권장. 남아 있으면 404.

## 추가(같은 날, bt-back 지시) — 가입 스타터 행 생성 제거
- `member_service._resolve_default_character` 가 가입 때 첫 캐릭터(0원)의 `member_character` 행을 만들던 것을 제거.
  대표 캐릭터(`member.character_id`) 지정은 그대로.
- 선행 확인(grep): 행이 있어야 돌아가는 코드 0 — 카탈로그·통화 소유는 파생, `iap_service` 는 유료 지급·복원 목록만
  (앱 `restoreOutcomeOf` 는 무료를 이미 걸러냄 — 앱 QA F003 혼란의 근원이 이 행), B2B·콘솔·scripts 참조 0.
- 기존 행 그대로. 회귀: 신규 가입 회원 행 0개 + 무료 보유 + 대표 캐릭터 지정 + 통화 캐릭터 일치.
- `owned_character_ids` 에 0원 캐릭터를 넣지 않는 것은 bt-back 결정으로 **현행 유지**(그 필드 = 실제 취득분).
