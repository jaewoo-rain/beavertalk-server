# §6 차시 제목 · §10 통화 제목 다국어 — 요청 시 번역 + 캐시 (2026-09-29)

요청서: 「비버톡 서버 추가 요청 — 앱 쪽」(2026-09-26) §6·§10. 계획 초안: `docs/plans/2026-09-28-다국어-3건-6-10-13.md`
(§13 은 앱팀 파일 대기 — 이번 범위 아님).

## 공통 방식(bt-back 확정)
**전량 미리 번역하지 않는다. 요청된 (항목, 언어)만 번역하고 캐시한다.**
- 언어는 요청에 싣지 않는다 — 서버가 `member.language` 로 고른다. 읽기는 `normalize_locale`,
  NULL 은 `en`(취약발음 `_locale_of` 선례와 같은 폴백 — 외국인 앱이라 모르면 한국어보다 영어).
- 번역기: `core/text_translate.translate_texts` — **분석 대본과 별개 경로**(잠금 프롬프트·판정 지시문 무변경).
  JSON 구조화 출력 1콜로 여러 문장을 한 번에, `thinking_budget=0`, HTTP 타임아웃(`TRANSLATE_TIMEOUT_S`).
  모델 `TRANSLATE_MODEL`(기본 gemini-2.5-flash). 어댑터는 도메인·DB 를 모른다.
- ⛔ 실패는 조회를 막지 않는다(R5): genai 없음·타임아웃·파싱 실패·개수 불일치 → §6 은 `null`, §10 은 원문.
  실패는 캐시하지 않는다(다음 조회에서 다시 시도).

## §6 — `GET /cur/me` `lesson.situation_translation`
- 새 표 `cur_text_i18n`(kind, source, locale) 유니크 → text. **원문 문자열을 키로** 쓴다.
  - 왜 lesson_id/code 가 아닌가: 재시드(`cur_l1_layout`)로 id·code·문구가 바뀔 수 있다. 번역은 «그 한국어 문장»의
    함수라 원문 키가 가장 안전하다(문구가 바뀌면 자연히 새 번역). ko 과정과 ja 과정이 같은 문장을 공유해도 1행.
  - `kind` = `'cur_situation'`. 나중에 `topic`(cur_topic.name)도 같은 표에 kind 만 달리 넣을 수 있다(⛔ 지금은 안 한다).
  - ⛔ `ko` 행 금지(CHECK 제약 + 코드) — 원문이 한국어다(`sound_lesson_i18n` 의 `i18n/ko.json` 금지와 같은 이유).
- 회원 언어가 `ko` 면 `null`(번역할 게 없다). 캐시 있으면 그 값, 없으면 번역 → 저장 → 반환.
- ⛔ 원문 `situation` 은 그대로(통화 프롬프트에 들어간다). `/cur/lessons` 는 이번 범위 아님(요청은 `/cur/me`).
- ⚠ 기계번역이다. `sound_lesson_i18n` 의 「기계번역 금지」는 **조음 설명**(틀리면 엉뚱한 입 모양) 규율이고,
  상황 한 줄은 병기용 보조 번역이라 위험이 다르다 — 품질 문제가 보이면 행을 고쳐 넣으면 된다(요청 시 캐시가 원본을 덮지 않는다:
  이미 있는 행은 다시 번역하지 않는다).

## §10 — `GET /calls` `summary` 를 회원 현재 언어로
- `call.summary_lang` 추가 — 분석이 요약을 **실제로 쓴 언어**. 분석 지시문은 `LOCALE_LABEL.get(locale, 영어)` 이므로
  지원 밖 locale(ne·my 등)은 실제로 영어로 쓰인다 ⇒ 저장값도 그 규칙으로(`summary_lang_for`). 일반 통화(`_save_analysis`)·
  레벨테스트(`_save_level_assessment`) 둘 다.
- 과거 행(`summary_lang` NULL): 한글이 있으면 `ko`, 아니면 **모름**. 대상이 `ko` 가 아니고 원문 언어를 모르면 번역 대상에 넣되
  번역기에 «이미 그 언어면 그대로 돌려줘라»를 지시한다(비-ko 끼리 구분 불가 — 계획 초안의 절충안).
- 캐시 = **이미 운영에 있는 B2B 표 `call_summary_translation`**(call_id, locale) 유니크. 계획 초안 (가) 채택.
  - ⛔ 앱 서버는 이 표의 마이그레이션을 만들지 않는다(DDL 소유 = B2B alembic `e1f2a3b4c5d6`).
  - 그래서 앱 `Base.metadata` 에 **올리지 않고** 별도 `MetaData` 의 Core `Table` 로 둔다 — `alembic/env.py` 의
    `_OWNED_TABLES = Base.metadata` 라 여기 올리면 앱 autogenerate 가 이 표를 «우리 것»으로 보고 주석·인덱스 차이를 diff 로
    내거나(운영) create_table 을 만든다(표 없는 로컬 dev DB).
  - ⚠ B2B 가 이 표 스키마를 바꾸면 앱이 깨진다 — 모듈 docstring 에 적었다.
- ⛔ 목록 **한 페이지 분량만**(limit ≤100, 기본 20) — 캐시 미스분만 **1콜로 묶어** 번역. 전체 이력을 돌리지 않는다.
- 상세(`GET /calls/{id}`)는 이번 범위 아님(요청은 기록 카드 = 목록).
