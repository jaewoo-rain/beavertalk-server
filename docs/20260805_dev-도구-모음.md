## ⚠ 먼저 알아야 할 것 — 환경 게이트가 실서비스를 막지 못한다

dev 블록의 조건은 `settings.ENV != "prod"` 인데, **실서비스(app-api)의 `ENV` 는 `"prod"` 가
아니라 `"test"`** 다. 즉 이 블록이 **실서비스에도 열린다.**

그래서 데이터를 읽거나 쓰는 도구는 환경이 아니라 **`CurrentAdmin`(member.role == "admin")**
으로 막는다. HTML 페이지 자체는 열려 있어도 관리자 토큰 없이는 아무것도 못 읽고 못 쓴다.
새 dev 엔드포인트를 만들 때 이 규율을 반드시 따를 것.

## 1. 구독 상태 주입기 ⭐ 신규 (2026-08-05)

`POST /__dev/subscription-state` — 관리자 전용

구독 **상태 8종**을 실제로 만들어 프론트 화면을 확인한다.

```bash
curl -X POST "$BASE/__dev/subscription-state" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"state":"grace","plan":"max","email":"tester@example.com"}'
```

| 필드 | 값 |
|---|---|
| `state` | `free` · `trial` · `active_pro` · `active_max` · `grace` · `on_hold` · `ending` · `expired` |
| `plan` | `pro` \| `max` (기본 `pro`. `active_*`·`trial` 은 상태가 플랜을 결정) |
| 대상 | `member_id` 또는 `email`. 둘 다 없으면 호출한 본인 |

확인: 그 계정으로 `GET /subscriptions/status`

**왜 목데이터가 아니라 이건가**
- 응답에 가짜 값을 섞으면 ① 실제 사용자가 가짜 상태를 받을 수 있고 ② "진짜냐 목이냐"를
  가리는 분기가 응답 경로에 영구히 남는다.
- 여기서는 **DB 행만** 원하는 모양으로 만든다 → `resolve_status` 진짜 코드가 돌고 앱은
  진짜 wire 를 받는다. 판정 순서·`plan` 동봉 누락·날짜 직렬화 같은 건 목으론 못 잡는다.

**안전장치**
- 만든 행은 항상 `source='manual'` — 결제가 붙는 날 진짜 유료로 둔갑하지 않는다.
- 대상 회원의 기존 구독 행을 전부 지우고 1건만 남긴다(다중 활성 행이면 확인이 무의미).
- `trial` 은 `plan=max` 로 고정 — 앱이 체험을 Max 로 취급한다(`subscription_state.dart`).

## 5. 원가 계측 (2026-08-04 신규)

통화가 끝날 때마다 **로그 1줄**. 모니터링이 아니라 **조사 도구**다 — 주기 잡·대시보드·알람 없음.

```bash
gcloud logging read 'resource.labels.service_name="beavertalk-app-demo-api"
  AND textPayload:"normalcall usage"' \
  --project bt-dev-web-01 --limit 5 --freshness=30m --format="value(textPayload)"
```

출력(전부 `key=value` — 나중에 Cloud Logging 로그 기반 메트릭이 코드 변경 0줄로 붙는다):

```
normalcall usage: call_id=880 type=normal msgs=22 dropped=0 t=[13.6..299.2]
sum_prompt=142120 sum_resp=18040 sum_thoughts=0 sum_total=160160
last_prompt=11080 last_total=11900 monotonic=True
sum_in=AUDIO=120802,TEXT=21318 sum_out=AUDIO=17600,TEXT=440
```

`LIVE_USAGE_TRACE=true` 면 턴별 시계열 1줄 추가(압축 발동 판별용).

**판독**

| 관측 | 해석 |
|---|---|
| `monotonic=True` + trace 가 매끈한 증가 | 누적 의심 + 압축 미발동 → `last_*` 채택 |
| `monotonic=False` (톱니) | 증분 확정 + 압축 발동 → `sum_*` 채택 |

원가 = `in_AUDIO×$3.00 + in_TEXT×$0.50 + out_AUDIO×$12.00 + out_TEXT×$2.00` (per 1M)
