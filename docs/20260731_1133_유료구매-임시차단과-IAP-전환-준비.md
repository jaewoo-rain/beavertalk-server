# 유료 구매 임시 차단 (IAP 전환 전 손실 방지)

작성 2026-07-31 11:33 · 대상 `domains/commerce`

앱팀 `2026-07-27_1756_과금모델-게이팅부재-캐릭터결제-우려사항.md` §3 후속.

## 0. 결정 (사장님)

- 구독 상품: **Pro 월간 1종**
- 캐릭터: **영구 소유**(IAP non-consumable → 복원 지원 필요)
- **유료 구매를 지금 차단**한다(IAP 완성 전까지)

## 1. 왜 급한가

`POST /characters/{id}/purchase` 는 **미구현이 아니라 잘못 구현**돼 있다:

```python
price = self.char_service.effective_price(character)   # 가격 계산
mc = MemberCharacter(...)                              # 소유권 지급
payment = Payment(price=price, card_info=card_info)    # 결제 "기록" 생성
self.db.commit()
```

`card_info` 는 받아서 **저장만 하고 아무 데도 안 보낸다.** 즉 **$10 짜리 캐릭터가 공짜로 나간다.**
prod 실측: `payment` 11건 전부 `card_info=null` — 그렇게 생긴 것들이다.

구독도 같다 — `SubscribeCreate.price` 를 **클라가 정한다**(`gt=0` 만 검사). `0.01` 로 구독 가능.

IAP 는 상품 등록·샌드박스·심사까지 며칠이 걸린다. 그동안 계속 새므로 먼저 막는다.

## 2. 차단 방식

| 대상 | 처리 |
|---|---|
| **유료** 캐릭터 구매 | `503 PURCHASE_UNAVAILABLE` |
| **무료**(price 0) 캐릭터 | **허용** — 기본 캐릭터(BABA) 지급 경로라 막으면 온보딩이 깨진다 |
| 이미 보유 | 기존 `409 ALREADY_OWNED` 유지(차단보다 먼저 검사) |
| 구독 시작 | `503 PURCHASE_UNAVAILABLE` |

**왜 503인가**: 400/403 은 "네 요청이 잘못됐다", 404 는 "없다"는 뜻이라 앱이 오해한다.
503(Service Unavailable) = **"기능이 일시적으로 준비 안 됨"** 이 지금 상태와 정확히 맞고,
IAP 가 붙으면 이 분기만 제거하면 된다.

⛔ 라우터에서 막지 않고 **서비스 레이어**에서 막는다. 라우터는 얇게(CLAUDE.md), 그리고
데모·스크립트 등 다른 호출부가 생겨도 같이 막히게.

## 3. 되돌리는 법 (IAP 완성 시)

`purchase_service.py` / `subscription_service.py` 의 `_PURCHASE_ENABLED` 가드 블록을 지우고
영수증 검증 호출로 교체한다. 그 외 로직(멱등·지급·가격계산)은 그대로 재사용된다.

## 4. 범위 밖

- IAP 실구현(영수증 검증·웹훅·상품 매핑) — 별건. 계약서부터 쓴다
- 기존 결제 이력 11건 정리 — 이미 USD 로 전환만 해둠

## 5. 검증

- 유료 캐릭터 구매 → 503 + 소유권·결제기록 미생성
- 무료 캐릭터 구매 → 정상 지급
- 이미 보유 → 409(차단보다 먼저)
- 구독 시작 → 503
