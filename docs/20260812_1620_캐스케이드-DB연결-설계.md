# 캐스케이드 DB 연결 설계 — Live 와 **같은 기록**을 남긴다 (2026-08-12)

> 사장님: "**라이브처럼 db에서 캐릭터 목소리 받아서** 하면 될듯. 그리고 **통화내용 저장하던
> 방식도 그대로 저장**하면 돼."
>
> ⛔ **새 방식을 발명하지 않는다.** Live 가 쓰는 서비스 함수를 **그대로 재사용**한다.
> 이 문서의 목적은 하나다 — **두 경로가 만드는 통화 기록이 정말 같은 모양인지 증명하는 것.**
> 표기: **[실측]** 직접 확인 · **[코드]** 코드로 확인 · **[미상]** 확인 못 함(추측으로 안 채운다)

---

## §0. 지금 상태 [코드]

| | Live | 캐스케이드 |
|---|---|---|
| 회원 | `ws_router` 에서 `find_or_create_by_auth` → `member_id`·`target_language` | ⛔ **DB 조회 0곳**(토큰 검증만) |
| 캐릭터·음색 | `resolve_call_character` → `load_call_setup` → role·personality·**voice** | ⛔ env 전역 고정(`CASCADE_PERSONA_*`, `CASCADE_TTS_VOICE`) |
| 통화 행 | `create_call` → `call_id` | ⛔ 없음 |
| 전사·오디오 | 1분마다 `save_segments` 점진 flush + 종료 시 나머지 | ⛔ 없음 |
| 원가 | `save_call_usage(call_id, summary, engine=...)` | ⚠ `cascade_usage` 로 **계산은 하는데 로그로만** 나간다 |
| 종료 | `_finish_call`(call_ended → playback_done ack → close) | ⚠ 자체 종료(기록 없음) |

⇒ 지금 앱을 붙이면 **누가 통화해도 같은 캐릭터**, 모국어 미반영, **기록이 안 남아**
복습·발음평가·분석으로 이어지지 않는다.

## §1. 호출 표 — 어디서 무엇을 부르나

⭐ **왼쪽(Live)과 오른쪽(캐스케이드)이 같은 함수를 부른다.** 시그니처는 건드리지 않는다.

| 단계 | Live 위치 | 캐스케이드 위치(신규) | 함수 | 비고 |
|---|---|---|---|---|
| 회원 해석 | `ws_router.ws_call_stream` | `cascade_router.ws_cascade_stream` | `MemberService.find_or_create_by_auth` (via `svc.run_db`) | **같은 호출** — auth uuid → `(member_id, target_language)` |
| 캐릭터 결정 | `call_session.run_call` | `cascade_session.run_cascade` | `svc.resolve_call_character(db, member_id, inbound_call_id=None)` | 캐스케이드는 알람 수신통화가 없으므로 `inbound_call_id=None` |
| 프롬프트·음색 | 〃 | 〃 | `svc.load_call_setup(db, member_id, character_id, spec.code)` | role·personality·**voice**·level_profile·locale·interests·history |
| 통화 행 | 〃 | 〃 | `svc.create_call(db, member_id, character_id, call_type, target_language=spec.code)` | ⚠ `call_type` 은 캐스케이드에선 **항상 `"normal"`**(§4-3) |
| 전사·오디오 | `_flush_*_segment` + 1분 주기 | 같은 주기 태스크 | `svc.save_segments(db, call_id, segments, member_id, upload_audio=True)` | 통화중 True(점진), 종료 시 False(텍스트 먼저 커밋) |
| 원가 | `run_call` 종료부 | `run_cascade` 종료부 | `svc.save_call_usage(db, call_id, summary, engine=...)` | ⭐ **이미 캐스케이드용 규약이 함수 docstring 에 있다**(§3) |
| 종료 | `_finish_call` | 같은 함수 재사용 | `call_session._finish_call(ws, state, call_id)` | ⚠ `state` 가 Live 전용 구조라 §4-4 판단 필요 |

### 라우터가 넘겨야 하는 것

```
run_cascade(websocket, genai_client)                       # 지금
run_cascade(websocket, genai_client, session_factory,      # 신규
            member_id=..., member_target_language=...)     # Live 의 run_call 과 같은 모양
```
⛔ `session_factory` 를 **인자로 받는다**(전역 import 금지) — Live 가 그렇게 돼 있고,
테스트가 가짜 팩토리를 넣을 수 있어야 한다.

## §2. ⭐ 증명 — 두 경로의 **통화 행이 같은 모양인가**

`Call` 행을 만드는 곳은 **`create_call` 하나뿐**이다 [코드]. 캐스케이드도 그 함수를 부른다.
따라서 **필드 자체는 구조적으로 같다.** 값이 갈릴 수 있는 칸만 아래 표로 못박는다.

| 컬럼 | Live | 캐스케이드 | 같은가 |
|---|---|---|---|
| `member_id` | 라우터가 해석 | **같은 함수** | ✅ |
| `character_id` | `resolve_call_character` | **같은 함수** | ✅ |
| `call_date` | `create_call` 내부 `utcnow` | 〃 | ✅ |
| `status` | `create_call` 이 `ongoing` | 〃 | ✅ |
| `call_type` | `normal` \| `level_test` | **`normal` 고정**(§4-3) | ⚠ **의도된 차이** |
| `target_language` | `spec.code` | **같은 resolve** | ✅ |
| `usage_engine` | `live:gemini-native-audio` | `cascade:stt+llm+tts` | ⚠ **의도된 차이**(엔진 구분이 목적) |
| `in_text/out_text` | Live LLM 토큰 | **LLM 토큰**(STT·TTS 아님) | ✅ 규약 준수 |
| `in_audio/out_audio` | Live 오디오 토큰 | **0** | ⚠ 규약대로(§3) |
| `usage_json.vendors` | — | STT 초 · TTS 문자·오디오초 | ⚠ 캐스케이드에만 있다(그릇은 같다) |

`CallRawData`(전사·오디오)는 `save_segments` 하나뿐이고 **`{turn_index, role, text, pcm}`**
계약을 그대로 넘기면 된다 [코드]. ⇒ **분석·복습·발음평가는 두 경로를 구분할 필요가 없다.**

> ⛔ 이 표가 이 문서의 핵심이다. 여기 ✅ 가 아닌 칸(3개)은 **전부 의도된 차이**이고,
> 그 이유가 각각 §3·§4-3 에 적혀 있다. 그 외에 갈리는 칸이 생기면 **설계 위반**이다.

## §3. 원가 — 두 번 저장하지 않는다 [코드]

`save_call_usage` docstring 에 **캐스케이드 규약이 이미 적혀 있다**:

```
engine 은 계약 문자열('live:gemini-native-audio' / 'cascade:stt+llm+tts')이다.
⚠ 캐스케이드 호출부는 컬럼 규약을 지켜라 — in_text/out_text = **LLM 토큰**,
  in_audio/out_audio = 0. STT·TTS 는 단위가 초·문자라 컬럼이 아니라
  summary["vendors"] 로 넘긴다.
```

⇒ 우리가 이미 만드는 `CascadeUsage.summary()` 가 **그 그릇에 맞는다.**
지금은 `log_usage_summary` 로 **로그만** 낸다 — 저장은 **한 번**, 종료부에서 `save_call_usage`.
⛔ 로그와 저장이 **같은 요약 객체**를 쓴다(두 번 계산하면 두 숫자가 갈린다).

## §4. 판단이 필요한 자리 — 근거와 함께

### 4-1. ⭐ 음색 매핑 — **답이 코드에 있다** [코드]

`core/tts.py` 주석·`_resolve_voice` 로 확인:

```
프리빌트 음성 30종. 로스터(이름 목록)는 Gemini Live 캐릭터 voice·Gemini-TTS 와 같다 —
통화 캐릭터의 voice(예: "Fenrir")가 그대로 이 목록에 있다.
⛔ 그런데 API 가 요구하는 문자열 형식은 엔진마다 다르다:
    Chirp3-HD  : 'ko-KR-Chirp3-HD-Sulafat'    Gemini-TTS : 'Sulafat'
```

| 엔진 | DB voice("Fenrir") 를 어떻게 쓰나 | 판정 |
|---|---|---|
| **Gemini-TTS**(현 기본) | `_resolve_voice(..., gemini=True)` → `'Fenrir'` | ✅ **그대로 쓴다** |
| Chirp3-HD | `_resolve_voice(...)` → `'ko-KR-Chirp3-HD-Fenrir'` | ✅ 같은 함수가 변환 |
| **OpenAI TTS** | 로스터가 **아예 다르다**(nova·alloy…). 대응표 근거 없음 | ⛔ **[미상] → 서버 기본값**(`CASCADE_TTS_OPENAI_VOICE`) |

⇒ **DB 값이 이긴다**(Gemini/Chirp). OpenAI 는 조용히 틀린 음성을 쓰느니 **기본값**으로 가고,
그 사실을 **로그 한 줄**로 남긴다(`캐릭터 음색 미적용(엔진 로스터 불일치)`).
⚠ env `CASCADE_TTS_VOICE` 는 **dev 데모 덮어쓰기**로 남긴다 — 값이 있으면 그게 이긴다
(사장님이 화면에서 실험하신다). 우선순위: **env override > DB voice > 언어 기본**.

### 4-2. ⚠ 학습자 모국어를 STT 에 넣을 것인가 — **재고 정한다**

- 페르소나: **확실히 넣는다.** `load_call_setup` 의 `locale` 을 `build_system_instruction(locale=)` 로.
  지금 env 고정(`CASCADE_PERSONA_LOCALE`)이라 **모든 학습자가 같은 모국어**로 취급된다.
- STT: ⛔ **지금 바꾸지 않는다.** 실측 근거 — OpenAI 전사는 **언어 지정 없이 자동 감지**로
  41개 언어 중 39개 성공했고 [실측], `language` 를 미지정/en/ko 로 바꿔 재보니 **결과가 동일**했다
  [실측 3조건]. 즉 **넣어서 좋아진다는 증거가 없다.**
  → 넣으려면 **먼저 재야 한다**(모국어 지정 vs 미지정, 같은 오디오). 그 전엔 자동 감지 유지.

### 4-3. `call_type` — 캐스케이드는 `normal` 고정

레벨테스트는 **전용 대본·루브릭·판정**이 Live 경로에 얽혀 있다(`build_leveltest_instruction`,
승급 판정). 캐스케이드에 그대로 옮기는 것은 이번 범위가 아니다.
⇒ `create_call(call_type="normal")` 고정. ⚠ `load_call_setup` 이 `needs_level_test=True` 를
줘도 **무시하고 normal** 로 간다(그 사실을 로그로 남긴다).

### 4-4. `_finish_call` 재사용 여부 — ⚠ **부분 재사용**

`_finish_call(ws, state, call_id)` 은 `state.playback_done_event`(Live 전용 `_CallState`)를 쓴다.
캐스케이드는 프로토콜이 다르다(`turn_end`·`playback_progress`).
⇒ **함수를 옮기지 말고**, 캐스케이드 종료부에서 **같은 순서**를 지킨다:
`call_ended 송신 → 클라 ack 대기(상한) → close`. ⛔ Live 함수 시그니처는 안 건드린다.

### 4-5. R5 — DB 가 죽어도 통화는 산다

| 실패 지점 | 동작 |
|---|---|
| 회원 해석 실패 | ⛔ **통화 거절**(누구 통화인지 모르면 기록도 못 남긴다) — Live 와 같다 |
| `load_call_setup` 실패 | ⚠ **env 기본 페르소나로 계속**(지금 데모 동작) + WARNING |
| `create_call` 실패 | ⚠ `call_id=None` 으로 계속 — 기록은 못 남기지만 **통화는 된다** |
| `save_segments` 실패 | ⚠ 그 회차만 건너뛰고 다음 flush 에서 재시도(누적 커서 유지) |
| `save_call_usage` 실패 | ⚠ 조용히 False(함수가 이미 그렇게 돼 있다 [코드]) |

## §5. 작업 순서(착수 지시가 나오면)

1. **라우터** — 회원 해석 + `session_factory` 전달. 회귀: 인증 실패·DB 실패 경로
2. **세션 진입** — 캐릭터·setup 조회 → 페르소나·음색 주입. 회귀: 캐릭터가 바뀌면 음색·페르소나가 바뀐다
3. **통화 행 + 세그먼트** — `create_call`, 1분 점진 flush, 종료 persist. 회귀: 점진 저장·크래시 내성
4. **원가** — 종료부 `save_call_usage`. 회귀: 두 경로의 usage 행 형식 비교
5. **종료 규약** — call_ended → ack → close

### 검증(요구된 4건 + 1)

| # | 회귀 | 어떻게 |
|---|---|---|
| ① | 두 경로의 통화 행 필드가 같다 | 같은 member·character 로 두 경로를 돌려 **행을 필드 단위로 비교**(§2 표가 기준) |
| ② | DB 실패에도 통화가 산다 | 팩토리가 예외를 던지게 하고 통화가 끝까지 도는지 |
| ③ | 캐릭터가 바뀌면 음색·페르소나가 바뀐다 | 캐릭터 2종으로 `_resolve_voice` 결과와 system_instruction 차이 확인 |
| ④ | 세그먼트가 점진 저장된다 | 가짜 시계로 1분 주기 flush 호출 확인 + 커서가 안 겹치는지 |
| ⑤ | env override 가 DB 를 이긴다(dev) | `CASCADE_TTS_VOICE` 설정 시 DB 값 무시 + 로그 |

## §6. ⛔ 이 설계가 **하지 않는 것**

- Live 코드 수정(R4) · 공용 함수 시그니처 변경
- 레벨테스트 콜타입 · 승급 판정 · 체크판 주입(§4-3)
- STT 언어 지정(§4-2 — 재기 전엔 안 바꾼다)
- `CASCADE_ENABLED` 게이트 변경(실서비스 노출은 별개 결정)

## §7. 미확인 [미상]

| 항목 | 왜 |
|---|---|
| OpenAI TTS 음성 로스터 ↔ 캐릭터 voice 대응 | 대응표의 근거가 없다. 만들려면 **30종을 다 들어보고** 사장님이 고르셔야 한다 |
| 캐스케이드 통화가 통화후 분석·복습으로 실제로 이어지는지 | 기록이 남은 뒤 **한 통화를 끝까지 돌려봐야** 안다(설계상으론 같은 행이므로 이어져야 한다) |
| 세그먼트 오디오 업로드 비용·지연 | Live 실측은 있으나 캐스케이드는 TTS 오디오 형식이 달라(24k) 변환 비용 미측정 |
