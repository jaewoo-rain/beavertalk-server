## 0. 착수 전 현행 파악 — 코드가 말한 것

마스터플랜 §5 는 "현행 재접지(시각 비율 트리거)를 제거하고 압축 트리거로 합친다"고 적었다.
착수 전에 실제 코드를 읽었고, **플랜이 몰랐던 사실 하나와 결함 하나**를 찾았다.

### 0-1. 현행 구조 (call_session.py)

| 요소 | 현행 |
|---|---|
| 모드 스위치 | `REGROUND_MODE = "on_user_turn"` (다른 값: `legacy_idle` / `off`) |
| 중반 arm | `_reground_once` — `call_duration_s × 0.5` 시점에 `reground_pending=True` |
| 후반 arm | `_arm_late_continue` — `× 0.8` 시점에 문구를 `continue_reminder` 로 갈아끼우고 재arm |
| 실제 얹기 | 펌프(`_pump_gemini_to_client`)가 첫 `in_tr` 에 `send_reground(..., turn_complete=False)` |
| 가드 | 종료 구간(`should_close`/`close_seed_sent`) 금지 · 통화당 1회(`reground_injected`) |

즉 **arm(시각 판정)과 얹기(펌프)가 이미 분리돼 있다.** 마스터플랜이 "주입 경로는 현행
`on_user_turn` + `turn_complete=False` 를 승계한다"고 한 것이 정확히 이 구조를 말한다.
→ **바꿀 것은 arm 을 세우는 근거뿐이다. 얹기 경로·가드는 손대지 않는다.**

### 0-2. ⛔ 발견한 결함 — 후반 리마인더가 실제로는 한 번도 안 얹힌다

펌프의 얹기 조건이 `state.reground_pending and not state.reground_injected` 인데,
`reground_injected` 는 **통화 단위 1회성 플래그**이고 어디서도 되돌아가지 않는다.

```
중반 arm → 펌프가 얹음 → reground_injected = True   (영구)
후반 arm(_arm_late_continue) → reground_pending = True, 문구 교체
   → 펌프: reground_pending ✓ 인데 not reground_injected ✗  → 영원히 안 얹힘
```

즉 **중반 재접지가 실제로 얹힌 통화에서는 후반 "먼저 마무리하지 마라" 리마인더가
통째로 죽는다.** 후반 재접지는 실측 3건(call 836 12턴 전 / 744 16턴 전 / 782 4턴 전
조기 작별)을 막으려고 넣은 방어인데, 그 방어가 정작 정상 통화에서 안 돈다.

기존 테스트(`test_reground_not_rearmed_after_session_swap`)가 이걸 못 잡은 이유는
단언이 **"후반이 arm 됐는가"(`continue_injected`)** 까지만이기 때문이다 — 얹혔는지는 안 본다.
`de0133b`("세션 교체가 재접지를 되살려 후반 리마인더가 통째로 생략되던 것")가 고친 것은
*재arm 경로*였고, 이 1회성 게이트는 그 아래에 그대로 남아 있었다.

☞ 통합 설계는 어차피 주입을 **통화당 N회**로 바꾸므로(15분 6회) 이 결함은 설계상 사라진다.
  하지만 "사라졌다"가 아니라 **회귀 테스트로 못박는다** — 얹힌 문구 목록을 단언한다.

## 1. 설계

### 1-1. arm 을 세우는 근거 3층 (우선순위)

```
① 선제 arm   : prompt_token_count >= ARM_RATIO(0.85) × LIVE_CTX_TRIGGER_TOKENS
② 사후 감지  : prompt 가 직전 최고치 대비 급감(압축이 이미 일어남) → 보정 arm
③ 시간 폴백  : 마지막 주입 이후 max_gap 경과 (usage 가 아예 안 와도 도는 최후 층)
```

**왜 선제(①)가 본체인가.** 압축 **직전**에 얹은 요약은 컨텍스트 최신단에 있어 그 압축을
반드시 살아남는다. 압축을 감지한 **뒤** 주입하면 "이미 잊은 채로 1~2턴"이 뜬다.
②는 유저가 침묵해서 ①의 arm 이 얹히지 못한 채 압축이 지나간 경우의 보정이다.

**⛔ ③은 "R5 안전망"이 아니라 Free 5분 통화의 정규 경로다.**

여기가 이 설계에서 가장 잘못 읽히기 쉬운 곳이다. 마스터플랜 §5 는 "트리거를 시각 비율에서
압축 신호로 **교체**"라고 썼지만, 그대로 교체하면 **Free 5분 통화가 재접지를 통째로 잃는다.**

| 통화 | 최대 컨텍스트 | 압축(트리거 16k) | ①② 신호 | 재접지 |
|---|---|---|---|---|
| Free 5분 | 약 11,000 | **영영 안 걸림** | **영영 안 뜸** | ③이 없으면 **0회** |
| Pro·Max 15분 | 16k 초과 | 걸림 | 뜸 | ①②③ 모두 |

근거는 단계 4 논증에서 확정한 사실이다 — 5분 통화의 최대 컨텍스트는 약 11,000 토큰이고
압축 트리거는 16,000 이라, **지금까지 어떤 통화에서도 압축이 발동한 적이 없다**
(`docs/20260805_1830_압축-트리거-하향-논증.md` §1).

그래서 이 설계에서 압축 신호는 **교체가 아니라 추가**다: 시간 간격이 기본 층이고, 압축
신호는 그 위에 얹혀 "15분 통화에서 압축 시점에 맞춰 한 번 더" 넣는다. 부수적으로
`usage_metadata` 가 아예 안 오는 환경(필드 미제공·모킹 세션·SDK 변경)에서도 ③이 그대로
돌아 재접지가 사라지지 않는다(R5).

**임계를 통화 길이별로 스케일하지 않는 이유**: ①의 임계(0.85 × trigger)를 5분 통화에 맞춰
낮추자는 안이 있을 수 있는데, 그러면 **오지 않을 압축을 예고하는 신호**가 된다(11k 통화는
압축이 안 걸린다). 5분 통화에 필요한 건 압축 예고가 아니라 그냥 주기적 재접지이고,
그건 ③이 이미 정직하게 한다. **길이별로 달라져야 하는 것은 임계가 아니라 간격**이고,
`_reground_gap_s` 가 `call_duration_s` 를 받아 그 일을 한다.

`max_gap = clamp(call_duration_s / 2.5, 120, 240)`
- 5분(300s) → 120s → 시간 폴백만으로 2회 = **현행(0.5·0.8 지점 2회)과 실질 동일**
- 15분(900s) → 240s → 시간 폴백 3회 + 압축 신호 arm → 합계 ≈ 6회(0.40회/분, 5분과 동일 빈도)

### 1-2. 주입 내용 — 사이드카는 문장을 만들지 않는다

주입 텍스트는 **코드가 조립**한다(`persona_prompt` 의 "LLM 생성 0, 순수 조립" 규율).
사이드카는 서버가 준 **번호 목록에서 번호를 고르고** 짧은 슬롯 값만 돌려준다.

```
서버 → 사이드카 : 항목 목록(1. 안녕하세요 2. -고 싶다 …) + 최근 전사 꼬리
사이드카 → 서버 : {mode, covered: [1,3], topic: "여행 계획"}      ← 문장 없음
서버(코드)      : [제어태그] + 캐릭터 리마인더 + "1·3번은 이미 다뤘다" +
                  "화제는 여행 계획" + "먼저 작별하지 마라" 조립
```

사이드카가 죽거나 느리면 **현행 문구(캐릭터 리마인더 / 대화 지속 리마인더)로 폴백**한다.
재접지가 사라지지 않는다(R5).

### 1-3. 모드는 서버가 sticky 로 고정

`state.call_mode` 를 서버가 통화 시작 시 결정한다(study_items 있으면 `study`, 없으면 `chat`).
사이드카가 다른 모드를 줘도 **전사에 실제로 존재하는 인용**으로 명시적 전환이 증명될 때만
교체한다(AI 는 증인, 코드가 심판 — 레벨 시스템 관통원칙 ①과 같은 규율).
→ 압축이 통화 초반을 삼켜도 **모드는 사이드카 없이도 보호된다.**

### 1-4. ⛔ 최대 신규 위험과 그 방어

사용자가 "이제 그만할래요"라고 한 걸 사이드카가 슬롯에 담고, 서버가 그걸 **다시 컨텍스트에
주입**하는 경로. 태그를 분리해도 **어휘만으로 같은 일이 난다**(call 683: 재접지 30초 뒤 작별).

**방어는 프롬프트가 아니라 코드다.** 조립 직전에 종료 어휘 denylist
(`종료·마무리·작별·끝내·그만·안녕히·bye·goodbye`)를 걸어 **걸린 원소만 버린다**.
회귀 테스트는 적대적 페이로드(`topic="이제 그만할래요"`)를 넣어 결과 문자열에 안 나오는지 단언.

또 하나: 통합 주입은 약 250 토큰으로 **사용자의 한마디보다 크다.** 파트 맨 앞에
"학습자가 방금 한 말에 **먼저** 반응하고"가 없으면 비버가 유저를 무시하고 주입 텍스트에
응답한다(문맥 없는 화제 전환). 조립 템플릿의 첫 문장을 이것으로 고정한다.

## 3. 테스트 (마스터플랜 §6 판정 준수)

재접지 테스트 4건은 **폐기가 아니라 계약 이전**이다 — 기계는 바뀌어도
"1회성이 아닌 N회 · `turn_complete=False` · 완결 턴 파이프로 안 샘 · 종료 가드"는 그대로 필요.

| 신규 테스트 | 무엇을 못 박나 |
|---|---|
| `test_five_minute_call_still_regrounds_without_any_compression` | ⛔ **Free 5분 회귀.** 압축 임계에 안 닿는 것을 전제로 단언하고, 그래도 120s 간격으로 2회 얹히며 3회째는 안 얹힌다 |
| `test_arm_fires_before_compression_not_after` | 압축 임박(0.85×trigger)에서 arm — 압축 **전에** |
| `test_compression_detected_from_prompt_drop` | 16k→12k 급감을 압축으로 세고, 800 토큰 요동은 안 센다(미탐/오탐 양쪽) |
| `test_late_reminder_actually_attaches_not_just_arms` | §0-2 결함 회귀 — 통화당 2회 이상 **얹힌다**(arm 만이 아니라) |
| `test_reground_survives_session_swap_without_flooding` | 스왑 후 횟수·간격이 상태로 유지된다(폭주도, 소실도 없다) |
| `test_brief_drops_closing_vocabulary_slots` | 적대적 슬롯("이제 그만할래요")이 조립 결과에 안 나온다. 걸린 원소만 버린다 |
| `test_brief_leads_with_react_to_user_first` | 브리프 앞머리가 "유저에게 먼저 반응" |
| `test_mode_is_sticky_unless_quote_is_verified` | 인용 없는/환각 인용 모드 전환은 기각 |
| `test_reground_sidecar_failure_keeps_default_brief` | 사이드카가 죽어도 기본 문구가 얹힌다(R5) |
| `test_close_wins_over_reground_arm` | 종료 구간·상한 초과에서는 arm 하지 않는다 |
| 기존 `test_reground_skipped_near_close` | 그대로 통과해야 한다(종료 오염 방지) |
