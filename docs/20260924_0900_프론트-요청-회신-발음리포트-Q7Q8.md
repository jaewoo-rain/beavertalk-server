## 1. ✅ `call_date` · `call_id` 추가

```jsonc
// GET /calls/{call_id}/pronunciation-report → sessions[] 각 항목
{
  "label": "오늘",          // 종전 그대로 (구버전 앱 호환)
  "date": "9/23",           // 종전 그대로
  "sentences": 1,
  "score": 96,
  "delta": 4,
  "call_date": "2026-09-23T15:41:36.771138+00:00",  // ⭐ 신규 — UTC, tz 표기 포함
  "call_id": 1681                                    // ⭐ 신규
}
```

- `call_date` 는 **이력 행 원본 그대로**입니다. `label`·`date` 가 갖고 있던
  `or datetime.now()` 폴백을 **타지 않습니다** — «없음» 을 «지금» 으로 위조하지 않습니다.
- `label`·`date` 는 **안 건드렸습니다.** 지적하신 UTC 뭉갬·한국어 「오늘」 고정은 그대로 남아
  있으니, **`call_date` 가 있으면 그걸 쓰시고 `label`·`date` 는 무시**하시면 됩니다.
  (구버전 앱이 아직 그 문자열을 쓰고 있어 서버에서 못 바꿉니다.)
- 지적하신 `date` 형식 불일치(스키마 주석 「12월 21일」 vs 실제 `9/23`)는 **주석이 틀린 것**이었고,
  이제 앱이 `call_date` 로 직접 그리므로 형식을 맞추지 않았습니다.

## 2. ⛔ 「문장 0 · 점수 0」 — 앱 결함이 아니라 **서버 결함이었습니다**

### 원인
`recent_calls`(최근 5세션)가 **`call_type = 'chat'` 인 통화만** 골랐습니다.
지금 학습의 주력 경로인 **표현학습(`expression`)·프리토킹(`freetalk`)이 발음 이력에서 통째로
빠져** 있었습니다. 옛 `normal` → `chat` 개명(C3) 때 이 필터를 같이 못 바꾼 잔재입니다.

### 통화 1681 실측 (요청하신 확인 — 운영 DB 조회)

`1681` = `member_id=88` · **`call_type='expression'`** · `status='done'` · 활성 문장 1개 ·
복습 8회(그중 counted 5) · `evaluation.total_score = 96`.

| | 최신 5줄 (`member_id=88`) |
|---|---|
| **옛 필터 `= 'chat'`** | 1685(문장 0·점수 —) · 1682(0·—) · 1677(0·—) · 1676(0·—) · 1590(1·—) → **1681 없음** |
| **새 필터 `<> 'level_test'`** | 1685(0·—) · 1682(0·—) · **1681(1·96)** · 1680(0·—) · 1678(0·—) → **1681 있음** |

⇒ 앱이 본 「최신 줄 문장 0 · 점수 0」은 **통화 1681 이 아니라 통화 1685(`chat`, 문장 0)** 였습니다.
방금 복습한 1681 은 목록에 **들어오지도 못했습니다.** 앱 렌더링은 정상이었습니다.

### 수정
`call_type != "level_test"` 로 바꿨습니다 — **학습 달력(`calendar_calls`)과 같은 기준**입니다.
같은 잔재가 있던 `scored_call_ids`(마이페이지 「최근 N세션 평균」)도 같이 고쳤습니다.

⇒ **배포 후 첫 조회부터 표현학습·프리토킹 통화가 이력에 나타납니다.** 과거 통화도 소급됩니다
(데이터를 새로 쓰는 게 아니라 조회 필터만 바뀌므로 백필 불요).

### ⛔ 그리고 여기서 결함이 하나 더 나왔습니다 — `score` 가 「없음」과 「0점」을 구분 못 했습니다

위 표에서 보듯 **점수 없는 통화가 실제로 훨씬 많습니다**(통화만 하고 발음 챌린지를 안 누른 경우).
그런데 서버가 그걸 **`score: 0` 으로 뭉개서** 보내고 있었고, `delta` 를 그 0 기준으로 계산했습니다.

`member_id=88` 실측을 그대로 계산하면:

| 세션(오래된순) | 1678 | 1680 | **1681** | 1682 | 1685 |
|---|---|---|---|---|---|
| 실제 | 점수 없음 | 점수 없음 | **96점** | 점수 없음 | 점수 없음 |
| 종전 `score` | 0 | 0 | 96 | 0 | 0 |
| 종전 `delta` | — | 0 | **+96** | **−96** | 0 |

⇒ 화면에 **「96점 → 0점, 96점 하락」** 으로 그려집니다. 실제로는 그냥 발음 챌린지를 안 누른 것입니다.
Q7(필터)을 고치면 표현학습 통화가 이력에 들어오면서 **이 줄이 훨씬 많아지므로**, 같이 고쳤습니다.

**수정**: `score` 를 **nullable** 로 바꿨습니다 — 점수 없는 세션은 `null` 입니다(키는 그대로 옵니다).
`delta` 는 **양쪽 다 점수가 있을 때만** 계산하고, 점수 없는 세션은 비교 사슬을 끊지 않습니다.

> ⭐ **구버전 앱은 안 깨집니다** — 확인했습니다.
> `lib/screens/home/learning_summary.dart:16` 의 `_asInt(null)` 은 `0` 을 돌려주므로
> 구버전은 지금과 **똑같이** 동작합니다. 신버전만 `null` 을 보고 「—」 로 그리면 됩니다.
> `delta` 는 앱이 **이미** null 을 「—」 로 처리하고 있습니다(같은 파일 — 「"no previous
> session" is not "no change"」). `score` 에도 같은 규칙을 적용해 주세요.

## 3. 같은 화면에서 서버가 추가로 고친 것 (요청서엔 없던 건)

| 건 | 증상 | 수정 |
|---|---|---|
| **통과 수 2배 부풀림** | 현지인 표현 짝이 분모·분자에 같이 들어가 「N개 중 M개 통과」가 실제의 2배 | 통과 집계는 **기본 문장만**(`kind is null`) 셉니다. 평균 점수(`overall`·`pronunciation`·`fluency`·`rhythm`)는 `/result` 와 같게 **짝 포함** 유지 |
| **`kind` 노출** | 앱이 짝 문장을 구분할 수 없었음 | 발음 리포트 문장에도 `kind` 추가(기본 문장은 **키 자체가 빠짐**) |
| **`GET /calls/{id}` 순서·필드** | 지난 통화 상세가 `/result` 와 순서가 다르고 `kind`·`nuance`·`paired_sentence_id` 가 없었음 | `/result` 와 **같은 헬퍼**로 같은 순서(기본→그 짝) · 세 필드 추가 |

> `GET /calls/{id}` 의 세 필드도 **없으면 키가 빠지는** 종전 규약 그대로입니다.
> ⚠ **북마크 목록(`GET /members/me/bookmarks`)은 종전과 동일** — `kind`·`nuance` 만 오고
> `paired_sentence_id` 와 순서 보장은 **없습니다**. 통화와 무관한 문장 단위 목록이라 짝의
> 「부모」가 그 목록에 없을 수 있어서입니다(앱이 존재하지 않는 id 를 찾게 됩니다).
