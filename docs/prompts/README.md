## §2. 두 엔진의 차이 (프롬프트 관점)

|  | Live (`call_session`) | 캐스케이드 (`cascade_session`) |
|---|---|---|
| 엔진 | Gemini Live 네이티브 오디오 | STT → Gemini 2.5 Flash(텍스트) → TTS |
| system_instruction | 세션 시작 시 **1회** 주입, 컨텍스트에 상주 | ⭐ **매 턴 재전송**(`generate_content_stream` 을 턴마다 새로 연다) |
| ⇒ 프롬프트 길이의 의미 | 드리프트 요인(비용은 간접) | **턴당 입력 토큰 = 직접 원가** |
| 감정 태그 | ⛔ **절대 켜지 마라** — 모델이 태그를 소리로 읽는다(걷어낼 자리가 없다) | ✅ 서버가 걷어내고 TTS 스타일로 변환 |
| 언어 마커 | ❌ 불필요(모델이 직접 발음) | ✅ **필수** — 구간별로 그 언어 음성을 고른다 |
| 체크판·이력 재료 | ✅ 전부 주입 | ❌ **하나도 안 넘긴다**(§6 미해결) |
| 재접지 | ✅ 중반·후반·압축트리거 | ❌ 없음 |
| 레벨테스트 | ✅ 자동 라우팅 | ❌ 레벨 미확정도 `call_type=normal` 강행 |
| 응답 길이 | 상한 없음(문구는 기본 4문장) | `CASCADE_LLM_MAX_SENTENCES` 가 **문구와 강제를 같이** 만든다 |

**⭐ 캐스케이드만 고치는 두 가지 안전한 통로** (Live 를 안 건드린다):
1. **호출부 인자** — `cascade_session._system_instruction()` 에 넘기는 값
2. **옵트인 블록** — `_EMOTION_TAG_RULE` · `_LANGUAGE_MARKER_RULE`

⛔ 그 밖(규칙 1~5 본문·페르소나·선톡·종료 시드)은 **Live 와 공유**다. 건드리면 Live 통화가 같이 바뀌고
동결 스냅샷이 깨진다. 스냅샷 통과 = **Live 무영향의 자동 증명**이니, 깨졌다면 공용 자산을 건드린 것이다.

## §3. 튜닝 원칙 (노션 결정 로그에서 추출)

### 원칙 1 — 톤은 캐릭터에 반납한다
프롬프트에 **부사·예시 대사를 쓰지 않는다**("따뜻하게"·"부드럽게"·"친절히"·"이렇게 말해요").
캐릭터는 DB(`role`/`personality`)에 있고 제각각이다 — 톤을 처방하면 **츤데레·독설 캐릭터가 다정한 선생으로
뭉개진다.** 대신 `반응(칭찬·핀잔 등)은 네 캐릭터대로` 처럼 **캐릭터에 위임**한다.
> 2026-07-24 에 이 한 가지로 페르소나·규칙1·규칙4·체크판 블록 4곳을 고쳤다.

### 원칙 2 — 금지 예시는 씨앗이 된다. 전진 지시로 쓴다
`"슬슬 끊자" 같은 말 금지` 라고 적었더니 비버가 **그 예시를 그대로 뱉었다**(call 782).
"하지 마라" 대신 **"대신 이걸 해라"**로 쓴다.
⚠ 단 **일반화하지 마라** — 금지 예시가 없고 "안 하기"가 곧 올바른 행동인 부정 지시
(메타 발언 금지·자문자답 금지·과교정 금지)는 그대로 두는 게 맞다.

### 원칙 3 — 중복은 한 규칙에 위임한다
같은 말이 두 곳에 있으면 **어느 게 진짜인지 아무도 모른다.** 설명 언어는 규칙3, 교정 톤은 규칙4가 소유.
숫자도 마찬가지 — 손으로 쓴 값이 두 곳에 있으면 안 된다(응답 길이는 `_max_sentences()` 하나에서 나온다).

### 원칙 4 — ⭐ 예시가 곧 규칙이다
모델은 규칙과 예시가 다르면 **예시를 따른다.** 프롬프트를 고칠 때 **규칙만 고치고 예시를 안 고치면
아무것도 안 고친 것**이다. 2026-08-16 에 이 계열로 2건을 찾았다(§8).
⚠ 리터럴 예시는 **특정 언어 짝에서만 맞다.** 멀티랭귀지에서는 `{target}`/`{locale_label}` 로 쓴다.

### 원칙 5 — 개념을 지워야 수단이 사라진다
종료 메커니즘을 지시문에서 가르치면 모델이 그걸 **실행 수단으로 쓴다.** 세 번 당했다:
리터럴 노출 → 낭독 종료(706) / 난수 접미 → 난수까지 복사(852) / 성질만 서술 → **없는 태그 발명**(870).
흉내낼 원본을 지우는 걸로는 부족하다. **모델이 수단을 모르면 그 수단을 못 쓴다.**

### 원칙 6 — 프롬프트로 부탁하지 말고 파라미터로 시켜라
"또박또박"이 한국어 발화 속도의 절반을 먹고 있었다. **속도는 `speaking_rate` 가 맡는다** —
문구와 파라미터가 싸우면 어느 게 진짜인지 못 가린다.

### 2026-08-22 — 종료 시드에 **우선순위**를 적는다 (무음 종료)

⭐ **두 통화가 같은 문장을 가리킨다.** 비버는 규칙을 어긴 게 아니라 **지켰다**:

> 규칙 3 `[공부 모드 — 지금 항목으로 착지]` 끝문장(옛): "화제는 네가 고르는 게 아니라 **지금 항목이 정한다**."

|---|---|---|
| 1284 t11 | 꽃/피우다 | "혹시 꽃을 피우는 걸 본 적 있어?" |
| 1286 t9·t11 | 피우다 | "Do you like gardening?" → "어떤 꽃을 제일 좋아해?" |

비버 입장에선 규칙 준수다. 앞 조건("그 표현을 넣어야 답할 수 있는")은 흘렸다.
⇒ 결함은 **착지의 판정 기준이 '화제'로 적혀 있는 것**이다. 기준을 **학습자의 산출**로 옮긴다.

   ⛔ 한 축만 보면 안 된다 — 요청어만 보면 위 문장이 통과하고("want"), 주제어만 보면

2. **chat 판에 도착점 한 줄**(`build_reground_brief`) — "학습자가 이번 턴에 답할 것은 그

    1) 지시문 재배치 — **규칙(정적) 앞 · 항목 목록(동적) 뒤.** 목록이 두 번째 줄이면 표시가 바뀔 때마다 접두
       100자부터 달라진다. 정적 접두가 판정마다 같아야 implicit caching 이 걸릴 여지가 생긴다(효과는 측정 몫,
       손해 없음). 서버-사실 문장도 표시 유무와 무관하게 **같은 문구**로 고정했다. 시험이 «표시 유무로 접두가
       안 달라진다» 를 잠근다
    2) 상한 1.2초 → **2.0초**(`EXPR_FINAL_JUDGE_TIMEOUT_S`) — 조각2 경합 최악 3초 중 여유 1초. 실측점이
       «6.2k = 1.2초» 하나뿐이라 6.4k 가 1.2초 안에 들 근거가 없다. 마지막 퀴즈 유실(확정)이 조각2 재드릴
       위험(여유 1초)보다 비싸다. 상수 주석의 옛 근거(요약 소요 유추)는 지웠고 이 수치를 적었다
    3) 계측은 이미 있다(«마지막 판정 %.0fms») — **첫 실통화에서 그 줄을 보고 다시 정한다**
**P2** 겹침과 이번 구간 사이에 **경계 표시가 없었다.** 겹침이 회차 중간에서 시작하면 창이 «복창(U)·승인(B)»
부터라 공개(B)가 창 밖 ⇒ 판정기가 «(오답) 항목을 스스로 냈고 승인받았다, 공개 없음» 으로 읽어 **앵무새가
통과로 승격**. 새는 방향이 통과뿐(강등은 서버가 막는다)이라 더 위험하다. ⇒ keep_from 자리에 구분선
`―― 여기부터 이번 구간 (위는 문맥) ――`(`EXPR_WINDOW_BOUNDARY_LINE`, 겹침이 실제로 들어갔을 때만) + 지시문
«문맥 구간에서 **시작된** 회차는 판정하지 마라 — 이미 판정됐다. 문맥 구간에서 (오답) 항목이 다시 보여도 새
회차가 아니다.»
**P2(잠복)** 1차 고침 «절단이면 커서 불전진» 은 커서 0 에서 절단 → 다음도 since 0 → 창은 앞에서만 커지므로
잘린 머리는 **어디에도 다시 들어가지 않고** 그 뒤 모든 판정이 12k 최대 입력 → 마지막 판정 확정 타임아웃.
(«다음 판정에 다시 들어간다» 경고 문구는 거짓이었다.) ⇒ 절단이어도 커서는 «본 끝» 까지 간다 — 손실을
[커서, first_seen) **그 한 번**으로 한정하고 경고 로그에 «세그먼트 N~M 미판정» 을 적는다. ⚠ bt-back 은
«first_seen 까지» 라 했는데 first_seen..끝은 이 판정이 **다 봤으므로** 본 끝까지 가는 게 맞다 — first_seen 에
두면 다음 판정이 같은 12k 를 다시 읽어 후과 ②가 그대로 남는다. 도달성: 1397 = 316초에 3.4k ⇒ 12k ≈ 16분,
5분 소켓에선 못 채운다 — 잠복이지만 싸서 고쳤다.

#### ⚠ 알고 가는 것 — «(통과)» 는 되돌릴 길이 없다
목록의 **(통과)** 표시는 앞선 LLM 판정이다. 지시문(«passed 를 failed 로 되돌리지 마라») · 서버 단조성
(`_apply_expression_progress`) · DB(`quiz_passed_at` 은 NULL 일 때만 채운다) — **3겹**이 전부 한 방향이라, 한 번
잘못 찍힌 통과는 이 통화 안에서도 다음 통화에서도 고쳐지지 않는다. **비대칭**이다: (오답)은 다음 통화 선별이
그 항목을 다시 내서 자연 치유되지만, (통과)는 선별에서 빠져 다시 나오지 않는다. 이건 결함이 아니라 **전제**다
(D12 강등 없음) — 그래서 통과 판정 쪽 규칙(공개 뒤 복창 = failed · 문맥 구간 회차 제외 · 격식 독립)이 무겁다.
잘못 찍힌 통과를 고치는 길은 사람 손(DB)뿐이다.

## §9. 통화 후 볼 로그 (계측은 이미 붙어 있다)

| 로그 | 무엇을 알려주나 |
|---|---|
| `마커 fixed=N` | 언어 마커가 몇 번 뒤집혔나. **0 이면** 애초에 안 뒤집히고 있었다는 뜻(가설 기각) |
| 감정 태그 개수(`read_emotion_tags`) | 모델이 **1개만** 내면 프롬프트 몫, **여러 개** 내면 우리가 뒤를 버리는 것 → 문장별 감정을 만들지 판단 |
| `버린태그:` / `라벨 낱말로 시작` | 대괄호 라벨 충돌이 아직 사는지 |
| `truncated` | 응답 길이 문구와 토큰 상한이 부딪히는지 |
| `tts_fallbacks=N` | 통화 도중 목소리가 몇 번 바뀌었나(429 폴백) |

dev 도구: `scripts/dev_inspect_call.py <call_id>` (전사·문장·증거·레벨 덤프)

## 부록. 프롬프트 전문 뽑기

⚠ 새 스크립트 파일을 만들지 않는다 — **사본은 낡는다.** 필요할 때 이걸 붙여 실행한다.
`core/persona_prompt.py` 는 표준 라이브러리만 쓰므로 **의존성 없이 돈다.**

```python
# 캐스케이드 통화에 실제로 들어가는 system_instruction 전문
import sys, pathlib
sys.path.insert(0, r"<프로젝트 루트>")
from core.persona_prompt import build_system_instruction, seed_opening

text = build_system_instruction(
    role="한국어를 가르치는 다정한 비버 선생님",
    personality="친근하고 밝다. 짧게 말하고 자주 되묻는다.",
    level_profile="아주 쉬운 단어와 짧은 문장으로 말한다.",
    locale="en", interests=["여행", "K-pop"], name="Sam",
    lang_band="beginner", target_language="한국어", max_sentences=4,
    language_marker=True,                                   # ← 캐스케이드 전용
    emotion_tags=("neutral","happy","surprised","sad","angry"),  # ← 캐스케이드 전용
)
# Live 일반 통화를 보려면 위 두 줄을 빼고, 체크판을 보려면 study_items=[...] 를 넣는다.
# 콘솔 한글이 깨지면 print 하지 말고 파일로 쓴 뒤 읽는다:
pathlib.Path("prompt.txt").write_text(text, encoding="utf-8")
```

고치기 **전후로 각각 뽑아 `diff -u` 하면** 의도한 줄만 바뀌었는지 바로 보인다.
