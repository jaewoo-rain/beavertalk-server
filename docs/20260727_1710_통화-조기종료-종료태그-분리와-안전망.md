# 통화 조기 종료 — 종료 태그 분리 + 자기낭독 안전망

작성 2026-07-27 17:10 · 대상 `core/persona_prompt.py`, `domains/learning/realtime/call_session.py`

## 1. 증상

비버가 서버 종료 신호 없이 혼자 작별 인사를 하고, **통화는 안 끊긴 채로 남는다.** 사용자는
"여보세요", "왜 꺼? 내?" 하며 수십 초를 기다리다 직접 종료 버튼을 누른다.

실측 — `call_id=706`(2026-07-27 07:06:54 시작, 135s 만에 사용자가 끊음):

```
07:06:55  통화 시계 시작                       ← CALL_DURATION_S=300 → 종료 시드는 t=300s
07:08:14  BEAVER[t15]: "[시스템]" 종료          ← 프롬프트 문구 낭독
07:08:17  BEAVER[t17]: 잘했어요! 다음에 또 통화해요!
07:08:24  BEAVER[t19]: Bye! See you next time!
   (47초간 통화 유지 — 서버는 종료 절차를 시작하지 않음)
07:08:50  USER[t20]:  여보세요.
07:09:03  USER[t24]:  왜 꺼? 내?
07:09:10  클라 연결 종료                        ← 사용자가 직접 끊음
```

로그에 `normalcall: 종료 시드 주입` **없음**. 재접지·무음 넛지도 미발동. 즉 서버는 아무것도
주입하지 않았다.

7일치 로그 기준 `app-api`·`demo-api` 양쪽에서 **최소 7건**. 7/26 `call_id=683` 은 인과가 더 명확하다:

```
17:06:33  재접지 얹기(유저 발화 턴)            ← "[시스템] (이 지시문…" 주입
17:07:02  BEAVER[t29]: [시스템] 종료 신호가 왔습니다. 대화를 마무리…
17:08:00  저장 완료 duration=240s              ← 300s 전에 끝남
```

## 2. 원인 — 결함 2개

### 결함 A. 제어 태그 충돌 (오독)

`_RULE_CLOSE_PROTOCOL` 이 **접두어 `[시스템]` 자체를 종료 트리거로 정의**한다.

> `"[시스템]" 신호가 오면 그때 마무리`

그런데 서버가 `[시스템]` 으로 보내는 제어 메시지는 5종이고, 그중 종료는 2종뿐이다.

| 위치 | 용도 | 접두어 |
|---|---|---|
| `call_session._CLOSE_SEED` | 종료(일반) | `[시스템]` |
| `persona_prompt.CLOSE_SEED_LEVELTEST` | 종료(레벨테스트) | `[시스템]` |
| `persona_prompt.build_reground_reminder` | 캐릭터 재접지 | `[시스템]` |
| `call_session._NUDGE_SEED_1/2/_LEVELTEST` | 무음 넛지 3종 | `[시스템]` |

**재접지·넛지가 종료 신호로 읽힌다.** 넛지는 본문에 "작별하지 말고"라고 써놨는데도 접두어가 이긴다.

### 결함 B. 자기낭독 → 자기 트리거 (자기충족 루프)

제어 시드는 전부 `role="user"` 텍스트 턴으로 들어간다(`core/gemini_live.py:154`). 모델에겐
system_instruction 이 아니라 **대화 채널**이다 — "학습자가 그렇게 말했다"와 구분되지 않는다.
한국어 학습 통화에서 상대가 한국어 문장을 말하면 따라 읽는 게 모델에겐 자연스럽다.

`call_id=706` 은 직전 3턴이 낭독 드릴이었다:

```
BEAVER[t11]: … "어서 오세요!" One more time!
USER  [t12]: one more time.        ← 사용자가 비버 말을 그대로 따라함
BEAVER[t13]: 어서 오세요.
USER  [t14]: 어서, 들어오세요.
BEAVER[t15]: "[시스템]" 종료        ← 낭독 모드에서 컨텍스트의 다음 인용문을 읽음
```

한번 뱉으면 그 출력이 자기 컨텍스트에 남아 다음 턴에 종료 신호로 읽힌다. **서버 주입 0이어도
종료 발화가 난다.**

규약 문단이 리터럴 `"[시스템]"` 을 따옴표째 3회 반복 노출해 낭독 후보로 진열한 것도 확률을 키웠다.

### 왜 "읽지 마라"로 못 막나

실측 로그에 이런 게 있다.

```
BEAVER: [시스템] (낭독 금지.) 오늘 대화는 여기까지. 어려운 질문을 하던 중이었어도…
```

**낭독 금지라고 쓴 문장을 통째로 낭독했다.** 지시 기반 방어는 실패가 증명됐다.

### 부수 결함 C. 역방향 안전망 부재

종료 파이프는 서버 상태(`should_close` / `close_seed_sent`)로만 돈다. 비버의 작별 발화는 서버에게
평범한 오디오 턴이라 아무 영향이 없다. 이건 설계 의도다(모델이 멋대로 못 끊게 — R4). 문제는
**모델이 규약을 어겼을 때 되돌리지도, 마무리하지도 않는다**는 것. 그래서 死구간(706 기준 47초)이 생긴다.

## 3. 수정안

### 3-1. 종료 태그 전용화 + 통화별 난수 (결함 A, B 완화)

- 종료 전용 태그를 도입한다. 기본 `[통화종료]`, 런타임은 통화마다 `new_close_tag()` → `[통화종료:9f2a]`
- 종료가 **아닌** 제어(재접지·넛지·재개)는 `[안내]` 접두어로 이전
- 선톡 `[통화 시작]` 은 이미 분리돼 있어 유지
- `build_system_instruction` / `build_leveltest_instruction` 에 `close_tag` 키워드 인자 추가.
  기본값 `[통화종료]` → **스냅샷은 기본값 기준으로 안정**, 순수 함수 규율 유지(난수는 호출자가 주입)

난수의 이점은 모델이 태그를 우연히·낭독으로 재현할 확률을 없애는 것. 프롬프트에 적혀 있으니
낭독 자체가 불가능해지진 않지만, `[시스템]` 같은 일반명사보다 재현이 훨씬 어렵다.

### 3-2. 규약 문단 리터럴 노출 축소 (결함 B)

`_RULE_CLOSE_PROTOCOL` 에서 태그 리터럴을 **정의 1회**만 노출하고, 이후는 "그 신호"로 지칭.

### 3-3. 서버 안전망 — 태그 누출 검출 → 대화 재개 (결함 B, C)

1~2 를 뚫어도 死구간이 안 생기게 하는 **유일하게 모델에 의존하지 않는 방어**.

- 검출: 비버 턴의 **누적** 출력 텍스트(`cur_beaver_text` 합본)에 제어 태그 패턴이 있으면 누출로 판정
  - out_tr 은 토큰 단위로 쪼개져 온다(`[시스템]` / ` 통화가`). 청크 단위 검사는 놓치므로 누적본을 본다
  - 패턴 `\[\s*(시스템|안내|통화종료|통화 ?시작)[^\]]*\]` — 실측 7건 전부 매칭
- 조치: 그 턴의 `turn_end` 에서 `_RESUME_SEED`(`[안내]` 접두)를 주입해 대화를 이어붙인다
- 가드: `should_close` / `close_seed_sent` 면 주입 안 함(정상 종료 중엔 되돌리면 안 됨),
  통화당 최대 `_RESUME_MAX=2` 회(무한 루프 방지)
- 저장 정화: `_flush_beaver_segment` 에서 태그를 제거해 통화후 분석·문장 추출 오염 방지
  (자막 마스킹은 하지 않는다 — 청크가 쪼개지면 부분 마스킹이 되어 더 이상해진다. 오디오는 이미 나간 뒤라 실익도 없음)

### 3-4. 범위 밖 (이번엔 안 건드림)

- `role="user"` 주입 방식 자체의 대안(상황 서술체 등) — 실측 A/B 가 필요해 별건
- 작별 **문구** 검출(예: "Bye") — false positive 위험이 크고, 실측 7건 전부 태그 낭독이 선행했다
