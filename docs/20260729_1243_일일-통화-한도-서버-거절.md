# 일일 통화 한도 — 서버가 통화 시작을 거절한다

작성 2026-07-29 12:43 · 대상 `domains/learning/realtime`, `domains/learning/service/call_service.py`

앱팀 `2026-07-27_1756_과금모델-게이팅부재-캐릭터결제-우려사항.md` §2 후속.

## 0. 지시

> 일일 통화 제한부터 구현. 레벨테스트는 일일 통화 제한에서 **벗어난다**.
> 유저는 하루에 **레벨테스트 1회 + 일반 통화 1회**까지.

## 1. 현황 (코드 확인)

```
통화 시작(WS)에서 한도 검사        0건 — 아무것도 안 막는다
구독 여부(is_subscribed) 사용처    마이페이지 표시 1곳뿐
CallService.daily_status           세기만 한다. 거절 코드 없음
```

즉 **로그인한 모든 사용자가 무제한**이다. 통화 1건마다 Gemini Live·분석·TTS 원가가 나간다.

> ⚠ 앱팀 문서 §2.1 의 "통화 시간 제한 부재"는 **틀렸다**. `CALL_DURATION_S = 300`(5분) +
> 종료 시드 + 540s 백스톱이 이미 있어 **전원 5분에서 끊긴다**. 없는 건 "Free 5분 제한"이
> 아니라 "Pro 가 더 길게 쓰는 것"이다.

## 2. 설계

### 2-1. 한도 (콜타입별로 **따로** 센다)

| 콜타입 | 하루 한도 |
|---|---|
| `level_test` | 1 |
| `normal` | 1 |

둘은 서로의 한도를 깎지 않는다. 레벨테스트를 했어도 일반 통화 1회가 남는다.

### 2-2. 어디서 막나

`run_call` 안, **콜타입 라우팅 직후 · `create_call` 직전**. 이유:

- 한도가 콜타입별이라 **라우팅 결과를 알아야** 판정할 수 있다
- `create_call`(통화 행)·Live 세션 open 이 모두 그 뒤라 **거절 시 잔여물도 Gemini 비용도 0**

거절하면 `ServerError(code="DAILY_LIMIT", recoverable=False)` 를 보내고 소켓을 닫는다.

### 2-3. 하루 경계 = 클라이언트 타임존

서버가 UTC 로 고정하면 한국 사용자는 오전 9시에 날짜가 바뀐다. 기존 `daily_status` 가
이미 클라 `local_date` + `tz_offset_min` 을 받아 경계를 잡고 있으므로 **같은 방식**을 쓴다
(외국인 학습자라 타임존이 제각각이다 — 그게 그 API 의 설계 이유다).

`ClientStart` 에 `tz_offset_min: int | None` 추가. 미전송(구버전 앱)이면 **UTC(0)** 로 본다.

### 2-4. "통화했다"의 정의 — 기존 것을 그대로 쓴다

`has_call_in_window` 의 유효 통화 정의를 재사용한다:

```
call_date ∈ [로컬 자정, +1일)  AND  total_time >= 10s  AND  status in (done, analyzing)
```

**같은 정의를 쓰는 게 중요하다.** 홈 화면의 "오늘 통화함" 배지가 이 값으로 그려지는데,
한도 판정이 다른 정의를 쓰면 "배지는 안 했다는데 서버는 거절"하는 모순이 생긴다.

부수 효과(의도한 것):
- 연결만 하고 10초 안에 끊은 통화는 **소모되지 않는다** — 사고로 하루를 날리지 않는다
- 크래시로 `ongoing` 에 남은 통화도 소모되지 않는다

### 2-5. 판정은 SELECT 1회

`has_call_in_window` 에 `call_type` 필터를 더한다(기존 호출부는 기본값으로 무영향).
`create_call` 직전에 이미 DB 세션을 여는 지점이 있어 **왕복이 늘지 않는다**.

## 3. 안 하는 것 (범위 밖)

- **구독(Pro)별 한도 차등** — 구독 상품이 확정되지 않았다(앱팀 문서 §5). 지금은 전원 동일
  한도. 나중에 이 판정 함수 하나에 구독 분기를 넣으면 된다
- **통화 중 한도 도달 처리** — 시작 시점만 막는다. 이미 시작된 통화는 5분 시계가 끝낸다
- **분석 상세도 분기** — 별건

## 4. 남는 구멍 (알고 넘어갈 것)

10초 미만 통화는 소모되지 않으므로, **9초짜리 통화를 반복하면 무제한으로 Gemini 세션을
열 수 있다.** 세션 open 비용은 나간다.

지금 막지 않는 이유: 그걸 막으려면 `ongoing` 도 소모로 쳐야 하는데, 그러면 크래시 한 번에
하루가 날아간다. 실사용자 24명 규모에선 후자가 더 큰 손해다. 남용이 관측되면 "시간당 세션
오픈 횟수" 같은 별도 레이트리밋으로 잡는 게 맞다(한도와 다른 축).

## 5. 검증

- 콜타입별 독립 카운트(레벨테스트 1회 후에도 일반 통화 가능)
- 한도 초과 시 `DAILY_LIMIT` + 통화 행 미생성 + Live 세션 미오픈
- 10초 미만·`ongoing`·`failed` 통화는 소모 안 됨
- 타임존 경계(KST 자정 직후/직전)
- `tz_offset_min` 미전송 시 UTC 폴백
