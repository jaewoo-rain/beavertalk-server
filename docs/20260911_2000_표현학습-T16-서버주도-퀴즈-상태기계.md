## 0. 왜 (한 문단)
판정기 지시문에 «드릴 정답은 passed 가 아니다» 가 **명시돼 있는데도** 4통화 일관해서 드릴 첫 시도 정답이
passed 로 찍혔다(1404: 7/18 전부 이 유형). 비버 대본에 «퀴즈는 3·6·9번 직후에만» 이 있는데도 4통화 중
3통화가 6·7·10번째에 냈다 — 압축 전(55초)이었다. 둘 다 **LLM 이 세거나 구간을 가르는 일**이고, 세 번(T8·T14·T15)
고쳐도 남았다. ⇒ 세는 것과 구간 여는 것을 **서버가** 한다. 사장님 결정(2026-09-11): «배웠는가 → 서버가 퀴즈를
연다 → 그때만 맞췄는가». 레벨 시스템 관통원칙 ①(AI 는 증인, 판정은 코드)을 이 코스에도 적용한다.

## 2. 판정 — ⭐ QA 반영(fable P1-5): **passed/failed 는 서버가 직접 찾는다. LLM 은 STT 폴백만.**
창(open_seg..close)과 quiz_set 을 서버가 여니 옛 문자열 판정이 실패한 이유(드릴/퀴즈 못 가름·앵무새)가 없다.
항목마다 창을 순서대로 훑어 **먼저 나오는 사건**으로 확정(`_server_judge_quiz`):
```
U 에 표면형(템플릿 인식 quiz_judge.mentions) + V4 격식(keeps_formality)   → passed
B 에 표면형                                                                → failed(공개)
둘 다 없음                                                                 → 미판정 (침묵 ≠ 오답 — failed 로 바꾸지 않는다)
```
반말 산출(표면형은 있는데 격식 표지가 없음)은 **사건이 아니다** — 계속 훑는다(뒤에 공개가 오면 failed, 안 오면 미판정).
단조 규칙(passed → failed 되돌림 금지) 유지. 지연 0 · 비용 0. 이게 하네스 관찰 A·B·E·C 를 다 잡는다.

## 3. STT 폴백 — 미판정 항목에만 LLM (관통원칙 ①: LLM 은 제안, 코드가 확정)
하네스 M: 「이거 주세요」→「이거 지세요」 3/3 — 글자 대조만 쓰면 그 학습자는 영원히 통과 불가다. ⛔ 편집거리는 쓰지
않는다(가세요/계세요). 미판정 항목만 목록에 주고, 전사는 세그먼트 번호를 붙여(`B12:`/`U13:`) 넣는다. 스키마
`ExpressionQuizOut = {items: [{num, answer_seg}]}` — 문장 필드 없음.
서버 검증 3조건(`_verify_stt_fallback`) — 전부 참이어야 passed, 하나라도 거짓이면 미판정 그대로:
```
① answer_seg 는 창 안 U 세그먼트다
② 그 앞 창 안 B 세그먼트에 표면형이 없다(공개 없음)
③ 그 **다음** B 세그먼트에도 표면형이 없다(비버가 정정하지 않고 넘어갔다 = 소리를 들은 쪽의 증언)
```
통과하면 로그 `provenance=stt_fallback` — 하네스가 빈도·정확도를 잰다. 마지막 판정 상한 `EXPR_FINAL_JUDGE_TIMEOUT_S`(2.0s)는
**폴백 호출에만** 적용(서버 검색은 즉시). 폴백은 학습자 줄이 하나도 없으면 부르지 않는다.
- V2 = `quiz_judge.mentions` 는 **템플릿 인식**이다(bt-back 결정): 자리표시(◯◯ · 홀로 선 라틴 대문자 N/V/A)는 와일드카드,
  「이/가·을/를·은/는·와/과」 한 글자 교체는 선택, 「이에요/예요」 같은 다글자 교체는 (a|b), 대괄호 [없어요] 는 제거(주형만 인정 —
  「없어요」 로 답하면 미판정, 안전 방향). 고정 조각이 정규화 발화에 **순서대로** 있어야 참. 자리표시 없는 표면형은 기존
  낱말 경계 규칙 그대로. ⚠ covered 경로(`_note_covered_items`)와 **같은 함수**다 — 갈리면 covered 는 되는데 V2 는 안 되는
  항목이 생긴다. 「저는 ◯◯ 사람이에요」 가 부분문자열로는 영원히 covered 가 안 돼 큐 자체가 안 열리던 구멍을 이걸로 막았다.
- V4 격식(bt-back 확정, codex P1-3): 표면형 **마지막 어절의 종결 표지** — 요(어요·아요·예요·세요·주세요 전부) / 니다(습니다·ㅂ니다)
  / 십시오 / 죠. 그 표지가 학습자 발화의 **어느 어절 끝**에 있어야 참. 표지가 없으면(명사·반말 항목·자리표시 주형) 항상 참.

## 4. 비버 대본 (core/prompts/expression.py)
- `[퀴즈]` «언제» 줄을 교체: `퀴즈는 [안내] 이 «지금 퀴즈를 내라» 고 알릴 때만 낸다. 스스로 퀴즈·복습·테스트를 시작하지 마라. 알림이 오면 거기 적힌 표현들을 한 문제씩 내고, 끝나면 다음 새 표현으로 간다.` («어떻게» 아래 문장들은 그대로. «세 개» → «표현들» — 오답 재출제·꼬리 큐는 개수가 다르다. 옛 «3·6·9…»·꼬리 규칙 문장은 지웠다 — 세는 것은 서버 몫)
- 재접지 쪽지(build_expression_reground_brief)의 «다음에 다룰 것» 은 유지. 「아직 틀린 표현」 칸도 유지(오답 재출제 큐의 재료 확인용).
- 그 외 문장은 건드리지 않는다. README §8 결정 로그에 T16 한 줄.

## 7. 재측정 (harness-build 의 하네스)

## 9. 구석 (구현 때 놓치기 쉬운 것)
- 닫힘 조건 ①은 **열린 뒤(expr_quiz_open_seg 이후)에 추가된** 번호만 본다. 큐가 얹히기 전에 비버가 4번 표면형을 먼저 말해
  covered 가 4 가 된 경우, 그건 «새 항목 소개» 가 아니라 큐 이전 사건이다.
- 큐 arm 조건은 `>= 3*(seq+1)` — 두 개가 한꺼번에 covered 돼 3 을 건너뛰어도 큐가 빠지지 않는다. quiz_set 은 «아직 퀴즈에 안 오른 covered 앞 3개».
- 학습자 발화 없이 비버가 혼자 이어가면 얹을 자리가 안 온다 — 재접지와 같은 한계. 무음 넛지 경로에서 자리가 생기면 거기서 얹힌다(추가 배관 금지).
- 마지막 판정 상한 `EXPR_FINAL_JUDGE_TIMEOUT_S=2.0` 유지. 입력이 퀴즈 구간뿐이라 실측은 줄어들 것 — 로그 1줄로 확인.
