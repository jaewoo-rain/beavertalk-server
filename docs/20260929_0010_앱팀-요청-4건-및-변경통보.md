# 요청 1. ⭐ 만료된 구독 4건 — 「구매 복원」 1회 눌러 주세요

**가장 급합니다.** 지금 store 구독 4건이 만료 상태로 남아 있고, 그 회원들은 **서버가 혼자 복구할 수 없습니다.**

## 왜 서버 혼자 안 되나
§24 수정 전까지 서버가 **`purchase_token` 을 저장하지 않았습니다.** 스토어에 다시 물으려면 토큰이 필요한데, 그 4건은 토큰이 없습니다(추측으로 채울 수 없어 백필하지 않았습니다).

## 무엇을 하면 되나
해당 계정에서 **「구매 복원」을 한 번** 누르면 앱이 토큰을 실어 보내고, 서버가 그 자리에서

1. `end_date` 를 스토어 값으로 올리고(**한 방향만** — 내리지 않습니다),
2. 비어 있던 `purchase_token` 을 채우고,
3. `is_trial` 도 정정합니다.

⇒ **그 뒤부터는 자동 복구가 그 회원에게도 작동합니다.** 앱 코드 변경은 **필요 없습니다** — 이미 있는 버튼입니다.

## 신규 구매는?
처음부터 토큰이 저장되므로 아무 조치가 필요 없습니다. 앱을 켜면(상태 조회) 또는 **매시 20분(KST) 스윕**이 갱신을 반영합니다.

# 요청 2. §17 해지 사유 — 와이어 코드를 snake_case 로 변환해 주세요

서버 `POST /members/me/churn-reasons` 가 받는 값은 **5개 고정**이고 CHECK 제약으로 막혀 있습니다:

| Dart (`winback_survey.dart:12`) | 서버가 받는 값 |
|---|---|
| `expensive` | `expensive` ✅ 그대로 |
| `unused` | `unused` ✅ 그대로 |
| `missing` | `missing` ✅ 그대로 |
| **`otherApp`** | **`other_app`** ⛔ **변환 필요** |
| `other` | `other` ✅ 그대로 |

`otherApp` 을 그대로 보내면 **거절됩니다**(CHECK 위반). 보낼 때 snake 로 바꿔 주세요.

## 함께 보내는 값
- `subscribe_id` — 「어느 만료에 대한 답인지」. 앱 DTO 가 이미 파싱합니다(`subscription_status_dto.dart:17`). ⭐ 시각 문자열(`expiresAt`)이 아니라 **이 id** 로 보내 주세요 — 서버가 소유만 검증합니다(남의 구독 id 는 404)
- `offer_shown` — 윈백 오퍼를 보여줬는지
- 같은 (회원, 구독)으로 다시 보내면 **마지막 값으로 갱신**됩니다(재설치 후 다른 답을 골라도 최신 의사가 남습니다)

# 요청 3. ⭐ 알람 시간대 — 기존 알람에 `tz` 를 한 번 재전송해 주세요

## 지금 무슨 일이 벌어지고 있나
활성 알람 **11개** 중 **10개가 한국어가 아닌 회원** 것인데, 시간대가 비어 있어 **서울 기준으로 울립니다.**

⛔ 문제는 시·분이 아니라 **요일**입니다. 뉴욕 회원이 고른 「**월** 08:00」은 서울 월요일 08:00 = **뉴욕 일요일 19:00** 에 울렸습니다. 서버는 이번에 고쳤습니다(알람 시간대의 시·분·요일을 같이 계산).

## 무엇을 하면 되나
알람 생성·수정 시 **IANA 시간대 이름**을 실어 주세요 — `tz: "America/New_York"`.

- **위치 권한은 필요 없습니다.** 기기 시간대 설정값이면 됩니다
- **나라 코드는 답이 아닙니다** — 미국 하나에 시간대가 6개입니다
- `tz_offset_min` 도 받지만 **서머타임에 틀립니다.** `tz` 를 우선 보내 주세요(둘 다 보내면 `tz` 가 이깁니다)
- 범위 검사 추가됨: `tz_offset_min` 은 **−840~840**(±14시간) 밖이면 **422**

사용자가 알람을 수정하면 자동으로 채워지지만, **수정 없이도 한 번 재전송**해 주시면 기존 11개가 즉시 정상화됩니다. 안 하면 그 회원들은 알람을 직접 고칠 때까지 계속 서울 기준으로 받습니다.

## 서머타임 한 가지
봄에 건너뛰는 시각(그 지역 로컬 02:30 이 없는 날)은 **그날 울리지 않습니다.** 이건 받아들인 결정입니다 — 「가까운 시각으로 밀어서라도 울린다」는 사용자가 예상 못 한 시각에 전화를 받게 되어 더 나쁩니다. 1년에 한 번, 서머타임 지역에서만 생깁니다.

# 통보 1. ⛔ §11 Free 분석 깊이 잠금 — **취소됐습니다**

`GET /calls/{call_id}/result` 의 `analysis_depth`(`full`·`score_only`·`locked`) 는 **만들지 않습니다.**

「Free 는 누적 3회까지만 분석 전체」 정책 자체가 취소됐습니다. 서버는 이 필드를 내려보내지 않고, 분석은 **지금처럼 전부 열립니다.**

⇒ 앱에서 준비 중이던 잠금 표시·업셀 연결(Figma `overlay/free_limit`)은 **중단해 주세요.** 요금제 비교 화면의 「처음 3번의 통화는 분석 전체」 문구도 사실과 달라지니 확인이 필요합니다.

# 통보 2. 캐릭터 묶음 — 이제 노출해도 됩니다

`bt_character_bundle` 이 서버 카탈로그에 등록됐습니다(전에는 404 `UNKNOWN_PRODUCT`).

| | |
|---|---|
| 지급 | Popo · Rara · Dudu 중 **없는 것만** |
| 일부 보유자 | 사장님 확정 — **앱이 숨깁니다.** 다만 서버는 거절하지 않고 없는 것만 지급합니다(스토어 결제가 끝난 뒤 도착하는 요청을 거절하면 돈만 받는 게 되므로) |
| 구성 관리 | `character.in_bundle` 플래그. 앞으로 캐릭터를 추가해도 **기본 제외**라 묶음이 멋대로 커지지 않습니다 |

⚠ **묶음 내용물은 스토어에서 읽을 수 없습니다.** Play `oneTimeProducts` 를 실제로 조회해 확인했습니다 — 스키마에 자식 상품 필드가 없고, 내용물을 말하는 곳은 영어 설명 한 줄(`"Unlock Popo, Rara and Dudu, yours forever"`)뿐입니다. 그래서 서버 DB 가 정본입니다. **묶음 구성을 바꾸면 Play Console 설명도 같이 고쳐야 합니다.**
