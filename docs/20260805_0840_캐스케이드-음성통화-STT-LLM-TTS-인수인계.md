## 0. 한 줄 요약

지금 통화는 **Gemini Live 네이티브 오디오**(오디오 in → 오디오 out, 한 덩어리)다.
이걸 **STT → LLM(텍스트) → TTS** 세 조각으로 분해한 파이프라인을 따로 만들어 보고,
원가·품질·제어권을 재서 어느 쪽을 쓸지 정하자는 것.

## 1. 왜 하나 (동기 — 사장님 확인)

### 1-1. 비용

Live 는 **오디오 토큰이 텍스트의 6배**다. 통화 원가가 사실상 여기서 다 나온다.

| 항목 | 단가(1M 토큰) |
|---|---|
| 텍스트 입력 | $0.50 |
| **오디오 입력** | **$3.00** |
| 텍스트 출력 | $2.00 |
| **오디오 출력** | **$12.00** |

실측(`call_id=880`, 5분 통화):

```
in AUDIO 120,802 / in TEXT 21,318 / out AUDIO 17,600 / out TEXT 440
→ $0.585
```

15분이면 **약 $1.65/통화**. 무제한 플랜(Pro·Max)에서 이 값이 그대로 원가로 쌓인다.

⚠ 이 숫자는 한 번 뒤집혔다가 확정된 값이다. 초기 계측이 **출력 토큰을 안 모아서** 낮게
나왔었다($0.31로 잘못 정정한 적 있음). 팀원의 계측 코드(현재 배포됨)가 입·출력 모달리티를
모두 잡으면서 $0.585로 확정됐다. **다시 계산할 일이 있으면 출력 모달리티가 포함됐는지부터
확인할 것.**

캐스케이드로 가면 오디오 출력 $12 자리가 TTS 단가로 바뀐다(Cloud TTS Chirp3-HD). 여기가
절감의 핵심이고, **얼마나 줄어드는지는 만들어서 재봐야 안다.**

### 1-2. 제어권 — barge-in

지금 normalcall 은 **barge-in off** 다. 비버가 말하는 동안 마이크를 안 보낸다.
관문은 `call_session.py:1785` 의 `state.turn_id is None` 한 줄이다.

왜 껐나: Live 는 오디오 스트림을 자기가 쥐고 있어서, 끼어들기를 켜면 자기 목소리를
사용자 발화로 오인하는 에코 루프가 생긴다(실기기에서 확인).

캐스케이드는 **파이프를 우리가 직접 쥔다.** 재생 중인 TTS 오디오가 뭔지 서버가 알고 있으니
끼어들기 판정을 우리 규칙으로 짤 수 있다.

☞ **결정: barge-in 켠다.** 이게 캐스케이드를 하려는 두 번째 이유다.

### 1-3. 미확정 — 발음 품질

Live 네이티브 오디오는 억양·감정이 자연스럽다. TTS 로 갈아끼우면 **한국어 학습 앱인데
선생님 발음이 나빠지는** 위험이 있다(치명적일 수 있음).

☞ **결정: 논리로 정하지 말고 만들어서 들어보고 판단한다.**

## 3. 핵심 미해결 문제 — 턴 감지

D2 때문에 **"사용자 말이 끝났다"를 서버가 스스로 알아야 한다.** 이게 캐스케이드 전체의
성패를 가르는 지점이고, 아직 안 정했다.

후보 3개:

| 방식 | 내용 | 메모 |
|---|---|---|
| **STT endpointing** | STT 가 주는 final 신호로 턴 종료 판정 | LiveKit 이 **프로덕션 기본**으로 미는 방식 |
| VAD | 음성 에너지로 침묵 감지 | 단순하지만 생각하느라 쉬는 걸 종료로 오인 |
| 의미 기반 모델 | 문장이 끝났는지를 모델이 판정 | 정확하지만 지연·비용 추가 |

⚠ **외국인 학습자**가 대상이라는 게 변수다. 말이 느리고 중간에 오래 멈춘다 —
일반 대화용 튜닝값이 그대로 안 맞을 가능성이 높다. (관련 메모리: 실사용자 대다수가
생존회화도 안 되는 진짜 초보)

☞ **이건 논리로 못 정한다. 실측해야 한다.** 그래서 다음 스텝이 아래 4번이다.

## 5. 이미 있는 것 — 바퀴를 다시 만들지 말 것

⭐ **이 프로젝트에는 캐스케이드 부품이 거의 다 있다.** 발음 챌린지 기능을 만들면서
STT 스트리밍 WS 를 이미 붙여놨다.

### 5-1. STT — `core/stt.py`

Google Cloud Speech-to-Text 스트리밍 어댑터. 인터페이스가 **캐스케이드에 그대로 맞는다**:

```
start()            스트림 개시
push_audio(bytes)  마이크 PCM(LINEAR16) 청크 투입
results()          (text, is_final) 를 yield 하는 async iterator
close()            정리
```

- `GoogleSttStream` / `FakeSttStream` 두 구현 + `make_stt_stream(sample_rate, words)` 팩토리
- 키 부재·미설치·인증실패·`STT_FAKE` 면 **페이크 스트림으로 폴백**(과금 0, 서버 정상 기동)
  → 테스트에서 실제 STT 없이 돌릴 수 있다
- 키: `STT_SA_KEY_FILE`(비우면 `TTS_SA_KEY_FILE` 재사용 — 같은 GCP 프로젝트 `bt-dev-web-01`)

☞ `results()` 의 `is_final` 이 **STT endpointing 후보의 재료**다. 4-1 은 이걸 그대로 쓰면 된다.

### 5-2. 이미 도는 STT WS 세션 — `domains/learning/realtime/stt_session.py`

발음 챌린지용이지만 **구조가 캐스케이드와 같다**(2펌프 + TaskGroup):

```
client → (audio) → STT
STT    → (partial/final) → client
```

프로토콜:
```
client→server: 첫 텍스트 {"type":"config","words":[...],"sampleRate":N}
               이후 바이너리 PCM, 선택 {"type":"stop"}
               (테스트 훅: {"type":"__test_say","text":...})
server→client: {"type":"ready"} / {"type":"partial","text"} / {"type":"final","text"}
               / {"type":"error","error"}
```

⭐ `PronSttSession` 이 `SttTransport` Protocol 로 WS 를 추상화해놔서 **테스트에서 스텁으로
갈아끼울 수 있다.** `__test_say` 훅도 있다. 4-1 데모는 이 파일을 베껴 시작하는 게 가장 빠르다.

### 5-3. TTS — `core/tts.py`

```python
async def synthesize(text: str, language: str = "ko", voice: str | None = None
                     ) -> tuple[bytes, str] | None
```

- Google **Cloud** TTS(Chirp3-HD, 다국어). Vertex 아님 — 빌린 프로젝트라 Cloud TTS 를 쓴다
- **MP3 를 직접 준다**(ffmpeg 불필요)
- `voice` 에 통화 캐릭터의 Gemini Live voice 이름(예: `"Fenrir"`)을 넘기면 그 목소리로,
  미지원이면 언어 기본 음성으로 폴백
- 키 부재/실패는 `None`(graceful) — 호출부가 건너뛴다

⚠ **캐스케이드는 MP3 가 아니라 스트리밍 PCM 이 필요할 수 있다.** 지금 앱 재생 경로는
PCM24k 이고(아래 5-4), MP3 한 덩어리는 첫 소리까지의 지연이 크다. Cloud TTS 의
스트리밍 합성 지원 여부부터 확인할 것 — 여기가 미조사 구멍이다.

### 5-4. 오디오 규격 (기존 통화 기준 — 앱이 이미 이렇게 말하고 듣는다)

```
입력  PCM16 / 16kHz   (앱 마이크 → 서버)
출력  PCM24k          (서버 → 앱 재생)
WS    바이너리=오디오, 텍스트=JSON 제어(discriminated union, protocol.py)
```

☞ 앱을 안 고치려면 이 규격을 맞추는 게 유리하다.

### 5-5. 프롬프트 — `core/persona_prompt.py`

`build_system_instruction(...)` — **LLM 생성 0, 순수 문자열 조립.** 캐릭터 role/personality/
rules + 레벨 + 흥미 + 이력. 캐스케이드의 LLM 단계에 **그대로 재사용 가능**하다.
(레벨테스트용은 `build_leveltest_instruction`)

### 5-6. 원가 계기판 (현재 배포됨)

통화 종료 시 로그 1줄. **같은 형식으로 내면 Live vs 캐스케이드가 바로 비교된다.**

```
normalcall usage: call_id=880 type=normal msgs=22 dropped=0 t=[13.6..299.2]
sum_prompt=142120 sum_resp=18040 sum_total=160160
last_prompt=11080 last_total=11900 monotonic=True
sum_in=AUDIO=120802,TEXT=21318 sum_out=AUDIO=17600,TEXT=440
```

전부 `key=value` 라 Cloud Logging 로그 기반 메트릭이 코드 변경 0줄로 붙는다.
`LIVE_USAGE_TRACE=true` 면 턴별 시계열 1줄 추가(demo-api 에만 켜져 있음).

## 6. 손대면 안 되는 것 (R4 불변식)

캐스케이드는 **별도 경로**로 만든다(D5). 아래는 기존 normalcall 의 불변식이고, 캐스케이드가
이걸 건드리면 안 된다:

- **2펌프 + TaskGroup**, `asyncio.timeout` 절대 백스톱(540s)
- **barge-in off** (`state.turn_id is None` 관문) ← 캐스케이드는 **켜지만**, 기존 통화는 그대로
- 종료 규약: 서버만 종료 시점을 정한다("[시스템]" 종료 시드 전엔 비버가 먼저 작별 금지)
- 세션 재연결(세대 루프): `SESSION_ROTATE_AT_S=480`, `MAX_RECONNECTS=4`
  — Live 는 **연결 수명 ~10분**이라 15분 통화는 연결 2개 이상으로 돈다
- 회귀 테스트: `tests/test_normalcall_ws.py`
