# 안드로이드 통화 끊김 수정 — `feat/seoyeon-v3` → `feat/multilang` 포팅 계획

작성 2026-08-02 · 대상 저장소: `beavertalk-flutter` · 작업 브랜치 `feat/audio-merge`

---

## 0. 무엇을 왜 옮기나

`feat/seoyeon-v3` 가 안드로이드 통화 재생 끊김(1분쯤부터 시작해 갈수록 악화)을 고쳤다.
실기기(SM-N986N)에서 서버 `call_ended` 까지 **약 4분 무끊김 완주**를 확인한 조합이다.

문제는 그 브랜치가 `feat/multilang` 에서 **99커밋 전에** 갈라져 나왔다는 것이다.

```
merge-base 4bbbca7  (packages/ 벤더링 없음)
   ├─ feat/multilang   99커밋   ← feat/mypage 포함(PR #6)
   └─ feat/seoyeon-v3   2커밋   77e9aca(버퍼링 3종+벤더링) → f5b90f7(능동 푸시)
```

`normalcall_controller.dart` 를 양쪽이 크게 고쳤다(multilang +960/-94, seoyeon +604/-62).
그래서 **`git merge` 를 하지 않고 포팅**한다 — 충돌을 손으로 푸는 과정에서 오디오 경로의
미묘한 순서 의존이 깨져도 실기기 없이는 안 드러나기 때문이다.

## 1. 서연님이 고친 것 (커밋 본문 근거)

원인은 서버가 아니었다. iOS·웹은 같은 서버로 정상이었고 AudioTrack 도 무정지였다.
남은 공백 94~263ms 는 평범한 지터 크기 — **문제는 지터가 아니라 그걸 못 견디는 버퍼링**이었다.

| | 무엇 | 효과(측정) |
|---|---|---|
| ① | **재개 쿠션** — `_playing` 이 게이트 맨 앞이라 한 번 재생이 열리면 버퍼를 다시 안 봤다. 끊김→120ms 조각으로 재개→즉시 재끊김 루프 | 쿠션 미달 시작 10/27 → 1/32 |
| ② | **피드 쿠션 200ms → 1.5s** — 피드가 핑퐁이라 왕복보다 쿠션이 짧으면 native 큐가 말라 20ms 무음 주입 | Dart 큐 백로그 7.5s → 3.1s |
| ③ | **적응형 지터버퍼** — 굶으면 +300ms(상한 2.5s), 깨끗하면 −150ms(하한 900ms). 증가폭 > 감소폭이라 실제 지터 위로 안착 | — |
| ④ | **`flutter_pcm_sound` 벤더링** — 재생 루프가 큐 빔에 `take()` 무한 블록 → AudioFlinger 가 유휴 트랙을 active list 에서 제거(BUFFER TIMEOUT) → 재활성화 ~130ms. `poll(5ms)` 후 무음 write 로 트랙을 계속 active 유지 | underrun 100+ → 0~1 |
| ⑤ | **능동 푸시(핑퐁 제거)** — 재생 피드가 `native 요청 → 안드로이드 메인스레드 → Dart 응답` 이라 **재생 경로의 심장박동이 UI 스레드에 묶여 있었다**. Dart 가 40ms 타이머로 능동 푸시하고, native `feed` 가 잔량을 반환해 매 피드마다 재동기화 | 4분 무끊김 완주 |
| ⑥ | (별건) `_tryUngateMic` 이 호출마다 hangover 타이머를 재시작해 정상 경로로 마이크가 안 열림 | 22회 중 13회가 느린 안전망으로만 열림 |

## 2. ⚠ 착수 전 뒤집힌 전제 3가지

### (a) 벤더 패키지 "통째 교체"는 컴파일을 깨뜨린다
seoyeon 판은 `getStats()` 를 Java·Dart 양쪽에서 **삭제**했는데, multilang 컨트롤러가 쓴다
(`normalcall_controller.dart:1440`, `_startDiag` 계측). **Java 에 그 케이스만 되살린다.**

### (b) 벤더 패키지는 "seoyeon 이 무조건 개선판"이 아니다
서로 다른 축을 고쳤다.

| | multilang | seoyeon |
|---|---|---|
| 청크 분할 | 4096B (~85ms) | **200B (~4.2ms)** ← 상류로 회귀 |
| 트랙 버퍼 | `max(minBuf, 250ms)` | `minBuf * 4` |
| 재생 루프 잔량 | `synchronized` + 카운터 | `AtomicLong` lock-free |
| 큐 빔 | `take()` 무한 블록 | **`poll(5ms)` → 무음** ★ |
| feed 반환 | `true` | **잔량(frames)** ★ |

**4096 청크 복원은 포팅 이후 별도 실험으로 미룬다** — seoyeon 판이 실기기 검증된 조합이므로
그대로 베이스로 쓴다. 다만 재생 루프의 O(n) 스캔이 사라져서 200B 조각의 원래 비용(큐 전체
순회)은 없어졌고, 남는 비용은 `AudioTrack.write()` 호출 빈도(240회/초)뿐이다.

### (c) `pubspec.yaml` / `pubspec.lock` 은 seoyeon 것을 절대 가져오지 않는다
seoyeon 판은 multilang 기준 훨씬 옛날이다 — `video_player`·`audio_session`·`sign_in_with_apple`
·`crypto`·`assets/avatar/*` 가 전부 없고 대신 `vosk_flutter_2` 가 있다.
`dependency_overrides` 블록은 **multilang 에 이미 있다**. pubspec 은 손댈 게 없다.

## 3. ★ 회귀 위험 3가지 — seoyeon 의 4분 검증이 이 조합을 증명하지 않는다

multilang 에는 그 브랜치에 **없던 것**이 붙어 있다(아바타 영상, CallKit 프리롤 등).

### ① 아바타 립싱크가 최대 2.5초 앞선다
`_takeArray` 가 재생 직전 PCM 의 RMS 를 `_envQueue` 에 넣고 `_startEnvelope` 가 **실시간으로**
뽑아 `avatarLevel` 로 흘린다. 즉 **엔진이 물고 있는 양 = 립싱크 선행량**이다.
`_envLeadMs = 25` 라는 전제(“native player buffers a little ahead”)를 `_pump` 가 1.2~2.5초로
바꿔버린다. `sync_avatar.dart` 의 "controller aligns level to what is actually audible" 계약이
깨진다. **로그로는 안 보이고 실기기에서 눈으로만 보인다.**

→ `_envQueue` 를 `(audibleAtMs, level)` 로 스탬프. `_takeArray` 시점의 엔진 레벨을 ms 로 환산해
`audibleAt = now + engineMs + k*_envStepMs`. `_startEnvelope` 는 `audibleAt <= now` 만 pop.
`_envQueue` 3s 캡도 `engineTarget + 여유` 로 상향(2.5s 엔진 + 1.3s take 면 캡에 걸려 앞이 잘린다).

### ② 마이크가 비버 발화 중에 열린다 (에코 루프)
`_tryUngateMic` 이 `_queueLen < 2`(**Dart 큐**)만 본다. `_pump` 는 Dart 큐를 엔진으로 최대 2.5초
앞당겨 옮기므로 **엔진에 2.5초가 남았는데 Dart 큐는 비어** 게이트가 통과한다. 스피커폰에서
비버 목소리가 마이크로 들어가 서버 STT 로 되돌아간다 = 반이중 게이트가 존재 이유를 잃는다.
seoyeon 브랜치도 이걸 고치지 않았다(4분 검증에서 안 터진 건 AEC 가 흡수했거나 운 — **추측**).

### ③ 마지막 인사가 잘린다 — ②와 같은 뿌리
`_maybeFinishClosing` 도 `_queueLen >= 2` 만 본다. `_drainScheduled` 는 쿠션 게이트를 우회하므로
`_pump` 가 종료 라인을 즉시 엔진에 밀어 넣는다 → Dart 큐 즉시 빔 → `playback_done` → `_teardown()`
→ `release()`. **엔진에 남은 최대 2.5초가 통째로 날아간다.**

②③ 공통 수정:
```dart
bool get _audioFullyDrained =>
    _queueLen < 2 && _engineLevelFrames < _drainedSlackFrames;  // ~60ms
```
적용: `_pump` 말미 · `_tryUngateMic` · `_armIdleUngate` 콜백 · `_maybeFinishClosing` 2곳.

### (부수) seoyeon 자체 버그
`_startAudio` 에서 통화별 상태 리셋(`_cushionBytes`·`_turnStarved`·`_resumeFlushed`)이
`_startPushFeed()`/`_pump()` **뒤**에 있다. `_pump` 는 첫 `await` 전까지 동기 실행되므로
**첫 펌프가 직전 통화 값으로 판단**한다. teardown 도 이 셋을 리셋하지 않는다.
→ **포팅하면서 리셋을 앞으로 옮긴다.**

## 4. seoyeon 에서 가져오면 안 되는 것

| 대상 | 이유 |
|---|---|
| `_startAudio` 의 큐 리셋(`_pcmQueue`/`_pcmHead`/`_pcmTail`) | multilang 은 **일부러** 리셋하지 않는다 — CallKit 프리롤 보존. 가져오면 **잠금화면 수신통화 첫 인사가 통째로 날아간다** ★ |
| `enableVoiceProcessing: true` 하드코딩 | 블루투스 마이크(HFP)가 죽는다. multilang 의 헤드셋 분기가 더 정확 |
| `Uint8List` head/tail 큐 재작성 | multilang 의 `Queue<Uint8List>` 청크 링버퍼가 **더 낫다** — enqueue 가 O(1) 무복사(참조 저장), seoyeon 판은 `setRange` 로 매 청크 복사. 게다가 multilang `_takeArray` 는 아바타 훅을 물고 있다 |
| `_kDebugSkipMic` | 마이크 격리 실험용. multilang `_startMic` 은 재시도 6회·watchdog 까지 훨씬 풍부 |
| `_feedPlayer`↔`_feedPlayerBody` 분리 + FP-TIMING | multilang `_startDiag` 가 같은 질문에 더 나은 답. 병합 충돌 지점만 늘린다 |
| `pubspec.yaml` / `pubspec.lock` | §2-c |

## 5. 커밋 계획

에이전트는 A(패키지)와 B(푸시)를 나누자고 했으나 **합친다.** A 단독은 `poll(5ms)+무음` 이
`_pump` 없이 도는 상태라 **스트림 인플레이션**(재생 스트림이 실시간보다 부풀어 백로그 단조 증가)
위험이 있어서, "A 만 5분 통화로 재라"가 성립하지 않는다(에이전트도 "A 단독으로 오래 하지 마라"고
같이 적었다 — 모순).

**제약: 실기기 테스트를 마지막에 한 번만 한다.** 그래서 깨졌을 때 위에서부터 한 커밋씩
되돌리며 원인을 좁힌다(`git checkout <커밋>` → 빌드 → 통화). 이 방식이 성립하려면
**모든 커밋이 단독으로 빌드·실행돼야** 한다 — 아래 순서가 그 제약을 지킨다.

되돌리는 순서는 **위험한 것이 위**에 오도록 잡았다(4 → 3 → 2 → 1).

```
커밋 1  벤더 패키지(getStats 복구 + Java 로그 DEBUG 게이트) + .gitignore
          단독 실행 가능. 다만 poll+무음이 _pump 없이 도는 상태라
          ⚠ 인플레이션 위험이 있다 — 여기까지 되돌려도 안 되면 브랜치를 버리고
            multilang 원본으로 돌아가는 게 맞다(이 커밋이 바닥이 아니다).

커밋 2  피드 상수 + _pump 능동 푸시 + _tryUngateMic 버그 + 배선/teardown
        + 회귀 ②③ (_audioFullyDrained) + 계측 재조준
          핵심 메커니즘. 계측을 여기 넣는 이유: 위 커밋을 되돌려도 진단 수단이
          남아 있어야 한다.

커밋 3  회귀 ① 립싱크 리드 보정
          되돌려도 오디오는 무영향(입만 앞선다). 그래서 2보다 위.

커밋 4  적응형 쿠션 + 재개 쿠션
          모든 응답에 900ms~2.5초 지연을 덧붙인다. 체감상 싼 값이 아니라
          **맨 위**에 둔다 — 끊김이 이미 잡혔으면 이것부터 되돌리면 된다.
```

되돌림 해석표:

| 되돌렸더니 좋아졌다 | 뜻 |
|---|---|
| 4 제거 | 쿠션이 과했다(지연만 늘리고 끊김은 이미 2에서 잡혔다) |
| 3 제거 | 립싱크 보정이 뭔가 깼다(엔진 레벨 환산 오류 의심) |
| 2 제거 | 능동 푸시가 이 기기/조합에 안 맞는다 → 콜백 모델 유지하고 패키지만 |
| 1 까지 갔는데도 안 됨 | 포팅 문제가 아니다. multilang 원본으로 복귀 후 재검토 |

## 6. 계측 처리

**원칙**: 포팅 자체가 아직 검증되지 않았으므로 계측을 지금 걷어내는 건 이르다.
다만 seoyeon 것을 그대로 다 가져오면 계측기가 3중이 된다.

**남긴다** (multilang `_startDiag` 에 필드로 흡수 — 이미 5초 타이머 + release 가시 `print` 인프라)
- `_engineMinFrames` — 이번 아키텍처의 **단일 판정 지표**. 낮으면 native 가 말랐다, 높은데도
  버벅이면 Dart 큐/서버.
- `_startEventLoopProbe`(20ms 타이머 lag) — `_pump` 도입 후 "메인 아이솔레이트가 얼마나 밀렸나"를
  재는 **유일한** 수단. 아바타 `video_player` 부하를 정량화한다.
- `cushion grew → Nms`, `audio resumed after Nms gap (starved)`
- `SERVER GAP Nms mid-utterance` — 서버/클라 책임 분기

**버린다**
- `_kDebugDumpRxPcm`/`_dumpSink`/`_openDump` + `dart:io`·`path_provider` import —
  커밋 본문이 스스로 함정을 자백했다: *"파일은 받은 바이트를 이어붙이므로 타이밍 구멍이 사라져
  항상 매끄럽게 들린다."* 이미 답이 난 질문용 도구다.
- `_startInflateLog` — `_startDiag` 와 100% 중복. `fed/elapsed %` 개념만 흡수.
- multilang 의 `_dbgLastFeedMs`/`_dbgMaxGap` — 콜백이 안 불리는 게 정상이 되면 무의미.
  `_pump` 틱 지연 계측으로 재조준.

**Java 로그(중요)**: seoyeon Java 의 `Log.w("BeaverTalkPCM", ...)` 5종은 release 에서 안 지워진다.
`maybeLogStats` 가 200B write 마다(초당 240회) 호출되고 `STALL` 은 60ms 임계라 자주 찍힌다.
**재생 스레드가 logcat 에 블로킹되면 그 자체가 언더런 원인이 된다.**
→ `private static final boolean DEBUG` 로 전부 감싼다. 포팅 중 true, 검증 후 false.

## 7. 검증 — 사람이 봐야 하는 것

실기기(SM-N986N), **release 빌드**, 통화 5분. debug 는 `debugPrint` 백로그가 원인을 오염시킨다.

| 항목 | 어떻게 |
|---|---|
| 끊김 | 귀 + `[DIAG]` underrun/starve |
| 엔진이 버티나 | `engineMin` 이 1.2s 근처 유지되나 |
| 메인 아이솔레이트 잼 | `elLagMax` — 크면 아바타 `video_player` 가 범인(감정 클립 첫 `_open`) |
| **인플레이션** | `fed/elapsed %` 가 100% 근처인가. 105% 넘으면 §2-b 이중 무음 주입 |
| **마이크 조기 개방** | 서버 전사에 비버 발화가 섞이나 (로그로만 확인 가능) |
| **마지막 인사** | 귀 — 잘리는가 |
| **립싱크** | 눈 — 입이 소리보다 앞서는가 |

마지막 3개는 **숫자가 아니라 사람이 확인해야 한다.**

## 8. 남은 실험 (포팅 이후)

- 4096B 청크 복원(§2-b) — seoyeon 판의 200B 는 상류 회귀다
- 아바타 감정 클립 프리로드 — 첫 `_open` 이 `_engineLowFrames`(1.2s) 예산을 먹는지
- Oboe/AAudio 전환 (서연님 문서의 남은 단계)
