# 캐스케이드 원가 실측 스냅샷 (엔진 삭제 전 마지막 측정)

- 측정일: 2026-09-23
- 왜 이 문서가 있나: **C14(70e20e2)로 `estimate_cascade_cost_usd` 를 지웠다.** 지우고 나면
  `usage_engine='cascade:…'` 인 과거 통화의 원가를 더는 계산할 수 없다(원본 usage 컬럼은
  DB 에 그대로 남지만 단가표가 없어졌다). 그 숫자가 «Live 로 간다» 는 결정의 근거였으므로,
  **코드를 지우기 전에 결과를 여기 못 박는다.**
- 측정 방법: 삭제 전 코드(본 체크아웃 `fix/live-model-name`)에서
  `scripts/dev_call_cost.py --limit 3000` 을 운영 DB 에 **읽기 전용**으로 1회 실행.
  원가는 `estimate_call_cost_usd` 한 곳에서만 나온다(직접 곱셈 없음).

## ⛔ 이 숫자를 인용할 때 반드시 같이 말해야 하는 것

**같은 조건의 비교가 아니다.** 아래를 빼고 "Live 가 3배 비싸다" 만 인용하면 틀린 주장이 된다.

1. **측정 시기가 다르다.** 캐스케이드는 2026-08-12 전후의 실험 통화가 대부분이고, Live 는
   그 이후 지금까지 전부다. 그 사이 모델(2.5 → 3.1)·설정·압축 문턱이 여러 번 바뀌었다.
2. **통화 성격이 다르다.** 캐스케이드 77건은 대부분 짧은 실험 통화다(총 235분 / 77건 ≈ 3분).
   Live 1,501건에는 레벨테스트·표현학습·프리토킹·영상통화(3.1 + set_face)가 섞여 있다.
3. **3.1 툴콜 턴은 usage prompt 가 2배로 합산된다**(별도 실측). 영상통화 비중이 Live 쪽
   분당 원가를 끌어올린다 — 이건 엔진 차이가 아니라 **기능 차이**다.
4. **캐스케이드는 컨텍스트·총토큰 컬럼을 안 쓴다.** 그 칸이 `-` 인 건 "0" 이 아니라
   "잰 적 없음" 이다.

⇒ 정직한 요약은 이렇다: **"우리 실사용 데이터에서 Live 경로의 분당 원가는 $0.037,
캐스케이드 실험 구간은 $0.012 였다. 3배 차이지만 통화 성격과 시기가 달라 엔진만의
차이로 볼 수 없다."**

---

## 그래서 왜 Live 를 택했나 (원가 말고)

원가만 보면 캐스케이드가 쌌다. 그런데도 Live 로 갔다 — 원가는 선택 기준 중 하나였을 뿐이다.
결정 근거는 `docs/prompts/README.md` 와 통화 품질 실측에 있다(응답 지연, 자연스러움,
끼어들기·턴 전환, 유지보수 면적). 이 문서는 **원가 축의 숫자만** 보관한다.

---

## 삭제 후 도구가 어떻게 보이나

`scripts/dev_call_cost.py` 는 이제 cascade 행을 이렇게 다룬다:
- 원가 칸에 `0.0000` 을 찍고 바로 아래 `⚠ 단가 미상: engine:cascade:…` 경고를 붙인다
- **길이별 평균 집계에서는 제외한다** — 0 을 평균에 넣으면 분당 원가가 실제보다 낮게 나온다
- 제외한 건수를 집계표 아래 한 줄로 알린다(조용히 버리지 않는다)

정밀한 소급 원가가 다시 필요해지면, 엔진 코드를 되살리지 말고 **이 문서의 숫자를 쓰거나**
로그 기반 백필로 따로 계산한다.
