# GPT 전용 — 죽은 코드 삭제 (2026-10-10)

## 전제 (사장님 확인)

- **이 브랜치(`feat/openai-live`)는 GPT 전용이고 실서비스에 배포하지 않는다.** 실서비스
  (`beavertalk-app-api`)는 `main` 에서 돌고 `OPENAI_REALTIME_COURSES` 가 미설정이라 전부
  Gemini 다. 그래서 **이 브랜치에서 Gemini 경로를 지워도 실사용자는 안 다친다.**
  ⛔ 뒤집어 말하면 — 이 브랜치를 `dev`/`main` 에 머지하는 순간이 **컷오버**다. 그 전에
    머지하면 실서비스 통화가 죽는다.
- **통화후 분석은 Gemini 로 둔다**(사장님 결정). 전사 분석·체크판·국적 추론·이어하기
  요약·제목은 `gemini_analysis.generate_structured` 로 계속 간다 — 싸고 이미 검증됐다.
- 삭제 깊이: **죽은 코드만.** `run_call`(1,733줄) 수술은 이번 범위가 아니다.

## 순서 — 네 단계, 각 단계가 끝나면 회귀 초록

작은 것부터 해서 방식을 먼저 검증한다. 중간에 멈춰도 깨진 것이 없어야 한다.

1. **압축 관측**(76줄) — 호출 1곳. 가장 안전. 방식 검증용.
2. **밴드 관측**(112줄) — 호출 1곳, 레벨테스트 전용.
3. **재접지**(407줄) — 호출이 서로 물려 있다. `state` 필드·env(`LIVE_REGROUND_MODE`)까지.
4. **퀴즈 상태기계**(946줄) — 가장 크고 시험이 가장 많이 딸린다. 마지막.

각 단계: ①삭제 → ②`state` 필드·`__slots__` 정리 → ③죽은 시험 삭제 → ④회귀 전량 →
⑤커밋(단계별 1커밋). 커밋 메시지에 지운 시험 수를 적는다.
