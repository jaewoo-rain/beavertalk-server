# GPT 통화 이중발화 — 시드 통로 한 곳에 가드

작성 2026-10-07 · 대상 `feat/openai-live` · 지시 순서 **①가드 → ②프롬프트 재구성**
(서버 검출 안은 보류 — 프롬프트로 안 될 때)

⛔⛔ **이 문서의 원인 진단은 틀렸다.** `docs/20261007_1741_gpt통화-흐름과-이중발화.md` §1
  에서 교정됐다 — 아래 「증상」의 공백 없는 이어 붙음은 **응답 2개의 증거가 아니다**(이
  모델은 문장 경계 델타를 공백 없이 준다). 진짜 원인은 벤더의 `interrupt_response`
  기본값이었다(같은 문서 §2). 가드 자체는 실재하는 실패 모드를 막는 방어로 남겼다.

## 증상 (call 1758)

```
[t22] user    (빈 턴)
[t23] beaver  Alright, let's move ahead with the next item.You got it, nice work. / ...
```
`next item.You` — 공백 없이 붙었다.

## 당시 진단

| | 사실 | 근거 |
|---|---|---|
| ① | `TURN_DETECTION={"type":"semantic_vad"}` — `create_response` **기본 true**. 유저 턴 커밋이 응답을 **자동 생성**한다 | `core/openai/session.py:76` |
| ② | `_create_response()` 가 진행 중 응답을 보지 않는다. 시드 6곳이 무조건 쏜다 | `session.py:317-323` |

호출부 가드(`state.turn_id is not None`)로는 못 막는다 — `turn_id` 는 첫 `audio`/`out_tr`
에 열리므로(`call_session.py:6522·6608`) 자동 생성과 첫 델타 사이가 **빈 창**이다.

## 고친 것 — `core/openai/session.py` 한 파일

1. `response.created` → 활성 / `response.done` → 해제. 해제는 `_response_done` **앞**에
   둔다(그 안에서 예외가 나도 플래그가 서 있으면 통화가 벙어리가 된다).
2. `send_text_turn` 이 활성이면 **아무것도 안 한다**(항목도 안 넣는다). 시드 호출부 6곳이
   전부 이 통로를 지나므로 가드는 여기 하나다.
   - 항목까지 거르는 이유: 응답만 막으면 시드가 `user` 역할로 남아 **다음 턴에 낭독된다**.
   - 떨궈도 안전한 근거: 넛지·루프차단·태그복구는 다음 턴에 다시 판정하고, 종료는 절대
     백스톱이 따로 책임진다(R5).
3. `_create_response` 자체에도 같은 가드 — `send_reground(turn_complete=True)` 통로용.

⛔ `call_session.py` **무변경.** Gemini 경로 바이트 동일, 불변식(2펌프·백스톱·barge-in
off·종료 규약) 무변경 — 바뀐 건 「시드를 쏠까」 하나다(R4).

⚠ **실측에서 이 가드는 한 번도 발동하지 않았다**(call 1757~1766 전부 `시드 생략` 0건).
