## 1. 무엇이 바뀌었나

**전**: 레벨테스트만 레벨을 정했습니다. **표현학습을 아무리 해도 레벨이 오르지 않았습니다.**

**후**: 레벨테스트는 «시작 차시» 를 정하고, 그 뒤로는 **진도가 레벨을 올립니다.**

```
레벨 = 커리큘럼을 어디까지 갔나
L1 생존회화 3차시를 끝내고 A1 첫 차시로 넘어가면 → 레벨 1→2
```
이런 경계가 12곳 있습니다(레벨 13까지).

### 레벨업 시점
**프리토킹 통화가 끝나고 다음 차시로 넘어갈 때**입니다.
값은 `call_ended` 프레임을 **받기 전에** 이미 커밋됩니다 — 통화후 분석을 기다릴 필요 없습니다.

### ⚠ 레벨업을 알려주는 UI 가 없습니다
서버도 알림을 안 보내고 비버도 말하지 않습니다. 사용자는 **마이페이지에 들어가야 압니다.**
축하 화면이 필요하면 서버에 요청하세요 — 통화 결과에 «레벨이 올랐다» 를 실어 드릴 수 있습니다
(프롬프트를 안 건드리는 방식이라 안전합니다).

### 레벨은 이제 내려가지 않습니다
통화로는 절대 떨어지지 않습니다. 내려가는 유일한 길은 **사용자가 레벨테스트를 다시 보는 것**입니다.
⇒ 「레벨테스트 다시하기」가 유일한 복구 경로입니다. **그 진입점을 없애지 마세요.**

## 2. ⭐ 앱에 요청 — 「레벨테스트 다시하기」 경고 문구

재측정하면 **진도가 그 레벨의 첫 차시로 되돌아갑니다.**

| 재측정 결과 | 진도 |
|---|---|
| 레벨이 올라감 | 새 레벨 첫 차시로 **앞으로** |
| 레벨이 내려감 | 새 레벨 첫 차시로 **뒤로** |
| **레벨이 같음** | **그 레벨 첫 차시로 되돌아감** |

⛔ **세 번째 줄이 중요합니다.** 레벨 2 회원이 no=15 차시까지 배운 뒤 재측정해서 **또 레벨 2** 가
나오면 진도가 no=4 로 되돌아갑니다. 의도된 동작이지만 **사용자는 모르고 누릅니다.**
지금 버튼은 확인 다이얼로그 없이 바로 호출됩니다.

> **요청 문구 예시**
> *"레벨을 다시 측정하면 학습 진도가 그 레벨의 처음으로 돌아갑니다.
> 이미 끝낸 차시도 다시 거쳐야 합니다. 계속할까요?"*

### 정확히 무엇이 되돌아가나

| | 되돌아가나 |
|---|---|
| 진도 포인터 | ✅ 그 레벨 첫 차시로 |
| **차시 완료 표시** | ✅ **리셋** — 되돌아간 지점부터 다시 끝내야 합니다 |
| 배운 항목 기록 | ❌ 보존 — 다시 할 때 **「복습」으로 표시** |
| 항목 진행률(`items_drilled`) | ❌ 보존 — **0 으로 리셋되지 않습니다** |
| 통화 기록·발음 점수 | ❌ 보존 |

**지워지는 데이터는 없습니다.** 되돌아간 차시는 «표현학습 1통화 + 프리토킹 1통화» 를 다시
거치는 것이고, 항목을 처음부터 다시 떼는 게 아닙니다(이미 익힌 항목은 전부 복습으로 나옵니다).
⇒ **앱이 진행률을 0 부터 그리지 않아도 됩니다.**

## 3. 레벨 없는 회원이 「학습」을 누르면 → 레벨테스트

전엔 **표현학습이 열렸습니다.** 서버 버그였습니다 — 레벨테스트 라우팅이 `call_type` 을 안 보내는
경로에만 있었고, 앱은 `auto` 를 명시로 보내니 그 분기를 안 탔습니다. 그동안 레벨 없는 회원은
레벨 2 재료로 표현학습을 하고 레벨테스트를 영영 못 봤습니다.

**앱은 바꿀 게 없습니다** — `auto` 를 그대로 보내면 서버가 판단합니다.

⚠ **레벨 없는 기존 회원 22명**이 다음에 「학습」을 누르면 레벨테스트로 들어갑니다.
«표현학습 눌렀는데 레벨테스트가 떴다» 는 문의가 올 수 있으니 알고 계세요 — 의도된 동작입니다.
⚠ 마이페이지 「레벨테스트 다시하기」 경로는 **종전과 동일**합니다(그 경로는 원래 잘 됐습니다).

## 4. API — 변경 없음 · 값은 언제 갱신되나

| 엔드포인트 | 상태 |
|---|---|
| `GET /members/me/profile` (`korean_level`·`level_top_percent`) | 필드·모양 그대로 |
| `GET /cur/me` (`lesson`·`status`·`next_course`·`items_drilled`) | 그대로 |
| `GET /cur/lessons` (`level` 필터·`status`) | 그대로 |
| `POST /members/me/level-test/retake` | 그대로 (§2 부작용 있음) |

### 언제 새 값이 보이나

| | 반영 시점 |
|---|---|
| **프리토킹으로 레벨업** | `call_ended` **받은 직후 이미 반영됨** — 분석 대기 불요 |
| **레벨테스트로 레벨·진도 변경** | **통화후 비동기(수초)** — 그 전 조회는 옛 값. 분석 완료(`GET /calls/{id}/result`)를 확인한 뒤 읽는 게 안전 |

### `GET /cur/me` 가 어떻게 보이나

| 상황 | `lesson` | `status` | `next_course` | `items_drilled` |
|---|---|---|---|---|
| 프리토킹 끝 → 레벨업 | 다음 차시 | `learning` | `expression` | 보통 0 (전에 배운 차시면 그 수) |
| 재측정 후 | 그 레벨 첫 차시 | `learning` | `expression` | 그 차시에 이미 익힌 수 |

### 캐시 — 앱이 따로 무효화할 필요 없습니다
확인 결과 앱이 이미 필요한 무효화를 하고 있습니다(레벨·`cur/me` 프로바이더가 `autoDispose`,
홈이 통화 화면 이탈 시 `cur/me` 무효화, 마이페이지가 재측정 후 레벨 무효화).
**화면에 다시 들어가면 최신 값이 옵니다.**

## 5. ⚠ 적용 범위 — 한국어·일본어만

새 규칙은 **커리큘럼이 시드된 언어**에서만 돕니다. 지금은 **한국어·일본어뿐**입니다.

| 언어 | 레벨이 오르는 방식 | 운영 회원 |
|---|---|---|
| 한국어 · 일본어 | **진도** — 차시 경계를 넘으면 | 38 · 2 |
| 그 외(영어·중국어·프랑스어·베트남어) | **옛 방식** — 그 레벨 표현을 전량 통과하면(표현학습 퀴즈가 트리거) | fr 1 |

⇒ 그 외 언어는 «프리토킹 끝나면 레벨업» 이 아닙니다. 새 언어에 커리큘럼을 시드하면
자동으로 새 규칙으로 넘어갑니다(앱·서버 코드 변경 불요).

## 6. 협의 필요 — 지금은 급하지 않습니다

운영 회원 레벨을 **전부 1 로 통일**했으므로(2026-09-24, 뒤죽박죽 정리) **지금은 차시를
건너뛰는 사용자가 없습니다.** 아래 둘은 신규 회원이 레벨테스트로 2 이상을 받기 시작하면 필요합니다.

- **`GET /cur/lessons` 의 건너뛴 앞 차시** — 레벨 3 을 받으면 진도가 no=21 부터라 앞 20차시가
  전부 «안 시작»(`status` null)으로 내려갑니다. 회색 빈칸으로 두면 «내가 빼먹었나» 로 읽힙니다.
  숨길지, 「이 레벨부터 시작했어요」로 구분할지 정해 주세요. (되돌아가 배우는 기능은 아직 없습니다)
- **진도율 표기** — 전체 491차시 대비 «n/491» 로 그리면 레벨 3 시작 사용자가 21/491 로 보입니다.
  레벨 안에서의 진도(«A1 3/17차시»)가 맞아 보이는데 어떻게 그릴지 알려 주세요.
