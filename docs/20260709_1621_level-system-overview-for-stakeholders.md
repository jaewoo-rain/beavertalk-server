## 1. 한 줄 요약

**사용자가 비버(AI 선생님)와 5분 통화를 반복하면, 시스템이 알아서 실력을 측정하고 · 딱 맞는 것을 가르치고 · 배운 것을 추적하고 · 실력이 늘면 난이도를 올려주는** 자동 학습 관리 시스템입니다. 사용자는 그냥 전화만 걸면 됩니다.

## 2. 왜 만들었나 (문제)

기존 BeaverTalk은 모든 사용자에게 사실상 같은 난이도로 통화를 제공했습니다. 그 결과:

- 왕초보에게는 너무 어렵고, 중급자에게는 너무 쉬움 → 양쪽 다 이탈 위험
- "내가 뭘 배웠고 얼마나 늘었는지"를 시스템이 모름 → 매 통화가 일회성
- 커리큘럼(문법 459개 · 어휘 10,636개)이 있어도 통화와 연결되지 않음

## 3. 사용자가 겪는 경험 (전부 자동)

```
① 가입 후 첫 전화
   → 비버가 "너에게 수업을 맞추려고 오늘은 가볍게 얘기해 볼게, 시험 아니야"라며 수다
   → 사실은 레벨테스트: 질문 난이도가 몰래 계단식으로 올라감
   → 통화가 끝나면 AI가 대화 내용을 분석해 레벨(1~13)을 매김

② 이후 매 통화 — 비버가 "공부할래, 대화할래?" 물음
   → 공부: 그 사람이 아직 모르는 문법 1개 + 단어 몇 개를 골라 가르침
   → 대화: 그 사람이 아는 표현 범위 안에서 자유 수다 + 배운 표현을 슬쩍 꺼내게 유도

③ 통화가 끝날 때마다 (사용자는 모름)
   → AI가 녹취록을 분석: "이 사람이 오늘 어떤 문법/단어를 실제로 입으로 말했나"
   → 항목별 체크판에 기록 (배움 → 연습중 → 잘씀)

④ 조건이 차면 자동 레벨업 (알림 없음)
   → 다음 통화에서 비버가 자연스럽게: "저번에 정말 잘했으니까 오늘은 조금 어려운 것도 해볼까?"
```

**핵심 정책: 사용자에게 레벨·점수·진행률을 일절 보여주지 않습니다.** 시험 스트레스 없이 "그냥 비버랑 통화하는데 점점 잘 통한다"는 경험만 남깁니다.

## 4. 시스템의 4가지 부품

### ① 레벨 체계 — 13단계

| 레벨 | 내용 | 근거 데이터 |
|---|---|---|
| 1 | 생존 회화 — "안녕하세요, 감사합니다, 이거 주세요" 통짜 문장 46개 | 자체 설계 (완전 입문자용, 문법 없음) |
| 2~13 | CEFR 12단계 (A1~C4) | 대표님 제작 커리큘럼: 문법 459개 + 어휘 10,636개 + **예문 문장 10,639개** |

- 13단계로 잘게 나눈 이유: 한 단계 통과가 약 6~7주 — 승급이라는 보상이 계속 돌아옵니다. (4단계로 크게 나누면 통과에 6~8개월 → 동기 사망)
- 레벨 1은 일부러 짧게(약 2주) 설계해 첫 승급을 빨리 줍니다.

### ② 레벨테스트 — 첫 통화, 대화로 위장한 측정

- 퀴즈("이 단어 아세요?")가 아니라 **자연스러운 수다**입니다. 질문 난이도만 몰래 올라갑니다: "이름이 뭐예요?" → "어제 뭐 했어요?" → "기억나는 여행 얘기해 주세요" → "SNS가 사람 사이를 가깝게 만든다고 생각해요?"
- 통화 중에는 판정하지 않고(부담 제거), 끝난 뒤 녹취록을 AI가 분석해 레벨을 매깁니다. 애매하면 낮은 쪽으로 — 낮으면 쉬울 뿐이지만 높으면 첫 경험이 좌절이 되기 때문입니다.
- 레벨 5를 받으면: 레벨 3 이하 내용은 "이미 앎" 처리, 레벨 4는 "배운 적 있음" 처리하고 시작합니다.

### ③ 체크판 — 항목별 학습 추적

문법 459 + 어휘 10,636 + 생존 문장 46 = **약 1만 1천 개 항목**을 사용자별로 추적합니다:

```
미학습 → 배움(가르침 받음) → 연습중(스스로 써봄) → 잘씀(확실히 내 것)
```

"잘씀" 판정이 이 시스템의 심장입니다. **사용자가 체크하는 게 아니라, 통화에서 실제로 말한 증거로만 켜집니다**:

- 증거에 등급이 있음: 따라 말함 < 시켜서 말함 < **안 시켰는데 스스로 말함**
- 잘씀 확정 조건: **스스로 포함 성공 3회 이상** + **서로 다른 날, 다른 통화 2번 이상** (한 통화에서 같은 문장 100번 반복해도 안 됨 — 부정 방지)
- AI 판정도 못 믿습니다: AI가 "이 표현을 썼다"고 해도 **실제 녹취록에 그 발화가 없으면 서버가 기각**합니다. 판정의 심판은 항상 코드입니다.

대표님이 만든 예문 문장 10,639개는 여기서 "교과서" 역할입니다 — 항목을 가르칠 때 읽어주는 검증된 예문이고, 문장 하나가 문법 1개 + 단어 여러 개를 동시에 담고 있어 한 문장을 잘 따라하면 여러 항목에 체크가 쌓입니다.

### ④ 자동 레벨업

- 조건(AND): 그 레벨 **문법의 90%를 배웠고** + **60% 안팎을 "잘씀"까지** + 최근 오류율 낮음 (통화 횟수 조건은 없음 — 배움·잘씀을 채우려면 통화는 자연히 쌓이므로 별도 규제가 불필요)
- 승급 판정은 어휘를 세지 않습니다(대표님 결정) — 문법이 레벨의 정의이고, 어휘는 어차피 매 통화 자동으로 함께 가르쳐지기 때문입니다.
- **강등은 없습니다.** 승급 후 버벅이면 시스템이 조용히 복습 비중만 70%로 올립니다(사용자는 모름).
- 부정 방지: 승급 판정은 같은 통화로 두 번 실행돼도 이중 승급이 불가능하게 잠겨 있고, 모든 판정 근거가 감사 로그로 남아 나중에 기준을 바꿔도 전체 재계산이 가능합니다.

## 5. 설계 원칙 3가지 (전체를 관통)

1. **AI는 증인, 코드가 심판** — AI의 모든 판정(레벨·항목 사용)은 서버 검증을 통과해야만 데이터가 됩니다. 환각·과잉 인정을 구조적으로 차단.
2. **증거가 원본, 상태는 계산값** — "잘씀", "버벅임", "승급" 전부 증거 로그에서 파생 계산합니다. 기준 수치를 바꾸면 과거 데이터로 재계산 가능 — 출시 후 튜닝이 안전합니다.
3. **AI에게 데이터를 골라서 떠먹임** — AI가 DB를 뒤지는 게 아니라, 서버가 SQL로 "오늘 가르칠 10개, 판정할 후보 30개"만 잘라 넣습니다. 벡터DB 등 추가 인프라 불필요, 비용은 통화당 고정(판정 1회 ≈ $0.007).

## 6. 현재 상태 (2026-07-09 기준)

### 완료 (서버 구현 + 테스트)

| 단계 | 내용 | 검증 |
|---|---|---|
| P0 | 13레벨 재편 + 커리큘럼 1.1만 항목 DB 적재 파이프라인 (CEFR 최종본 반영, 원본 오류 11건 교정) | 시니어 리뷰 + 테스트 통과 |
| P1 | 레벨테스트 통화 (자동 진입·판정·저장) | 시니어 리뷰 + 테스트 통과 |
| P2 | 체크판·증거 파이프라인·자동 레벨업·통화 프롬프트 연동 | 최종 리뷰·테스트 진행 중 |

- 자동화 테스트 113개+ 전부 통과 상태로 유지하며 개발 (통화 실시간 안정성 관련 기존 코드는 무변경 원칙)
- 클라이언트 앱은 **수정 없이 동작** — 레벨테스트 진입을 서버가 알아서 판단

### 남은 것

1. **DB 반영** — 마이그레이션 + 데이터 적재 실행 (백업 후 진행, 대표님 확인 필요)
2. **실전 검증** — 실제 Gemini 통화로 레벨테스트·검출 판정 스모크
3. **P2.5** — 왕초보(레벨 1) 전용 화면: 통화 중 배우는 문장을 카드로 띄우고 힌트 버튼 제공 (유일한 앱 수정 사항)
4. **P3 고도화** — 망각 감쇠(안 쓰면 복습 우선순위 상승), 판정 정확도 튜닝, 어휘 다국어 번역 배치 생성

## 7. 주요 의사결정 기록 (대표님 확정)

| 결정 | 내용 |
|---|---|
| 레벨 비노출 | 사용자에게 레벨·점수·진행률을 보여주지 않음. 승급도 비버의 대사로만 |
| 서버 자동 라우팅 | 첫 통화 레벨테스트 진입을 앱이 아닌 서버가 판단 (앱 수정 0) |
| 승급 = 문법 전용 | 어휘는 추적·교육은 하되 승급 계산에서 제외 |
| 잘씀 = 3회 이상 | 시켜서/스스로 말한 성공이 3회 이상 + 다른 날 2회 분산이어야 확정 |
| 커리큘럼 최종본 | CEFR 12단계 문장 데이터(10,639문장)가 단일 기준 |
| 강등 없음 | 레벨은 내려가지 않음. 부진 시 복습 비중만 조정 |
