## ✅ 요청 1 — 알람별 통화 모드

요청하신 내용 **그대로** 구현했습니다. 진단(FCM 페이로드에 알람 id 가 없어 앱이 되짚을 수 없다)도 정확했고,
서버가 이미 `inbound_call_id → push_dispatch_log → alarm` 경로를 갖고 있어 **새로 만든 배관이 없습니다.**

### API

**`Alarm.call_type`** — `"auto"`(학습, 기본값) · `"chat"`(자유대화)

| 엔드포인트 | 변경 |
|---|---|
| `POST /api/v1/alarms` | 입력에 `call_type` 추가. **키가 없으면 `"auto"`** |
| `PUT /api/v1/alarms/{alarm_id}` | 입력에 `call_type` 추가(선택 — 다른 필드와 같은 부분갱신 규율) |
| `GET /api/v1/alarms` · `GET /api/v1/alarms/{alarm_id}` | 출력에 `call_type` 추가(항상 있음) |

> ⚠ **요청서에 `PATCH` 라고 적혀 있는데 서버는 `PUT` 입니다.** 새로 만든 게 아니라 원래부터 `PUT` 이었습니다
> (`domains/alarm/routers/alarm.py:32`). 앱이 이미 쓰고 있는 그 엔드포인트 그대로이니, `PATCH` 를 찾지 마세요.

값이 `auto`·`chat` 이 아니면 **422** 입니다(`Literal` 로 받습니다).

```jsonc
// POST /api/v1/alarms
{ "character_id": 3, "time": "2026-09-24T08:00:00+09:00",
  "days_of_week": ["MON","WED","FRI"], "call_type": "chat" }

// GET /api/v1/alarms → 각 항목
{ "alarm_id": 12, "time": "...", "is_activate": true,
  "character": { "character_id": 3, "name": "...", "image_url": "..." },
  "days_of_week": ["MON","WED","FRI"],
  "call_type": "chat" }
```

**기존 알람은 전부 `"auto"`** 로 채워집니다(컬럼 기본값). 앱이 마이그레이션 걱정할 것 없습니다.

### 통화 시작 동작

요청하신 대로 **알람 값이 `start.call_type` 을 이깁니다.**

```
start.inbound_call_id 있음
  → 그 알람의 call_type 으로 통화 시작
  → start.call_type 이 함께 와도 알람 값이 이김
```

⭐ 그래서 **앱은 알람 통화에서 `call_type` 을 신경 쓸 필요가 없습니다.** 홈 버튼 값을 그대로 실어 보내도
서버가 알람 설정으로 덮습니다. (요청서가 이 점을 정확히 짚으셨습니다 — start 를 우선하면 앱이 알람을
식별할 수 없으니 알람 설정이 영영 안 먹습니다.)

**⛔ 딱 하나 예외 — 레벨테스트는 덮지 않습니다.**
레벨 미확정 회원이 알람 통화를 받으면 알람이 `chat` 이어도 **레벨테스트가 먼저** 나갑니다.
알람 모드는 「학습이냐 자유대화냐」만 정하고, 레벨테스트 판정은 건드리지 않습니다.

**남의 알람 id 를 보내면** 캐릭터도 모드도 넘어가지 않습니다(기존 소유 검증 그대로).

### 앱이 할 일
- 알람 추가·수정 시트에 모드 선택 카드 2장 → `call_type: "auto" | "chat"`
- 알람 목록에 모드 표시 (`GET /alarms` 의 `call_type`)
- 알람 통화 시작 시 **`call_type` 을 따로 맞출 필요 없음** — 서버가 알아서 덮음

- `resolve_call_character` 가 `ResolvedCall(character_id, alarm_call_type)` 을 돌려주도록 바꿔
  **캐릭터와 모드를 쿼리 1회로 함께** 읽습니다. 따로 조회하면 DB 왕복이 늘고, 그 사이 알람이 수정되면
  캐릭터와 모드가 서로 다른 알람 것이 될 수 있습니다.

  바꾸면 됩니다(`PUT /alarms/{id}`). 개발자도구 6버튼은 `inbound_call_id` 를 안 보내므로 영향 없습니다.
