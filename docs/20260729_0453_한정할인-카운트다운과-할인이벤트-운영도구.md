# 한정 할인 카운트다운 + 할인 이벤트 운영 도구

작성 2026-07-29 04:53 · 대상 `domains/commerce`, `main.py`(dev 도구)

앱팀 요청서 `2026-07-27_1730_서버-요청_샘플음성-이미지-금액.md` §4(D) 후속.

## 1. 현황

```
discount_event      0건
effective_price     == price (전 캐릭터)
앱 노출 조건        effective_price < price  → 절대 안 뜸
```

앱 코드는 정상이고 데이터만 없다. 그리고 **할인 계산 로직은 이미 서버에 다 있다**:

| 위치 | 내용 |
|---|---|
| `character_service.active_discount()` | 활성 + 기간 내 할인 1건 반환(`activate` && `start_time <= now <= end_time`) |
| `character_service.effective_price()` | 위를 반영한 실가 |
| `CharacterDetail.active_discount` | `{discount_price, start_time, end_time}` — **단건 상세에만** |

즉 요청서가 "`discount_ends_at` 필드가 필요하다"고 한 것은 이미 `end_time` 으로 존재한다.
문제는 **목록 응답(`CharacterSummary`)이 그 값을 버린다**는 것뿐이다 —
`_to_summary` 가 `effective_price` 만 남기고 할인 객체를 안 싣는다.

## 2. 왜 목록에 실어야 하나

아바타 상세는 **목록에서 카드를 눌러 진입하고 추가 조회를 하지 않는다**(`background_story` 때와
같은 N+1 회피 구조 — 요청서에 앱팀이 명시). 따라서 카운트다운을 그리려면 종료 시각이
**목록 응답에** 있어야 한다.

## 3. 변경

### 3-1. `CharacterSummary` 에 `active_discount` 승격

```python
class CharacterSummary(BaseModel):
    ...
    active_discount: Optional[DiscountOut] = None   # 신규 — 카운트다운용
```

`CharacterDetail(CharacterSummary)` 는 이미 같은 필드를 자기 몸에 들고 있으니 **중복 선언을
제거**하고 상속받는다(출력 형태 불변).

`_to_summary` 가 `active_discount(c)` 를 한 번 호출해 `effective_price` 와 함께 채운다.
`active_discount` 는 이미 로드된 `character.discount_events` 를 순회할 뿐이라 **추가 쿼리 0**.

`OwnedCharacterOut`(보유 목록)에는 넣지 않는다 — 이미 산 캐릭터라 할인이 무의미하다.

### 3-2. 할인 이벤트 운영 도구 (dev 웹)

`/__levelcalldemo` 와 같은 방식: `ENV != "prod"` 일 때만 등록되는 HTML 페이지 + JSON 엔드포인트.

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/__discounts` | 관리 HTML |
| GET | `/__dev/discounts` | 캐릭터별 할인 목록(전체) |
| POST | `/__dev/discounts` | 생성 — `{character_id, discount_price, start_time, end_time, activate}` |
| PATCH | `/__dev/discounts/{id}` | 부분 수정(활성 토글·기간·가격) |
| DELETE | `/__dev/discounts/{id}` | 삭제 |

편의: "지금부터 N시간" 프리셋과 "할인율(%)로 입력 → 가격 자동 계산" 을 페이지에서 제공한다
(운영자가 원하는 건 `-50%` 이지 `5.00` 이 아니다).

## 4. 접근성·권한 (⚠ 짚고 갈 것)

실서비스 `beavertalk-app-api` 의 `ENV` 는 `prod` 가 아니라 **`test`** 다. 따라서
`ENV != "prod"` 게이트를 쓰면 **이 도구가 실서비스에도 노출된다.** 그게 요청("웹에서 접근
가능하게")에 부합하지만, 사실을 명시해 둔다.

- 인증은 `CurrentMember`(로그인 필수)를 요구한다 — `/__dev/level-reset` 과 동일 패턴
- 다만 **로그인한 아무 회원이나** 호출 가능하다. 관리자 개념이 시스템에 없다
- 정식 런칭 전까지의 운영 도구로 간주한다. 런칭 시 ① `ENV` 정리 ② 관리자 권한 도입 ③ 별도
  내부 시크릿(`INTERNAL_DISPATCH_SECRET` 같은) 중 하나가 필요하다

## 5. 앱 영향

- `-N%` 배지·"한정 할인" 섹션: `effective_price < price` 면 이미 뜬다 → **데이터만 넣으면 동작**
- 카운트다운: 앱이 `active_discount.end_time` 을 읽어 그려야 한다 → **앱 작업 필요**
  (서버가 목록에 실어주면 그때부터 가능)
