# 포트폴리오 재료 — 캐스케이드 음성 통화 (서버)

> 용도: 개발자 취업·이직. 읽는 사람이 면접에서 **캐물을 것**을 전제로 썼다.
> 모든 수치에 출처를 달았고 **실측/추정**을 구분했다. 확인 못 한 것은 그렇게 적었다.
> 관통 주제: **측정할 수 없으면 고칠 수 없다.**

**맥락 한 줄**: 오디오를 그대로 주고받는 통합 모델(Gemini Live)로 돌던 한국어 회화 통화를
**STT → LLM → TTS 세 조각**으로 분해해 재현했다. 목적은 원가 절감 하나였고, 그래서
**"싸졌다"를 증명할 계측**이 기능만큼 중요했다.

---

## 1. 계측을 먼저 만들었고, 그 계측이 실제로 결함을 잡았다

### 1-1. 벤더 값의 의미를 모를 때 **셋을 다 기록**해 4배 과대계상을 막았다
STT 응답의 과금 초가 증분인지 누적인지 proto 문구로 안 갈렸다(v1 과 표현이 바뀌었다).
한쪽으로 정하지 않고 **sum·max·건수를 다 남기고** 실통화 한 건으로 판정했다.
→ 실제 오디오 **104.5초** / max **102.0초** / sum **419.0초**. **sum 을 썼으면 STT 원가가 4배**였고,
하필 그 숫자가 "캐스케이드가 싼가"의 근거로 쓰였을 것이다. (출처: 실통화 `cascade usage` 로그)

### 1-2. `첫소리=-1ms` 판별식 하나가 무음 사고를 즉시 잡았다
비버가 한마디도 못 하는데 **HTTP 200 이고 ERROR 로그도 없었다**(합성 실패를 graceful 하게
삼키는 구조라). 대답 로그에 "첫 오디오까지 몇 ms"를 넣어 뒀더니 `-1`(= 소리가 한 조각도 안
나감)로 즉시 드러났다. 원인은 스트리밍이 `LINEAR16` 을 거부한 것.
→ **성공/실패가 아니라 "무엇이 실제로 일어났나"를 재는 값**이 사고를 잡는다.

### 1-3. 폴백을 **시끄럽게** 만들어 둔 덕에 권한 문제가 1분에 규명됐다
TTS 엔진 A/B 를 붙이며 "실패하면 조용히 폴백"을 금지했다 — 조용하면 *"제미나이가 느리다"* 가
아니라 *"제미나이인 줄 알았는데 다른 엔진이었다"* 가 되기 때문이다. 모델 ID 를 로그에 박았다.
→ 실제로 `403 aiplatform.endpoints.predict denied` 가 그 줄에서 바로 나왔다(코드가 아니라 IAM).

### 1-4. "실험이 성립하지 않았다"를 알아채게 만들었다
대상 언어를 `__마커__` 로 감싸는 기능을 넣고 **로그를 한 줄도 안 늘렸다**. 그런데 폴백이
조용해서, 모델이 마커를 안 써도 통째로 재생돼 **소리는 정상**이다. 즉 "끊김이 줄었다"는 판단이
마커가 걸린 상태의 결과인지 아닌지 **귀로는 못 가른다.**
→ 마커 상태를 **셋으로** 갈라 찍었다: `없음`(모델이 규칙을 안 지킴) / `있음`(짝 맞음) /
`짝안맞음`(반만 지켜서 폴백). 구간 수만 찍으면 앞의 둘이 뭉개진다.
⛔ 대사 원문은 안 찍는다(통화 내용이 로그에 남는다). "원문이 로그로 새지 않는다"도 테스트로 잠갔다.

### 1-5. 못 모았을 때 **"못 모았다"를 남긴다**
기존 통합 모델 경로는 사용량 수집 실패를 3중으로 조용히 삼켰다(식별자 없음 / 데이터 0건 /
예외). 원가가 안 남아도 아무도 몰랐다. 새 경로는 **`collected=0 reason=…` 한 줄**을 남긴다.
→ 같은 원칙을 산식에도 적용했다: **모르는 벤더는 0원이 아니라 '미상'**(0원으로 먹으면
"공짜"라는 그럴듯한 거짓말이 나온다).

## 2. 가설이 틀렸고 **실측이 뒤집은** 것

### 2-1. "중복 턴을 막는다" → 진짜 발화를 버리고 있었다
한 발화가 턴 2개로 쪼개지는 결함을 고치며 "늦게 온 전사는 꼬리이므로 차단"을 넣었다.
그랬더니 이번엔 **말했는데 빈 턴**이 됐다(speech 1~4초인데 전사 없음).
분류는 맞았다 — 그건 정말 그 턴의 꼬리다. **버린다는 처리가 틀렸다.**
→ **닫힌 턴이 비어 있었으면 버리지 않는다**(전달한 게 없으니 중복이 생길 수 없다).
한쪽만 고치면 다른 쪽이 되살아나는 관계라 두 성질을 같은 파일에 나란히 테스트로 묶었다.

### 2-2. "엔진이 v2 로 뜨면 STT 가 붙은 것" → 아니다
운영 문서에 그렇게 적었는데, 클라이언트 생성은 **로컬에서 키 파일만 읽는다.** 권한이 없으면
**첫 전사 시점에야** 실패가 드러난다. 문서를 고쳤다("진짜 확인은 첫 전사가 뜨는 것").

### 2-3. "음색 이름 체계가 같으니 그대로 넘기면 된다" → 형식이 달랐다
로스터(이름 목록)는 같은데 **API 가 요구하는 문자열이 다르다**:
`ko-KR-Chirp3-HD-Sulafat` vs `Sulafat`. 섞으면 400/404.
→ 주석을 사실로 정정. **문서로 같아 보여도 한 번 쏴봐야 확정된다**를 같이 남겼다.

### 2-4. 내가 쓴 타이밍 테스트가 원래 깨져 있었다
실패를 내 변경 탓으로 넘기지 않고, 변경을 스태시한 뒤 **5회 재현해 4회 실패**를 확인했다.
기대값이 정확히 임계와 같아 경계에 앉아 있었고(윈도우 이벤트 루프는 clock resolution 만큼
일찍 깨어난다) 임계를 조정했다. **아무도 모를 수 있었지만 먼저 보고했다.**

### 2-5. "상대 모듈은 아직 문자 기준이다" → 머지 전 옛 코드를 본 것이었다
브랜치가 갈라진 채 상대 코드를 1차 자료로 삼으면 **구조적으로 생기는 착각**이다.
머지 커밋에 그 사실을 남겼다.

## 3. 갈림길 — 고른 것과 **버린 것**

### 3-1. 턴 종료를 벤더 설정으로 하려다 접었다
`voice_activity_timeout` 을 턴 노브로 쓰려 했는데 proto 원문이 **"the server will automatically
close the stream"** 이었다. 800ms 로 뒀으면 **0.8초 쉴 때마다 스트림이 죽었다.**
→ **턴 시작은 엔진 VAD / 턴 종료는 서버 자체 타이머.**
**버린 것**: 벤더 설정 하나로 끝내기(간단하지만 스트림이 죽는다).

### 3-2. 원인을 모르면 값을 덮지 않았다
계측이 79초로 튀는 결함에서 보정값을 넣지 않고 **판정용 로그 3줄**을 심어 다음 통화로 후보를
갈랐다(롤오버 0회인데 79초 → 기준점이 다르다는 뜻). 확정 후에도 **벤더의 의미를 안다고
가정하지 않고**, "우리가 확실히 아는 것"(흘려보낸 오디오보다 한참 과거는 침묵 계산에 못 쓴다)
만으로 거절 규칙을 만들었다.
**버린 것**: 오프셋 무시(계측이 통째로 죽는다) / 감으로 보정값 빼기.

### 3-3. 임계값을 만지고 싶은 자리에서 **재는 시점**을 고쳤다
끼어들기가 거의 다 기각됐다(에너지 0.0000~0.0017 < 임계 0.05). 임계를 낮추는 게 제일 쉬웠지만,
그 값은 별도 실측으로 정하기로 되어 있었다.
→ 원인은 **에너지를 '지금' 값으로 재고 판정은 ~800ms 전 오디오로 하고 있었던 것**이라,
(시각, 에너지) 짧은 이력을 두고 **그 이벤트가 가리키는 시각의 에너지**를 보게 했다.
**버린 것**: 임계 하향(증상은 사라지지만 에코 방어가 같이 무너진다).

### 3-4. 이력 상한을 **턴 수 → 글자 수**로 바꿨다
12턴 상한은 15분 통화(72턴 관측)에서 앞부분을 통째로 잊게 만든다. 그리고 턴 수는 애초에
**잘못된 단위**다 — 긴 발화 몇 개가 짧은 턴 12개보다 크고, 과금은 글자·토큰으로 된다.
→ 정상 통화가 절대 안 걸릴 크기의 **글자 백스톱**. 잘라낸 내용은 **버리지 않고 보관**한다
(통합 모델은 압축으로 날아간 대화를 되살릴 수 없었지만, 여기선 원문이 우리 손에 있다).

### 3-5. 실험을 오염시키지 않는 **순서**로 냈다
사용자가 "끊김"을 직접 재보겠다고 한 시점에, 끊김에 영향을 주는 두 변경을 같이 내지 않았다.
같이 내면 무엇 때문에 달라졌는지 못 가린다.
**버린 것**: 한 번에 내서 배포 횟수 줄이기.

### 3-6. 깨진 게이트 **위에** 기능을 얹지 않았다
"dev 전용"이라던 블록이 실서비스에도 열려 있었다(운영 환경 값이 `prod` 가 아니었다).
근본 수정은 같은 조건을 쓰는 다른 블록까지 동시에 닫는다 → 영향 범위 조사가 선행이다.
→ **전용 스위치(기본 꺼짐)로 이 기능만** 막았다. 환경 값이 틀려 있어도 안전한 구조다.
⭐ 그리고 **틀린 주석이 다른 팀의 설계 전제가 됐던 사례**(클라이언트가 "운영에선 소켓이 안
열린다"를 안전장치로 세고 있었다)를 주석에 남겼다.

### 3-7. 판정 재료를 지시받은 것과 **다르게** 골랐다
"들린 글자 수가 0이면 취소하지 마라"는 지시에서, 글자는 **문장 단위**라 2초를 들었어도 0 일 수
있었다. 그대로 쓰면 진짜 끼어들기를 막는다.
→ **오디오 시간**으로 바꿔 제안하고 그 근거를 같이 냈다.

### 3-8. 설계 예산보다 **실사용 판정**을 위에 뒀다
첫 소리 3.5초는 설계 예산(1.5~2.5초) 초과였지만 실사용자가 "느리지 않다"고 판정했다.
→ 예산을 합격선에서 내리고 참고값으로 뒀다. 다만 **"실사용자 대다수는 초보라 체감이 다를 수
있다"** 를 남겨, 나중에 다시 볼 자리를 표시했다.

## 4. 조용한 실패를 **보이게** 만든 설계

| 무엇이 조용했나 | 어떻게 드러냈나 |
|---|---|
| TTS 합성 실패(200·로그 0) | 대답 로그의 `첫소리=-1ms` 판별식 |
| 엔진 폴백(소리는 정상) | 폴백 WARNING 에 **모델 ID + 실패 사유** |
| 마커 미준수(소리는 정상) | 마커 상태를 3분류로 로깅 |
| 사용량 미수집 | `collected=0 reason=…` 한 줄 |
| 모르는 벤더 단가 | 0원이 아니라 **'미상'** 으로 표시 |
| 스트림 롤오버 | 서버 로그에 한 줄도 없던 것을 추가(그래서 79초 결함 진단이 막혀 있었다) |
| 샘플레이트 불일치 | 클라가 값을 안 보내면 "기본값 가정"을 로그로(조용히 어긋나면 목소리만 이상해진다) |

## 5. 동시성·타이밍 (실시간 오디오의 진짜 난점)

### 5-1. 같은 값처럼 보이는 **시계가 세 번 달랐다**
| 무엇 | 증상 | 실측 |
|---|---|---|
| 파이프라인 지연 vs 침묵 임계 | 한 발화가 턴 2개 | 지연 810~914ms > 임계 800ms |
| VAD 지연 vs 전사 지연 | 말했는데 빈 턴 | VAD 291·338·348 / 전사 723~870 |
| 에너지 측정 시점 vs 이벤트 시점 | 짧게 말하면 끼어들기 안 먹음 | 기각 시 0.0000~0.0017 |
세 번 다 **"두 값이 같은 시계일 것"** 이라는 가정에서 나왔다. 로그의 **분포**가 단서였다
(예: "빈 턴만 유독 지연이 절반").

### 5-2. 취소 태스크가 세션을 죽이는 문제
`asyncio.TaskGroup` 의 자식을 밖에서 취소하면 **그룹 전체가 무너진다**(실측 확인).
우리가 건 취소를 **태스크가 흡수하고 정상 종료**하게 만들어야 세션이 산다.
→ "취소 뒤에도 세션이 살아 있다"를 테스트로 잠갔다.

### 5-3. 스트림 교체 중 오디오를 잃지 않기
STT 스트림엔 수명 한도가 있어 통화 중 교체가 필요하다. 교체 중 들어온 오디오를 버퍼에 담았다가
새 스트림에 흘리고, **오프셋 기준점을 다시 잡아** 이벤트 시각이 연속되게 했다.
⭐ 그런데 재생 구간에 **이미 인식이 끝난 부분**이 섞이면 같은 말이 두 번 인식된다(턴 중복 +
그 구간 이중 과금). → 확정된 지점까지는 **잘라내고** 흘린다.

### 5-4. 순서 보장이 곧 계약이다
서버 출력에 불변식을 두고(턴 시작이 오디오보다 먼저 / 실시간보다 앞서 밀지 않기 / 취소된 턴엔
종료를 내지 않기) **한 클래스에 모아 테스트로 고정**했다. 클라이언트의 "취소 이후 도착분은
버린다" 판별식이 이 순서에 의존하기 때문에, 깨지면 **정상 오디오를 조용히 버린다.**

## 6. 회귀로 **못박은** 것 (다음 사람이 되돌리지 못하게)

- **실측 수치를 테스트에 박았다** — 관측된 지연·오프셋 값을 그대로 넣어, 같은 가정이 되살아나면
  실패하게 했다(예: 지연 900ms > 임계 800ms 조건에서 한 발화는 한 턴).
- **수정이 실제로 필요한지 증명** — 세 겹 방어를 **하나씩 꺼서** 각 테스트가 실패하는 것을
  확인했다(꺼도 통과하면 그 수정은 불필요하다는 뜻이다).
- **스트리밍 인코딩** — 비스트리밍에선 유효한 값이라 "통일하자"며 되돌아오기 쉬운 자리라,
  스트리밍은 PCM / 비스트리밍은 MP3 를 **둘 다** 테스트로 고정했다.
- **엔진별 음성명 형식** — 실사격에서만 드러난 결함이라 테스트가 없으면 다음 리팩터에 돌아온다.
- **로그에 통화 원문이 새지 않는다** — 나중에 "디버깅 편하게" 원문을 얹지 못하게.
- **노출 게이트** — 환경 값이 틀린 상태(운영과 동일 조건)에서도 닫히는지를 테스트에 넣었다.

  잘못 통과시킬 뻔했다 → **실제 응답**(연결 종료 코드)으로 바꿨다.

## 8. 확인 못 한 것 (면접에서 물으면 이렇게 답한다)

- **새 TTS 엔진의 실제 지연·품질** — 권한 문제로 아직 통화가 안 돌았다. 스트리밍 동작 자체는
  실사격으로 확인됐다.
- **모델이 언어 마커를 얼마나 지키는가** — 측정 장치는 넣었고 아직 통화 데이터가 없다.
- **끼어들기 임계값(에너지)의 적정값** — 별도 실측으로 정하기로 되어 있어 **감으로 만지지
  않았다.** 지금은 "재는 시점"만 고친 상태다.
- **실기기 끼어들기** — 브라우저 데모는 캡처·재생을 같은 엔진이 소유해 에코 제거가 실제로
  걸린다. 그래서 **이 데모 결과는 실기기 판정 근거가 되지 못한다**(그 사실을 문서에 남겼다).
