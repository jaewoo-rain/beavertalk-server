## 1. 진단은 정확했고, 한 가지가 더 있었습니다

앱팀이 지적한 3가지를 코드로 전부 확인했습니다(갱신 수신 경로 0건 · 만료는 검증 때 한 번만 저장 ·
판정은 저장된 `end_date` 만 봄). 운영 store 구독 **4건이 4건 다 만료** 상태였습니다 — 증상 실재.

### ⛔ 앱팀 문서에 없던 진짜 병목: `purchase_token` 을 저장하지 않았다
`iap_receipt`·`subscribe` **어디에도** 없었습니다. 토큰은 요청 → `verify()` → `acknowledge()` 로
흐르고 버려졌습니다.

⇒ 제안된 두 방안이 **둘 다 이것 없이는 불가능**했습니다. 스토어에 다시 물으려면 토큰이 필요합니다.
⇒ RTDN 도 불가능했습니다: 알림에 토큰은 실려 오지만 **토큰 → 회원** 매핑이 필요하고, 그 매핑이
   곧 저장된 토큰입니다. (09-28 이후 구매는 회원 해시로도 되지만, 지금 만료된 4건은 그 전 구매입니다.)

### ⭐ 반대로 좋은 소식: 재조회 코드는 이미 있었다
`core/iap.py` 의 `_verify_google` 이 이미 `purchases/subscriptionsv2/tokens/{token}` 을 GET 해서
`subscriptionState` 를 보고 `expiryTime` 을 돌려줍니다(애플도 동형).
⇒ **재조회 = 같은 `verify()` 재호출.** 새 스토어 API 코드가 필요하지 않았습니다.

## 2. 무엇을 바꿨나 — **입구 4개, 갱신 함수 1개**

```
① 상태 조회 때 자기치유 ─┐
② 스케줄 스윕(매시) ────┤→  _refresh_from_store()  →  subscribe.end_date · billing_state · is_trial
③ 복원/재검증 ──────────┘    ⭐ 알림 본문은 믿지 않는다 — 진실은 항상 스토어 재조회
④ (보류) 스토어 알림 ────┘
```

| 입구 | 언제 도나 | 무엇이 좋아지나 |
|---|---|---|
| ① 자기치유 | `/subscriptions/status` · `/purchases/entitlement` 호출 때 `end_date` 가 지났으면 | **앱이 시작할 때 자동 복구.** 앱 변경 0 |
| ② 스윕 | Cloud Scheduler `beavertalk-refresh-subscriptions` · **매시 20분(KST)** | 앱을 안 열어도 해지·환불 반영 |
| ③ 복원/재검증 | 「구매 복원」·재검증 요청 | **토큰 없는 기존 영수증에 토큰을 채운다**(아래 §3) |
| ④ 알림 | 보류 | (즉시 반영 — 출시 뒤) |

### 저장 추가
`iap_receipt.purchase_token`(인덱스) · `iap_receipt.last_store_check_at`(재조회 쓰로틀).
둘 다 NULL 허용 · 기본값 없음 · **기존 행 백필 없음**(토큰이 어디에도 없어 추측할 수 없음).

### ⛔ 절대 원칙 4가지 — 전부 회귀 테스트로 고정
1. **`source='store'` 만 재조회한다.** 수동 부여 Premium(운영 7건)을 스토어에 물으면 전부
   `invalid` 가 나와 날아갑니다. 최우선 안전장치입니다.
2. **스토어 장애(`unavailable`)에 박탈하지 않습니다.** 저장값을 그대로 두고 다음에 재시도합니다.
   스토어가 잠깐 죽었다고 유료 회원이 Free 로 떨어지지 않습니다.
3. **통화 경로에 스토어 호출이 없습니다.** 통화가 스토어 장애에 묶이면 안 됩니다. 앱이 시작할 때
   치유되고, 통화는 치유된 저장값을 읽습니다.
4. **`purchase_token` 을 로그에 찍지 않습니다.** 세 파일의 모든 로그 호출을 정적 스캔해 고정했습니다.

### 부수 수정 — 결제 로그가 운영에서 안 보였습니다
`main.py` 로거 목록에 `domains.commerce` 가 빠져 있어서 「지급 완료」·**「acknowledge 실패」**·
「동시 요청 경합」이 **한 줄도** 안 떴습니다. acknowledge 를 3일 안에 못 하면 구글이 자동 환불하는데
(돈은 돌아가고 지급은 남음) 그 경고가 안 보였습니다. 추가했습니다.

## 3. ⭐ 앱이 해야 할 것 — 하나뿐입니다

### 만료된 기존 구독 회복: 「구매 복원」 1회
지금 만료된 4건은 **토큰이 저장돼 있지 않아** 서버가 혼자 재조회할 수 없습니다.
「구매 복원」을 한 번 누르면 앱이 토큰을 실어 보내고, 서버가 그 자리에서

- `end_date` 를 스토어 값으로 올리고(**한 방향만** — 내리지 않습니다),
- 비어 있던 `purchase_token` 을 채우고,
- `is_trial` 도 채웁니다.

⇒ **그 뒤부터는 ①②가 그 회원에게도 자동으로 작동합니다.** 앱에 이미 있는 버튼이라 **코드 변경
없습니다.**

### 그 밖에 앱이 바꿀 것: 없음
신규 구매는 처음부터 토큰이 저장되므로 아무 조치가 필요 없습니다.

③ RTDN 은 공개 엔드포인트 신설 + 서명 검증이 전부라, 출시 직전에 넣을 변경이 아닙니다.

## 6. §22-⑤⑦ 체험·주기 — 배포 완료

`GET /subscriptions/status` 응답에 4개가 추가됐습니다(배포된 서버 OpenAPI 로 확인):

| 필드 | 의미 |
|---|---|
| `billing_period` | `monthly` · `yearly` — 「₩33,000 per month」 오표기 해결 |
| `product_id` | 스토어 상품 ID 원본 |
| `is_trial` | 체험 중인지 |
| `trial_ends_at` | 체험일 때의 종료 시각(별도 컬럼 아님 — `is_trial` 일 때의 `end_date`) |

체험 판정 근거: Google `lineItems[].offerDetails.offerId == "trial-7d"` · Apple `offerType == 1`.
**검증·재조회·재검증 세 자리 모두**에서 채우므로, 복원만 눌러도 기존 회원의 `is_trial` 이 정정됩니다.

## 7. 앱팀이 재현할 수 있는 테스트

테스트 구독은 월간 5분 · 연간 30분 · 체험 3분 주기로 갱신됩니다.

1. 월간 `bt_max_monthly` 결제 → verify 200 → 앱 「Premium」
2. **5분 넘게 기다린다**(첫 기간 종료 + 스토어 갱신)
3. 앱을 끄고 다시 켠다 → 상태 조회가 돌면서 **자동으로 `end_date` 가 미래로 이동**
   - 전에는 여기서 「Your Premium trial ended · You are on Free now」가 떴습니다
4. 추가 확인: 앱을 아예 안 켜도 **매시 20분(KST)** 스윕이 같은 일을 합니다
5. 해지 테스트: 스토어에서 해지 → 기간이 끝나면 위 두 경로 중 먼저 오는 쪽이 Free 로 내립니다

### 검증 결과(서버 쪽)
- 스윕 엔드포인트 실호출: `{"refreshed":0}` **HTTP 200** (지금은 토큰 있는 만료 구독이 0건이라 0)
- 잘못된 시크릿: **403**
- 스케줄러 잡 `beavertalk-refresh-subscriptions` **ENABLED** · `20 * * * *` Asia/Seoul
