## ⛔ 0. 먼저 읽을 규칙 — «키 없음 ≠ 0»

이번에 추가된 필드는 **값이 없으면 키 자체를 보내지 않는다.** `0`·`""` 으로 채우지 않는다.

| 응답 | 이유 |
|---|---|
| `"remaining_s": 180` | 남은 시간 180초 |
| (키 없음) | **해당 없음** — 예산 대상이 아니거나 집계된 값이 없음 |
| `"remaining_s": 0` | 남은 시간이 진짜 0초(= 오늘 다 씀) |

`0` 과 «없음» 은 다른 뜻이다. 파싱할 때 `json['x'] ?? 0` 으로 뭉개면 "데이터 없음" 이 "0분 학습" 으로 보인다.
→ **nullable 로 받고, null 이면 UI 에서 그 항목을 숨겨라.**

적용 대상: `call_started` 의 `remaining_s`·`course`·`fragment_index`·`max_fragments` /
`daily-status` 의 `budget_s`·`used_s`·`remaining_s` / 달력의 `words` /
결과 문장의 `kind`·`paired_sentence_id`·`nuance`.

## 1. 구독 2단화 — pro·max 가 사라지고 premium 하나

`GET /subscriptions/status` (`SubscriptionStatusOut`)

```jsonc
{ "state": "active_premium", "plan": "premium", ... }
```

**state (7종)** — 종전 8종에서 `active_pro`·`active_max` 가 `active_premium` 하나로 합쳐졌다:
`free` · `trial` · `active_premium` · `grace` · `on_hold` · `ending` · `expired`

**plan (1종 + null)** — `"premium"` 뿐. Free 는 `plan: null` 이다(구독 행이 없다는 뜻).
`free`·`expired` 를 뺀 모든 state 에서 `plan` 은 반드시 채워진다.

> ⚠ `state` 와 `plan` 은 다른 축이다. `grace`/`on_hold`/`ending` 은 "직전 플랜을 유지" 하는
> 상태라 state 만 보고 기능을 열고 닫으면 안 된다. **기능 판정은 `plan` 으로 한다.**

**앱이 할 일**
- `active_pro`/`active_max` 분기 삭제 → `active_premium` 하나로
- `plan == "pro" | "max"` 분기 삭제 → `plan == "premium"` 하나로
- 스토어 상품 ID 는 **그대로**(`bt_pro_monthly`·`bt_max_yearly` 등) — 서버가 전부 `premium` 으로 매핑한다.
  스토어 정리 전까지 앱은 기존 상품 ID 를 계속 쓴다.

**플랜별 통화 모양**

| | Free (`plan == null`) | Premium |
|---|---|---|
| 통화 | **음성**(영상 화면 감춤) | **영상**(표정 on) |
| 조각 수 | 1 (연장 없음) | 3 |
| 하루 총량 | 5분(300초) | 15분(900초) |

→ 화면도 갈라야 한다: **Free 는 영상통화 UI 를 띄우지 않고, "이어서(Keep talking)" 시트도 열지 않는다.**

## 2. `call_type` — 앱이 보내는 값은 이제 2개뿐

WS `start` 프레임의 `call_type`:

| 값 | 뜻 | 누가 보내나 |
|---|---|---|
| `"auto"` | **학습** — 서버가 표현학습/프리토킹 중 무엇을 할지 정한다 | 홈 «학습» 버튼 |
| `"chat"` | **자유대화**(신규) | 홈 «자유대화» 버튼 |
| (미전송) | 레벨 미확정이면 레벨테스트, 아니면 `auto` | 구버전 앱 |

- `"normal"` 은 **죽은 값**이다. 보내도 서버가 조용히 `chat` 으로 취급한다(구버전 호환).
- `"expression"` / `"freetalk"` 는 **개발자도구·하네스 전용**이며 admin 계정에서만 의미가 있다. 일반 앱은 보내지 않는다.
- 서버가 `auto` 에서 무엇을 골랐는지는 `call_started.course`(`"expression"` | `"freetalk"`)로 알려준다.

### ⭐ 알람 통화도 같다
알람에서 거는 통화도 **앱이 `call_type` 을 실어야 한다.** 알람 설정에 «학습 / 자유대화» 선택이 필요하다.
안 보내면 서버 기본값(학습=`auto`, 레벨 미확정이면 레벨테스트)으로 떨어진다.

### 자유대화(`chat`)가 다른 점
- 한국어 위주 대화. 학습자가 «모르겠다» 거나 모국어로 물으면 그 턴만 모국어로 설명하고 바로 한국어로 돌아온다.
- Premium 은 영상 + 표정, Free 는 음성.
- 통화가 끝나면 서버가 **대화 기억**(요약·관심사·핵심 요소)을 저장해 다음 자유대화 시작에 넣는다. **앱이 할 일 없음.**
- 통화 후 분석·문장 추출·복습·발음은 **다른 통화와 동일**하다.

## 3. `tz` — IANA 존 이름을 보내라 (신규)

하루 경계(자정)를 **기기 로컬 기준**으로 잡는다. 종전 `tz_offset_min`(분) 대신 **IANA 존 이름**을 보내면 서머타임 경계에서도 정확하다.

| 보낼 곳 | 파라미터 |
|---|---|
| WS `start` | `"tz": "Asia/Seoul"` (기존 `tz_offset_min` 과 함께 보내도 됨) |
| `GET /calls/daily-status` | `?tz=Asia/Seoul` |
| `GET /stats/calendar` | `?tz=Asia/Seoul` |

- 우선순위: `tz`(IANA) → `tz_offset_min`/`tz_offset`(분) → UTC
- 잘못된 이름이면 조용히 offset 폴백. 셋 다 없으면 UTC — **한국 사용자는 오전 9시에 날짜가 바뀐다. 반드시 보내라.**
- Flutter: `DateTime.now().timeZoneName` 은 IANA 가 아니다(`KST` 등). `flutter_timezone` 의 `getLocalTimezone()` 을 써라.
- ⚠ **세 곳에 같은 값**을 보내야 한다. 하나만 다르면 "달력엔 어제인데 통화는 오늘로 셌다" 가 된다.

## 4. 하루 총량(15분) — `call_started.remaining_s` 와 종료 규칙

### 예산
- Free 300초 / Premium 900초. **콜타입 무관 합산**(학습·자유대화·프리토킹 전부 한 주머니).
- **레벨테스트는 예산에서 제외**한다.
- 경계는 기기 로컬 자정(위 `tz`). 23:58 에 시작한 통화는 그 날에 달리고, 자정을 넘기면 **다음 날 예산이 새로 시작**된다.
- Free 로 5분 쓰고 결제하면 남은 시간은 **10분**(= 900 − 300).

### `call_started.remaining_s` (신규)
```jsonc
{ "type": "call_started", "call_id": "1234", "remaining_s": 420,
  "fragment_index": 2, "max_fragments": 3, "course": "expression" }
```
- **이 조각이 지금 쓸 수 있는 초** = `min(남은 하루 예산, 조각 상한 360)`
- 조각마다 새로 계산해 내려준다. 조각2 를 열면 다시 받는다.
- 키가 없으면 **예산 대상 아님**(admin 면제) 또는 조각을 잇지 않는 통화(레벨테스트). 이때는 타이머를 예산으로 제한하지 마라.

### 종료 규칙 — 조각 경계와 동일
- 앱은 `remaining_s` 로 카운트다운한다.
- `remaining_s` 가 0 이 되면 **그 조각을 닫는다**. `fragment_index == max_fragments` 이거나 다음에 받을 `remaining_s` 가 없을 상황(예산 소진)이면 **재연결하지 않고 통화를 끝낸다**.
- 서버에도 안전판이 있다: 경과가 `remaining_s + 60` 을 넘으면 서버가 **작별 인사를 시키고** 닫는다(뚝 끊지 않는다). 앱이 늦어도 흉하게 끊기진 않지만 **UI 타이머는 `remaining_s` 를 따라야 맞다.**
- 예산이 소진된 상태에서 통화를 걸면 WS 가 `ServerError(code="DAILY_LIMIT", recoverable=false)` 를 보내고 닫는다.

### 새 에러 코드
- `ALREADY_IN_CALL` (`recoverable=false`) — 이 회원의 다른 통화가 이미 진행 중. "이미 통화 중입니다" 를 띄우고 **재시도하지 마라.**

## 5. `GET /calls/daily-status` — 새 필드 3개

```jsonc
{
  "date": "2026-09-23",
  "called_today": true,
  "level_test_today": false,
  "can_call_normal": true,
  "can_call_level_test": true,
  "max_fragments": 3,
  "budget_s": 900,       // ⭐ 신규 — 이 회원의 하루 총량(초)
  "used_s": 480,         // ⭐ 신규 — 오늘 쓴 초
  "remaining_s": 420     // ⭐ 신규 — 남은 초
}
```
- 셋은 **한 묶음**이다. 예산 대상이 아니면(admin 면제) **셋 모두 키가 빠진다.**
- `remaining_s` = `budget_s − used_s` (오늘 남은 총량). ⚠ **`call_started.remaining_s` 와 뜻이 다르다** — 저건 «이 조각» 이 쓸 수 있는 초라 최대 360 으로 잘린다. 같은 이름이지만 같은 숫자가 아니다.
- `can_call_normal` 은 이제 «횟수» 가 아니라 «예산이 남았나» 다. 통화 시작 전 1차 검증은 이 값으로 한다.
- ⛔ `date` 는 **오늘 날짜로만** 물어라. 과거 날짜로 물으면 `called_today` 만 유효하고 `can_call_*` 은 여전히 "지금" 기준으로 답한다.

`GET /calls/{call_id}/resume-status` 의 `can_resume` 에도 «남은 예산 > 0» 이 들어갔다 — 조각 상한이 남아도 예산이 없으면 `false` 다.

## 6. 결과 문장 — 현지인 표현 짝 (`kind` · `paired_sentence_id` · `nuance`)

통화 후 분석이 학습한 표현마다 **원어민이 실제로 쓰는 표현**을 하나 더 만든다.
예: `배고파요` → `뱃가죽이 등에 붙을 것 같아요`

### 필드 (`GET /calls/{call_id}/result` 의 `sentences[]`)

| 필드 | 기본 문장 | 현지인 표현 |
|---|---|---|
| `kind` | (키 없음) | `"native"` |
| `paired_sentence_id` | (키 없음) | 짝이 되는 기본 문장의 `sentence_id` |
| `nuance` | (키 없음) | 뉘앙스 설명(모국어) |

> **기본 문장에는 이 세 키가 아예 없다.** `kind == null` 로 오는 게 아니라 **키가 없다.**

### 순서 — 서버가 이미 정렬해서 준다
3개를 배웠으면 6개가 온다. 순서는 **「기본1 · 짝1 · 기본2 · 짝2 · 기본3 · 짝3」**.
앱은 재정렬하지 말고 **받은 순서대로** 그리면 된다. 짝을 기본 바로 아래 들여쓰기로 붙이면 된다.

같은 규칙이 **복습·발음평가**에도 적용된다 — TTS·발음 채점이 현지인 표현에도 똑같이 붙는다.

북마크 목록은 통화와 무관한 목록이라 `kind`·`nuance` 만 오고 `paired_sentence_id` 와 순서 보장은 없다.

## 7. 학습달력 — `GET /api/v1/stats/calendar` (신규)

```
GET /api/v1/stats/calendar?start=2026-09-01&end=2026-09-30&tz=Asia/Seoul
Authorization: Bearer <JWT>
```

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `start` | ✅ | 로컬 날짜 `YYYY-MM-DD`(포함) |
| `end` | ✅ | 로컬 날짜 `YYYY-MM-DD`(포함) |
| `tz` |  | IANA 존 이름. 권장 |
| `tz_offset_min` |  | `tz` 없을 때 폴백(분, 동쪽 +) |

### 응답
```jsonc
{
  "days": [
    { "date": "2026-09-22", "sentences": 6, "words": 132, "call_count": 2, "call_minutes": 14 },
    { "date": "2026-09-23", "sentences": 3, "call_count": 1, "call_minutes": 5 }   // words 키 없음
  ],
  "total": {
    "sentences": 9, "words": 132, "call_count": 3, "call_days": 2, "call_minutes": 19
  },
  "streak_days": 2
}
```

| 필드 | 뜻 |
|---|---|
| `sentences` | 그 날 배운 문장 수 |
| `words` | 그 날 **사용자가 말한 단어 수**. 대략치다(중복 포함). 집계된 게 없으면 **키 자체가 빠진다** |
| `call_count` | 통화 수 |
| `call_minutes` | 통화 시간(분, 올림). `total.call_minutes` 는 일별 올림의 합이 아니라 **전체 초를 한 번 올림**한 값이라 일별 합과 다를 수 있다 — 정상이다 |
| `call_days` | (total 전용) 통화한 날 수 |
| `streak_days` | **학습 연속일** — 오늘까지 이어진 연속 통화 일수. 최대 999. **연속이 끊겼으면(오늘도 어제도 통화 없음) 키 자체가 빠진다** — 0 이 아니다 |

- **통화가 없는 날은 `days` 에 아예 없다.** 달력 셀을 채울 때 빠진 날짜 = 통화 없음.
- `streak_days` 는 `start`/`end` 범위와 무관하게 **오늘 기준**으로 계산한다. 어제까지 이어져 있고 오늘 아직 통화를 안 했으면 어제 기준 연속일이 온다(오늘 통화하면 +1).
- 집계 대상은 «성립 통화»(학습자가 최소 한 번 말한 통화). **레벨테스트는 제외**.
- 422: `start > end`, 범위가 400일 초과, 날짜 형식 오류.
- 일본어·중국어는 띄어쓰기가 없어 `words` 를 글자 수 기반으로 환산한다 — **"대략 이 정도 말했다" 용도**이지 정확한 수치가 아니다.

## 8. 개발자 도구 — `plan_override`

admin 계정에서만 동작하는 «Premium 으로 통화 / Free 로 통화» 스위치.

| 보낼 곳 | 값 |
|---|---|
| WS `start` | `"plan_override": "free"` \| `"premium"` |
| `GET /calls/{call_id}/resume-status` | `?plan_override=free` \| `premium` |

- **엔진 선택(영상/음성·모델)과 조각 수**를 그 플랜 기준으로 맞춘다 — 실사용 모양을 그대로 재현한다.
- admin 이 아니면 **조용히 무시**(본인 플랜으로 진행). 에러가 아니다.
- 이어하기 조각에도 **같은 값을 다시 보내야 한다**(서버가 조각마다 재적용).
- 결제·구독 상태는 이 값을 전혀 모른다.

## 10. 배포 순서

### ⛔ 서버를 **단독으로 먼저 올릴 수 없다**
맨 위 P0 3건 때문이다. 서버만 올리면 그날로 **프리미엄 결제자가 영상통화를 못 보고**(P0-1),
**결과 화면이 "새로운 표현 6개" 라고 거짓말하며**(P0-3), **QA 도구가 죽는다**(P0-2).

### 순서
1. **앱에서 P0 3건을 먼저 고쳐 둔다** (서버 배포 전에 코드만 준비 — 배포는 아직)
   ⚠ P0-1·P0-2 는 **지금 서버(구버전)에서도 안전하다** — 구서버는 `active_pro`/`active_max` 를
   보내니 새 맵에 옛 키를 **둘 다 남겨두면** 두 서버 모두에서 돈다. `plan_override` 도
   구서버는 `extra=ignore` 라 모르는 값을 조용히 버린다(통화는 열린다).
   ⇒ **P0-1·P0-2 는 서버보다 먼저 올려도 된다.** 그게 제일 안전한 순서다.
2. **서버 배포** (C3 `call_type` 과 C7 자유대화 대본은 짝이라 따로 못 나간다 — 한 번에)
3. **앱 배포** (P0-3 + P1 + P2 새 기능)

### 왜 P0-3 은 서버보다 먼저 못 올리나
현지인 표현 짝은 **서버가 배포돼야 생긴다.** 그 전엔 `kind` 가 아예 안 와서 앱이 새 코드를
써도 티가 안 난다 — 그러니 같이 나가도 되고 뒤에 나가도 된다. 다만 **서버가 먼저 나가고
앱이 늦으면 그 사이 사용자는 "6개" 를 본다.** 간격을 짧게 가져가라.
