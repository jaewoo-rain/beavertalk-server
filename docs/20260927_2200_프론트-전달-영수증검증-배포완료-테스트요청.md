## 1. 영수증 검증 — 무엇이 됐나

### 구글 Play
- `purchases.subscriptionsv2.get`(구독) · `purchases.products.get`(캐릭터)
- 유효 판정: `subscriptionState` **ACTIVE 또는 IN_GRACE_PERIOD** + `product_id` 일치
  (캐릭터는 `purchaseState == 0`)
- ⭐ **`acknowledge` 구현 완료** — v1 `purchases.subscriptions.acknowledge` /
  `purchases.products.acknowledge`
  ⛔ 순서는 **「검증 → 지급 커밋 → acknowledge」** 다. 지급 전에 acknowledge 하면 지급이
  실패해도 환불 창구가 닫힌다. acknowledge 실패는 **지급을 되돌리지 않는다**(구글이 3일 준다)
- 인증: 서비스계정 JSON → JWT-bearer(RS256) → access token(만료 60초 전 갱신 캐시)
  ⚠ 새 의존성 없음 — `httpx` + 기존 `pyjwt`(APNs 가 이미 쓴다)로 직접 돌렸다

### 애플 App Store
- App Store Server API 「Get All Subscription Statuses」
  `GET /inApps/v1/subscriptions/{transactionId}`
- ⭐ base URL 을 `api.storekit.apple.com` / `api.storekit-sandbox.apple.com` 로 잡았다 —
  **흔히 잘못 쓰는 구식 `itunes.apple.com/verifyReceipt` 가 아니다**(애플 공식 라이브러리
  소스를 직접 읽어 확인)
- 인증: `.p8` → ES256 JWT(exp 5분) · Issuer ID · Key ID
- 유효 판정: `product_id` 일치하는 `lastTransaction` 의 `status` **1(활성)·4(유예)** 만
- ⚠ 애플에는 **acknowledge 류 절차가 없다.** 환불 구조가 다르다(요청 발생 시 소비 데이터
  제출 방식). 원문으로 「전혀 없다」를 확정하진 못해 **코드 주석에 「확인 못 함」을 남겼다**

### 테스트 구매 구분 — 사용자 결정 (가) 반영
> 「응답에 `testPurchase` 표시가 붙는다. 운영 지급에서 구분할지 서버가 결정」

**구분합니다. 다만 지급은 막지 않습니다.**

```
구글: testPurchase / purchaseType == 0     (라이선스 테스트 계정)
애플: environment == "Sandbox"
        ↓
iap_receipt.is_sandbox = 앱이 신고한 값  OR  스토어가 확인한 값
        ↓
지급은 그대로 → 테스터도 Premium 을 쓴다 (QA 안 막힘)
```

- 나중에 매출 집계는 `WHERE is_sandbox = FALSE AND is_stub = FALSE` 로 걸러낸다
- ⭐ **앱이 신고한 값과 스토어 값이 다르면 경고 로그**가 남는다
  (`iap: sandbox 불일치 클라=False 스토어=True`) — 앱이 테스트 사실을 안 보낸 경우를 잡는다
- ⚠ **`is_sandbox` 는 `iap_receipt`(영수증)에만 붙는다.** `subscribe`(구독 상태)에는 없다 —
  「지금 Premium 인가」와 「이 돈이 진짜인가」는 다른 질문이라 다른 표에 뒀다
- 윈백(`offerDetails.offerId`, 예: `winback-50-1m`)은 **로그로만 기록**한다. 지급 로직을
  가르지 않았다(요청서 §16 의 윈백 기록은 선택 항목)

⛔ **왜 「막지 않는다」인가**: 라이선스 테스트 그룹이 **누구나 가입 가능**이라 막지 않으면
공짜 Premium 경로가 열린다. 그런데 막으면 **운영에서 결제 QA 자체가 불가능**해진다.
⇒ 표시를 남기고 집계에서 빼는 쪽이 둘 다 만족한다.
