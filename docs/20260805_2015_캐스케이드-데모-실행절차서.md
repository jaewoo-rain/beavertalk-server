## 1. 준비 — 파일 3개 복사 + 패키지 1개 설치

### 1-1. 파일 복사 (전부 gitignore 대상이라 커밋되지 않는다)

메인 레포(`C:\Users\jaewoo\Desktop\beavertalkweb\beavertalk-server`)에서 **워크트리로** 복사한다.
PowerShell 기준:

```powershell
$src = "C:\Users\jaewoo\Desktop\beavertalkweb\beavertalk-server"
$dst = "C:\Users\jaewoo\.herdr\worktrees\beavertalk-server\feat-cascade-voice"
Copy-Item "$src\.env"          $dst
Copy-Item "$src\.env.local"    $dst   # ← 이걸 빼먹으면 운영 DB에 붙는다
```

무엇이 왜 필요한지:

| 파일 | 안에서 쓰이는 키 | 없으면 |
|---|---|---|
| `.env` + `.env.local` | `DATABASE_URL_POOL`(필수), `SUPABASE_URL`·`SUPABASE_SERVICE_KEY`(데모 로그인), `ENV` | 서버가 아예 안 뜨거나 / 로그인 실패 / 운영 DB 접속 |
| `tts_key.json` | 설정의 `TTS_SA_KEY_FILE` 기본값. STT 전용 키(`STT_SA_KEY_FILE`)를 안 주면 **이 키를 재사용**한다 | **가짜 STT 폴백 → 실증 불가** |

> 값 자체는 이 문서에 적지 않는다. 파일을 그대로 복사하면 된다.

→ GCP 콘솔에서 해당 프로젝트의 **Speech-to-Text API 사용 설정**을 켜면 된다(1분).

### 5-1. 상단 지표 카드 4개

```
턴 수 | 감지지연 중앙값 | 파이프라인 지연(중앙값) | 잔여 오버헤드(중앙값) | 롤오버 갭(최대)
```

### 5-2. 턴 표 (한 줄 = 턴 하나)

```
#  턴 시작   턴 종료   발화     감지지연   파이프라인   잔여오버헤드   시작지연   전사
3  12.84s   15.62s   2780ms   921ms     310ms       -189ms        140ms     안녕하세요 저는…
```

| 열 | 뜻 |
|---|---|
| **감지지연** | 브라우저의 로컬 VAD가 본 *마지막 유성 프레임* → `user_turn_end` 도착까지. **사용자가 체감하는 값**. 1.2s 이하면 초록, 넘으면 빨강 |
| **파이프라인** | 서버가 보낸 오디오 총량 − STT 이벤트가 가리키는 오디오 시각 = **리전 왕복 + STT 인식 지연** |
| **잔여오버헤드** | 감지지연 − 침묵임계(800) − 파이프라인. 우리 코드 몫 |
| **시작지연** | 첫 유성 프레임 → `user_turn_start` 도착. **barge-in 반응 속도의 상한** |
| **롤오버 갭** | STT 스트림 교체로 생긴 오디오 공백(로그에도 `↻`로 찍힌다) |

### 5-3. ⚠ 요청하신 "리전 왕복 / STT 자체 / 서버 타이머" 3분할 — **정확히는 이렇게 보인다**

| 항목 | 화면에 분리돼 보이나 |
|---|---|
| **서버 타이머(침묵 임계)** | ✅ 보인다. 엔진 표시줄의 `침묵임계 800ms`, 계산에서 그대로 차감 |
| **리전 왕복 + STT 인식** | ⚠ **합쳐서 한 값**(`파이프라인` 열)이다 |
| **우리 코드 몫** | ✅ 보인다(`잔여오버헤드`) |

**리전 왕복과 STT 인식 지연은 서버 입장에서 분리할 수 없다** — STT가 주는 건 "이 이벤트가
가리키는 오디오 시각" 하나뿐이고, 그 값에는 네트워크와 엔진 처리가 이미 섞여 있다.
분리하려면 별도 실험이 필요하다: **같은 시나리오를 `STT_V2_LOCATION=global`과 `us`로 각각 돌려
`파이프라인` 값의 차이를 본다.** 그 차이가 리전 왕복 성분의 하한이다. (필요하면 그때 돌려 드린다.)

## 6. 판정 기준

### 6-1. 숫자 기준

| 지표 | 합격 | 경계 | 불합격 |
|---|---|---|---|
| **감지지연 중앙값** | **≤ 1,200ms** | 1,200~1,600ms | > 1,600ms |
| **파이프라인 지연 중앙값** | ≤ 400ms | 400~700ms | > 700ms → 리전/모델을 의심 |
| **잔여 오버헤드** | ≤ 150ms | ~300ms | > 300ms → 우리 코드가 느린 것 |
| **시작지연** | ≤ 500ms | ~800ms | > 800ms → barge-in 체감이 나쁘다 |
| **롤오버 갭** | ≤ 300ms, 그리고 **갭 때문에 놓친 말이 없을 것** | | 전사가 빠지면 불합격 |

왜 1,200ms인가: 침묵 임계 800ms는 **설계상 반드시 포함**되는 값이다(Live와 같은 값으로 시작했다).
거기에 우리가 감수하기로 한 파이프라인 여유 400ms를 더한 값이 상한이다. 이걸 넘으면
"Live만큼"이라는 목표를 못 맞춘 것이다.

### 6-2. 정성 기준 (숫자보다 이쪽이 중요할 수 있다)

- ✅ **시나리오 B에서 표가 1줄**이면 통과. 2줄이면 "3초 쉬면 말이 잘린다"는 뜻이다.
  → 이 경우 곧바로 불합격은 아니다. `CASCADE_TURN_SILENCE_MS`를 1500~2500으로 올려 재측정한다
  (그만큼 응답이 느려지는 맞교환이라, **어느 값이 견딜 만한지는 들어보고 정하는 것**이다).
- ✅ 시나리오 C에서 짧은 대답이 **전사와 함께** 잡히는가(전사가 비면 STT 모델을 바꿔야 한다).
- ✅ 시나리오 D에서 20초 넘게 말해도 턴이 임의로 쪼개지지 않는가.
- ✅ 전사 내용이 **알아들을 만한가**(한국어 인식 품질 자체).

## 7. 안 될 때 (증상 → 원인)

| 증상 | 원인 / 조치 |
|---|---|
| 화면에 노란 **"페이크 STT" 배너** | 키 미복사 / `google-cloud-speech` 미설치 / API 미활성 → 1단계 |
| `/health`의 `env`가 `prod` | `.env.local`이 없다. **즉시 중단**(운영 DB) |
| 로그인 실패 | `.env.local`의 Supabase 값 문제. 서버 로그 `dev_login:` 줄 확인 |
| 마이크 권한 팝업이 안 뜸 | 주소가 `localhost`/`127.0.0.1`인지 확인. 다른 호스트면 https 필요 |
| 소켓이 바로 닫힌다(1008) | 로그인 먼저. 토큰 없이는 소켓을 열지 않는다(과금 방지) |
| 전사가 계속 비어 있다 | 모델/리전 문제. `STT_V2_MODEL=chirp_3`, `STT_V2_LOCATION=us`로 바꿔 재시도(ko-KR 스트리밍 GA 조합) |
| `NOT_FOUND` / `INVALID_ARGUMENT` 로그 | 위와 동일. `global`에서 해당 모델이 안 서는 경우다 |
| 로그에 `↻ 롤오버`가 너무 잦다 | `STT_V2_STREAM_MAX_S`가 짧게 잡힌 것(기본 240s) |

설정은 전부 env라 **재빌드 없이** 바꿔 재측정할 수 있다. 예 — 침묵 임계를 1.5초로:

```powershell
# PowerShell (서버를 껐다 이 상태로 다시 띄운다)
$env:CASCADE_TURN_SILENCE_MS = "1500"
conda run -n beavertalk-server python -m uvicorn main:app --port 8000
```

같은 방식으로 `STT_V2_MODEL`, `STT_V2_LOCATION`, `STT_V2_STREAM_MAX_S`도 바꿀 수 있다.
원래대로 되돌리려면 그 PowerShell 창을 닫으면 된다(환경변수가 창 단위로만 산다).

## 7-2. (별도) 취소 배관 검증 — STEP 3

턴 감지(P0)와 **독립된 검증**이다. 마이크·STT와 무관하게 **취소 경로만** 잰다.

1. STEP 1에서 세션을 시작한다(마이크 권한은 필요하지만 말할 필요는 없다).
2. STEP 3의 **[🔊 가짜 비버 5초 재생]** → 440Hz 톤이 5초간 들린다.
3. 톤이 나오는 중에 **[✋ 지금 끊기]** → 소리가 즉시 멎어야 한다.
4. 아래 표에 실측이 뜬다.

| 표의 값 | 뜻 | 합격선 |
|---|---|---|
| **왕복 지연** | 서버가 `audio_cancel`을 쓴 시각 → `playback_progress` 도착. ⚠ **네트워크 왕복 포함** | 로컬은 ≤200ms |
| **클라 자체 정지 시간** | 앱이 취소를 받고 **실제로 조용해지기까지**. ⭐ 이게 진짜 봐야 할 값 | **50~120ms** |
| 네트워크 왕복(추정) | 왕복 − 클라 자체 | 참고용 |
| 버려진 양 | 보낸 것 중 안 들린 밀리초 | 클수록 취소가 빨랐다는 뜻 |
| **원장 절단 결과** | 실제로 들린 데까지의 대사만 남았는지 | `문장1 문장2 …`가 끊긴 지점까지만 |

> ⭐ **`CASCADE_MIC_ALWAYS_OPEN`을 켤 필요가 없다.** 이 취소는 STT 음성감지를 타지 않고
> 서버가 버튼 신호로 직접 쏜다. AEC 정비 전이라 그 플래그를 켜면 스피커폰에서 자기-대화
> 루프가 나므로, **끈 상태로 검증하는 것이 안전하면서 충분하다.**
>
> 브라우저의 "클라 자체 정지 시간"은 보통 한 자릿수 ms다(WebAudio는 즉시 정지). **의미 있는
> 값은 실기기(Flutter)에서 나온다** — 이 페이지는 서버 쪽 배관과 계약이 맞는지 보는 용도다.
