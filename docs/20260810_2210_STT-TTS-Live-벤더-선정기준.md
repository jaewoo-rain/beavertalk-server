# STT · TTS · Live 벤더 선정 기준 (2026-08-10)

> **이 문서를 먼저 읽고 판단한다.** 기억으로 판단하면 흔들린다 — 2026-08-10 하루에만
> 같은 요건을 두고 결론이 세 번 바뀌었다(아래 §5 사고 기록).
> 요건은 **코드에서 뽑았다.** 추측이 아니라 "이걸 안 주면 어디가 깨지는지"가 근거다.

---

## §0. 판정 규칙 — ⛔ 여기가 제일 중요하다

| 규칙 | 내용 |
|---|---|
| **R-A** | **실측 > 1차 문서 > 벤더 주장.** 벤더 주장은 "주장"이라고 표기하고 결론에 안 쓴다 |
| **R-B** | ⛔ **측정 안 한 것을 탈락시키지 않는다.** "문서에 없다"는 탈락 사유가 아니다 — 재보고 탈락시킨다 |
| **R-C** | 요건은 **hard / soft** 로 갈라 적는다. soft 를 hard 로 부르면 멀쩡한 후보를 버린다 |
| **R-D** | 한 후보에 적용한 정정은 **전 후보에 적용**한다(§5-③이 이걸 어긴 사고다) |
| **R-E** | 비교는 **같은 오디오·같은 지표**로만. 시험 방법이 다르면 결론이 아니라 잡음이다 |

## §1. STT 요건 — 코드 근거

우리 STT 어댑터는 `core/stt.py` 가 **4종 이벤트**로 정규화해 세션에 넘긴다(`SttV2Event`).
후보 벤더가 무엇을 주는지는 **이 4종으로 환산해서** 본다.

```
SPEECH_BEGIN     사용자가 말을 시작했다
SPEECH_END       엔진이 본 발화 종료
TRANSCRIPT       부분/최종 전사 (text, is_final)
STREAM_ROLLOVER  내부 스트림 교체(진단용)
```

### hard (없으면 제품이 성립 안 함)

| # | 요건 | 코드 근거 | 없으면 |
|---|---|---|---|
| H1 | **실시간 스트리밍** | `cascade_session` 이 오디오를 흘리며 턴을 판정 | 통화 자체가 불가 |
| H2 | **부분 전사(interim)** | `_on_transcript` → `ServerInputPartial`, 전사 정지 타이머 | 화면 자막 X + 턴 종료가 6초대로 밀림. **chirp_2/3 가 여기서 탈락했다(실측)** |
| H3 | **최종 전사(is_final)** | `_close_turn` → `_start_reply` | 비버가 대답을 못 함 |
| H4 | **PCM16 / 16kHz 입력** | `INPUT_SAMPLE_RATE` | 클라 오디오 규약 변경 필요 |
| H5 | **한국어 + 학습자 모국어 code-switching** | 어학 앱의 본질 — 학습자는 모국어로 묻고 한국어로 따라 말한다 | 통화의 절반이 사라짐(실측: `좋아해요`→`who are you`) |

### soft (있으면 좋지만, 없으면 코드로 메운다)

| # | 요건 | 없을 때의 대체 | 대가 |
|---|---|---|---|
| S1 | `SPEECH_BEGIN` | 첫 전사 도착을 시작으로 본다. **`_on_transcript` 에 이미 폴백이 있다** | ⭐ **barge-in 지연 0** — 어차피 확정을 전사로 하므로(2026-08-10 사장님 지시). 잡음 턴 관측만 잃는다 |
| S2 | `SPEECH_END` | 전사 정지 타이머(1.5초)가 주 경로 | 조용한 방에서 0.8초 → 1.5초 |
| S3 | `offset_ms`(오디오 시각) | `-1`(미상) 폴백이 이미 있다 | 침묵 임계에 왕복 지연이 얹힘 |

### 원가·운영

- **침묵 과금 여부** — 우리는 마이크 상시개방이다(실측: 발화 10초 / 과금 102초).
  초 단위 과금이면 침묵도 다 낸다. **문서로 안 나오면 소액 결제 후 청구서로 확인**한다.
- **리전** — 서울에서의 왕복. STT v2 는 서울·도쿄가 없어 이미 global/us 로 나간다.
- 기준선: **Google STT v2 $0.016/분** = 15분 통화 $0.23 = **통화 원가의 53%**.

## §2. TTS 요건 — 코드 근거

`core/tts.py: synthesize_stream()` 이 계약이다.

### hard

| # | 요건 | 코드 근거 |
|---|---|---|
| H1 | **스트리밍(조각 단위 산출)** | 페이서가 조각을 받는 즉시 송출 |
| H2 | **PCM16 / 24kHz 출력** | `CASCADE_TTS_SAMPLE_RATE = 24000`, 클라 재생 규약 |
| H3 | **첫 조각 지연이 작을 것** | 실측 벤더 TTFB: Chirp 165~212ms / Gemini 805~1271ms |
| H4 | **한국어 발음 정확** | ⛔ 비버는 **발음 선생님**이다. 학습자가 그대로 따라 한다 |
| H5 | **실시간 배속 ≥ 1.0** | 합성이 재생보다 느리면 끊긴다(실측 Gemini 1.48~1.94x — 통과) |

### soft

| # | 요건 | 비고 |
|---|---|---|
| S1 | **스타일/감정 지시** | Gemini-TTS 만 받는다. Chirp 은 무시 → 감정 태그가 안 들림 |
| S2 | **speaking_rate** | 범위 [0.25, 2.0] |
| S3 | **다국어 단일 음성** | 있으면 마커 분할이 줄어 429·구간 침묵이 같이 줄어든다 |

### ⛔ 함정 (실측으로 확인된 것)

- **구간마다 앞뒤 침묵이 붙는다.** Gemini 는 3글자 구간이 1.3~1.7초였다.
  → `CASCADE_TTS_TRIM_*` 로 잘라낸다. 벤더 비교 시 **이 보정 전/후를 구분**할 것.
- **스타일 프롬프트의 낱말이 속도를 바꾼다.** `"또박또박"` 하나가 한국어 속도를 절반으로 깎았다.
- **할당량**: Gemini-TTS 는 **분당 10회**(전 리전·전 모델 공통). 대답 1건이 3~6회를 쓴다.
  → 동시 3~5명이 상한이다. 증액 신청 중(2026-08-10, 1000 요청).

### 목표 속도 — ⭐ 라이브가 정답지다

사장님이 "라이브 속도는 딱 좋다"고 하셨다. 그 실측이 목표다.

```
Live 한국어  6.3~8.5 자per초 (중앙 7.7, 표본 9)
```
⛔ **`자per초` 는 언어 간 비교가 불가능하다.** 한국어 1글자(음절)가 영어 3~4글자 소리다.
**같은 언어끼리만** 비교한다. 영어 목표는 Chirp 실측 **19.6 자per초**.

## §3. Live(음성↔음성) 요건

현행 Gemini Live 를 대체하려면:

| 요건 | 현행 |
|---|---|
| 네이티브 오디오 입출력 | `gemini-live-2.5-flash-native-audio` |
| 세션 유지·재연결 | 연결 ~10분 한계를 세대 루프로 넘김(15분 통화) |
| context window compression | 드리프트 완화 |
| 입출력 전사 | 통화후 분석·문장 추출의 재료 |
| barge-in | ⛔ 현재 **off**(불변식) |

### 단가 (100만 토큰당, 2026-08-10 확인)

```
Gemini Live         in_audio  $3.00   out_audio $12.00     ← 현행. 15분 실측 $1.87
gpt-realtime-mini   in_audio $10.00   out_audio $20.00     3.3배 / 1.7배 비쌈
gpt-realtime        in_audio $32.00   out_audio $64.00     10배 / 5.3배
```
⚠ **초당 토큰 수가 벤더마다 달라** 단가만으로 최종 비교 불가. 같은 통화 실측이 필요하다.
⭐ 현시점 결론: **Live 대체는 원가상 이길 이유가 없다.** 캐스케이드($0.44/15분)가 원가 답이다.

## §4. 확정된 실측 (2026-08-10, 같은 합성 오디오)

| 구성 | 부분전사 | 첫 전사 | VAD | ko+en code-switching |
|---|---|---|---|---|
| `global/long` + [ko,en] (**현행**) | 56건 | 2703ms | BEGIN | ⛔ `"Today I want to study"` → `"주제에 원 투 쓰리"` |
| `us-central1/chirp` + [ko] | 58건 | 1811ms | BEGIN+END | ✅ 정확 |
| `us-central1/chirp_2` + [ko] | **1건** | 6313ms | BEGIN+END | ✅ 정확하나 **H2 탈락** |
| `us/chirp_3` + [ko] 또는 [ko,en] | **0건** | 6079ms | BEGIN+END | ✅ 정확하나 **H2 탈락** |

- **다국어(language_codes 2개+)는 `eu`·`global`·`us` 에서만** 된다. `us-central1` 은 400.
- **`global` 에는 chirp 계열이 없다.** ko-KR 기준.
- ⛔ **chirp 은 ko+en 외의 쌍에서 한국어까지 잃었다**(ja/hi/ar/zh 는 `안녕하세요` 소실, fr 은 전무).
  ⚠ 단 그 시험은 언어별 합성을 이어붙인 것이라 **이음매가 오염원일 수 있다**(재시험 중).
- **`global/long` 은 ar-XA·zh-CN 을 아예 지원 안 한다**(400) → 아랍어·중국어 학습자 수용 불가.

⇒ **Google 안에서는 어느 조합도 H1~H5 를 다 못 채운다.**

### §4-2. 벤더 비교 — 같은 오디오(ko + X + ko 이어붙임), 2026-08-10

| | 영어 | 일본어 | 프랑스어 | 중국어 | 아랍어 | 힌디어 |
|---|---|---|---|---|---|---|
| `global/long` +[ko,X] | ✅ | ⛔ 음차 | ⛔ 음차 | ⛔ 400 | ⛔ 400 | ⛔ 음차 |
| `us-central1/chirp` +[ko] | ✅ | ⛔ 전무 | ⛔ 한국어 소실 | ⛔ 전무 | ⛔ | ⛔ |
| `gpt-4o-transcribe`(배치) | ⛔ 영어소실 | ⚠ 한국어로 번역 | ✅ | ⛔ | ⛔ | ⛔ |
| `gpt-4o-mini-transcribe`(배치) | ✅ | ⚠ 일본어로 번역 | ✅ | ⛔ | ⛔ | ⛔ |
| **`scribe_v1`(배치)** | ✅ | ✅ | ✅ | ✅ | ✅ | ⚠ 음차 |
| `scribe_v2_realtime`(실시간) | ✅ | ⛔ 소실 | — | ✅ | — | — |

⭐ **배치 ≠ 실시간.** Scribe 는 배치에서 6/6 에 가까웠지만 **실시간에서 일본어가 사라졌다.**
  벤더 비교는 반드시 **실시간 경로로** 해야 한다.
⚠ `secondary_languages`(ElevenLabs) 를 지정해도 결과가 바뀌지 않았다. 자동 감지가 최선이다.
⚠ OpenAI·ElevenLabs 는 `language` 를 **하나만** 받는다 — 다국어는 "안 넣기"가 유일한 방법이다.

### §4-3. 실시간 후보 지표

| 구성 | 부분전사 | 첫 전사 | 발화 이벤트 |
|---|---|---|---|
| `global/long` (현행) | 56건 | 2703ms | BEGIN |
| `us-central1/chirp` | 58건 | 1811ms | BEGIN+END |
| `scribe_v2_realtime` | 4~7건 | ~2650ms | ⛔ 없음(S1) |

⛔ **일본어를 실시간으로 처리하는 후보가 아직 하나도 없다.** 일본어는 우리 2위 사용 언어다
(ja 57 · en 19 · fr 11 통화).

## §5. 사고 기록 — 같은 실수를 반복하지 않기 위해

1. **"chirp 이 답이다"** — ko+en **한 쌍만** 보고 일반화했다. 5쌍을 재니 무너졌다.
   → **R-E**: 한 표본으로 결론내지 않는다.
2. **"첫소리가 2배 느려졌다"** — 지표가 페이서 시간을 포함하고 있었다. 잘못 잰 숫자로 하루를 태웠다.
   → 지표가 **무엇에서 무엇까지인지** 먼저 코드로 확인한다.
3. ⛔ **ElevenLabs Scribe 를 "VAD 이벤트 없음"으로 탈락시킨 뒤, 같은 요건을 Soniox 에는 완화했다.**
   → **R-C/R-D**: S1 은 soft 다. 그리고 정정은 전 후보에 적용한다.
4. **"또박또박"** — `"천천히"` 를 지우면서 같은 뜻인 낱말을 남겼다. 회귀 테스트로 박았다.

| 후보 | 측정 가능? | 상태 |

| **OpenAI** (`gpt-4o-transcribe`, `-mini`) | ✅ 키 보유 | 측정 중. $0.006 / $0.003 per 분(구글의 1/2.7 · 1/5.3) |

| Deepgram / AssemblyAI / Speechmatics | 무료 키 넉넉 | ⛔ **한국어가 code-switching 대상이 아님**(1차) — H5 탈락 |

| Whisper(원본·Groq) | — | ⛔ 배치 전용 — H1 탈락. "Whisper 가 다국어에 강하다"는 **배치 성능** 이야기다 |
| Typecast | — | STT 아님(TTS 전용). ⭐ TTS 후보로는 유효 — 한국 회사 + 감정 TTS |

## §7. 다음에 이 문서를 고칠 때

- 실측이 나오면 §4 에 **같은 오디오·같은 지표**로 추가한다. 다른 시험은 섞지 않는다.
- 요건이 hard↔soft 로 바뀌면 §1·§2 를 고치고 **§5 에 왜 바뀌었는지** 남긴다.
- ⛔ 후보를 탈락시킬 때는 **어느 요건 번호 때문인지** 적는다. "느낌상 안 맞다"는 사유가 아니다.
