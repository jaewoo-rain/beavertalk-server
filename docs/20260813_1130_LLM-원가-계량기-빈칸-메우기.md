# LLM 원가 계량기가 60~87% 비어 있던 것 — 상한이 원인, 추정으로 메운다

작업일시 2026-08-13 11:30 · 담당 bt-back · 대상 `feat/cascade-voice`

## 1. 무엇이 잘못돼 있었나

실통화 6건의 `cascade usage:` 줄:

```
llm_calls=23  unknown=14   (61%)
        =26        =17     (65%)
        =23        =20     (87%)
        =27        =23     (85%)
        =22        =17     (77%)
        =26        =20     (77%)
```

LLM 호출의 **60~87%가 토큰 수 없이** 끝나고 있었다. 그 회차는 원가 계산에서 통째로 빠진다.
23콜 중 9콜만 세어 `llm_in=28,192` 였으니, 실제는 **약 2.5배**(≈72,000)다.
⇒ 원가 계기판이 **하한을 진실로 표시**하고 있었다.

## 2. 원인 — 벤더가 아니라 우리다

사슬 (전부 코드로 확인):

1. `cascade_session.py:2300-2308` — 문장 상한(`CASCADE_LLM_MAX_SENTENCES=3`)을 채우면
   `await stream.aclose()` 로 **남은 생성을 안 받는다**(원가·지연 절감이 목적).
2. `core/gemini_chat.py:54-58` — usage 는 조각마다 갱신될 수 있으나, Gemini 는 실제로
   **마지막 조각에만** `usage_metadata` 를 싣는다.
3. ⇒ 상한에서 끊은 회차는 그 마지막 조각을 **영영 못 받는다**.

⚠ **상한이 잘 걸릴수록 장부가 더 빈다** — 87%짜리 통화가 상한이 제일 잘 걸린 통화다.
계량기가 "잘 도는 통화일수록 더 모른다"는 방향으로 틀려 있었다.

## 3. 고른 처방과 버린 처방

| 안 | 내용 | 판정 |
|---|---|---|
| A | `aclose()` 를 되돌려 끝까지 받는다 | ⛔ 상한의 목적(원가·지연 절감)을 없앤다 |
| B | `count_tokens` API 로 프롬프트를 센다 | ⛔ 턴마다 추가 호출 — 비용·지연을 내고 장부를 산다 |
| C | **같은 통화의 실측 회차로 메운다** | ⭐ 채택 — 추가 호출 0·비용 0 |

### C 의 산식

- **입력** = 그 회차와 **가장 가까운 실측 회차**의 `prompt_token_count`.
  ⛔ 평균이 아니다 — 프롬프트는 이력이 쌓이며 **단조 증가**하므로 평균은 초반을 과대,
  후반을 과소 추정한다. 거리가 같으면 **앞쪽**(더 작은 값)을 택한다.
- **출력** = 그 통화의 **글자→토큰 비율** × 그 회차가 생성한 글자수.
  비율을 통화 안에서 뽑는 이유: 언어(한국어/영어)마다 글자당 토큰이 배로 다르다.
- ⛔ 실측이 **한 건도 없으면 아무것도 추정하지 않는다.** `unknown` 으로 비워 둔다.

## 4. 계약 변화 (읽는 사람이 알아야 할 것)

⚠ **`llm_in`·`llm_out` 의 의미가 바뀌었다** — 2026-08-13 부터 **실측+추정**이다.
그 전 값은 과소집계였으므로 시계열에 계단이 생긴다. 그 계단은 사고가 아니라 이 수정이다.

⛔ **실측과 추정을 한 칸에 섞어 두고 끝내지 않는다.** 되가를 수 있게 남긴다:

```
vendors.llm = { in_text        : 실측+추정 (원가는 이걸 쓴다)
                in_text_measured / out_text_measured : 실측만
                in_text_est      / out_text_est      : 추정만
                est_calls  : 메운 회차 수
                unknown    : **끝내 못 메운** 회차 수 }
```

로그 줄에는 추정이 섞이면 **항상** 이 칸이 함께 뜬다 — 합계만 보고 실측으로 읽지 않게:

```
llm_in=2000 llm_out=150 llm_calls=2 llm_est=1콜(in+1000 out+100)
```

원가는 `estimate_cascade_cost_usd` 가 `vendors.llm` 을 읽으므로 **자동으로 교정된다**
(입구가 하나라서 다른 데를 안 고쳐도 된다).
