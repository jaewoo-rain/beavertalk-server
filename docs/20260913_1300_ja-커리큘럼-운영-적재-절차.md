# 일본어(ja) 커리큘럼 — 운영 DB 적재 절차 (2026-09-13)

> 대상: bt-back(적재는 사장님 «적재» 뒤 bt-back 이 한다). 원료·시드 = `assets/curriculum_v3/cur_seed_ja.json`(345차시 · 어휘 4,328 · 문법 618) + 옛 `learning_item`(language=ja, kind=chunk) 청크 46 → 레벨1 3차시(L1-S01-1/S02-1/S03-1, ko 와 동일 — 사장님 2026-09-13) = **차시 348**,
> 로더 = `scripts/curriculum/load_cur_seed.py --language ja`. 배선 = feat/curriculum-v3(2단계 커밋) 이 **먼저 배포**돼 있어야 한다.

## 0. 왜 순서가 중요한가
`curriculum_service.available(db, language)` 는 «그 언어의 cur_lesson no=1 이 있나» 로 cur 경로를 연다. 배선 전 코드에 ja 행이 있으면
`target_language=ja` 회원이 cur 경로로 들어가 **ko 차시를 받는다**(옛 코드의 open_call 기본값이 ko). ⇒ **배선 배포 → 적재**. 반대 순서 금지.
배선 뒤·적재 전에는 ja 회원은 `available("ja")=False` 로 옛 경로(안전).

## 1. 적재
```bash
# 워크트리가 아니라 **운영 체크아웃**(.env = 운영, DATABASE_URL_DIRECT 5432)에서. 먼저 dry-run 으로 불변식만 본다(롤백).
PYTHONIOENCODING=utf-8 conda run -n beavertalk-server python scripts/curriculum/load_cur_seed.py --language ja --dry-run
# PASS 7종 확인 뒤 실제 적재(트랜잭션 1개, 불변식 실패 시 자동 롤백·exit 1)
PYTHONIOENCODING=utf-8 conda run -n beavertalk-server python scripts/curriculum/load_cur_seed.py --language ja
```
멱등이다 — 두 번 돌려도 행 수가 늘지 않는다(시험 `test_ja_load_passes_invariants_and_is_idempotent`). ko 행은 건드리지 않는다(언어별로 센다).
⚠ 청크 3차시 없이 적재된 ja(345, A1-T01-1=no 1)가 이미 있어도 그대로 다시 돌리면 된다 — 재적재는 code 기준 갱신이고 **no 재매김은 2단계**(바뀌는 행을 음수 no 로 비켜 두고 flush → 새 no, `stats.renumbered`)라 `uq_cur_lesson_no` 충돌이 없고, 회원 진도(cur_member_progress·cur_member_lesson·cur_call)는 lesson_id 로 묶여 있어 그대로다(시험 `test_ja_reload_renumbers_lessons_in_place_when_chunk_lessons_are_added`). ja 청크 46 은 옛 `learning_item` 에 있어야 한다(없으면 exit 1).
`cur_topic` 은 언어 공유(코드 65) — ja 적재가 ko 주제 행을 UPDATE(area·name·kind 같은 값)한다. 정상.

## 2. 검증 SELECT (적재 직후)
```sql
SELECT COUNT(*) FROM cur_lesson WHERE language='ja';                                   -- 348
SELECT MIN(no), MAX(no), COUNT(DISTINCT no) FROM cur_lesson WHERE language='ja';        -- 1, 348, 348
SELECT code, no, level_no, item_count FROM cur_lesson WHERE language='ja' AND no<=4 ORDER BY no;
  -- L1-S01-1 1 1 15 · L1-S02-1 2 1 15 · L1-S03-1 3 1 16 · A1-T01-1 4 2 18
SELECT kind, COUNT(*) FROM cur_item WHERE language='ja' AND retired_at IS NULL GROUP BY kind;  -- vocab 4328 · grammar 618 · chunk 46 (= 4992)
SELECT COUNT(*) FROM cur_lesson_item li JOIN cur_lesson l ON l.lesson_id=li.lesson_id WHERE l.language='ja';   -- 5038
SELECT meanings FROM cur_item WHERE language='ja' AND kind='chunk' ORDER BY item_id LIMIT 1;   -- {"en": ..., "roman": ..., "ko": ..., "kana": <옛 reading>}
SELECT key, meanings->>'ko' FROM cur_item WHERE language='ja' AND kind='chunk' AND key IN ('どうも','ありがとうございます','ごめんなさい','すみません');
  -- 2026-09-14 ③ 뜻풀이 구분(CHUNK_MEANING_OVERRIDES_JA 12개): どうも «고마워요(가볍게·아주 짧게 — ありがとう 아님)» · ありがとうございます «감사합니다(정중하게)» …
  -- 이미 적재된 ja 에 같은 명령을 다시 돌리면 meanings 만 덧씌워진다(멱등, 회원 진도 무영향).
SELECT COUNT(*), COUNT(DISTINCT li.item_id) FROM cur_lesson_item li JOIN cur_item i ON i.item_id=li.item_id
  JOIN cur_lesson l ON l.lesson_id=li.lesson_id WHERE l.language='ja' AND i.kind='vocab';      -- 4328, 4328 (어휘 전건 정확히 1차시)
SELECT meanings FROM cur_item WHERE language='ja' AND kind='vocab' AND key='名前';            -- {"en": "name", "ko": "이름", "kana": "なまえ"}
SELECT COUNT(*) FROM cur_topic;                                                        -- 65 (변화 없음)
-- ko 무변화
SELECT COUNT(*) FROM cur_lesson WHERE language='ko';                                   -- 491
SELECT COUNT(*) FROM cur_item WHERE language='ko' AND retired_at IS NULL;              -- 11144
```
앱 확인: `target_language='ja'` 회원(레벨테스트 뒤 `member_language_level(ja)` 행 필요)으로 `GET /api/v1/cur/me` → `lesson.code="L1-S01-1"`, `no=1`,
`level_no=1`, `items_total=15`(청크). auto 통화 로그 «normalcall cur 표현학습: lesson=L1-S01-1(no=1) …». 청크 3차시 뒤 `A1-T01-1(no=4)` 부터 대본에 «격식 표지(です·ます)».
초기화 `POST /__dev/cur-reset`(lesson_no 없음)도 ja 에서 no=1 = L1-S01-1 로 놓는다(시험 `test_cur_reset_ja_points_at_lesson_1_which_is_the_survival_chunk_lesson`).

## 3. 롤백 (ja 행 삭제 — 회원 진도가 있으면 그것부터, FK 순서)
```sql
BEGIN;
DELETE FROM cur_member_item   WHERE lesson_id IN (SELECT lesson_id FROM cur_lesson WHERE language='ja');
DELETE FROM cur_member_lesson WHERE lesson_id IN (SELECT lesson_id FROM cur_lesson WHERE language='ja');
DELETE FROM cur_call          WHERE lesson_id IN (SELECT lesson_id FROM cur_lesson WHERE language='ja');
DELETE FROM cur_member_progress WHERE language='ja';
DELETE FROM cur_lesson_item   WHERE lesson_id IN (SELECT lesson_id FROM cur_lesson WHERE language='ja');
DELETE FROM cur_lesson        WHERE language='ja';
DELETE FROM cur_item          WHERE language='ja';
COMMIT;
```
`cur_topic` 은 지우지 않는다(ko 가 쓴다). 롤백 뒤 `available("ja")=False` → ja 회원은 옛 경로로 돌아간다(코드 되돌림 불필요).
⚠ 회원 진도(cur_member_*)를 지우는 것은 **그 회원의 ja 학습 기록 삭제**다 — 실사용자 진도가 있으면 사장님 확인 뒤.
