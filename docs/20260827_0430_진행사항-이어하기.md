## §1. 오늘 확정한 것 (⭐ 가장 중요)

### ⛔ 착수 전제가 뒤집혔다 — "15분 동안 성격이 흐려진다"는 사실이 아니다

실통화 `call_id=1232`(바바·15분 26초·3조각·비버 44턴/학습자 42턴)로 확인했다.
조각 경계 첫 발화 3개가 전부 캐릭터 그대로였다:

| 조각 | 첫 발화 |
|---|---|
| 1 (0s) | "Hey qlqj! Do you want to study Korean today...?" |
| 2 (312s) | "Hey, qlqj. **Don't get distracted!** We were talking about weather." |
| 3 (624s) | "Hey, qlqj, **stop daydreaming about Jeju!**" |

15분 끝자락(880s)에도 `HAHAHA! ... are you salty about being bad at this?` 가 나왔다.
조각마다 `system_instruction` 이 재조립돼 들어가므로 `build_resume_brief` 에 캐릭터가 없어도
문제가 되지 않는다. **착수 때 세운 "이어하기 브리프에 캐릭터가 없어 조각 첫 턴이 무채색이 될 것"
가설은 반증됐다.**

### ⭐ 진짜 문제 — 캐릭터가 나올 자리가 턴의 1/3뿐

독설이 실린 비버 턴 = **44턴 중 13턴(30%)**. 나머지는 "Okay / Fine / Simple enough / Whatever".
그리고 **이건 지시를 어긴 게 아니라 지시대로다** — 현행 `personality` 는 '반응'(칭찬·핀잔)만
규정하고 **'진행'(다음 문제를 내는 부분, 턴의 2/3)에는 지시가 0줄**이다. 5명 전부 같다.

⇒ 개선 방향은 "유지"가 아니라 **"발현 자리 넓히기"**.

### 지분 실측 (DB·서버 없이 재현 가능)

`build_system_instruction` 은 순수 문자열 조립 + 표준 라이브러리라, CSV 값만 있으면 통화 없이
지시문 전문이 그대로 나온다.

| 항목 | 값 |
|---|---|
| 지시문 전문 | 46줄 / 3,650자 |
| 캐릭터가 바꾸는 줄 | **6줄** (40줄은 5명이 글자까지 동일) |
| `personality` 447자 중 5명 공통 | **286자 (64%)** |
| **캐릭터 고유** | **161자 = 전체의 8.3%** |

## §5. demo-api 장애 (미해결)

```
00:50  demo-api 통화 정상(마지막 성공)

01:12~01:14  demo-api 시도 7건 전부 즉사 (segments=0 duration=0s)
```

- 시크릿 `beavertalk-app-gcp-key` 는 **07-25 이후 안 바뀌었다**. 리비전도 08-22 이후 없다
- 갈림: **app-api = `USE_VERTEX=false` + `GEMINI_API_KEY`(정상)** / **demo-api = `USE_VERTEX=true` + SA 키(깨짐)**
- ⚠ app-api 배포가 demo-api 를 깰 경로는 안 보인다 — **인과 미확인**

**우회안**(원인 규명 아님, 승인 필요):
```
gcloud run services update beavertalk-app-demo-api --project bt-dev-web-01 \
  --region asia-northeast3 --update-env-vars USE_VERTEX=false,GEMINI_API_KEY=<app-api 의 그 키>
```
