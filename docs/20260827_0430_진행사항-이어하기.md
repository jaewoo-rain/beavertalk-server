### ⛔ 착수 전제가 뒤집혔다 — "15분 동안 성격이 흐려진다"는 사실이 아니다

실통화 `call_id=1232`(바바·15분 26초·3조각·비버 44턴/학습자 42턴)로 확인했다.

### ⭐ 진짜 문제 — 캐릭터가 나올 자리가 턴의 1/3뿐

독설이 실린 비버 턴 = **44턴 중 13턴(30%)**. 나머지는 "Okay / Fine / Simple enough / Whatever".
그리고 **이건 지시를 어긴 게 아니라 지시대로다** — 현행 `personality` 는 '반응'(칭찬·핀잔)만

⇒ 개선 방향은 "유지"가 아니라 **"발현 자리 넓히기"**.

## §2-1. ⭐ 침묵의 원인 규명 — "서버가 느린 것"이 아니다

### 측정이 방향을 가른다
학습자 전사가 찍힌 시각 → 비버 첫 응답 = **중앙값 0.0초**(42턴 전부).
⇒ **"말이 끝났다"고 판정되는 순간 모델은 즉시 답한다. 서버·모델 생성 지연은 사실상 0이다.**
침묵은 **그 판정이 떨어지기까지**에 있다.

### 결정적 증거 — 두 번 말한 게 *한 턴 안에* 들어갔다
```
👤 USER[t4]: 이 옷은 정말 싸요.이 옷은 정말 싸요.
```
두 번째가 **새 턴이 아니라 같은 턴**이다. "비버가 첫 발화를 못 들었다"면 별개 턴이어야 한다.
한 턴이라는 건 **Gemini 가 첫 문장 뒤에도 계속 듣고 있었다**는 뜻이다 — 다시 말하니 그제야
턴을 닫았다. 중복 7건이 전부 같은 모양이다.

### 원인 = 자동 VAD(말끝 감지) 임계값 + 반이중
그 임계를 조절하는 자리는 `realtime_input_config` 인데 **일부러 안 넣고 있다**:
- `core/gemini_live.py:131` — *"realtime_input_config 는 넣지 않는다(무음 버그)."*
- `docs/20260625_0936_normalcall-backend-design.md:122` — **불변식 목록에 들어 있다**
  ("`realtime_input_config` 금지(간헐 무음 버그)")
- `tests/test_gemini_live_config.py:114` — `assert cfg.realtime_input_config is None` 로 **강제**

⇒ 지금 침묵은 **기본 임계값**이다.

여기에 **반이중(barge-in off)** 이 겹친다. 비버가 말하는 동안 마이크가 서버로 안 간다
(`micGateReason: '라이브 통로 — 반이중 게이팅'`). 그리고 ⚠ **로그의 비버 "발화 길이"(2~5초)는
텍스트 생성 시간이지 소리 길이가 아니다** — 40단어 응답은 텍스트가 3초에 끝나도 소리는 15~20초다.

**한 턴의 실제 흐름:**
```
비버 오디오 재생(10~20초, 마이크 닫힘)
  → 마이크 열림 → 학습자 발화(2~3초)
  → ⏳ VAD 가 말끝을 확정할 때까지 대기   ← 사장님이 "침묵"으로 느낀 구간
  → 모델 응답(0.0초, 즉시)
```
학습자 차례 중앙값 16.5초의 대부분은 **앞 두 구간**이다.

### ⛔ 확정 못 한 것
**VAD 임계가 몇 초인지는 로그로 못 잰다.** 서버는 판정을 *받는* 쪽이라 "학습자가 말을 멈춘 시각"이
어디에도 안 남는다. 재려면 **클라 계측(마이크 입력 RMS 하강 시각)** 이 필요하다 — 08-23 방식.

### 고치려면 (⛔ 오늘 하지 않기로 한 이유 포함)
프롬프트로는 못 고친다. 유일한 프롬프트 우회는 응답을 짧게 해 오디오 재생을 줄이는 것인데
**08-22 에 사장님이 막으셨다**("응답 길이 짧게 하지 마셈").

| 필요한 것 | 비고 |
|---|---|
| `core/gemini_live.py` config 수정 | 코드는 몇 줄 |
| `tests/test_gemini_live_config.py` 고정 계약 변경 | "금지" → "이 값으로 허용" |
| 통화 회귀(`test_normalcall_ws.py`) | **R4 요구** |
| 실통화 검증 | ⛔ **demo-api 가 살아야 한다** |
| 사장님 승인 | **R4 불변식 변경** |

⚠ **"간헐" 무음 버그다.** 통화 한 번 해보고 "괜찮네" 하면 안 된다. 그래서 금지 규칙이 생겼다.

### ⇒ 권장 순서
1. 캐릭터 성격(DB 문구) 먼저 끝낸다
2. demo-api 복구
3. **클라에 마이크 RMS 계측을 붙여 VAD 대기를 숫자로 잡는다** — 숫자 없이 불변식을 건드리지 않는다
4. 그 숫자를 근거로 승인받아 `realtime_input_config` 를 건드린다

⛔ **캐릭터 작업과 섞지 마라.** 하나는 DB 문구, 하나는 통화 배관이다. 섞으면 뭐가 뭘 고쳤는지
못 가린다(08-23 교훈: *"끊김은 클라, 굼뜸은 서버 — 섞지 마라"*).
